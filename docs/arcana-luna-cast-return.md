# 루나의 지팡이 시전에서 현재 걸음으로

2026-11-08 · 컨셉 개발 50회차. 기준 `7403db217dfc4348f041130303c55e14906dae56`, 개발 브랜치 `codex/arcana-stage-experience-20261106`.

## 컨셉과 선택한 차이

원본 `art-source/defense/atlases/ranged-motion.png`의 루나 행에서 큰 귀·구리색 머리카락·녹색 망토·가지 지팡이를 확인하고 현재 PC/모바일 전장과 비교했다. 기존 시전 진입은 앞 회차에 끝났지만, 시전 뒤에는 고정 회수 이미지에서 다음 보행 이미지로 바로 넘어갔다. 이번에는 몸이 먼저 돌아오고 지팡이 손이 작은 호로 접힌 뒤 망토·머리카락·귀가 따라오는 실제 동작을 추가했다. 기존 체형·재질과 고유 실루엣을 유지한다.

서리늑대 보행·피격·쓰러짐, 영웅의 기존 방향별 시전, 주요 포탑 조준·반동, 지형·성문의 완료 계보를 보존했다. main `2eabc76`, Claude `nice-meitner` `bf7c1c6`를 확인했다. `wizardly-shannon`은 `0ac6ac5`로 진행되어 새 `cycles/57-physics.md`의 약점 명중 소리 필터·별도 재생 제안을 읽었다. 소리 변경과 PR81의 번개탑 표적 선택은 이번 동작과 별개다. 작업 트리는 깨끗했고 다른 편집 세션은 없었으며 기존 Vite 프로세스를 유지했다.

## 실제 동작과 전투 연결

- `luna-return-0`~`7`, 각각 0.12초·100fps·17개 애니메이션 노드의 실제 GLB 클립이다. 시작은 기존 0.15초 발사 자세, 끝은 여덟 보행 자세와 일치한다.
- 몸의 회수를 먼저 시작하고 양손·지팡이는 0.02초, 머리카락·망토·귀·옷자락은 0.025초 늦게 따라온다. 지팡이 손은 높이 0.045 모델 단위의 작은 호로 접힌다. 양팔을 공통 어깨·팔꿈치·손 끝점으로 다시 계산해 소매 연결을 유지한다.
- 다음에 들 발을 조금 들어 보행에 합류하고 다른 발바닥은 지면 높이를 유지한다. 모델 내부 접지이며 월드 좌표나 경사에 맞춘 IK는 아니다.
- **0.15초 발사, 전체 0.33초 공격, 피해·이동·투사체 소켓과 엔진 상태를 유지한다.** 새 회수는 공격 0.21~0.33초에만 표시한다.
- 기존 발사 이미지 → 새 체중 회수 이미지 → 새 발 들기 이미지 → 현재 보행 이미지를 사용한다. 경계는 0.225/0.27/0.32초이며 새 이미지는 클립의 0.04/0.10초에서 베이크했다.
- 공격 시작 시 기록한 걸음이 아니라 **현재 이동 거리의 걸음**을 선택한다. 이동 방향과 공격 방향의 8방향 구간이 같을 때만 적용하고 정지·방향 불일치·동작 줄이기는 기존 회수를 따른다. 필살기·돌진 우선순위를 유지한다.
- 새 회수 세트의 이미지 하나라도 실패하면 기존 회수로 돌아간다. 앞 회차 진입 세트의 실패는 회수 세트를 끄지 않는다. 기존 시전/보행 세트의 실패 대체 규칙도 유지한다.

전투는 베이크 WebP 기반 2.5D다. 모델 작업실에서 복귀 걸음을 선택해 단일 실시간 3D 장면의 GLB를 재생한다. 유닛별 WebGL 렌더러는 추가하지 않았다.

## 원본과 재생성

## 검증 기록

증거 폴더 `/tmp/arcana-hourly-20261108-1841/`에 시작 시 기준·소유 브랜치·범위·수용 기준·미완료 상태를 남기고 단계별로 갱신했다.

- 전체 테스트 **325개 중 324개 통과**. 실패 1건은 기준에서도 재현한 수학 게임 `(3×7)/5`의 4/4.2 불일치다. 기준 복사본의 외부 `math_speed` 경로를 복원한 뒤 같은 실패를 확인했다.
- GLB 저작 시점 104개·보간 시점 392개: 발사 시작 오차 `2.40e-7`, 보행 끝 오차 `2.40e-7` 미만. 한 발바닥이 높이 0.005 부근을 유지한다. 최대 팔 연결 오차는 모델 단위 0.000579, 공통 카메라 약 **0.033px**다. 원본·생성기·산출물 해시 143개 통과.
- 0.04초 시점의 회수 진행은 몸 약 26%, 지팡이 손 약 15~18%, 가지 지팡이 약 10%, 망토 약 7%로 순서를 확인했다. `.blend` 재열기에서 153개 메시×8세트 시작/끝 변환 오차 `5.52e-18` 미만이다.
- 스테이지 1·4·5·8의 영웅/용병 8게임·14,400스텝을 기준과 비교해 **제외 필드 없이 게임 상태가 일치**했다.

- 타입 검사·프로덕션 빌드 통과. PNG 128장·WebP 128셀의 해상도·투명 경계, 최소 여백 15px, 빌드 파일 11개와 원본 일치를 확인했다.
- 실제 UI 첫 검사는 왕복 이동 중 공격 방향이 달라 중간 복귀 포즈를 충분히 포착하지 못했다. 이 경로의 실패 로그를 보존하고 가까운 적을 향해 이동하는 입력으로 확인했다. 2배속 전환 후 기존 공격이 끝나도록 시간을 진행시켜 새 공격을 검사했다.
- 실제 게임 UI에서 PC 1440px·390px 터치로 입장→이동→웨이브→자연 시전→보행 회수, 1·2배속, 회수 중 일시정지→동작 줄이기→복원→재개를 조작했다. 8보행 프레임과 준비·발사·회수, 현재 걸음으로 달라지는 복귀를 확인했다. 모바일 전장 확대도 조작했다.
- 작업실 PC 8클립, 390/320px 각각 3클립에서 재생·최종 자세 유지·메시 보기·회전·초기화·동작 줄이기·단일 캔버스와 GLB 실패 시 PNG 명시 대체를 확인했다. 기존 이안 정지 항목도 정상이다.
- 원본 컨셉, 같은 조건의 전후 전장, 실제 전투·모바일 확대와 3D 작업실 화면을 직접 확인했다. 모바일은 Chromium 터치 에뮬레이션이다. Browser 스킬을 읽고 도구를 검색했으나 연결용 `js`/클라우드 CUA 실행 도구가 없어 워크스페이스 Playwright를 사용했다. URL·제목·유의미한 화면·오류 오버레이·페이지 오류·조작 후 상태를 확인했다.
- 실제 `DefenseBoard`의 영웅/용병×8방향×8걸음·시전 시점, 1440/390/320px, 동작 줄이기, 새 회수·기존 진입·시전·보행 이미지 실패 **3,072조합**이 통과했다. 현재 걸음 재선택·승급 크기·정지/방향 불일치·필살기/돌진 우선순위도 확인했다. 페이지 오류·가로 넘침·전투 GLB 요청은 없었다.

## 남은 차이와 다음 후보

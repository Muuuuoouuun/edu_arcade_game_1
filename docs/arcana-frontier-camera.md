## 구현

- `src/games/frontier/camera.ts`에서 화면 비율·전장 높이·모드별 카메라 정책을 분리했다. 모바일 솔로의 기본 높이는 전장 높이/20을 12.1~25로 제한하고 수평 오프셋은 높이의 1.6배다. 절벽 측면이 드러나며 실제 메시를 더 크게 볼 수 있다.
- 지휘 모드는 솔로보다 카메라 높이를 1.33배로 두어 분대와 주변 전초 지점을 함께 보여 준다. 타워 디펜스는 기존 고정 전선 시점을 유지하며 효과 없던 전체 보기 버튼을 제거했다. 확대·축소는 유지한다.
- 이동 방향으로 최대 1.4 월드 단위를 미리 보여 준다. 강타 준비부터 회수까지는 직전 프레이밍을 고정해 타격 대상과 예고가 화면에서 흔들리지 않는다. 공격 종료 후 다시 부드럽게 추적한다.
- 일시정지 시 추적은 정지한다. 동작 줄이기는 선택적 미리보기와 보간을 없애고 실제 영웅 위치를 따른다. 전체 보기·화면 방향 변경은 즉시 적용한다. 배속은 카메라 보간 시간에 곱하지 않는다.
- 입력은 기존 실제 지형/교량 raycast를 사용한다. 전장 크기·캐릭터 배율·사거리·체력·피해·보상은 그대로다. 기본 배율에서는 마지막 이동 방향으로 카메라가 치우친 상태에서도 반경 8 충격파가 화면에 들어오도록 최소 거리를 검사한다. 사용자가 최대로 확대하면 범위 일부가 화면 밖에 있을 수 있다.

기존 `.blend`·GLB·공통 카메라 렌더·WebP·재생성 스크립트는 수정하지 않았다. 신규 모델 제작으로 집계하지 않는다. 기존 캠페인은 베이크 2.5D이며 변경 전장은 React UI와 단일 Three.js 장면을 사용하는 독립 훈련이다.

## 성능 비용과 미완료

Chromium SwiftShader, 844×390 뷰포트/844×242 전장, 같은 영웅·적 수, 3.5초 준비 후 3초 측정이다. 다른 빌드/테스트와 겹친 첫 측정은 제외했다. 아래는 CPU 소프트웨어 렌더 결과이며 실기기 FPS로 해석하지 않는다.

| 1 | 82.37ms | 89.15ms |

30명에서 실행 순서를 뒤집고 6초간 재확인한 결과는 이전 118.11ms → 변경 130.85ms였다. 약 11~15% 프레임 비용 증가가 관찰됐으며 **성능 개선/회귀 없음으로 보고하지 않는다**. 가독성 개선에 따른 비용은 남은 문제다. draw call은 53~55, 삼각형 약 7.5만, canvas 1개이며 개체별 WebGL 렌더러를 추가하지 않았다. 실제 Android GPU 성능은 미검증이다. 후속 후보는 근접 시점의 지형/가림 비용 최적화와 실기기 측정, 지휘 목표를 포함한 프레이밍이다. 새 확장 맵이나 캠페인 전체 3D 전환 완료로 집계하지 않는다.

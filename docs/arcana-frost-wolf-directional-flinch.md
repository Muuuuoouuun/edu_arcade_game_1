원격 main `2eabc76`, Claude `bf7c1c6`·`d0484f2`, 깨끗한 단일 작업 트리와 진행 중인 프로세스를 확인했다. Claude 52회차는 정예 클리어 저장 필드 기획으로 이번 움직임과 겹치지 않는다. 기존 통합 지형·성문·통나무 병사·영웅 전환·서리늑대 접지 보행은 보존했다.

## 컨셉과 현재 화면에서 선택한 차이

[은서리 늑대 컨셉](../art-source/defense/concepts/2026-10-29/beasts/silverfrost-wolf.png)과 실제 PC/모바일 설산 전투를 비교했다. 회백색 갈기·긴 주둥이·짙은 발의 체형은 이미 구현돼 있다. 그러나 아래나 위를 향해 걷다가 일반 피해를 받으면 고정된 옆모습으로 바뀌어 방향과 발 디딤이 끊겼다. **현재 방향과 걸음을 유지하며 몸·목으로 충격을 흡수하는 짧은 동작**을 선택했다.

기존 여덟 보행 자세 각각에서 출발하고 돌아오는 실제 0.16초 피격 클립을 추가했다. 몸이 약간 뒤로 낮아지고 목·머리·턱·꼬리가 따라 움직인다. 상부 다리·무릎·발 관절을 풀어 네 발의 기존 위치를 유지한다. 지지 발은 지면에, 들고 있던 발은 그 높이에 머문다. 외형 메시와 재질은 기존 보행 원본을 사용한다.

전투에서는 피격 중에도 누적되는 현재 `walkCycles`와 `walkHeading`으로 8방향×8걸음을 선택한다. 모바일 확대 크기를 보폭 계산에 반영하고 좌우 반전하지 않는다. 모델 자체에 들어 있는 반응과 중복되는 전체 이미지 흔들기·늘이기·기울이기를 제거했다. 체력바 높이는 기존 보행과 같게 유지한다.

| 기존 피격 타이머의 남은 시간 | 표시 |
| --- | --- |
| 0.16–0.09초 초과 | 압축: GLB 0.03초 베이크 |
| 0.09–0.02초 초과 | 이완: GLB 0.11초 베이크 |
| 0.02초 이하 | 현재 걸음의 기존 방향 보행 |

일반 피격만 적용한다. 넉백·동작 줄이기·쓰러짐은 기존 경로이며 방향별 이미지가 하나라도 실패하면 기존 피격 이미지로 대체한다. 기본 모델까지 실패하면 기존 삽화를 사용한다. **피해량·피격 타이머·발사 시점·이동 속도·전투 판정은 바꾸지 않았다.**

## 산출물과 재생성

- [편집 원본](../art-source/defense/frost-wolf-flinch.blend): 66메시·17관절, 관절마다 `Frost wolf flinch N / 관절 이름` 액션. N=0–7을 같은 값으로 지정한다. 모든 액션은 fake user로 보존한다. 기존 `frost-wolf-stride.blend`는 수정하지 않았다.
- [실제 GLB](../public/defense/models/frost-wolf-flinch.glb): `frost-wolf-flinch-0`…`frost-wolf-flinch-7`, 각 0.16초·200fps·33키 시점. 하나의 메시 집합을 공유하는 8클립, 66메시·2,300삼각형·6재질, 424,472바이트. 정지 이미지 평면 모델이 아니다.
- [공통 카메라 미리보기](../public/defense/models/frost-wolf-flinch.png)와 [원본 PNG 128장](../art-source/defense/wolf-flinch/): 8방향×8걸음×2포즈, 384×384. 기존 접지 보행의 카메라·조명·크롭·표시 크기를 따른다.
- `frost-flinch-{0..7}-atlas.webp`: 16셀·3072×192, 셀 192×192, 크롭 (4,20,184,152). 압축 합계 422,290바이트, 추가 RGBA 디코드 픽셀 합 18MiB. 실제 GPU 메모리 측정값은 아니다.
- [메타데이터](../public/defense/models/frost-wolf-flinch.json): 카메라·지면·방향·경계·264개 관절 시점·클립·타이머 구간·원본/생성기/산출물 해시.
- 작업실 `/model-lab.html?model=frost-wolf-flinch`: **서리늑대 · 걸음 위 피격**, 피격 걸음 1–8 선택·재생·끝 자세 유지. 기존 단일 WebGL 장면이며 전투는 GLB를 요청하지 않는 베이크 2.5D다.

```bash

npm run models:wolf-flinch -- --check      # 렌더 없는 관절/접지 검사
npm run models:wolf-flinch:check           # 납품 GLB 보간과 해시 검사
```

## 검증

- 납품 GLB의 키 사이까지 520시점 검사: 원본 보행과 시작/끝 변환 차이 최대 6.39e-7, 발 위치 오차 0.000393 미만, 발 기울기 6.57e-7라디안 미만. 보간 중 최소 발바닥 높이 -0.000318이며 0.001 허용치 안이다. 첫 100fps 버전의 발 오차 0.001347은 기준을 넘어서 200fps로 재생성했다.
- 편집 원본을 다시 열어 66메시×16개 시작/끝 월드 변환 비교: 최대 오차 2.39e-7. 142개 해시, 원본 PNG 128장·WebP 128셀의 크기/투명 경계/잘림, dist 배포 파일 11개 일치 검사 통과. 크롭 내 최소 알파 여백 3픽셀.

- 스테이지 1·4·5·8×영웅/용병 총 14,400스텝: 기준 엔진과 제외 필드 없이 전체 상태 동일. 엔진 소스 변경 없음. 60Hz 고정 스텝의 2/4/6틱 화면 게시와 모든 시작 오프셋에서 적어도 한 피격 자세가 표시되는 것을 검사했다.
- 실제 DefenseBoard의 PC 1440×900, 터치 화면 390×844·320×844, 동작 줄이기·피격/보행/기본 이미지 실패 총 2,688표시 시점 검사. 8방향·8걸음·압축/이완·보행 복귀·넉백 우선순위·고정 체력바를 확인했다. 페이지 예외와 전투 GLB 요청은 0건이다. 최종 재생성한 8개 WebP의 해시는 이 UI 검증에 사용한 이미지와 모두 일치한다.

## 남은 범위와 다음 후보

전투 피격은 두 베이크 자세이므로 연속 관절 보간이 아니다. 보행 위상은 계속 진행되고 현재 위상의 대응 자세로 바뀐다. 모델 내부에서 발 위치를 유지한 것이며 전장 좌표의 발 고정·지형 IK는 아니다. 넉백·쓰러짐·동작 줄이기는 여전히 기존 단일 방향 이미지다. 추가 디코드 비용의 실제 Android 메모리·성능은 측정하지 않았다.

다음 후보는 서리늑대의 방향별 넉백/쓰러짐 연결, 리엘·브론의 방향 전환을 동반한 공격 복귀, 성문 앞 유닛 가림 개선이다. 이번 회차에서 예약 조회/변경·Claude API 호출·main 병합·서비스 배포는 수행하지 않았다.

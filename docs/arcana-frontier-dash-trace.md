# 변경 전장 · 실제 경로를 따르는 돌진 흔적

녹음 숲 컨셉과 가로 화면을 비교했다. 솔로 카르는 기존에도 다리·강·경계를 검사해 최대 5단위를 돌진하지만 화면에서는 중간 모습 없이 위치만 바뀐다. 연결된 OpenAI 이미지 도구로 만든 시안에서 지면 가까이의 청록색 바람과 작은 접지 파편을 참고했다. 시안은 3D 모델이나 게임 화면이 아니다.

유효한 실제 시작점과 도착점을 시뮬레이션 시간에 기록하고, 경로 양옆에 최대 24개의 바람 조각과 6개의 짧은 지면 파편을 단일 Three.js 장면의 두 인스턴스 배치로 표시한다. 영웅에게 가려지지 않도록 경로 옆에 두며 통행 불가능한 지점과 급격한 높이 단차는 생략한다. 흔적은 표면 높이를 따르고 불투명 물체 뒤에 가려지며 0.36초 후 사라진다. 좌표·거리·쿨다운·공격 준비 취소/환급·판정은 바뀌지 않는다. 이동이 0이면 흔적을 만들지 않는다.

일시정지에서는 효과가 멈추고 배속에 맞춰 사라진다. 동작 줄이기에서는 흔적과 파편을 생략한다. 지형 입력 레이에 효과를 넣지 않아 클릭·터치를 막지 않으며 모델 로딩 실패 시에도 기본 입체 영웅과 함께 동작한다. 위치 이동 자체는 기존처럼 즉시 처리된다. 이 연출은 진짜 연속 이동, 관절 대시 클립, 물리 엔진이나 2.5D 캠페인 전환이 아니다. 기존 편집 가능한 카르 모델과 GLB를 그대로 쓴다.

## 검증

- 8방향과 평지·경사·다리·막힌 경계에서 실제 이동 범위, 통행 불가 영역, 흔적 높이·수명·일시정지·2배속·동작 줄이기·리소스 재사용/해제를 검사했다. 검사한 표본이 모든 지형 조합을 보증하지는 않는다.
- 전체 자동 테스트 527개와 웹·모바일 빌드가 통과했다. 새 테스트에서 발견된 TypeScript 재질 타입 오류는 수정 후 빌드를 재실행했다.
- PC 1024×576 키보드 및 가로 모바일 844×390 터치에서 보행→충격파 준비→돌진 취소·환급과 흔적, 정지·2배속·동작 줄이기를 조작했다. 두 영웅 GLB 요청 실패 시에도 폴백에서 확인했다. 같은 기준 커밋의 조작에서 위치는 이동하지만 흔적은 없었다. PC 마우스와 모바일 터치로 실제 지면 입력이 효과에 막히지 않는 것도 확인했다. 모바일 빌드 결과물의 타이틀→거점→솔로 진입과 같은 돌진·정지·배속 흐름도 확인했다. 모바일은 Chromium 에뮬레이션이다.
- 실제 WebGL 픽셀로 흔적이 불투명 물체에 가려지는 것을 확인했다. 844×242 Chromium SwiftShader의 동일 장면을 3초 예열한 뒤 5초씩 표본으로 비교하면 드로콜 36→38, 삼각형 45,874→46,210, 평균 프레임 간격 85.8→86.2ms, p95 100.1→100.1ms였다. 소프트웨어 표본이며 실기기 성능을 보증하지 않는다.
- 기존 Three.js 그림자 모드 대체와 SwiftShader ReadPixels 경고는 기준과 변경 양쪽에서 재현됐다. 페이지 오류나 개발 서버 오류 화면은 없었다.

혼잡한 적 무리 뒤의 가독성과 실제 Android/iOS GPU, 극단적 경계의 모든 시점은 후속 확인이 필요하다. 착지까지 실제 시간을 쓰는 대시·충돌/공격 타이밍 변경은 별도 게임플레이 작업이다.

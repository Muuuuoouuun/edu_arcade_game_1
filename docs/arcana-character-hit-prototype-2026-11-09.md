# 북극곰·도마뱀 피격 시안

## 제작 단계와 범위

- 콘셉트: `art-source/defense/concepts/2026-11-09/{polar-bear-guardian,gecko-ranger}.png` 기존 이미지. 북극곰은 흰 털·푸른 방패·닻망치, 도마뱀은 잎 두건·꼬리·씨앗 쇠뇌를 유지한다.
- 새 이미지: `art-source/defense/concepts/2026-11-09/motion/guardian-ranger-hit-reference.png`. 두 기존 콘셉트를 입력으로 OpenAI 이미지 생성 도구에서 2026-11-09에 생성했다. 2행 3열은 각 캐릭터의 대기·피격·복귀 포즈다. 생성 결과를 직접 확인해 방패를 앞세운 무거운 반응과 무기를 놓지 않는 작은 반응 및 꼬리의 후속 동작을 참고했다. 그림은 해부학·완성 모델의 정확한 청사진이 아니다.
- 편집 가능한 모델 원본: `art-source/defense/prototypes/{polar-bear,gecko-ranger}/*.blend` 및 `tools/blender/build_{polar_bear,gecko}.py` 기존 파일. 이번에는 생성 스크립트를 실행하거나 기존 모델을 변경하지 않았다.
- 실제 애니메이션: `src/model-lab-hit.ts`는 기존 GLB의 독립 노드에 0.48초 회전 키프레임을 생성한다. 0.09초에 피격, 0.25초에 반동, 0.48초에 복귀한다. 북극곰은 몸·방패 팔·머리·망치 팔, 도마뱀은 몸·머리·쇠뇌와 잡은 팔·꼬리를 움직인다. 선형 쿼터니언 보간을 쓴다. 발 노드는 그대로다. 이 코드는 편집 가능한 애니메이션 원본이며 GLB 내부의 새로운 클립이 아니다.
- 작업실: 피격 버튼은 두 시안에만 나타난다. 새 입력 시 현재 동작을 멈추고 재시작하며 기존 강타·발사와 전환한다. 동작 줄이기 설정에서는 재생하지 않는다. 캠페인, 전장, Android 패키지에는 연결하지 않았다.
- 이전 동작: 곰의 준비·타격·회복 0.8초, 도마뱀의 조준·발사 반동·복귀 1초는 기존 GLB에 이미 있다. 새로운 걷기·호흡 대기 클립, 발사체 및 피격 판정은 없다.

## 검증과 한계

- 자동: `npm run build`, `npm test` (166개), `node --experimental-strip-types --test tools/tests/model-lab-hit.test.mjs` (2개) 통과. 실제 GLB를 로드해 0.09초 몸 회전, 정적 발 노드의 월드 위치, 10ms 간격 유한 회전, 마지막 복귀를 검사한다. 이것은 발 메시 관통이나 모든 메시 충돌을 증명하지 않는다.
- Chromium 소프트웨어 WebGL: `npm run dev`를 실행한 뒤 Playwright가 설치된 환경에서 `node tools/tests/model-lab-browser.cjs`. 390×844 및 844×390에서 두 모델 로딩, 피격 반복·피격에서 공격 전환·종료를 확인했다. 의도적으로 GLB 요청을 차단했을 때 PNG 대체와 피격 버튼 비활성화를 확인했다. 테스트 키 하나가 작업실 조작 후 보존됨을 확인했으며 실제 캠페인 저장 데이터의 마이그레이션 검증은 아니다. 모바일 세로 정지 화면과 아래의 소형 피격 샘플을 직접 확인했다. 전체 프레임의 관통·무기 궤적은 아직 시각 검수하지 않았다.
- Android 실기기 성능·터치·화면 방향·전투 저장은 미실행. 작업실에서 방패·망치·쇠뇌의 관통, 카메라별 실루엣과 반복 이음새를 프레임 단위로 독립 검수해야 한다. 이 변경은 모델 품질이나 게임 적용 승인이 아니다.

## 회귀 수정 및 소형 렌더 추가 검수

공격 포즈 슬라이더 입력값을 동작 초기화 전에 저장하고 복원한다. `node tools/tests/model-lab-browser.cjs`는 두 캐릭터를 390×844와 844×390에서 열어 70% 입력값 및 표시, 포즈→피격→공격→피격→대기, 피격 반복 및 로드 실패 대체를 확인한다. 4개 화면 조합과 실패 대체가 모두 통과했다. `npm run build`도 통과했다.

`npm run dev` 후 `node tools/tests/model-lab-hit-visual.cjs`로 재현 가능한 Chromium 소프트웨어 WebGL 정지 렌더는 [48·64·96px 캔버스와 0·0.09·0.25·0.48초](evidence/arcana-character-hit/hit-48-64-96.png)를 보여 준다. 작업실의 카메라 방향·정규화를 사용하되 조명은 간략화했고 바닥·그림자는 없다. 캔버스 안의 캐릭터 실제 높이는 이 숫자보다 작다. 눈으로 확인하면 두 캐릭터의 실루엣과 색은 구분되지만 48px 캔버스에서는 무기 형태와 피격 변화가 작아 판별하기 어렵고, 64·96px에서도 작은 반응이다. 곰의 방패·망치와 도마뱀의 쇠뇌가 이 한 시점 방향에서 보이나 작은 이미지로 몸과 무기의 관통 유무는 판정할 수 없다. 정지 발 노드의 월드 위치는 자동 검사로 확인했으나 바닥이 없는 이 렌더는 발바닥 접지나 지면 관통의 시각 증거가 아니다. 모든 프레임과 다른 카메라 각도, 충돌 검사 및 실기기 검증은 여전히 필요하다.

## 전장 배경에서의 피격 가독성 개선

독립 검수에서 작은 피격 동작이 읽히지 않아 몸과 장비의 X·Z 회전 방향을 더 분명히 하고, 피격 시작 후 0~0.16초 안에서 0→최대 0.38→0으로 돌아가는 붉은빛 재질 강조를 추가했다. 중간 회복 포즈와 마지막 원래 자세를 유지하고 중단·전환 시 원래 색을 복원한다. 동작 줄이기 설정에서는 피격을 실행하지 않는다.

[전후 비교](evidence/arcana-character-hit/battle-hit-before-after.png)는 실제 게임의 `forest.png`, `snow.png` 일부를 사용한 합성이다. 62차 모델 기록의 영웅 약 36~39px을 참고해 정지 자세의 캐릭터 높이를 약 38px로 맞췄다. 기존과 변경된 두 동작을 같은 작업실 카메라, 간략 조명, 0·0.09·0.25·0.48초에서 나란히 렌더했다. 게임 전투 화면이나 Android 화면을 캡처한 것은 아니며, 지면 정렬도 합성 위치다. 눈으로 보면 타격 순간이 이전보다 잘 보이지만 작은 크기에서 자세 변화보다 색 강조에 더 의존한다. 숲에서 도마뱀의 녹색 몸이 여전히 배경에 섞이며, 설산에서 곰의 밝은 털도 대비가 약하다. 실제 전장에서 다른 적·이펙트와 겹칠 때는 추가 검수가 필요하다.

`npm run dev` 뒤 `node tools/tests/model-lab-battle-visual.cjs`로 정지 비교와 `requestAnimationFrame` 0.48초 재생 중 렌더를 재현한다. 소프트웨어 WebGL에서 두 캐릭터 모두 끝까지 진행하고 강조값이 다시 0으로 돌아가는 경로를 실행했다. 샘플 실행에서 각각 12·6프레임만 렌더되어 이 결과는 부드러움이나 실기기 성능을 입증하지 않는다. 발 노드 고정은 자동 검사했지만 발바닥과 지면의 실제 접지, 몸·무기 관통은 이 합성 및 한 방향만으로 판정할 수 없다. 다각도·전 프레임 검사와 Android 실기기 검증은 남았다.

## 모바일 우선 기준

사용자 결정에 따라 아르카나 수비대는 계속 모바일 게임을 기준으로 개발한다. 피격 동작도 휴대폰의 작은 전투 화면에서 식별되는지, 터치 조작을 방해하지 않는지, 휴대폰에서 감당할 수 있는지 우선 검토한다. PC Chromium은 검증 수단이며 제품의 우선 대상이 아니다. 위 브라우저 결과는 실제 Android 실기기 결과가 아니며, 터치 조작 및 기기 성능 검증은 아직 완료되지 않았다.

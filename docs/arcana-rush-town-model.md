# Rush 녹음 성채의 실제 석조·목재 구조

2026-11-12, 기준 `4639166`. 기존 Rush의 원형 기초·상자·원뿔 성채를 [녹음 숲 컨셉](../art-source/defense/concepts/2026-11-06/verdant-heart.png)의 큰 쐐기돌 아치, 보강한 목재 양문, 청록 지붕과 황동 잎 문장으로 발전시킨다. 원본을 그대로 복제하지 않고 작은 전투 크기에 맞춰 벽돌 줄과 재료 경계를 크게 구분했다.

새 성채는 네 개의 낮은 보조 탑, 중앙의 사면 지붕, 앞쪽의 큰 아치·닫힌 양문과 뒤쪽의 작은 닫힌 보급문으로 구성된다. 현재 전장 카메라가 자주 보는 후면에서도 목재·석조·청록 지붕을 구분할 수 있다. 문은 실제 통로를 새로 만들지 않는 닫힌 구조이며 이동·피해·공격 범위를 바꾸는 메시 충돌체를 추가하지 않는다.

## 원본과 배포

- 편집 원본: `art-source/defense/rush-town.blend` — 각 벽돌·지붕·문짝·철띠가 분리된 실제 메시.
- 정면/후면 공통 규격 렌더: `art-source/defense/rush-town/front.png`, `rear.png` — 640×640, 지면 0, 같은 7.7 정사영 범위와 중심 높이 2.35.
- 실제 3D: `src/rush/models/forest-town.glb` — Y-up, 정면 -Z, 지면 원점, 정점 색의 단일 표면과 단일 재질. 외부 이미지 텍스처·관절 애니메이션 없음.
- 이미지: `public/defense/models/rush-town.png`, `rush-town-game.webp` — WebP는 256px 투명 베이크이며 2.5D 사용이 가능한 보존 산출물이다. 이 파일만으로 기존 캠페인에 새 건축을 연결한 것으로 보지 않는다.
- 규격·해시: `public/defense/models/rush-town.json`.

```bash
blender --background --python-exit-code 1 --python tools/blender/build_rush_town.py
node tools/check-rush-town.mjs
```

Blender 생성기는 개별 구조의 모든 월드 정점을 검사한 뒤 편집 파일을 저장하고, 배포 때만 정점 색의 한 표면으로 합친다. 검사기는 원본과 배포 해시, 실제 GLB 정점의 반경 2.6 이하·지면 0·높이 5.85 이하, 단일 표면과 4,500삼각형 예산을 검증한다. 이 범위는 기존 Rush의 원형 마을 반경과 높이 안에 맞춘 것이다. 원본 앞면과 후면의 닫힌 문은 실제 목재 메시이며 그림 평면을 3D로 표현한 결과가 아니다.

실제 전장의 로딩·실패 대체·가림·입력·성능 검증은 통합 변경에서 따로 기록한다. 이 정적 건축 자산만으로 움직임이나 실기기 성능을 검증했다고 표현하지 않는다.

## 게임 연결과 검증

Rush는 같은 WebGL 장면에 새 GLB의 본체 한 개와 외곽선 한 개를 그린다. GLB가 없거나 형상 검증에 실패하면 기존 기본 성채를 유지한다. 모델 작업실 `model-lab.html?model=rush-town`도 같은 파일을 로드하며, 실패 시 원본 렌더 이미지를 보여 준다. 전투에서는 WebP를 사용하지 않는다.

건물 뒤 영웅의 몸이 가려지는 구간에는 기존 변경 전장의 국소 시야 처리를 재사용한다. 성채 전용 재질만 패치하므로 다른 엄폐물의 외형은 바뀌지 않는다. 영웅 앞의 성채 픽셀만 처리하고, 건물 뒷면과 다른 지역은 유지한다. 모델 교체 전 기하와 마스크를 정리해 비동기 로딩 뒤에도 기존 화면 모드를 유지한다.

`npm run models:rush-town:check`는 산출물 해시·GLB 범위·실패 대체·재질 소유와 가림 해제를 검사한다. 전체 자동 검사 674개, 웹/모바일 빌드와 모바일 자산 검사 3개가 통과했다. PC 1280×720·가로 모바일 844×390의 실제 키/터치 조작으로 성채 충돌, 측면 이동, 사격, 정지/재개, 1배/2배와 동작 줄이기를 확인했다. GLB 요청을 차단한 경우에도 같은 입력이 통과했다.

같은 시드·틱·그래픽 설정의 PC 북쪽 시점에서 draw call은 41→41, 삼각형은 35,780→43,704였다. 추가 7,924삼각형은 새 성채 본체와 외곽선의 구조 증가다. 성채 북쪽 원주의 제어 위치 13곳을 두 화면에서 검사했으며 각 화면 두 위치에서 국소 가림이 작동했다. 이는 모든 위치의 가림을 보증하지 않는다. 이동 카메라 500개 합성 표본의 가림 계산은 Node CPU 중앙값 1.84ms/p95 2.23ms였으며 휴대폰 GPU나 FPS 측정이 아니다.

기본 전투 구도는 적 쪽을 바라보므로 성채의 하단은 화면 밖에 남는다. 더 넓은 맵·입체 바닥, 건축 성장 단계, 피해에 따른 실제 문짝/지붕 반응과 Android/iOS 실기기 성능은 후속 범위다.

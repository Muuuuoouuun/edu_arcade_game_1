# 서리 성문의 문짝 충격과 뒤따르는 등불

2026-11-09 · 69회차 · `codex/arcana-stage-experience-20261106`

극지 컨셉의 보강 목재 문짝·철띠·등불과 실제 변경 전장을 비교했다. 이전 성문은 열린 석조 아치여서 성문 체력이 줄어도 건축물이 반응하지 않았다. 이번에는 고정 석조 안에 두꺼운 목재 양문과 매달린 등불을 모델링하고, 적의 실제 몽둥이 접촉으로 성문 피해가 발생할 때 반응하게 했다.

## 실제 구현

- 문짝별 곡선 상단의 널판 5개, 중앙 맞댐목, 앞뒤 철띠·경첩·볼트, 등불의 황동 테두리와 매달림 구조. 기존 돌기둥·눈·깃발은 원본에서 이어받았다.
- 0.55초 클립: 문짝이 0.083초에 약 8.6도 밀리고 회복한다. 등불은 뒤늦은 0.15초에 약 17.2도 흔들린다. 석조 받침과 기둥은 움직이지 않는다.
- 기존 0.28초 몽둥이 접촉과 피해 10은 그대로다. 실제 체력 감소 시각 `coreHitAt`을 기록하고 동일 시뮬레이션 시간으로 모델과 지면 표시를 샘플링한다. 반복 타격은 마지막 접촉에서 재시작한다.
- 타워 디펜스는 닫힌 문, 지휘·솔로는 90도 열린 문을 사용한다. 체력 0은 열린 파손 자세와 정적인 붉은 표시다. 일반 건물 충돌이나 석조 붕괴 시뮬레이션을 추가한 것은 아니다.
- 일시정지·배속을 따르며 동작 줄이기는 문짝/등불 동작과 표시 확대를 멈추고 정적인 피해 표시를 남긴다. GLB가 실패하면 기본 입체 문과 같은 반응을 유지한다.
- PC 고정 디펜스에서 잘리던 성문 바닥과 타격 고리를 기본 카메라 안에 넣었다. PC 거리 45→52, 모바일 가로 거리 32.4는 유지한다. 모델 크기·공격 거리·맵 크기는 바꾸지 않는다.
- 장면당 렌더러 하나를 유지한다. 고정 석조 그림자는 캐시하고 움직이는 문/등불은 그림자를 투사하지 않아 매 프레임 전체 지형 그림자를 다시 만들지 않는다.

## 편집 원본과 재생성

| 산출물 | 경로 |
|---|---|
| 컨셉 원본 | `art-source/defense/concepts/2026-11-09/polar-battlefield.png` |
| 편집 가능한 원본 | `art-source/defense/frontier-frost-gate-impact.blend` |
| 전장/작업실 모델 | `public/defense/models/frontier-frost-gate-impact.glb` |
| 공통 카메라 4포즈 | `art-source/defense/frontier-gate-impact/{idle,contact,secondary,settled}.png` |
| 2D용 베이크 | `public/defense/models/frontier-frost-gate-impact-atlas.webp` |
| 메타데이터·해시 | `public/defense/models/frontier-frost-gate-impact.json` |

119개 편집 메시와 4개 경첩 액션을 보존했다. 전장 GLB는 고정 석조 1개·문짝 2개·등불 2개의 **5메시/1,428삼각형**, 0.55초 클립 1개다. 정지 이미지를 붙인 평면 모델을 사용하지 않는다. WebP는 384px 공통 카메라의 4칸 베이크이며 칸 번호·원본 프레임1/6/10/34·시각을 메타데이터에 기록했다. 실시간 3D 변경 전장에는 GLB를 연결했다. 기존 2.5D 캠페인에 새 성문 베이크를 연결한 것으로 집계하지 않는다.

```sh
npm run models:frontier-gate-impact
npm run models:frontier-gate-impact:check
node --experimental-strip-types --test src/games/frontier/gateView.test.ts src/games/frontier/camera.test.ts src/games/frontier/woodAttack.test.ts src/games/frontier/engine.test.ts
npm run build
```

Blender 4.3.2·Cycles CPU·ffmpeg를 사용한다. 생성기는 이전 `frontier-frost.blend`를 읽고 별도 원본을 만들며 기존 원본·GLB·보행은 변경하지 않는다. 모델 작업실의 **서리 성문 · 충격과 등불**에서 회전·와이어·피격을 볼 수 있다.

## 검증과 인계

- 모델: 원본 재개방, 10개 산출물 해시, 고정 석조 111시점, 닫힌 문 가림과 90도 열린 통로를 확인했다. WebGL 뒤쪽 파란 검사 물체의 픽셀은 닫힐 때 `[33,50,67]`, 열릴 때 `[0,0,255]`다.
- 관련 단위 검사: 엔진·몽둥이·성문 20개, 최종 카메라·성문 14개 통과. 초기 검사에서 문 중앙 틈을 발견해 맞댐목을 추가했고 최종 모델 검사를 통과했다.
- 전체 검사: 카메라 추가 검사 전 433개 중 432개 통과. 수학 게임의 `(3×7)÷5` 기대값 4.2/실제 4 실패는 기준 커밋을 별도 경로에서 실행해 동일하게 재현했다. 성문 변경의 회귀가 아니다.
- 최종 모델·카메라 변경 후 `npm run build` 통과.
- 실제 작업실: PC1440×900/모바일390×844에서 GLB·회전·와이어·피격·초기화·동작 줄이기 확인. GLB 실패→PNG와 둘 다 실패하는 경로를 검사했다.
- 실제 지휘 UI: PC1440×900/가로 모바일844×390에서 열린 문 자세가 누적되지 않고, 복귀 버튼으로 영웅이 (-14,14)→(-14,21) 이동하는 것을 확인했다.
- 실제 전투 UI: PC1440×900/가로 모바일844×390의 GLB/기본 모형 네 조합에서 실제 적 접촉→180→170 피해, 반동, 일시정지 픽셀 고정, 동작 줄이기, 2배속, 반복 타격을 확인했다. PC 실제 패배 시 열린 파손 자세도 확인했다. 첫 검사 모드 전환 때 가상 시간을 멈춘 채 새 렌더를 기다린 스크립트 시간 초과는 검사기를 수정하고 지휘 입력을 별도 검사했다.
- PC·모바일 기준 커밋의 실제170HP 화면과 변경 후 실제170HP 화면을 저장하고 직접 비교했다. PC에서 잘리던 성문 바닥/고리가 보인다. 캔버스는 하나이며 브라우저 실행 오류가 없다.

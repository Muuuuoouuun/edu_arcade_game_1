# 변경 전장 회복 수정 · 2026-11-10

서리 해안과 녹음 숲의 원본 콘셉트 및 가로 전장 화면을 비교했다. 솔로 원정의 기존 옅은 팔면체는 눈과 밝은 지면에 섞이고 공중에 떠 보였다. 어두운 석재 받침·황동 고정쇠·청록 결정으로 지면과 실루엣을 분리하고, 가까워졌을 때 실제 상호작용 반경에 금빛 지면 고리를 보여 준다. 수정은 원정의 기존 목표물이며 지형이나 UI를 추가로 덮지 않는다.

## 제작과 연결

- `npm run models:frontier-relic`는 [편집 가능한 Blender 원본](../art-source/defense/frontier-relic.blend), 실제 메시 GLB, 공통 카메라의 대기·수집·빈 받침 PNG, 3포즈 WebP와 해시 메타데이터를 재생성한다. GLB는 2개 메시·230삼각형·22,888바이트다. 모델 작업실은 같은 GLB를 불러온다.
- GLB는 하나의 장면에서 공유하며, 단위별 렌더러를 만들지 않는다. 하나의 원본을 복제한 세 수집 지점이 메시와 재질을 공유한다. GLB가 없거나 불완전하면 입체 기본 모형을 사용한다. 작업실은 GLB 실패 시 PNG로 대체한다.
- 원래 수집 반경 `< 3.5`, 즉시 체력 25 회복, 수집 횟수와 탈출 조건은 그대로다. 원 내부에 있을 때만 지형을 따르는 고리가 보이고, 수집하면 고리가 사라진다. 수정 몸체는 시뮬레이션 시간 0.4초에 걸쳐 위로 작아진 뒤 숨겨지고 빈 받침이 남는다. 일시정지에서는 자세가 멈추고 배속에 맞춰 진행하며 동작 줄이기는 즉시 숨긴다.
- Blender 파일의 동작은 제작 미리보기다. 전장 수집 동작은 GLB 애니메이션이 아니라 기존 게임 시간과 연결된 절차적 변환이다. WebP는 보존용 베이크이며 기존 2.5D 캠페인에 새로 연결하지 않았다.

`npm run models:frontier-relic:check`는 Blender의 접지·고정 받침·공통 카메라와 GLB 구조·피벗·해시를 검사한다. 수집 범위 경계·한 번만 회복·지면 고리·정지·배속·동작 줄이기·기본 모형은 관련 단위 테스트에서도 검사한다.

## 검증

전체 자동 테스트 520개와 웹·모바일 빌드가 통과했다. Chromium에서 PC 키보드와 844×390 가로 모바일 터치로 실제 진입·이동·범위 밖 실패·수집·일시정지·2배속·동작 줄이기를 확인했다. 모바일에서 GLB 요청 실패 시에도 기본 입체 수정으로 같은 수집이 가능했다. 빌드된 모바일 패키지의 타이틀부터 전장 진입과 GLB HTTP 200도 확인했다. 모델 작업실에서는 GLB 및 PNG 실패 대체를 확인했다. 실제 3D 깊이 버퍼로 앞쪽 물체가 수정을 가리는지 검사했고, 세 인스턴스의 공유 자원과 대체 모형 제거를 확인했다.

동일 844×242 장면에서 Chromium SwiftShader의 한 차례 전후 표본은 드로콜 24→26, 삼각형 28,328→28,614였다. 프레임 평균 78.6→72.6ms는 소프트웨어 렌더러의 짧은 표본이라 실제 기기 속도 개선이나 안정적인 프레임률로 해석하지 않는다.

## 범위와 한계

변경 전장은 실시간 단일 3D 장면이고 기존 캠페인은 베이크된 2.5D다. 이 작업은 원정의 수정 하나를 개선하며 신규 이동형 맵이나 캠페인 전체의 3D 전환은 아니다. 심한 지형 단차에서는 투영된 고리에 작은 틈이 생길 수 있고 실제 휴대기기 GPU 성능은 별도로 측정해야 한다. 모든 전투 모드에서 조작·스킬 이외 UI를 숨기라는 기존 요청은 이 수정 작업과 별도로 남아 있다.

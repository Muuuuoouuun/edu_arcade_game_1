# 녹음 숲 전경과 모바일 영웅 시야

2026-11-11, 기준 `19002557387248673c92fe731a317ac6f13e0254`. 녹음 심장 컨셉의 숲과 실제 가로 변경 전장을 비교했다. 동쪽 끝에서 카메라와 영웅 사이에 수관이 들어오면 머리만 보이고 몸과 발이 가려졌다. 숲의 입체 실루엣과 실제 지면을 유지하면서 영웅의 위치와 움직임을 읽는 것이 이번 범위다.

동쪽 전경의 나무열을 x=38에서 x=43으로 옮기고, 나무가 뜨지 않도록 외곽 지면과 그 기초를 x=46까지 늘렸다. 나무의 줄기·가지·잎은 기존 실제 편집 메시와 재질을 유지한다. 전체 나무 28개, 편집 메시 430개, 단일 재질 GLB의 13,612삼각형을 유지한다. 이 바깥 지면은 시각적 숲 경계이며, 이동 가능한 64×64 전장의 규칙을 확장한 것이 아니다. 화면에 구멍을 내거나 별도 렌더러를 추가하지 않는다.

GLB를 불러오지 못할 때의 기본 숲도 동쪽 나무열과 경사 지면을 같은 위치에 둔다. 대체 지형은 여전히 단순한 입체 원뿔과 기본 재질이며, 사용자 입력은 원래 통행 지면과 다리에만 적용한다. 설산 폴백의 배치는 바꾸지 않았다.

`npm run models:frontier-terrain`으로 [편집 원본](../art-source/defense/frontier-terrain.blend), [전장 GLB](../public/defense/models/frontier-terrain.glb), 공통 카메라 PNG·교량 PNG·WebP와 [해시/좌표 메타데이터](../public/defense/models/frontier-terrain.json)를 재생성한다. WebP는 메뉴·참조용이며 기존 2.5D 캠페인 전장을 실시간 3D로 바꾼 것은 아니다.

## 검증과 남은 범위

- `npm run models:frontier-terrain:check`: 나무 수와 위치·트렁크 접지, 기존 강·다리·도로 높이, 산출물 해시를 확인한다. PC/가로 모바일, 솔로·지휘, 세 확대와 전체 보기의 1,344개 시선 표본은 원본 및 분할 광선 검사 결과가 일치하고 영웅 주변 가림이 없었다. 이 표본은 가능한 모든 위치를 보증하지 않는다.
- `BASE_URL=http://127.0.0.1:3100 node tools/tests/frontier-fallback-visibility.cjs`는 실행 중인 개발 서버에서 GLB를 차단하고, 기본 지형의 영웅 시선과 나무 아래 경사 지면을 실제 WebGL 장면에서 검사한다. `terrainView.test.ts`는 외곽 지면의 높이와 통행 불가 경계를 별도로 검사한다.
- 전체 테스트 541개와 웹·모바일 빌드가 통과했다. PC 1440×900과 가로 모바일 844×390 Chromium에서 실제 이동으로 다리를 건너 문제 지점까지 이동하고 터치/클릭, 일시정지·배속·동작 줄이기 및 모바일 충격파 적중을 확인했다. 모바일은 에뮬레이션이다. 숲 메뉴 이미지와 작업실의 GLB/PNG 실패 시 대체 안내도 확인했다.
- 같은 844×390 Chromium SwiftShader 장면에서 적 12명과 이동하는 영웅을 3초씩 순차 비교했다. 정상 GLB의 드로콜은 50→50, 장면 삼각형은 60,122→60,122, 평균 프레임 간격은 136.07→131.89ms였다. GLB 실패 폴백은 드로콜 202→197, 삼각형 56,990→57,038이고 평균은 순차 측정 102.18→111.24ms, 역순 측정 111.22→106.22ms로 방향이 엇갈렸다. 짧은 소프트웨어 표본이며 실기기 성능이나 개선을 보증하지 않는다.
- 기존 나무는 전체 길이에 걸쳐 동일한 수관 높이와 배치를 반복한다. 실제 모바일 기기 GPU·발열, 숲의 더 풍부한 밀도 및 경사 발 IK는 후속 검증과 제작이 필요하다. 기본 지형은 기존부터 드로콜이 많아 별도 최적화가 필요하다.

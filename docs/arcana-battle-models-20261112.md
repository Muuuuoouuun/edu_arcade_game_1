# 실시간 전투 모델과 인간 창방패병 · 2026-11-12

**같은 날 후속 갱신:** 최신 통합 main에 이 작업을 연결하고 이안 및 기본 석궁·포격·마법탑을 추가해 원정 모델이 8종이 됐다. 이동 모션은 최신 엔진의 이동 거리·방향을 따른다. 아래 4종/192개 검증은 최초 연결 시점의 기록이다. [최신 복구 결과와 검증](arcana-3d-recovery-20261112.md).

현재 작업 트리에서 카르·브론·관통 석궁 Lv2·나무 병사를 기존 캠페인의 실제 3D 지형에 연결했다. 인간 창방패병은 참고 이미지에서 제작한 새 모델 시제품으로 작업실에서 검토한다. 새 병과·고용·소환 규칙은 추가하지 않았다.

## 캠페인에 연결한 범위

| 대상 | 실제 연결 | 남은 범위 |
| --- | --- | --- |
| 카르 | 영웅/용병 위치·방향, 보행·망치 공격, 필살기 복귀 자세, 돌진 기울기 | 최종 질감, 다방향 무기 간섭·실기기 검증 |
| 브론 | 영웅/용병 위치·방향, 망치 공격, 필살기 복귀 자세, 돌진 기울기 | 원본에 보행 클립이 없어 이동 중 다리 동작은 없음 |
| 관통 석궁 | `crossbow / pierce / level 2`만 GLB, 고정 기단과 회전 조준부, 발사·복귀 | 기본·속사·Lv3 및 마법·포격 타워는 기존 표현 |
| 나무 병사 | 실제 경로·진행량 기반 보행, 방향·피격 색, 개체별 독립 동작 | 전용 사망/공격 동작은 미연결 |

영웅 해금·전투 수치·길찾기·공격·보상·저장 형식은 기존 엔진이 담당한다. 모델의 방향·자세를 엔진 상태에서 읽으며, 애니메이션에서 추가 피해를 발생시키지 않는다. 숲과 설산에 공통으로 적용한다. 다른 영웅·적·성문·효과는 스프라이트/SVG다.

전투와 지형은 **하나의 WebGL 렌더러**를 공유한다. 모델이 실제로 로딩·렌더링된 뒤 해당 SVG 본체를 숨긴다. 개별 자산 로딩 실패는 해당 유닛의 SVG를 남기며 자동 재요청하지 않는다. WebGL 미지원·컨텍스트 손실은 SVG 지형/유닛 대체 화면으로 돌아가고 복원 시 같은 캔버스에서 다시 그린다. 옛 2D 전장 배경 이미지는 사용하지 않는다.

## 자산·좌표·클립 계약

원본과 SHA-256은 [런타임 자산 목록](../public/defense/models/battle/manifest.json)에 기록했다. Frontier 자산 출처는 `bec804114a26a85a800379058463f4e9fd0bf2cf`, 브론은 기존 `dwarf-guardian.glb`다. 카르 망치 디테일 후보는 편집 메시와 런타임 메시의 차이가 남아 있어 이번 연결에는 보존한 원본을 사용했다.

| GLB | 바이트 | 실제 삼각형 | 클립 길이 / 접촉 | 원래 전방 → Y 회전 보정 |
| --- | ---: | ---: | --- | --- |
| 카르 | 1,320,844 | 9,474 | 보행 0.8초, 공격 0.56초 / 0.28초 | −Z → π |
| 브론 | 1,326,260 | 23,190 | 공격 0.8초 / 10÷30초 | −Z → π |
| 발리스타 | 230,188 | 3,492 | 발사 0.4초 / 0.1초 | +Z → 0 |
| 나무 병사 | 134,616 | 1,024 | 보행 1초 | +X → −π/2 |

합계 3,011,908바이트. 필요한 종류만 지연 로딩한다. 현재 자산은 텍스처와 스킨 없이 관절 노드를 움직이는 GLB이며, 인스턴스마다 독립 믹서를 둔다. 나무 병사의 피격 재질만 개체별로 복제한다.

- `sampleAttackAnimation`은 엔진의 `elapsed / hitAt / duration`을 위 클립 접촉 시각에 맞춘다. 즉시 피해를 주는 필살기는 접촉 자세에서 복귀하며, 돌진은 남은 공격 복귀 자세보다 우선한다.
- 크기와 바닥 기준은 **정지 자세의 실제 정점 경계**로 한 번만 구한다. 무기 휘두르기로 매 프레임 크기가 바뀌거나, 회전된 나무 병사의 느슨한 경계 상자 때문에 발이 뜨지 않게 했다. 발리스타 원본 내부 배율 1.6도 보존한다.
- 지면 60도 정사영과 기존 900×600 좌표를 유지한다. 다리·고지의 표시 높이만 보정하며 이동 가능 영역·충돌 규칙은 바꾸지 않는다.
- 정적 지형을 같은 재질끼리 합쳐 그린다. 숲 1 준비 화면의 카르만 포함한 같은 비교 조건에서 호출 수는 **341회 → 40회**였다. 삼각형과 지형 경계 회귀를 확인했다. 이 수치는 기기의 FPS·발열 개선 실측이 아니다.
- 키보드·터치·적 선택 영역·체력·전술 UI는 기존 입력 경로를 사용한다. `prefers-reduced-motion`에서는 위치는 유지하고 모델 클립을 멈춘다.

## 새 인간 창방패병

[14-A 인간 기본 병사 시안](../art-source/defense/concepts/2026-11-12-characters/human-roles/14-human-garrison-troops.png)을 바탕으로 약 2.6등신, 청록 제복·아이보리 소매·철투구·목재 원방패·창을 모델링했다. 얼굴과 둥근 귀를 포함한 편집 가능한 Blender 원본과 GLB를 보존했다.

작업실 주소: `/model-lab.html?model=human-guard`. 호흡(2초), 보행(0.8초), 창 찌르기(1초·최대 도달 0.4초)를 각각 재생할 수 있다. [모델 원본·미리보기·검증 기록](../art-source/defense/prototypes/human-guard/README.md).

GLB는 8개 메시·43개 프리미티브·23,028개 삼각형·15개 재질, 1,164,924바이트다. 기본 비율과 의상/무기 구조를 검토하는 시제품이며 최종 손그림 질감·텍스처, 스킨 리깅, 발 IK와 실제 전장 채택은 후속 작업이다. 제작용 모델은 모바일 빌드에서 제외한다.

## 재현과 검증

```sh
npm test
npm run build
npm run build:mobile
python tools/tests/check-human-guard.py
npm run dev -- --port 3110
# 별도 터미널, playwright 및 Chromium 필요
node tools/check-battle-models.cjs
```

브라우저 검사 도구는 독립 프로필에 해금된 시험 저장을 생성한다. 사용자의 실제 저장을 수정하지 않는다. `ARCANA_BASE_URL`, `CHROMIUM_PATH`, `ARCANA_EVIDENCE_DIR`로 실행 환경을 지정할 수 있다.

- 게임 자동 테스트: **192개 통과**. 실제 GLB와 엔진 상태를 사용한 새 회귀 12개, 숲·설산 지형 결합 검사 포함.
- 인간 병사 GLB: 60Hz 샘플의 발 접지·루트 고정·무기 종속·반복/복귀·최대 창 도달 시점 및 해시 검사 통과.
- 웹·모바일 빌드 통과. 네 전투 GLB의 해시와 두 빌드의 바이트 일치를 확인했다. 모바일 출력에는 전투 모델을 보존하고 제작용 모델·작업실 진입점은 제외한다. Android APK 생성·실기기 설치는 이번 범위에 포함하지 않았다.
- Chromium 브라우저 5개 시나리오 통과: PC의 석궁 건설/관통 강화·나무 적·일시정지·컨텍스트 손실/복원·방향키 이동, 모바일 화면의 설산 브론·터치 이동, 카르 자산 실패의 독립 대체 표시, WebGL 미지원 대체 화면, 인간 창방패병의 세 클립·동작 줄이기. [기계 판독 결과](arcana-battle-models-20261112/browser-verification.json).

실제 실행 캡처: [숲 전투](arcana-battle-models-20261112/forest-battle.png) · [설산 모바일 화면](arcana-battle-models-20261112/snow-mobile.png) · [인간 병사 작업실](arcana-battle-models-20261112/human-guard-workshop.png) · [WebGL 미지원 대체 화면](arcana-battle-models-20261112/no-webgl.png). 브라우저 검증은 SwiftShader 소프트웨어 렌더링이며 실제 모바일 GPU 측정이 아니다.

## 다음 제작 순서와 제한

1. 기본 석궁과 관통 Lv3의 형태·피벗·동작을 만들어 강화 단계의 3D 전환을 이어간다.
2. 브론 보행과 나머지 영웅의 이동/공격을 동일 계약으로 연결한다. 새 인간 병사는 작업실에서 비율·얼굴·무기 간섭을 검토한 뒤 채택 범위를 정한다.
3. 실제 Android에서 숲·설산/다수 적의 프레임 시간·메모리·발열·복귀·터치를 측정한다. Chromium 소프트웨어 렌더링이나 모바일 화면 에뮬레이션은 이를 대체하지 않는다.

3D 모델끼리는 깊이 검사를 공유하지만, 남은 SVG 유닛/효과는 캔버스 위에 표시된다. 이 혼합 표현의 가림과 체력바·무기 겹침을 최종 해결했다고 보지 않는다. 모든 영웅·타워·적의 전면 3D 전환이나 출시 검증 완료도 아니다.

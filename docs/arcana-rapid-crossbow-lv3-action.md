## 컨셉과 구현

[모듈 컨셉](../art-source/defense/concepts/2026-10-29/props/six-tower-modules.png)의 적층 목재·붉은 문양·금속 활대를 실제 Lv.3 모델과 PC/모바일 전투 화면에서 비교했다. **Lv.2에서는 조준·장전하던 연발 석궁이 최종 강화하면 정지 모델로 돌아가고, 기초까지 흔들리던 차이**를 해결한다.

기존 Lv.3의 금장 활대 끝·세 갈래 화살·붉은 사냥꾼 깃발을 유지한다. 상부 포대가 8방향으로 조준하고, 발사 시 금장 활대와 시위가 풀리며 장전된 화살 묶음이 사라진다. 탄창·레버·되감기 바퀴가 움직여 다음 발사를 준비한다. 새 황동 가로대와 높이가 다른 강철 밀대 3개는 두 고정 레일을 따라 왕복한다. 중앙의 짧은 밀대는 발사 레일 뒤에 위치하고, 양옆 밀대는 측면 화살 아래로 들어간다.

원래 지붕 높이의 깃발은 비스듬한 조준에서 새 기구와 겹쳤다. 깃발과 금장 끝장식을 성곽 측면으로 낮추고 고정 황동 벽 받침 4개를 추가했다. 새 밀대뿐 아니라 기존 되감기 바퀴를 포함한 상부 전체의 회전 경로와 분리한다. 기초·문양·깃발·벽 받침은 움직이지 않는다.

기존 발사 시점 0.1초와 후속 반동 0.24초를 유지한다. 실제 GLB는 0.34초, 전투는 준비→발사→되감기→장전의 4포즈다. 같은 공통 카메라·기존 Lv.3 배율·접지를 사용하며, 화살촉 소켓을 발사 당시 방향과 등급으로 고정한다. 강화·판매·표적 이동 후에도 이미 발사된 탄의 출발점은 변하지 않는다. 세 화살은 기존 최종 강화의 외형이며 실제 탄 개수·명중·피해·연사 간격을 추가하지 않는다.

전투는 2.5D 베이크를 유지하고 작업실은 기존 단일 WebGL 장면에서 실제 GLB를 재생한다. 2단계/3단계는 독립된 이미지 세트를 요구하며 한 등급의 로딩 실패가 다른 등급의 동작을 막지 않는다. 동작 줄이기는 고정 조준 자세를 사용한다.

## 산출물과 재생성

- [편집 원본](../art-source/defense/rapid-crossbow-lv3-action.blend): 개별 메시·재질·베벨·관절·고정 깃발/벽 받침.
- [실제 GLB](../public/defense/models/rapid-crossbow-lv3-action.glb): `rapid-feed-release`, 100fps·35개 샘플 시점·0.34초. 10개 움직이는 관절, 화살 묶음의 크기 채널은 STEP 보간.
- [공통 카메라 PNG](../public/defense/models/rapid-crossbow-lv3-action.png), [8방향×4포즈 PNG](../art-source/defense/rapid-crossbow-lv3-action/): 640×640, 정사영 7.5, crop (32,24,576,576).
- 전투 `rapid-lv3-action-{0..7}-atlas.webp`: 각각 1024×256 RGBA. 표시 배율 `1.16×1.025`. 8장 디코드 픽셀 합 8MiB이며 실제 기기 GPU 측정값은 아니다.
- [메타데이터](../public/defense/models/rapid-crossbow-lv3-action.json): 원본/컨셉/생성기/산출물 해시, 32포즈 경계·소켓·고정 기초, 밀대와 레일/탄창의 간격, 상부 전체와 깃발의 표면 간섭 검사.
- 생성: `npm run models:rapid-action-lv3` (Blender 4.3+, ffmpeg). 원본·접지·간섭 검사만 실행: `npm run models:rapid-action-lv3 -- --check`.
- 내보낸 실제 GLB의 관절·고정 기초·복귀·발사 시점 검증: `npm run models:rapid-action-lv3:check`.
- 작업실: **연발 석궁 · 최종 강화**. GLB 실패 시 PNG라고 표시하고 재생 버튼을 비활성화한다.

## 검증 기록

- 최종 산출물: 31,970삼각형, 44메시, 13재질. GLB 1,588,404바이트, 전투 WebP 8장 합계 386,578바이트. 32개 PNG의 알파 경계와 원본·생성기·컨셉·산출물 해시 일치.
- 편집 원본과 실제 GLB의 35시점 검사: 10개 관절이 움직이고 기초 이동은 0, 시작 자세로 복귀한다. Three.js 복귀 오차는 약 `2.9e-8`, 원본 시위 끝과 활대 연결 오차는 `6.4e-7` 미만이다. 화살 묶음은 0.1초에 사라지고 0.26초에 다시 나타난다.
- 새 밀대 7개와 발사 레일·탄창·고정 레일 4개는 35시점에서 분리된다. 8방향×35시점에서 새 기구 13개와 고정 장식 10개, 상부 전체 91개와 깃발 8개의 표면 교차는 각각 0이다. 전체 모델의 모든 부품 쌍에 대한 물리 시뮬레이션을 의미하지 않는다.
- 최종 베이크 이후 실제 DefenseBoard 6조건×48상태 통과: PC 1440×900, 모바일 390×844, 좁은 화면 320×740, 동작 줄이기, 아틀라스 실패, 기본 이미지 실패. 발사 소켓의 화면 오차는 최대 0.000101px. 발사 후 강화·판매 시 출발점 유지, 전투 중 GLB 요청 없음.
- 실제 게임 UI에서 건설→분기→최종 강화→웨이브, 일시정지·재개, 1배·2배속, 모바일 터치·확대 보기 통과. 준비 중 조기 발사 포즈 0건, 네 포즈 재생, 동작 줄이기에서는 준비 자세 유지. 최종 화면을 직접 비교했다. 모바일 전체 보기의 세부 밀대는 작으며 확대 보기에서 더 명확하다.
- PC/모바일 작업실에서 실제 GLB 재생·정확한 자세 복귀·메시 보기·자동 회전·동작 줄이기·다운로드 주소를 확인했다. GLB 실패 시 `PNG · 렌더 이미지` 표시와 재생 비활성화 통과. 브라우저 오류와 가로 넘침 없음. 모바일은 브라우저 뷰포트/터치 검증이며 실기기 검증은 아니다.
- `npm run build` 통과. `npm test`: 248개 중 247개 통과, 기존 수학 엔진의 `(3 × 7) ÷ 5`에서 `4 !== 4.2` 1건 실패. 기준 커밋에서도 동일하게 재현했다. 관련 신규 실패 없음.
- 기준 커밋과 변경 후 엔진을 2스테이지×3난이도×1,800스텝으로 비교해 모든 상태가 일치했다. 제외한 필드는 없으며 강화·판매·배속·일시정지를 포함한다.

증거 폴더는 저장소 밖 `/tmp/arcana-hourly-20261107-2042/`다. `*-final.log`, `asset-check-final.json`, `motion-comparison-final.png`, 전후 전투·작업실 화면을 보관한다. 초기 새 기구/깃발 교차 524건과 중간 되감기 바퀴/끝장식 교차 4건의 발견 기록도 보존했다. 최종 고정 위치와 벽 받침으로 수정한 뒤 위 검증을 다시 실행했다.

## 남은 범위

전투는 4포즈·8방향이라 방향 사이의 연속 회전이나 관절 보간은 아니다. 탄창 속 낱개 화살을 실제로 이송하는 기계 시뮬레이션은 구현하지 않았다. 실제 Android 기기의 메모리·프레임 성능도 미검증이다. 다음 후보는 영웅 보행→공격 전신 연결, 파쇄포 Lv.3의 고유 반동, 마을 건축 가림이다.

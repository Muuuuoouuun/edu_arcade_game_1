# 은서리 컨셉 → 서리늑대 모델·사족 보행

2026-11-06 (Asia/Seoul). 컨셉 기반 반복 개발의 첫 구현 단위다.

## 컨셉에서 보존한 것

`art-source/defense/concepts/2026-10-29/beasts/silverfrost-wolf.png`와 `variants/silverfrost-wolf-variants.png`의 몬스터를 직접 비교했다. 원안은 회백색 털, 낮게 뻗은 몸, 가는 다리, 짙은 발과 청백색 눈이다. 이전 모델의 큰 파란 등 수정·푸른 발·붉은 발광 눈은 원안과 차이가 커 제거하거나 축소했다. 동료 버전의 목도리와 수인의 장구는 넣지 않았다.

가슴·허리 폭, 다리 두께, 발 크기를 조정하고 뒤로 쓸린 털 덩어리와 낮은 꼬리를 만들었다. 작은 화면에서는 머리카락 같은 미세 털을 재현하기보다 몸의 윤곽과 큰 갈기를 보존한다. 설산 길과 섞이지 않도록 흰 털의 밝기를 올리고 짙은 발·아랫면을 남겼다. 컨셉 삽화의 털 세부 묘사를 완전히 재현한 모델은 아니다.

## 움직임과 납품

대각선 다리 쌍이 교대로 지면을 짚는 8단계 트로트 보행이다. 목과 꼬리는 발보다 약간 늦게 움직이며, 디딘 발의 최저점은 지면에 맞춘다. 강체 부품 관절 방식이며 스킨 리그나 실시간 지형 IK는 아니다.

- 제작: `npm run models:wolf` → `tools/blender/build_wolf.py`
- 편집 원본: `art-source/defense/frost-wolf.blend`
- 포즈 원본: `art-source/defense/wolf-frames/`
- 실제 3D: `public/defense/models/frost-wolf.glb`, `frost-wolf-trot` 클립, 0.8초 반복
- 전투: `frost-wolf-atlas.webp`의 기존 3포즈 + `frost-wolf-trot-atlas.webp`의 8단계 보행
- 규격·해시: `public/defense/models/frost-wolf.json`
- 확인 화면: `/model-lab.html?model=frost-wolf`

카메라는 기존 정사영 시점을 유지한다. 공통 프레임 384×384, 지면 기준 (192, 284.49), 자르기 영역 (8, 100, 368, 228)이다. 포즈별 크기를 따로 맞추지 않는다. 모델 작업실에서는 실제 GLB를 회전·재생하며, 전투에서는 해당 GLB를 다운로드하지 않고 2.5D 이미지로 표시한다.

이 초기 보행은 이동 거리 40 논리 단위당 한 주기를 진행한다. 현재 기본 경로는 후속 [접지 보행·방향 보폭](arcana-frost-wolf-grounded-stride.md)을 사용하고, 여기 설명한 초기 보행은 이미지 로딩 실패 시 대체 경로로 보존한다. 기존 이동 거리 상태를 사용하므로 둔화·빙판 가속·일시정지를 따른다. 피격/넉백은 보행보다 우선한다. 새 보행 파일만 실패하면 같은 모델의 기존 포즈로, 기본 파일도 실패하면 삽화로 대체한다. 동작 줄이기는 고정 보행 포즈를 유지한다. 도약 공격·추가 피해·이동 속도 변경은 이번 범위가 아니다.

## 확인

실제 설산 2-1의 같은 뷰포트·영웅·경로 진행 구간에서 기존/변경 화면을 비교했다. Chromium 1440×900와 390×844에서 8포즈 순환, 일시정지/재개, 동작 줄이기, 보행 이미지 로딩 실패, 모델 작업실의 재생/정지·메시 보기를 확인했다. 연결형 Browser 실행 도구가 없어 설치된 Playwright/Chromium을 사용했다. 뷰포트 에뮬레이션이며 실제 Android GPU 측정은 아니다.

빌드 통과. 전체 테스트 163개 중 162개 통과, 기존 수학 엔진 정답 4/4.2 불일치 1건은 남아 있다. 추가 에셋 검사에서는 전 프레임의 공통 자르기 영역, 기본/보행 포즈의 같은 지면·배율, 부분 로딩 실패와 GLB 클립·파일 해시를 확인한다. 최종 용량은 재생성한 manifest를 기준으로 한다.

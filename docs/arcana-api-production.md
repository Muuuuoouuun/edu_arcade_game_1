# API와 Astra 제작 역할

2026-11-09 (Asia/Seoul). 사용자 요청에 따라 개발·모델링 전반에서 모델을 실제 작업에 활용한다. 호출 횟수 대신 구현·시각 검토·테스트에 반영된 결과를 남긴다.

| 역할 | 담당 | 입력 → 결과 |
| --- | --- | --- |
| 기획·게임성·화면·비주얼 방향 | Claude Fable 5.1 API | 현재 구현, 컨셉, 참고 화면 → 한정된 제작 지시와 수용 기준 |
| 코드 구현·테스트 보완 | Claude Sonnet 5.5 구현 리드 | 확정 범위, 코드, 재현 사례 → 변경과 검증 |
| Blender·모델링·동작·모델 검토 | Astra (`gpt-6-astra`) | 컨셉, 생성 스크립트, 실제 렌더 → 편집 모델·포즈·검토 결과 |
| 복잡한 로직·구조·최종 통합 검토 | Claude Opus 5.5 API | 최종 코드/모델 계약, diff, 실제 검증 증거 → 차단 결함·승인 판단 |
| 짧은 설명·선택형 교육 검토 | Claude Haiku 5.5 API | 문구와 실제 화면의 라벨 → 의미 있는 오류만 지적 |

Fable은 공식 모델 목록에서 확인한 `claude-fable-5-1`을 사용한다. Astra는 Anthropic 모델명이 아니라 Codex 작업자의 모델이다. 서로의 이름으로 실행 결과를 표시하지 않는다.

## 모든 분야에 적용하는 방식

- **기획·게임성:** Fable이 선택의 이유와 다음 한 판의 동기를 제안하고, 구현자는 작은 실험으로 확인한다. 재미는 자동 검사만으로 입증하지 않는다.
- **디자인·모바일 화면:** 사용자 참고 화면의 큰 무기·둥근 입체 형태·팀 색·여유 있는 전투 영역과 거점/전투 분리를 원칙으로 삼는다. 실제 본 이미지와 글로 전달받은 요약을 구분한다. 상점·알림·과금 요소를 그대로 이식하지 않는다.
- **모델링:** Astra가 큰 덩어리, 무기 결합, 피벗, 접지, 방향, 포즈를 제작·검토한다. Fable은 비주얼 방향, Opus는 내보내기·런타임 연결 계약을 검토한다. 실루엣을 먼저 보고 미세 장식은 나중에 더한다.
- **로직:** Opus 지적은 현재 소스와 재현 사례로 확인한다. 의도한 타깃 우선순위나 밸런스 선택을 자동으로 버그 취급하지 않는다.
- **교육:** Haiku에는 데이터 문구와 실제 UI를 함께 제공한다. 현재의 `전장 규칙`/`자연의 원리` 구분을 보존하고, 읽기를 진행 조건으로 만들지 않는다.
- **최적화:** 실제 삼각형·재질·자산 크기·프레임 비용을 측정한다. API가 제안한 예산은 목표이며 성능 개선 실측값이 아니다.

## 인증·증거

KR2는 기존 공식 Anthropic 인증 바인딩으로 사용하고, KRVIDEO는 지원되는 직접 이미지 검토에 사용한다. 변수 이름만으로 영상 생성 능력이 있다고 표시하지 않는다. API 키는 환경에서만 읽으며 앱·APK·저장소·로그에 복사하지 않는다. 상속된 프록시와 CA 검증을 유지한다. 다른 키나 모델로 조용히 바꾸지 않는다.

각 호출에서 모델 ID, 입력 경로/해시, 응답 완료 상태, 사용량과 반영한 판단을 남긴다. 잘린 응답은 완료 검토로 취급하지 않는다. 실패 시 응답이 알려 주는 지원 옵션으로 좁혀 수정하고, 성공한 역할을 불필요하게 재호출하지 않는다. 키·요청 헤더·이미지 base64는 증거 파일에 남기지 않는다.

최종 검토 후 변경된 파일은 영향을 받는 부분을 다시 검토한다. AI의 승인과 실제 테스트는 별개다. 컨셉 이미지, 실제 Blender 지오메트리, 베이크된 2.5D 스프라이트, 실행 중인 GLB를 구분한다.

## 시간당 작업과 Astra 연결

현재 예약 실행기는 Claude CLI 기반이다. Sonnet 리드와 Fable/Opus/Haiku 역할을 호출할 수 있지만 **Astra를 직접 호출하는 기능은 없다.** Codex 조정 세션에서 실제 Astra 작업자를 배정한다. Astra가 없는 회차는 Sonnet이 새 지오메트리를 대신 제작하지 않는다. 대기 중인 Astra 인계와 분야 전환 사유를 기록하고, 별도로 검증 가능한 비지오메트리 개선 하나를 선택한다. 모델링 후보는 완료 처리하지 않고 대기로 유지한다. 이 예외 전환 뒤에는 Astra 인계가 이행될 때까지 `next_lane=modeling`을 유지한다. Fable 기획 호출도 회차당 위임 검토 2회 한도에 포함하며, 한 자리는 최종 독립 검토를 위해 남긴다.

기존 한도인 1시간 간격, 회차 최대 50분·8달러·64턴을 유지한다. CLI 밖의 직접 API 호출은 CLI 영수증과 분리해 기록한다. API를 적극 사용한다는 요청을 무제한 병렬 호출이나 비용 한도 해제로 해석하지 않는다. 환경이 멈추면 예약 실행도 멈추며, 실제 `status`를 확인한 뒤에만 실행 중이라고 보고한다.

## 이번 적용 결과

공식 API 호출에서 Fable 5.1, Opus 5.5, Sonnet 5.5 이미지 검토, Haiku 5.5 문구 검토의 응답 모델과 정상 완료를 확인했다. Fable에는 사용자가 보낸 참고 화면의 관찰 요약을 전달했으며, 원본 스크린샷을 직접 본 것으로 표시하지 않는다. Sonnet 이미지 검토에는 북극곰·화산 거북 원본을 실제로 첨부했다.

- 채택: 큰 실루엣·색 덩어리·상징 무기 중심으로 컨셉을 단순화하고, 공통 카메라·접지·포즈 계약을 검증한다.
- 미채택: 전투 자원 HUD 일괄 제거는 현재 타워 건설 정보와 충돌하므로 적용하지 않는다. 교육 라벨 누락이라는 초기 지적은 실제 UI를 다시 제공해 철회됐다.
- 실제 제작: Astra가 [북극곰 Blender 시제품](../art-source/defense/prototypes/polar-bear/README.md)을 제작했다. 편집 모델, GLB, 4포즈 렌더와 재불러오기 증거를 보존한다. Opus는 생성 스크립트와 실제 렌더를 검토했다.
- 후속 제작: [모델 동작 제작 기록](arcana-model-actions-2026-11-09.md). 닻 망치 타격 윤곽을 개선하고 도마뱀 궁수를 제작해 3D 작업실에 연결했다. 48px 동작 구분, 실제 캠페인 전투 연결과 기기 성능 검증은 남아 있다. 현재 게임·APK에 연결된 새 영웅이라고 표시하지 않는다.

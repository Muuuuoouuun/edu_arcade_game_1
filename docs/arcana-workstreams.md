# 아르카나 수비대 작업 분담

## 현재 범위와 기준

- 기존 게임 허브의 **아르카나 수비대** 전용 화면에서 플레이하는 프로토타입이다.
- **청록의 숲 4개 + 서리산맥 4개, 총 8개 스테이지**를 다룬다. 첫 마을 방어에서 시작해 용병 방문, 시설 정착, 타워 강화, 선택 퀘스트, 두 번째 방어 거점과 다음 지역의 구조 요청으로 이어진다.
- 우선순위는 **게임성·오락성 → 그래픽 → 최소한의 교육 요소**다. 교육은 재질·속성 상성에만 반영하며 전투를 멈추는 퀴즈는 넣지 않는다.
- 처음에는 마법사로 시작하고, 클리어에 따라 엘프·드워프·도사·바바리안·수인 드루이드가 찾아온다. 해금은 방문·정착·도움 요청으로 표현한다.
- 숲·설산·사막·성채·무림·도원 등 **6개 지역 전체는 향후 기획**이다. 현재 범위는 숲과 설산 두 지역이며 사막·성채·무림·도원은 포함하지 않는다.
- 현재 자동 테스트 57개와 빌드, 숲·설산의 실제 브라우저 조작을 검증했다. 1366×768·1440×900 및 모바일 390/320px에서 화면·용병 선택·일시정지 경계를 확인했다. 모션 개선 후에는 1440×1000 실제 보스전과 모바일 이동·공격·배속을 다시 확인했다. 실제 사용자 대상 재미 검증은 후속 작업이다.

## 현재 작업 소유권

| 작업 | 담당 범위 | 소유 파일·영역 |
|---|---|---|
| 전투 | 적 이동·자동 공격·속성·웨이브·타워 분기·보스·전투 테스트 | `src/games/defense/engine.ts`, `data.ts`, `engine.test.ts` |
| 성장·해금 | 클리어 정산·방문자·영구 강화·시설·구조 요청·저장 데이터·중복 보상 방지 | `src/games/defense/campaign.ts`, `campaign.test.ts` |
| 화면 | 전투 조작·수비대·퀘스트·방문·결과·거점 화면과 반응형 배치 | `src/components/DefenseGame.tsx`, `DefenseBoard.tsx`, `src/defense.css`, `defense-board.css` |
| 아트 | 숲·설산 배경·캐릭터·몬스터·타워·시설・소품, 시안과 실제 화면 비교 | `public/defense/` 및 원본 생성 이미지 |
| 통합 | 공통 타입·기존 허브 연결·저장 기록·최종 빌드와 브라우저 검증 | `src/games/defense/types.ts`, 허브 공통 파일, 검증 결과 |

현재 전투는 `attacks`의 준비·타격·회복, `projectiles`의 비행·충돌, 실제 위치를 갖는 영웅·용병·펫과 적 넉백을 포함한다. 화면 모션은 시뮬레이션 시간을 사용하며 `DefenseEffects.tsx`가 투사체·타격·처치 효과를 그린다. 공격 포즈 규격은 `art.ts`, 공격별 소리는 `src/lib/sound.ts`에서 관리한다. 이번 개선의 검증과 후속 우선순위는 [모션 검토](arcana-motion-review.md)에 정리했다.

이 대화의 통합 담당이 최종 연결을 관리한다. 작업 공간은 공유되므로 **같은 파일을 동시에 수정하지 않는다.** 공통 타입이나 다른 담당의 API를 바꿔야 하면 변경 계약을 먼저 전달한다.

## 구현된 캠페인 API

저장은 기존 허브 기록과 분리된 `playground:defense:v1`을 사용한다. 버전은 1을 유지하며, 기존 4스테이지 클리어 저장을 읽으면 골드·영웅·강화·처리된 전투 기록을 보존한 채 5스테이지를 해금한다. 지역·방문자·퀘스트 기준은 공통 `data.ts`의 `STAGES`를 참조한다.

| API | 용도 |
|---|---|
| `createCampaign()` / `readCampaign()` | 초기 캠페인 생성 / 검증된 저장 데이터 복원 |
| `writeCampaign(campaign)` | 저장 성공 여부 반환; 실패해도 전투를 중단하지 않음 |
| `stageUnlocked(campaign, stage)` | 순차 스테이지 해금 확인 |
| `completeRun(campaign, runId, state)` | 종료된 전투의 보상·클리어·방문자 정산; 같은 `runId` 중복 지급 방지 |
| `acknowledgeVisitor(campaign, hero)` | 방문 연출 확인 상태 저장 |
| `selectHero(campaign, hero)` | 해금된 영웅 선택 |
| `trainingCost(campaign)` / `trainCampaign(campaign)` | 강화 가격 조회 / 드워프 합류 후 영구 강화 |
| `campaignFacilities(campaign)` | 숙소·정찰 초소·대장간·도원·영물 쉼터의 해금 상태와 표시 정보 |
| `campaignRequest(campaign)` | 다음 순차 미완료 스테이지의 요청자·지역·제목·이야기; 8개 모두 완료하면 `null` |

캠페인 규칙은 다음과 같다.

- 1·2·3스테이지 첫 클리어로 각각 엘프·드워프·도사가 합류한다. 5스테이지에는 바바리안 카르, 7스테이지에는 수인 드루이드 루나가 합류한다.
- 첫 클리어는 `100 + 스테이지 × 40 G`, 재클리어는 `30 + 스테이지 × 10 G`를 지급한다.
- 선택 퀘스트는 스테이지별 1회 `80 G`다. 1~3스테이지는 마을 체력 15 이상, 4·8스테이지는 외곽 거점 생존, 5·7스테이지는 마을 체력 12 이상, 6스테이지는 60마리 이상 격퇴가 조건이다. 클리어 후 조건을 충족했을 때 지급하며, 나중에 재도전해 받아도 된다.
- 실패 보상은 `처치 수 × 2 G`, 최대 `40 G`다. 실패는 지역·인물을 해금하지 않는다.
- 영구 강화는 최대 5단계이며 가격은 `100 + 현재 강화 단계 × 80 G`다.
- 캠페인 모듈 테스트 11개는 통과했다. 기존 저장 호환, 8개 스테이지 보상·재도전, 새 방문자, 퀘스트 기준, 시설·요청 해금 등을 검증한다. 전투·화면까지 포함한 전체 QA는 통합 담당이 별도로 확인한다.

## 별도 대화에 붙여 넣을 작업 요청

사용자용 새 대화를 자동 생성하는 도구는 현재 사용할 수 없다. 아래 요청문을 각각 새 대화에 붙여 넣고 담당 범위를 배정할 수 있다. 역할별 작업 분담과 실제 사용자 대화 생성은 별개다.

### 1. 다음 지역·몬스터·보스

> `docs/arcana-workstreams.md`와 `src/games/defense/types.ts`, `data.ts`를 읽고, 숲·설산 다음의 사막 지역을 기획해 주세요. 재미가 먼저이며 교육은 상성에만 넣습니다. 입력은 기존 8스테이지 진행·방문자·보상 규칙입니다. 지역의 핵심 지형 규칙 1~2개, 서로 다른 몬스터 3종, 공격 예고와 약점 노출이 있는 보스 1종, 방문자 1명, 선택 퀘스트 2개를 제안해 주세요. 결과는 신규 문서 `docs/arcana-desert-region.md`에 작성하고, 기존 전투·성장 코드와 공통 타입은 수정하지 마세요. 수치와 필요한 엔진 변경을 구분해서 통합 담당에게 전달하세요.

### 2. 캐릭터 아트·직업 개성

> `docs/arcana-workstreams.md`와 기존 `public/defense/` 아트를 참고해 다음 캐릭터 세트를 제작해 주세요. 무림 고수·관군 장수·인간 기사의 실루엣, 무기, 공격 연출, 전직 두 갈래를 구분하고 기존 게임의 색감·시점·크기를 유지해 주세요. 입력은 기존 캐릭터 스프라이트 규격과 전투 화면입니다. 먼저 규격을 확인하고, 새 파일은 `public/defense/characters-next/`에만 추가하세요. 투명 배경 원본, 이름·종족·출신·직업·전직·기술 설명을 함께 전달하세요. 기존 아트와 UI·전투·성장 코드는 덮어쓰지 마세요.

### 3. 밸런스·플레이 QA

> `docs/arcana-workstreams.md`를 읽고 현재 8스테이지 프로토타입을 검증해 주세요. 입력은 실행 가능한 허브, 전투 데이터, 캠페인 보상 규칙입니다. 초보 배치·속성 조합·용병 사용·무강화 플레이를 비교하고, 승패·소요 시간·거점 체력·보상·강화 시점을 기록하세요. 데스크톱과 모바일에서 실제 조작, 일시정지, 재도전, 방문 연출, 거점 시설, 지역 간 구조 요청, 기존 4클리어 저장의 복원을 확인하세요. 처음에는 소스 변경 없이 재현 절차·증거·수정 권고를 전달하고, 승인된 수정만 배정된 파일에서 진행하세요. 임시 스크립트와 스크린샷은 저장소 밖에 두세요.

각 대화의 결과는 이 통합 대화에 **변경 파일, API 영향, 검증 결과, 남은 문제**와 함께 전달한다. 새 지역·직업·밸런스 변경을 동시에 합칠 때는 공통 타입과 전투 데이터를 통합 담당이 순서대로 반영한다.

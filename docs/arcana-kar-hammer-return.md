# 카르 · 양손 망치 강타에서 현재 걸음으로

2026-11-08, 컨셉 개발 54회차. 기준 `3c01cc6a3a8a41f74ca35d7a7585ade09b3ebc4e`, 소유 브랜치 `codex/arcana-stage-experience-20261106`.

원본 `art-source/defense/atlases/melee-motion.png` 첫 줄과 실제 PC/모바일 화면을 비교했다. 붉은 머리·흰 털망토·양손 망치의 기존 실루엣과 강타 준비는 유지되지만, 공격 회수 중 발이 고정돼 있다가 보행으로 바뀐다. 이번에는 몸이 먼저 일어서고 무거운 망치와 털망토가 뒤따르며 현재 걸음에 합류하도록 연결했다.

원격 main `2eabc76`, Claude nice `bf7c1c6`, wizard `67fc1c4`는 이전 회차 이후 변하지 않았다. main 위의 통합 개발 69커밋과 서리늑대·포탑·지형·성문·브론·통나무 병사, 앞 회차 카르 준비를 보존했다. Claude 58회차의 리엘 활 두께·방향 시험은 별도 후속 후보로 유지한다.

## 실제 동작과 전투 연결

- `kar-return-0`~`kar-return-7`: 기존 강타 회수 프레임 44(원본 0.43초)에서 시작해 여덟 보행 자세로 끝나는 **0.14초·100fps·11관절** 실제 GLB 클립이다.
- 몸과 머리는 0.11초에 목표 보행 자세에 도달한다. 망치·털망토·수염은 0.02초 늦게 회수를 시작하고 0.14초에 합류해 무거운 장비가 뒤따르는 움직임을 만든다.
- 들릴 발은 낮은 호로 움직이며, 반대 발바닥은 모델 지면 높이를 유지한다. 어깨와 실제 망치 그립에서 팔꿈치·상완·전완을 다시 계산해 두 손이 무기에서 떨어지지 않는다.
- 영웅·용병의 현재 보행 방향이 공격 방향과 같은 8방향 구간이고 실제로 이동 중일 때만 복귀를 사용한다. 목표 걸음은 공격 시작 당시가 아닌 **현재 이동 거리**에서 선택한다.
- 원래 0.28초 타격과 반동을 유지한다. 0.42~0.44초는 기존 회수, 0.44~0.49초는 체중 회수, 0.49~0.54초는 다음 발 들기, 0.54~0.56초는 현재 보행을 표시한다. 두 중간 베이크의 원본 시간은 새 클립 0.04/0.12초다. 표시 구간은 실제 공격의 타격/종료 시각 비율을 따른다.
- 정지·반대 방향·방향 미확정·돌진·필살기에는 기존 표현을 유지한다. 동작 줄이기나 복귀 세트 실패에도 기존 강타·보행·준비는 동작한다. 준비 세트 실패는 복귀를 막지 않는다.

엔진은 변경하지 않았다. 타격·피해·이동·보상과 0.56초 공격 길이를 보존한다. 전투는 실제 3D 원본의 베이크 2.5D, 작업실은 단일 실시간 3D 장면이다. 전투는 두 중간 자세를 선택하는 방식으로, 연속 관절 보간이나 이동하는 월드 좌표에서의 발 고정·지형 IK가 아니다.

## 검증과 남은 범위

외부 증거 `/tmp/arcana-hourly-20261108-2240/`에 기준 커밋·소유 브랜치·범위·수용 기준·미완료 상태, 검증 로그와 전후 화면을 남겼다.

- Blender 자세 검사와 편집 원본 재열기 통과. 208메시×8개 시작/끝의 최대 월드 변환 오차 `5.52e-18` 이하.
- 전달 GLB 456시점 검사: 시작 오차 `1.79e-7`, 보행 끝점 오차 `3.59e-7` 이하. 발바닥 높이는 약 0.01, 양팔 연결 오차는 0.000352 이하(공통 카메라 약 0.020px). 몸은 0.11초에 보행과 일치하지만 망치는 모든 클립에 후속 움직임이 남는다.
- 생성기·컨셉·원본·산출물 143개 해시 일치. PNG 128장·WebP 128셀의 최소 투명 여백 14px. 빌드 산출물 11개가 원본과 일치한다.
- 전체 **338개 중 337개 통과**. 기존 수학 게임 `(3×7)/5`의 4/4.2 실패는 기준 커밋에서도 재현했다. 새 회귀는 없으며 타입 검사·프로덕션 빌드 통과.
- 스테이지 1·4·5·8×영웅/용병 8게임·14,400스텝에서 **어떤 필드도 제외하지 않고 모든 상태가 기준 엔진과 같다.** 공격·피해·체력·위치·보상·배속·일시정지·돌진·필살기·강화를 포함했다.
- 실제 `DefenseBoard`의 영웅/용병×8방향×8현재 걸음·여러 시점을 PC·390/320px·동작 줄이기·복귀/준비/강타/보행 이미지 실패로 검사한 3,328조합이 통과했다. 정지·방향 불일치·돌진·필살기 우선순위, 현재 걸음 변경과 강화 크기도 확인했다. 오류·가로 넘침·전투 GLB 요청은 없었다.
- 실제 PC 1440×900·390×844 터치 UI에서 이동·웨이브·자연 강타·1배속/2배속 복귀·복귀 중 일시정지·동작 줄이기/복원·재개·전장 확대를 조작했다. 첫 추적 경로에서는 정렬된 이동 복귀가 관찰되지 않았고, 모바일에서는 건설 지점 선택으로 전술 일시정지에 들어갔다. 타격 후에도 빈 땅으로 이동을 이어가는 입력 경로에서 검증을 완료했다. 제품 코드를 테스트 경로에 맞춰 바꾸지 않았다.
- 작업실 PC 8클립과 390/320px 각각 3클립에서 실제 캔버스 변화·끝 자세·메시 보기·회전·시점 초기화·동작 줄이기·단일 캔버스를 확인했다. GLB 실패 시 PNG를 렌더 이미지로 표시하고 재생을 끈다. 기존 이안 정지도 확인했다.
- 컨셉 원본·공통 카메라·동일 조건 PC/모바일 전후 화면·실제 모바일 전투·모바일 작업실을 직접 확인했다. 양쪽의 타격·반동·회수 시작 화면은 전후 픽셀이 동일하다. 모바일은 Chromium 터치 에뮬레이션이며 실제 Android 검증은 아니다.

# 러시 시제품의 통합과 조작·저장

2026-11-11. 통합 계보 `886b651`과 별도 러시 작업 `e843d9e`를 합쳤다. 기존 원정·군단·실시간 3D 변경 전장을 보존하고 거점에 러시 진입을 추가한다. 러시는 영웅 직접 이동·발사, 타워 설치·강화, 마을 성장과 스테이지/무한 도전이 이어지는 **별도 시제품**이다. 저장 키와 재화는 기존 원정이나 군단에 합치지 않는다.

- 러시 전장은 Three.js 단일 장면의 실제 메시·충돌 규칙을 사용한다. 기존 Meshopt GLB 영웅 세 명은 웹·모바일 번들에 포함되고, 모델 로딩 실패 시 기존 절차형 몸으로 게임을 계속한다. 적과 지면은 주로 절차형 모델과 평면 텍스처이므로 지역별 입체 지형과 정식 적 모델 완성으로 보지 않는다.
- 사용자의 전투 UI 결정에 따라 웨이브·마을 체력·골드 HUD와 개체 위 체력막대를 숨기고 이동·공격·필살기·건설·정지 조작을 유지한다. 탑 분기 버튼은 가로 화면의 왼쪽 위에 세로로 놓고 터치 크기 44px 이상을 지킨다. 건설 고리의 금색과 짙은 청록 바닥 대비를 높이고 동작 줄이기에서는 해당 고리의 맥동을 멈춘다.
- 세로 회전이나 앱 백그라운드·브라우저 포커스 이탈 시 전투를 멈춘다. 가로로 돌아오면 사용자가 재개해야 한다. 회전·정지·포커스 이탈에서 드래그·키·대기 발사를 비워 예기치 않은 공격이 이어지지 않게 한다.
- 저장이 차단되면 강화·보상·이미 지급한 전투 ID를 현재 창의 메모리에 보존하고 경고 및 다시 저장 버튼을 제공한다. 최초 읽기에 실패한 뒤 미확인 기존 저장이 발견되면 자동으로 덮어쓰지 않는다. 창을 닫은 뒤의 임시 데이터 복구는 보장하지 않는다.

검증 범위는 전체 자동 테스트, 웹·모바일 빌드, 모바일 결과물의 세 GLB와 글꼴 확인, PC·가로 모바일 브라우저의 실제 이동·발사·건설·정지·회전, 저장 실패/복구와 GLB 로딩 실패다. 재현은 개발 서버를 3134 포트에서 시작하고 `node tools/tests/rush-integrated-browser.cjs`, `node tools/tests/rush-blur-browser.cjs`, `node tools/tests/rush-pad-browser.cjs`, `node tools/tests/rush-fallback-browser.cjs`를 실행한다(`BASE`로 다른 서버 지정). 패드 화면 시험은 영웅 위치와 골드만 설정한 뒤 실제 터치로 건설·분기를 선택한다.

실제 기기 발열·메모리·GPU 성능과 사람 대상 재미 평가는 미측정이다. WebGL을 만들지 못하면 시작 화면 복귀·재시도 안내를 표시하고 입력을 막는다. 전투 중 컨텍스트가 유실되면 입력과 시뮬레이션을 멈추고 재시도/복귀를 제공한다. 재시도 시 저장되지 않은 진행은 사라질 수 있으며 기존에 저장된 마을은 유지된다. 이 시제품을 목표 품질 65점 달성으로 판단하려면 사람 플레이와 기기 측정이 필요하다.

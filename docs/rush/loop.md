# 아르카나 러시 · 1시간 개발 루프 규약

1시간마다 한 회차씩 시제품을 **하나의 검증된 개선**만큼 키운다. 기능 개수보다 “다음 판을 또 하고 싶은가”를 먼저 묻는다. 우선순위는 **재미 → 손맛·가독성 → 그래픽 → 확장성**이다.

**방향 (2026-11-10 사용자 결정)**
- **플레이는 킹샷식이다.** 마을 성장과 PvE 웨이브 방어가 중심이고, 실시간 PvP는 없다.
- **디자인·그래픽·렌더 톤은 브롤스타즈풍이다.** 기준은 [art-direction.md](art-direction.md)에 있다.
- 실행 방식은 TypeScript + Capacitor를 유지한다. 실기기 게이트를 통과하지 못할 때만 재검토한다([조사 문서](engine-research-2026-11.md)).

**대기 결정 정리 (2026-11-11, 사용자가 판단을 위임함)**
- **Android SDK 라이선스: 지금은 동의하지 않는다.** 사용자 이름으로 하는 법적 동의라 대신하지 않는다. 컨테이너 개발에는 필요 없다. 실기기 시험을 할 때 사용자가 APK를 요청하면 그때 진행한다.
- **러시 앱 묶음: 독립 앱(러시 전용 앱 ID).** 방향이 ‘독립 모바일 게임’이다. 공유 `capacitor.config.ts`는 건드리지 않고, 실기기 단계에서 러시 전용 설정으로 만든다.
- **영웅 GLB: 러시 전용 meshopt 사본을 만든다.** `src/rush/models/`에 둔다. 캠페인 원본(`public/defense/`)은 그대로다. 디코더는 three에 이미 들어 있어 새 의존성이 없다. 생성 도구는 `package.json`을 바꾸지 않고 `npx`로 돌린다. 굽기 코드에 float32 되돌리기를 넣는다(31회차 시험).
- **three.js 0.187: 보류.** 러시에는 이득이 없고 캠페인과 함께 쓰는 의존성이다. 캠페인 작업 때 함께 올린다(37회차).

## 실행 방식과 경계

- **실행 수단**: claude.ai 예약 작업이 1시간마다 이 클라우드 세션을 깨운다. 세션이 종료·보관되면 루프도 멈춘다. 진행 상태의 기준은 저장소의 [회차 기록](cycles/)이다.
- **브랜치**: `claude/confident-knuth-qc16ui`에 커밋하고 push한다. **PR은 사용자가 요청할 때만** 만든다. 병합하지 않는다.
- **범위**: `src/rush/`, `docs/rush/`, `tools/rush-*`, `rush.html`만 바꾼다. 기존 아르카나 캠페인(`src/components/`, `src/games/`, `src/ArcanaApp.tsx` 등)과 저장 키는 수정하지 않는다. 공용 `src/lib/`를 바꿔야 하면 그 회차에 `npm test` 전체를 통과시킨다.
- **시간**: 한 회차는 45분 안에 끝낸다. 넘으면 진행분을 커밋하고, 기록에 **미완료**로 남긴 뒤 멈춘다. 다음 회차가 이어받는다.

## 한 회차의 절차

| 구간 | 할 일 | 완료 조건 |
| --- | --- | --- |
| 0~5분 | `git status`, `git fetch origin claude/confident-knuth-qc16ui`, 마지막 회차 기록 읽기. 미커밋 변경이 이전 회차 것이면 이어서 마무리 | 기준 SHA와 이어받을 작업이 확인됨 |
| 5~10분 | 이번 레인에서 백로그 1개를 고른다. **편집 전에** `docs/rush/cycles/NN-<레인>.md`를 만들어 범위·가설·수용 기준을 적는다 | 한 문단짜리 범위와 확인 가능한 기준 |
| 10~35분 | 수치는 `data.ts`, 규칙은 `sim.ts`와 테스트, 표현은 `render.ts`·`input.ts`·`main.ts` | 게임에서 보이는 변경, 규칙 변경은 테스트 동반 |
| 35~42분 | `npm run test:rush`, `npx tsc --noEmit`, `npm run build`, `npm run smoke:rush -- <스크래치 폴더>`. 화면 변경은 스크린샷을 **직접 열어** 확인 | 모두 통과. 실패는 고치거나 기록 |
| 42~45분 | 범위 파일만 커밋·push, 회차 기록에 결과·다음 레인·백로그 상위 3개 갱신 | push 성공, 기록 완료 |

회차가 끝나면 사용자에게 한 단락으로 보고한다: 무엇을 바꿨나, 검증 결과, 다음 계획.

## 지키는 것

- **설계 기둥 테스트**(아무것도 안 함, 영웅만, 탑만 → 패배 / 영웅+탑 → 2~4분 안에 승리)는 항상 통과해야 한다. 기준 자체를 바꿔야 하면 이유와 새 기준을 기록한다.
- **참고작은 원칙만.** 브롤스타즈·킹샷의 이름·캐릭터·아트·UI·맵을 복제하지 않는다.
- **성능 주장 금지.** 컨테이너 브라우저는 소프트웨어 렌더링이다. 드로콜·삼각형 수 같은 **개수**로만 보고하고, FPS 개선을 주장하지 않는다.
- **API 키.** 현재 컨테이너에는 LLM·이미지 생성 키가 없다(GitHub 토큰과 클라우드 자격 증명뿐). 생성형 에셋이 필요하면 사용자에게 환경 설정의 네트워크 시크릿 추가를 요청한다. 키를 코드·저장소·로그에 남기지 않는다. 관련 없는 클라우드 자격 증명은 쓰지 않는다.
- **정직.** 돌리지 않은 검증을 했다고 쓰지 않는다. 가치 있는 변경이 없으면 ‘변경 없음’과 근거를 기록한다.

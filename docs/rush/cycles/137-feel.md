# 137회차: 전투 손맛, 쏠 수 없을 때 누른 단추가 아무 반응이 없다

| 항목 | 값 |

## 문제

131회차에 쏘기 간격 안의 탭을 0.25초 들고 있게 했다. 그래도 화살이 비었을 때(채움 1.25초)나 영웅이 쓰러져 있을 때 누른 탭은 그대로 사라진다. 필살기도 게이지가 차기 전에 누르면 아무 일도 없다. 단추가 눌렸는지, 눌렸는데 안 되는 건지 구별되지 않는다. 쏘기 단추에는 화살이 비면 `empty` 모양이 있지만, 누른 순간의 반응은 없다.

## 범위

- `fireBuffer.ts`: 들고 있던 탭이 쏘지 못하고 시간이 지나 버려지면 그것을 알린다(`expired()`, 한 번 읽으면 지워짐).
- `main.ts`: 그 순간 쏘기 단추에, 그리고 게이지가 차기 전에 누른 필살기 단추에 짧은 ‘헛누름’ 반응(`dry`): 0.25초 좌우 흔들림과 화살 칸의 붉은 깜빡임. 동작 줄이기 설정에서는 흔들림 없이 테두리만 붉게 깜빡인다.
- 소리·진동은 공용 `src/lib` 밖이라 이번 범위가 아니다(새 소리 종류가 필요함).

## 가설

헛누름이 보이면 ‘단추가 안 먹는다’가 ‘지금은 못 쏜다’로 바뀐다. 쏠 수 있을 때의 탭에는 반응이 생기지 않는다(멋대로 흔들리지 않음).

## 수용 기준

- [x] 시험: 화살이 빈 채 누른 탭은 0.25초 뒤 한 번 `expired`, 쏜 탭·새 탭으로 바뀐 탭은 `expired`가 아님
- [x] 브라우저: 화살을 다 쓴 뒤 탭하면 `#fire`에 `dry`가 붙고, 쏠 수 있을 때 탭하면 붙지 않음. 필살기도 같음
- [x] `test:rush`, `tsc`, `build`, `smoke:rush` 통과

## 결과

브라우저 확인(데스크톱 1280×720, F 키 = 쏘기, 스페이스 = 필살기; `dry`가 붙은 횟수를 셈):

| 누름 | 일어난 일 | 쏘기 `dry` | 필살기 `dry` |
| --- | --- | ---: | ---: |
| 쏠 수 있을 때 F | 1발 | 0 | 0 |
| 화살 0개에서 F | 쏘지 못함, 0.25초 뒤 버려짐 | **1** | 0 |
| 게이지 전 스페이스 | 필살기 안 나감 | 1 | **1** |
| 게이지 찬 뒤 스페이스 | 필살기 1번 | 1 | 1 (그대로) |

- **넣은 것.** `FireBuffer.expired()`(들고 있던 탭이 쏘지 못하고 버려지면 한 번 참), `RushInput.dryFire()`, `main.ts`의 `dryPress()`. 쏘기 탭이 버려지면 쏘기 단추에, 게이지 전에 누른 필살기는 필살기 단추에 `dry`를 단다. `dry`는 0.26초 좌우 흔들림(`translate`라 눌림 `transform`과 겹치지 않음)과 화살 칸 붉은 빛. 그동안 빈 화살통의 흐림(`empty` 필터)을 걷는다(첫 스크린샷에서 붉은색이 흐려 보여 고침). 동작 줄이기 설정에서는 흔들림 대신 붉은 테두리 깜빡임.
- 쏠 수 있을 때의 탭, 간격 안에서 기다렸다 나간 탭(131회차 버퍼), 찬 필살기에는 반응하지 않는다. 시연에는 없다.
- 소리·진동은 공용 `src/lib`(캠페인과 함께 씀)에 ‘헛누름’ 소리가 없어 넣지 않았다. 필요하면 사용자 승인 뒤 공용 소리에 하나를 더해야 한다.
- 스모크의 폰 ‘탭 쏘기’ 검사가 이번에도 한 번 실패했다(128회차 뒤 약 10번 중 2번). 탭 뒤 0.4초를 고정으로 기다리는 검사라 소프트웨어 GL의 긴 프레임에 걸린다. 데스크톱 클릭 검사처럼 쏠 때까지(최대 3초) 기다리게 바꿨다. 쏘지 않으면 여전히 실패한다.

## 문제

97회차에 높음 품질의 실제 그림자가 들어오면서 무거운 장면의 드로콜이 64에서 109로 늘었다. 실제 기기의 GPU 비용은 여기서 잴 수 없다(소프트웨어 렌더). 대신 컨테이너에서 잴 수 있는 것은 그림자 패스가 몇 번 그리는지, 무엇이 그림자를 드리우는지다.

지금 규칙(`frame.ts` `markShadows`)은 툰 재질의 단단한 메시를 모두 드리우게 한다. 장면 바깥 섬의 나무, 길가 풀 포기·꽃·조약돌 같은 작은 장식, 상자까지 모두 그림자 패스에 들어간다. 높은 고정 카메라에서 작은 장식의 그림자는 거의 보이지 않는다.

## 범위

- 디버그 전용 집계: 그림자를 드리우는 보이는 메시 수와 삼각형, 이름별로. 높음 품질에서 그림자를 켠 것과 끈 것의 드로콜 차이.
- 줄이기: 작은 장식(조각 하나가 낮고 작은 것)과 전장 바깥 장식이 그림자를 드리우지 않게 한다(`userData.noShadow`). 영웅·적·탑·바리케이드·성·성벽·바위·나무 같은 큰 것은 그대로 드리운다.
- 전후: 드로콜·삼각형, 같은 장면 스크린샷(숲·눈, 높음)을 직접 비교한다.

## 가설

그림자 패스 드로콜의 3분의 1 이상이 작은 장식이다. 이들을 빼면 높음 드로콜이 109에서 90 안팎으로 줄고, 화면 차이는 거의 보이지 않는다.

## 수용 기준

- [x] 그림자 패스 집계 표(전후)
- [x] 같은 장면 스크린샷 전후를 나란히 보고, 큰 물체의 그림자가 그대로임을 확인
- [x] `test:rush`, `tsc`, `build`, `smoke:rush` 통과

## 결과

가설은 크기에서 틀렸다. 그림자를 드리우는 메시 중 작은 장식은 3분의 1이 아니라 약 6분의 1이었다.

**누가 그림자를 드리우나**(디버그 집계 `__rush.shadowCasters()`, 휴대폰 가로, 높음, 적 61 + 보스 + 탑 4 + 바리케이드 3)

| 묶음 | 메시 | 삼각형 | 줄였나 |
| --- | ---: | ---: | --- |
| 적 묶음(인스턴스)·탑·바리케이드 | 16 | 약 28,000~29,800 | 그대로 |
| 맵 묶음: 성벽 1, 숨는 풀 6, 상자 6 등 | 13~15 | 5,600~6,400 | 숨는 풀 6개만 뺌 |
| 길가 장식(꽃·풀 포기·조약돌), 메시 하나 | 1 | 8,000~8,600 | 뺌 |
| 전장 바깥 풍경(관문·나무·섬) | 1 | 4,000~4,600 | 그대로 |
| 성 | 1 | 4,374 | 그대로 |
| 영웅 부위 | 10 | 약 8,500 | 그대로 |

**바꾼 것**: `frame.ts`에 `userData.noCast`(그림자를 받기만 하고 드리우지 않음)를 더했다. 숨는 풀·서리 갈대 6개와 길가 장식 메시 하나에 붙였다. 풀 위에 드리운 풀 그림자와 작은 꽃의 그림자는 이 카메라에서 거의 보이지 않는다.

**전후**(같은 장면)

| 장면 | 드로콜 | 삼각형 | 그림자를 드리우는 메시 |
| --- | ---: | ---: | ---: |
| 숲(3스테이지) | 116 → 110 | 163,857 → 153,283 | 45 → 36 |
| 눈(10스테이지) | 116 → 109 | 169,833 → 159,513 | 43 → 36 |

- 화면: 탑·성·성벽·적의 그림자는 그대로다. 전후 스크린샷에서 24/255 넘게 바뀐 화소는 2.5%(숲)·1.9%(눈)이고, 대부분 눈송이와 흘러가는 구름 그림자다(직접 봄).
- 성능 대리(`tools/rush-perf-check.cjs`, 높음, CPU 4배 느리게, 적 45 이상): 전후를 세 번 번갈아 쟀다. 전 17.98 / 16.12 / 16.24 ms, 후 16.81 / 14.55 / 15.89 ms(주 스레드 프레임당). 매번 조금 줄었다. 처음 잰 값(16.45, 22.19, 20.13 ms)은 다른 측정과 겹쳐 흔들린 값이라 버렸다.
- **알아 둘 것**: 높음 품질의 주 스레드 시간이 예산(16.7 ms) 근처다. 97회차에 잰 14.3 ms보다 높다. 그 뒤 스테이지별 배치, 전초 탑 자리, 영웅 키 등이 더해졌다. 소프트웨어 렌더라 주 스레드가 GPU 일까지 떠안는 몫이 섞여 있어, 실제 기기 값은 아니다. 느린 기기는 자동 품질이 낮음으로 내린다(낮음 5.0 ms, 97회차).

## 검증

- `npm run test:rush`: 142개 통과. `npx tsc --noEmit`, `npm run build`: 통과. `npm run smoke:rush`: 실패 0.
- 디버그 집계 `__rush.shadowCasters()`는 읽기만 한다(화면·규칙 무변경).

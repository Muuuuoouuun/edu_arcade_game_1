# 63회차: 엔진 스파이크, 첫 화면에서 받는 모델 미루기(측정만)

| 항목 | 값 |
| --- | --- |
| 시각 | 2026-11-12 13:42 ~ 13:52 KST (예약 회차) |
| 기준 | `ae5cffd` (main. PR #106이 #107 통합으로 병합돼 브랜치를 main에서 다시 시작) |
| 레인 | 엔진 스파이크 (62회차 다음 레인, 백로그 39) |
| 상태 | **완료** (측정만, 저장소 변경은 문서뿐) |

## 문제

62회차에서 영웅 GLB가 타이틀 화면에서 이미 받아진다는 것을 알았다. 그래서 단순화기(gzip 15 KB)도 타이틀에서 같이 받아진다. 그 사이 #107 통합으로 마을 숲 모델 `forest-town.glb`(402 KB)가 들어왔다. 첫 화면에서 무엇을 얼마나 받는지 다시 재 본 적이 없다.

## 범위

- **측정만 한다.** 빌드본(`vite preview`)에서 단계별 요청과 바이트를 잰다. 단계는 타이틀 → 마을 → 전투 시작이다.
- 작업 트리에서만 시험 손잡이(`?lazyModels=1`)를 넣는다. 타이틀에서는 영웅·마을 모델을 받지 않고, 마을 진입이나 전투 시작 때 받게 한다. 측정 뒤에는 되돌린다.
- 느린 회선(CDP 제한, 42회차와 같은 설정)에서 잰다.
  - 타이틀 표시까지의 시간과 바이트
  - 마을 진입 뒤 모델이 준비될 때까지
  - 전투 시작 뒤 영웅 자리표(절차형 몸)가 보이는 시간
- 결과로 채택 여부를 추천한다.

## 가설

- 타이틀에서 받는 바이트가 약 0.5 MB(숲 모델 402 KB + 영웅 73 KB + 단순화기 55 KB, 압축 전) 준다.
- 마을은 약 2초 머문 뒤 전투에 들어가므로, 그 사이 미리 받기로 전투 시작의 자리표 시간은 거의 늘지 않는다.

## 결과

**가설은 반만 맞았다.** 영웅 모델과 단순화기를 미뤄도 타이틀 바이트는 11%만 준다. 타이틀 화면 표시도 빨라지지 않는다. 큰 몫은 숲 마을 모델이다. 이 모델은 미루기 시험이 건드리지 않은 곳(마을 화면의 성 불러오기)에서도 따로 받는다.

**느린 회선 첫 실행** (빌드본, 휴대폰 가로, 1.6 Mbps·150 ms. 타이틀 3초 → 마을 2초 → 전투)

| 항목 | 지금 | 미루기(`?lazyModels=1`) |
| --- | --- | --- |
| 타이틀 화면 표시 | 2.2초 | 2.2초 |
| 타이틀 단계 받은 양 | 783 KB | 695 KB (−88 KB, −11%) |
| 마을 단계 받은 양 | 0 | 89 KB(영웅·단순화기) |
| 영웅 모델 준비 | 타이틀 3.0초 | 마을 6.2초 |
| 전투 시작 자리표 시간 | 0.01초 | 0.02초 |

- **숲 마을 모델(`forest-town.glb`, 402 KB)이 타이틀 바이트의 약 절반이다.** 두 곳이 같은 파일을 받는다.
  - 전투 장면의 마을(`render.ts` `buildTown`)
  - 마을 화면의 성(`townCastle.ts`)
  - 미루기 시험은 첫째만 미뤘다. 둘째가 타이틀에서 이미 받아서 줄지 않았다(두 번째 요청은 캐시에서 나옴).
- 마을에 2초 머무는 동안 영웅 모델(73 KB)과 단순화기를 다 받는다. 그래서 전투 자리표 시간은 미뤄도 사실상 0이다.
- 미루면 타이틀 뒤의 시연 전투가 절차형 영웅·마을로 보인다. 첫인상이 나빠진다.

**숲 마을 모델 압축 시험** (영웅 GLB와 같은 `tools/rush-glb.sh` 단계: prune → dedup → weld → meshopt high, 사본에만)

| | 크기 | gzip |
| --- | ---: | ---: |
| 지금 | 402,460 B | 40,788 B |
| meshopt 사본 | **51,508 B (−87%)** | 13,588 B |

- 질감(texture)이 없는 모델이라 영웅 GLB(43회차, −75%)보다 더 많이 준다.
- 정적 서버가 GLB를 gzip으로 보내지 않으면(미리보기 서버가 그렇다) 351 KB를 덜 받는다. Capacitor 앱에서는 앱 크기와 파싱 시간이 준다.
- **바로 넣을 수는 없다.** 두 불러오기 모두 `new GLTFLoader()`에 meshopt 해독기가 없다. 영웅처럼 양자화된 위치를 float32로 되돌린 뒤 구워야 한다(31·43회차). 이 코드는 #107 통합으로 들어온 다른 작업의 영역이다.

## 추천

- **영웅 모델 미루기는 비추천.** 11% 절약에 비해 타이틀 시연이 절차형으로 보이는 손해가 크다. 타이틀 표시 시간도 같다.
- **숲 마을 모델 meshopt 사본은 추천.**
  - 할 일 1: `forest-town.glb`를 `tools/rush-glb.sh`에 넣는다.
  - 할 일 2: 두 불러오기에 해독기와 float32 되돌리기를 붙인다(영웅용 `toFloat32` 재사용).
  - 할 일 3: 마을·전투 마을 모습을 전후 화소로 비교한다.
  - 같은 파일을 두 번 요청하는 것도 하나로 합칠 수 있다.
  - 백로그에 적었다(성능·모바일).

## 검증

- 시험 손잡이(`?lazyModels`)는 작업 트리에서만 썼고 되돌렸다. 저장소 변경은 문서뿐이다.
- main(`ae5cffd`) 위에서: `npm run test:rush` 94개 통과(#107 통합으로 시험이 늘었다), `npx tsc --noEmit`, `npm run build`, `npm run smoke:rush` 32/32 통과.

# 143회차: 전투 손맛, 탑 자리에서 뜨는 알약의 누르는 크기

| 항목 | 값 |
| --- | --- |
| 시각 | 2026-11-16 15:41 ~ 15:50 KST (예약 회차) |
| 기준 | `5548475` (142회차 뒤) |
| 레인 | 전투 손맛 (142회차 백로그 3) |
| 상태 | 완료 (허물기 알약 36 → 44 px) |
| 다음 레인 | 렌더 톤·모델 |

## 문제

전투 중 영웅이 탑 자리에 서면 왼쪽 위에 알약이 뜬다: 짓기·올리기(`#build`), Lv1 탑의 갈래 고르기(불 `#build` + 냉기 `#build-frost`), 허물기(`#demolish`). 싸우는 중에 엄지로 재빨리 누르는 단추들인데, 139회차의 누르는 크기 점검은 이 알약이 뜬 장면을 잡지 못했다. CSS로는 허물기가 36 px이다(기준 44 px).

## 범위

- 측정(스크래치패드): iPhone SE·Pixel 7 가로에서 (1) 빈 탑 자리, (2) Lv1 탑 위(갈래 고르기 + 허물기), (3) Lv2 탑 위(올리기 + 허물기)의 알약 크기와 서로·다른 단추와의 겹침.
- 44 px 아래이거나 겹치면 `rush.css`로 고친다.

## 가설

허물기만 36 px로 걸리고, 다른 알약은 44 px이다. 허물기를 44 px로 키우면 아래로 8 px 늘어 갈래 알약과 겹치지 않는지 확인이 필요하다.

## 수용 기준

- [x] 두 기기 × 세 장면 표: 44 px 아래 알약과 겹침(바꾸기 전·후)
- [x] 스크린샷 직접 확인
- [x] `test:rush`, `tsc`, `build`, `smoke:rush` 통과

## 결과

영웅을 첫 탑 자리(−4.6, 5.2)에 세우고 E로 짓고 올리며 쟀다(가려지지 않은 단추만). SE와 Pixel 7 결과가 같다(왼쪽 위 알약 자리는 화면 크기와 무관).

| 장면 | 보이는 알약(너비×높이 @ 위 끝) | 전: 44 px 아래 | 후 |
| --- | --- | --- | --- |
| 빈 탑 자리 | 짓기 131×44 @62 | 없음 | 없음 |
| Lv1 탑 위 | 화염 134×44 @62, 냉기 134×44 @114, 철거 85×**36** @166 | 철거 | 없음(철거 85×44, 아래 끝 210) |
| Lv2 탑 위 | 올리기 134×44 @62, 철거 85×**36** @114 | 철거 | 없음 |

- 겹침은 전후 모두 없다. 철거 알약이 8 px 길어져도 SE에서 아래 끝 210 px, ‘웨이브 시작’ 알약 위 끝 235 px다.
- 바꾼 것은 `rush.css` 한 줄(`.hud-build.demolish { min-height: 44px; }`).
- 가설대로 철거만 걸렸다.
- 덧붙여 본 것: 탑 자리 닿음은 거리 하나(`PAD_REACH`)로 정해, 자리 가장자리에서 서성이면 알약이 켜졌다 꺼질 수 있다. 67회차가 비슷한 깜빡임을 다뤘으므로 이번 범위에서는 바꾸지 않았다.

## 검증

- `npm run test:rush`: 149개 통과(설계 기둥 포함). `npx tsc --noEmit`, `npm run build`: 통과. `npm run smoke:rush`: 41개 통과, 실패 0.
- SE의 Lv1 탑 알약 세 개 스크린샷 직접 확인(높이가 같고 겹치지 않음).

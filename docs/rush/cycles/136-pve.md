## 문제

PvE 레인 백로그 맨 위(포포 균형과 기둥 시험 정의, 130·104회차)는 사용자 결정을 기다린다. 레인 질문 ‘영웅이 새 판단을 만드는가’의 다른 쪽을 본다.

세 영웅은 싸우는 법이 다르다. 레인저는 부채꼴 화살 세 발을 멀리 쏜다. 브론은 근접 망치로 휘둘러 밀쳐내고 체력이 두 배다. 포포는 눈덩이를 던져 범위로 맞히고 느리게 한다. 그런데 마을의 영웅 단추와 영웅 카드는 이름·레벨·성장·특기만 보여 준다. 브론·포포가 합류할 때 결과 화면의 동료 카드도 ‘출전 영웅으로 고를 수 있어요’뿐이다. 써 보기 전에는 무엇을 고르는지 알 수 없어 영웅 고르기가 판단이 되지 못한다.

## 범위

- `data.ts`에 표시용 `HERO_ROLE`(영웅마다 짧은 한 줄).
- 마을 영웅 단추의 작은 머리말 ‘영웅’ 자리에 ‘영웅 · <역할>’. 단추를 눌러 영웅을 바꾸면 따라 바뀐다.
- 결과 화면 동료 카드(브론·포포 합류)의 ‘출전 영웅으로 고를 수 있어요’ 뒤에 역할.
- 수치·밸런스는 바꾸지 않는다.

## 가설

역할 한 줄이면 세 영웅의 차이가 고르기 전에 읽힌다. 짧은 가로 화면에서도 단추·카드가 넘치지 않는다.

## 수용 기준

- [x] 마을 영웅 단추에 역할이 보이고 영웅을 바꾸면 바뀐다(폰 가로 스크린샷, iPhone SE·Pixel 7)
- [x] 브론 합류 결과 카드에 역할이 보인다
- [x] 단추·카드 글이 잘리거나 넘치지 않는다 (첫 문구는 133회차 맞춤을 깨서 줄였다, 아래)
- [x] `test:rush`(글꼴 시험 포함), `tsc`, `build`, `smoke:rush` 통과

## 결과

- `HERO_ROLE`(`data.ts`): 레인저 ‘원거리 · 부채꼴 화살’, 브론 ‘근접 망치 · 튼튼함’, 포포 ‘범위 눈덩이 · 느리게’. 표시에만 쓴다.
- 마을 영웅 단추의 머리말: ‘영웅’ → ‘영웅 · 원거리 · 부채꼴 화살’. 단추를 눌러 영웅을 바꾸면 ‘영웅 · 근접 망치 · 튼튼함’, ‘영웅 · 범위 눈덩이 · 느리게’로 바뀐다. iPhone SE(568 px 너비)·Pixel 7에서 단추 글이 넘치지 않는다(`scrollWidth` 확인, 스크린샷 직접 확인).
- 브론·포포 합류 카드: ‘출전 영웅으로 고를 수 있어요 · 마을의 대장간을 맡아요’ → ‘출전 영웅: 근접 망치 · 튼튼함 · 마을의 대장간을 맡아요’.
  - 첫 문구 ‘출전 영웅(근접 망치 · 튼튼함)으로 고를 수 있어요 · …’는 높이 320 px 화면(iPhone SE·갤럭시 S9+)에서 두 줄이 되어, 133회차에 맞춘 ‘다음 판’ 줄이 버튼 띠 아래로 12 px 밀렸다(줄 아래 끝 254 대 띠 242). 짧은 문구로 바꿔 한 줄이 되었고, 브론·포포 모두 238 / 238로 돌아왔다(Pixel 7은 258 / 258).
- 수치·밸런스는 바꾸지 않았다. 글꼴 부분 집합은 516자(81,916바이트).
- 소프트웨어 GL 화면에서 사람이 이 한 줄로 실제로 다르게 고르는지는 확인할 수 없다(사용자 플레이로만).

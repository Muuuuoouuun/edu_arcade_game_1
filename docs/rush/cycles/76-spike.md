## 문제

75회차에서 영웅 GLB를 glTF-Transform 4.5.1로 다시 쓰면 UV가 달라졌다. `dedup` 하나만 써도 궁수 전체 UV 범위가 0.008~0.991에서 −1.51~3.39가 됐다. 그래서 #111 계약 시험이 실패했다. 어느 프리미티브가 왜 바뀌는지 모른다.

## 범위

- **측정만 한다.** three.js를 거치지 않고 GLB 바이너리를 직접 읽는다(접근자·버퍼 뷰·`byteStride`·`byteOffset`).
  - 원본과 `dedup` 결과의 프리미티브마다 `TEXCOORD_0` 최소·최대를 비교한다.
  - 어느 프리미티브가 바뀌었는지, 원본 쪽 저장 방식(공유 버퍼 뷰, 교차 배치, 정렬)에 특이점이 있는지 본다.
- 원인을 알면 우회 방법을 시험한다(예: 질감만 WebP로 바꾸고 기하 버퍼는 그대로 두기). 계약 시험 통과 여부와 크기를 잰다.
- 저장소 변경은 문서뿐이다.

## 가설

원본에서 하나의 버퍼 뷰를 여러 접근자가 교차(`byteStride`)로 나눠 쓰고, 그중 일부 접근자의 `byteOffset`이 다른 속성 쪽을 가리킨다. 그래서 다시 쓰는 과정에서 다른 값이 UV로 읽힌다. 아니면 원본 UV 중 0~1 밖 값이 원래 있었는데, three가 읽는 순서 때문에 원본에서는 안 보였을 수 있다.

## 결과

**UV는 바뀌지 않았다.** 바뀐 것은 정점 버퍼의 **배치**다. 75회차 ‘UV 범위 −1.51~3.39’는 잘못 읽은 값이었다.

- 바이너리를 직접 읽어 비교했다(three.js 거치지 않음).
  - 원본 93개, `dedup` 결과 91개 프리미티브 모두 `TEXCOORD_0`가 0~1 안이다.
- 버퍼 뷰 배치
  - 원본: 359개 모두 `byteStride` 없음(속성마다 따로 있는 배치).
  - glTF-Transform 결과: `byteStride` 32인 것 53개, 24인 것 17개 등. 위치(12)·법선(12)·UV(8)를 **교차 배치**로 다시 썼다.
- three.js는 교차 배치를 `InterleavedBufferAttribute`로 읽는다. 그 `.array`는 위치·법선·UV가 섞인 **버퍼 전체**다.
  - #111 계약 시험(`heroAssets.test.ts`)과 75회차 확인 스크립트는 `uv.array`를 그대로 훑었다. 그래서 위치·법선 값을 UV로 셌다.
- **75회차 정정을 다시 정정한다**: 70회차 사본의 UV 자료는 멀쩡하다. 모습 비교(화소 차이 137)도 유효하다.

**우회: `--vertex-layout separate`** (모든 명령에 붙여 속성별 배치 유지)

| 영웅 | 원본 | prune→dedup→weld→webp, 분리 배치 | (참고) + meshopt(70회차) |
| --- | ---: | ---: | ---: |
| 궁수 | 891,740 | **413,476 (−54%)** | 262,716 (−71%) |
| 브론 | 1,935,780 | **1,226,764 (−37%)** | 394,332 (−80%) |
| 포포 | 998,920 | **485,088 (−51%)** | 261,048 (−74%) |

- 분리 배치 사본을 넣고 `heroAssets.test.ts`를 돌리면 **3/3 통과**한다(질감 3장, 애니메이션 세 개, 걷기 발 위치 포함).
- meshopt를 더하면 크기가 훨씬 준다. 하지만 meshopt는 UV를 정수로 양자화하므로 원 배열을 읽는 계약 시험과는 여전히 맞지 않는다.

## 추천

- **1단계(바로 가능)**: `tools/rush-glb.sh` 영웅 부분을 ‘prune → dedup → weld → webp, 모두 `--vertex-layout separate`’로 바꾼다. 계약 시험이 그대로 통과하고, 궁수(타이틀에서 받음)가 약 478 KB 준다.
- **2단계(생산 쪽과 합의)**: 계약 시험의 UV 검사를 `uv.getX(i)`/`getY(i)`(정규화·교차 배치 모두 올바르게 읽음)로 바꾸면 meshopt까지 쓸 수 있다. 영웅 셋 합이 3.8 MB → 0.92 MB가 된다. 시험은 #111 생산물이라 그쪽 결정이다.
- 어느 쪽이든 근접 화면에서 WebP 법선 질감의 띠·얼룩을 확인한다.

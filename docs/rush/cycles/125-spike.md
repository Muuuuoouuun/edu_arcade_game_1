# 125회차: 엔진 스파이크, 실제 기기 측정 경로(`?bench=1`)

| 항목 | 값 |
| --- | --- |
| 시각 | 2026-11-15 21:42 ~ 21:55 KST (예약 회차) |
| 기준 | `f9b7b03` (124회차 뒤) |
| 레인 | 엔진 스파이크 (124회차 백로그 2) |
| 상태 | 완료 (측정 경로 넣음. 실제 기기 값은 사용자 측정 대기) |
| 다음 레인 | 렌더 톤·모델 |

## 문제

100~124회차의 성능 숫자는 모두 이 컨테이너의 소프트웨어 GL에서 잰 대리 값이다. 드로콜은 절반 넘게 줄었지만(124회차) 실제 휴대폰에서 프레임 시간이 어떤지는 모른다. 사람이 휴대폰에서 주소 하나만 열면 같은 장면을 재고 숫자를 읽을 수 있는 길이 없다.

## 범위

- `rush.html?bench=1`: 시연 전투를 빨리 돌려 멈춘 뒤(기본 `freeze=900`, `speed=8`), 124회차와 같은 무거운 장면(적 40마리 7종 + 보스, 일부 얼림·막·번쩍임, 들판 가운데)을 만든다. 2초 데우고 10초 동안 프레임 간격을 모은다. 모의 진행은 멈춰 있고 그리기·애니메이션은 그대로 돈다.
- 결과를 화면 위 판에 보인다: 프레임 수, 평균 ms·fps, 중앙값·95%·99%(나쁜 1%)·최악 ms, 드로콜·삼각형, 품질 단계(자동이면 떨어졌는지), 화소 비율·버퍼 크기, GPU 이름(브라우저가 알려 주면). `__rush.bench`로도 읽는다. 바깥으로 보내지 않는다.
- 통계 계산은 순수 함수(`bench.ts`)로 두고 시험한다.
- 쓰는 법을 기록에 적는다(`quality=high|low|auto`).

## 가설

컨테이너(소프트웨어 GL)에서는 높음 평균 수십 ms가 나오고, 판이 화면을 가리지 않게 구석에 뜬다. 실제 기기 값은 사용자가 재야 한다.

## 수용 기준

- [x] `?bench=1`이 끝까지 돌고 판과 `__rush.bench`가 채워짐(높음·낮음)
- [x] 판 스크린샷을 직접 봄
- [x] 통계 함수 시험
- [x] `test:rush`, `tsc`, `build`, `smoke:rush` 통과

## 결과

**쓰는 법**(휴대폰 브라우저에서)
```
https://<배포 주소>/rush.html?bench=1&quality=high
https://<배포 주소>/rush.html?bench=1&quality=low
https://<배포 주소>/rush.html?bench=1            (자동 품질: 느리면 도중에 낮음으로 내려간다)
```
약 15~20초 뒤 왼쪽 위 판에 결과가 뜬다. 판을 사진으로 찍거나 숫자를 적어 기록에 붙이면 된다. 결과는 밖으로 보내지 않는다.

**이 컨테이너(소프트웨어 GL)에서 돌려 본 값**(실제 기기 값이 아님, 경로가 도는지만 확인)

| 품질 | 프레임 | 평균 ms (fps) | 중앙값 | 95% | 99% | 최악 | 드로콜 평균 | 삼각형 | 화소 비율·버퍼 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 높음 | 43 | 237.2 (4.2) | 233.3 | 533.3 | 583.2 | 583.2 | 39 | 142,722 | 2 · 1726×720 |
| 낮음 | 154 | 65.4 (15.3) | 66.7 | 116.7 | 166.6 | 200.0 | 28 | 81,808 | 1.25 · 1078×450 |

- 높음 드로콜 평균 39는 그림자 지도를 두 프레임에 한 번 그리기 때문이다(101회차, 그리는 프레임 47·건너뛰는 프레임 약 31).
- GPU 이름은 `SwiftShader`로 나와, 기기 측정에서는 어떤 기기인지 함께 남는다.
- 판(직접 봄): 왼쪽 위에 반투명 남색 판, 한국어 6줄. 장면의 위쪽 일부를 가리지만 측정이 끝난 뒤에만 숫자가 뜨므로 측정에는 영향이 없다(측정 중에는 한 줄).

**넣은 것**
- `bench.ts`: `benchStats`(프레임 간격 → 평균·fps·중앙값·95%·99%·최악), `benchEnemies`(124회차 무거운 장면의 적 41).
- `main.ts`: `?bench=1`이면 기본 `speed=8`·`freeze=900`으로 시연을 돌리고, 멈추면 무거운 장면을 만들고 2초 데운 뒤 10초를 재 판에 보인다. `window.__rush.bench`.
- `render.ts`: `gpuName()`(브라우저가 알려 주는 GPU 이름).
- `quality.test.ts`: 통계·장면 시험. `README.md`: 쓰는 법 한 줄.
- 판의 한국어 글자가 화면 글꼴 부분 집합에 없어 ‘글꼴 부분 집합’ 시험이 처음에 실패했다. `tools/rush-font-subset.py`로 다시 만들었다(513자, 80,208 → 81,580 바이트, +1.4 KB).

## 검증

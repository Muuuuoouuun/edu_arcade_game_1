## 문제

#111의 질감 영웅 GLB는 PNG 질감에 압축하지 않은 기하라 크다(궁수 892 KB, 브론 1,936 KB, 포포 999 KB). 궁수는 타이틀 화면에서 받는다. 70회차 측정에서 WebP + meshopt 사본은 263 / 394 / 261 KB였고, 모델 시트 크기에서 차이가 없었다.

## 범위

- `tools/rush-glb.sh` 영웅 부분에 `webp` 단계를 넣는다. 원본(`public/defense/models/characters-v2/`, 생산 단계 `models:characters` 결과)은 건드리지 않는다.
- 영웅 셋 사본을 다시 만든다(`src/rush/models/*.glb`). 숲 마을 사본은 손대지 않는다.
- **생산 쪽 계약을 지킨다**: #111의 `heroAssets.test.ts`가 요구하는 것을 그대로 둔다.
  - 재질 1개, 색·법선·ORM 질감 3장 내장
  - 애니메이션 세 개
  - 다리 마디 기본 자세, 걷기 중 발이 땅 위
  - ORM은 러시가 쓰지 않지만 이 계약 때문에 남긴다
- meshopt 양자화가 발 높이 검사(땅 아래 −0.005 미만 금지)를 깨면, 위치 양자화 비트를 올리거나 meshopt를 빼고 WebP + dedup만 쓴다.
- 바꾸는 파일: `tools/rush-glb.sh`, `src/rush/models/{gecko-ranger,dwarf-guardian,polar-bear}.glb`.

## 가설

70회차 크기가 나오고(합 3.8 MB → 약 0.92 MB) 영웅 시험·모델 시트·전투 화면이 그대로다. 빌드본 첫 화면 바이트가 궁수 몫만큼(약 −630 KB) 준다.

## 결과

**막혔다.** 사본 크기는 70회차대로 나왔다(궁수 891,740 → 262,716, 브론 1,935,780 → 394,332, 포포 998,920 → 261,048). 하지만 #111의 `heroAssets.test.ts`가 영웅 셋 모두에서 ‘UV는 0~1’ 검사로 실패했다. 사본·스크립트 변경은 되돌렸다.

**원인 좁히기**

| 파일 | 원 UV 범위(`TEXCOORD_0`, 전체 메시) | 형식 |
| --- | --- | --- |
| 원본 `characters-v2/gecko-ranger.glb` | 0.0078 ~ 0.9912 | Float32 |
| `prune --keep-attributes true` 뒤 | −1.5144 ~ 3.3900 | Float32 |
| `dedup` 하나만 적용 | −1.5144 ~ 3.3900 | Float32 |
| + `weld`, + `webp` | 같음 | Float32 |
| + `meshopt` | 정수로 양자화(시험은 원 배열을 읽어 실패) | Uint16 등 |

- glTF-Transform 4.5.1로 **어떤 명령이든 한 번 다시 쓰면** UV 범위가 바뀐다.
  - 확장은 원본·결과 모두 없다. 모두 Float32이고 `TEXCOORD_0` 하나다.
  - `dedup` 뒤 프리미티브가 93 → 91로 준다(같은 정의 병합).
  - 어느 프리미티브의 UV가 바뀌는지는 아직 못 찾았다. 후보: 원본의 버퍼 뷰 공유·`byteStride` 배치를 다시 쓰는 과정, 또는 병합 때 다른 접근자가 UV로 잡히는 경우.
- meshopt는 UV를 정수로 양자화한다(16비트 이하만 고를 수 있음). 그래서 원 배열을 읽는 지금의 계약 시험과는 어차피 맞지 않는다. 정규화 값으로 읽게 시험을 바꾸는 일은 생산 쪽(#111)과 정할 일이다.

**70회차 정정**: 70회차 사본도 같은 단계라 일부 부품의 UV가 0~1 밖으로 바뀌었을 수 있다. 모델 시트 크기(영웅 약 110화소)에서는 보이지 않았을 뿐이다. 원인을 찾기 전까지 그 사본을 쓰면 안 된다. 백로그 47에 적었다.

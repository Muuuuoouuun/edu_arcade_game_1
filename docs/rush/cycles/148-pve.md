## 문제

PvE 레인 맨 위(포포 균형·기둥 시험 정의)는 사용자 결정을 기다린다. 레인 질문 ‘웨이브가 새 판단을 만드는가’의 끝없는 도전 쪽을 본다.

끝없는 도전은 다섯 웨이브마다 한 바퀴를 돌고, 바퀴마다 변형이 붙는다: 빠른 걸음(적 이동 +20%), 방패 행렬(방패병 두 배), 쌍둥이 보스(보스 둘). 이것을 알리는 것은 알림(‘2바퀴째 · 빠른 걸음!’)과 웨이브 상자 깜빡임인데, 둘 다 #107부터 전투 화면에서 보이지 않는다(화면 읽기용만). 142회차의 ‘웨이브 시작’ 알약 미리보기는 쌍둥이 보스(‘보스 2’)와 방패 행렬(방패 수)은 숫자로 드러내지만, 빠른 걸음은 전혀 보이지 않는다. 변형을 모르면 냉기 탑(느리게)과 화염 탑 사이 고르기가 짐작이 된다.

## 범위

- `main.ts`: 끝없는 도전의 준비 시간에 ‘웨이브 시작’ 알약 둘째 줄 앞에 ‘N바퀴 · <변형>(짧은 설명)’을 붙인다. 변형이 없는 바퀴는 ‘N바퀴’만. 첫 바퀴는 붙이지 않는다.
- 화면 읽기용 웨이브 줄에도 같은 내용.
- 시뮬레이션·밸런스는 바꾸지 않는다.

## 가설

준비 시간에 바퀴 변형이 보이고, 알약이 넘치지 않는다(142회차의 230 px 줄바꿈 안).

## 수용 기준

- [x] 브라우저: 끝없는 도전 2바퀴 이상 준비 시간에 변형 이름이 알약에 보임(세 변형), 첫 바퀴는 없음(스크린샷, SE)
- [x] 알약이 필살기 단추와 겹치지 않음(SE)
- [x] `test:rush`, `tsc`, `build`, `smoke:rush` 통과

## 결과

iPhone SE 가로, 끝없는 도전 상태로 바꿔 각 바퀴의 준비 시간 알약 둘째 줄을 읽었다(굵게·밑줄 = 변형 이름):

| 바퀴(웨이브) | 둘째 줄 | 알약 오른쪽 끝 / 필살기 왼쪽 끝 |
| --- | --- | --- |
| 2바퀴(6), 빠른 걸음 | 2바퀴 · **빠른 걸음**(적 +20% 빠름) · 다음 돌격 8 | 362 / 366 px |
| 3바퀴(11), 방패 행렬 | 3바퀴 · **방패 행렬**(방패병 ×2) · 다음 돌격 8 | 361 / 366 |
| 4바퀴(16), 쌍둥이 보스 | 4바퀴 · **쌍둥이 보스**(보스 2) · 다음 돌격 8 | 357 / 366 |
| 5바퀴(21), 변형 없음 | 5바퀴 · 다음 돌격 8 | 312 / 366 |
| 1바퀴(3) | 다음 돌격 8 · 투척 8 · …(바퀴 표시 없음) | 362 / 366 |

- 설명의 숫자는 `TWIST`(sim.ts)에서 읽는다(빠르기 1.2 → +20%, 방패 ×2, 보스 2). 수치를 바꾸면 따라 바뀐다.
- 첫 스크린샷에서 줄바꿈이 ‘돌 / 격’처럼 낱말 가운데에서 갈라져 `word-break: keep-all`을 더했다(이제 ‘다음 / 돌격 8’처럼 띄어쓰기에서 바뀜). 142회차 캠페인 줄도 같은 규칙을 받는다.
- 화면 읽기용 웨이브 줄에도 같은 바퀴·변형이 앞에 붙는다. 바퀴 알림(토스트)은 그대로 두었다(화면 읽기용).
- 시뮬레이션·밸런스는 바꾸지 않았다. 새 글자가 없어 글꼴은 그대로.

## 검증

- `npm run test:rush`: 150개 통과(설계 기둥 포함). `npx tsc --noEmit`, `npm run build`: 통과. `npm run smoke:rush`: 41개 통과, 실패 0.
- SE 스크린샷 직접 확인(빠른 걸음 바퀴, 낱말 단위 줄바꿈).

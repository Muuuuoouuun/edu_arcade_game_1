# 101회차: 엔진 스파이크, 그림자 지도를 두 프레임에 한 번 그리기

| 항목 | 값 |
| --- | --- |
| 시각 | 2026-11-14 21:42 ~ 22:20 KST (예약 회차) |
| 기준 | `8a7e0cd` (100회차 뒤) |
| 레인 | 엔진 스파이크 (100회차 백로그 1) |
| 상태 | 완료 (넣음: 두 프레임에 한 번) |
| 다음 레인 | 렌더 톤·모델 |

## 문제

100회차에 잰 높음 품질의 주 스레드 시간이 예산(16.7 ms) 근처다(CPU 4배 느리게, 적 45 이상: 약 15.8 ms). 높음의 큰 몫은 그림자 패스다. 그림자를 드리우는 메시가 36개라, 그림자 지도를 그릴 때마다 드로콜 36개를 주 스레드가 내보낸다.

## 범위 (스파이크: 재고, 좋으면 넣는다)

- 그림자 지도를 매 프레임이 아니라 N 프레임(2)마다 다시 그린다(`shadow.autoUpdate = false`, 그릴 프레임에만 `needsUpdate`).
- **함정**: 그림자 상자는 카메라 초점을 따라간다(`SunRig.follow`). 지도를 그리지 않는 프레임에 상자만 옮기면, 새 행렬로 옛 지도를 읽어 그림자가 한 프레임 미끄러진다. 그래서 상자도 지도를 그리는 프레임에만 옮긴다.
- 잴 것
  - 주 스레드 시간(`tools/rush-perf-check.cjs` 높음), 전후를 번갈아 세 번
  - 프레임당 평균 드로콜
  - 화면: 영웅이 달릴 때 그림자가 몸에서 떨어져 보이는지(연속 스크린샷)

## 가설

평균 드로콜이 프레임당 약 18 줄고, 주 스레드 시간이 1~2 ms 준다. 60fps에서 한 프레임 늦은 그림자는 영웅이 5.2 m/s로 달릴 때 약 9 cm 밀린다. 툰 그림자 경계에서는 거의 보이지 않을 것이다.

## 수용 기준

- [x] 전후 주 스레드 시간(여섯 번 번갈아)과 평균 드로콜
- [x] 달리는 영웅의 그림자 스크린샷을 직접 보고 어긋남이 눈에 띄지 않음
- [x] `test:rush`, `tsc`, `build`, `smoke:rush` 통과

## 결과

**드로콜은 확실히 준다.** 자동 시연 전투(높음, 휴대폰 가로)에서 40프레임 연속으로 잰 드로콜

| 설정 | 평균 | 최소 | 최대 | 앞 10프레임 |
| --- | ---: | ---: | ---: | --- |
| 매 프레임(전) | 73.5 | 69 | 79 | 69 69 73 71 71 71 71 77 77 77 |
| 두 프레임에 한 번(후) | 63.3 | 48 | 79 | 50 67 48 73 54 73 52 77 57 77 |

그림자 지도를 그리는 프레임과 건너뛰는 프레임이 번갈아 나온다. 평균은 약 14% 준다. 무거운 장면(그림자를 드리우는 메시 36)에서는 건너뛰는 프레임마다 36씩 준다.

**주 스레드 시간은 재기 어렵다.** `tools/rush-perf-check.cjs`(높음, CPU 4배 느리게, 적 45 이상)를 여섯 번 번갈아 쟀다.

| 차례 | 매 프레임 | 두 프레임에 한 번 |
| ---: | ---: | ---: |
| 1 | 13.57 ms | 12.82 ms |
| 2 | 13.90 | 17.07 |
| 3 | 17.75 | 16.21 |
| 4 | 17.12 | 14.23 |
| 5 | 14.41 | 10.71 |
| 6 | 13.25 | 14.58 |
| 평균 | 15.0 | 14.3 |

평균은 약 0.7 ms 줄지만, 같은 설정 안의 흔들림(±2 ms)이 더 크다. 소프트웨어 렌더에서 초당 12~15프레임밖에 안 돌아 표본이 적은 탓이다. 그래서 ‘주 스레드가 줄었다’고 단정하지 않는다. 드로콜 수가 준 것만 확실하다.

**화면**: 영웅이 옆으로 달리는 연속 6프레임을 두 설정으로 찍어 나란히 봤다. 그림자가 발에서 떨어져 보이는 프레임은 없었다. 그림자 상자는 지도를 그리는 프레임에만 옮기므로, 카메라가 따라가도 그림자가 미끄러지지 않는다. 60fps 기기에서 그림자는 많아야 한 프레임(영웅 전속력에서 약 9 cm) 늦다.

**바꾼 것**
- `frame.ts`: 따라가는 그림자 상자(`SunRig.follow`)가 `shadowEvery` 프레임(기본 2)마다 지도를 다시 그리고, 그때만 상자를 옮긴다. 마을 섬(멈춘 장면)은 전처럼 `refresh()` 때만 그린다.
- `render.ts`: 그림자를 드리우는/받는 메시를 고르는 순회(`markShadows`)도 지도를 그리는 프레임에만 돈다.
- 디버그: `?shadowEvery=N`(1 = 매 프레임), `tools/rush-perf-check.cjs`의 `QUERY=` 환경 변수.

## 문제

마을의 강화 단추는 자원이 모자라면 비용만 보이고 꺼져 있다. 농장·제재소가 분마다 만드는데(레벨 × 8), 얼마나 기다리면 살 수 있는지는 알 수 없다. 129회차 결과 화면의 ‘(식량 120 · 목재 80 더 모으기)’도 마찬가지다. ‘기다릴까, 한 판 더 할까’를 고를 근거가 없다.

또 단추가 꺼지는 조건(`canUpgrade`)은 지금 가진 자원만 본다. 수확하지 않은 생산분이 이미 비용을 넘어도 단추가 꺼져 있다(올리기 자체는 먼저 수확하므로 누르면 된다). 무엇을 해야 하는지 알려 주지 않는다.

## 범위

- `kingdom.ts`: `minutesUntil(k, cost, now)`: 쌓인 생산분까지 쳐서 비용이 채워질 때까지의 분. 이미 되면 0, 생산으로 못 채우면(조각이 모자람) `null`. `nextStep`에 `eta`(분 또는 null).
- 마을 강화·훈련 단추: 못 살 때 비용 뒤에 ‘· 약 N분’, 수확하지 않은 생산분으로 이미 되면 ‘· 수확 먼저’.
- 결과 화면 ‘더 모으기’ 뒤에 ‘, 약 N분’.
- 밸런스·생산량은 바꾸지 않는다.

## 가설

못 사는 강화마다 기다릴 시간이 보여 ‘기다리기 대 한 판 더’를 고를 수 있다. 단추 글이 한 줄에 들어간다(iPhone SE).

## 수용 기준

- [x] 시험: 모자람이 없으면 0, 생산분으로 채워지면 0, 분 계산(올림), 조각 모자람이면 null
- [x] 마을에서 못 사는 강화 단추에 ‘약 N분’, 수확 전 생산분으로 되는 경우 ‘수확 먼저’(스크린샷, SE·Pixel 7)
- [x] 결과 화면 ‘더 모으기’에 ‘약 N분’
- [x] `test:rush`, `tsc`, `build`, `smoke:rush` 통과

- 결과 화면(식량 0·목재 0 저장, 2-1 패배): ‘할 일: **제재소 올리기** (식량 32 · 목재 6 더 모으기, 약 2분)’.
- ‘수확 먼저’는 이미 있던 틈을 드러낸다: 수확하지 않은 생산분이 비용을 넘어도 단추는 가진 자원만 보고 꺼져 있었다. 이제 무엇을 하면 되는지 단추가 말한다. 단추를 켜는 규칙은 바꾸지 않았다(눌렀을 때 먼저 수확하는 `upgrade()`는 그대로).
- 마을 화면은 1초마다 다시 그리므로 ‘약 N분’도 줄어든다. 창고는 120분치까지라 그보다 긴 기다림은 중간에 한 번 수확해야 하지만 표시는 그대로 맞다.
- 숫자 계산: `minutesUntil`(kingdom.ts), `waitText`(‘약 4분’, ‘약 1시간 20분’). 밸런스·생산량은 바꾸지 않았다. 새 글자가 없어 글꼴은 그대로(516자).
- SE 마을 스크린샷 직접 확인(성 카드 ‘240 240 · 약 25분’).

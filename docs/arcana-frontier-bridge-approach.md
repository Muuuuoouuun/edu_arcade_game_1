# 녹음 변경 전장 · 다리 접근로

녹음 숲과 협곡 컨셉의 연결된 길을 실제 3D 전장과 비교했다. 기존 목교는 강을 건널 수 있지만 양쪽 잔디에서 입구로 연결되는 표지가 없어 이동 가능한 폭을 읽기 어려웠다. 기존 서쪽 도로에서 다리로 이어지고 동쪽 둔치로 나가는 낮은 석재 길을 추가했다.

42개의 엇갈린 불규칙 석재와 두 바탕은 실제 편집 메시다. 기존 도로와 만나는 곳의 경계석 세 개를 비워 교차로를 열었다. 돌 표면은 기존 지면 위 최대 0.012 전장 단위이며 강의 실제 통행 범위·목교 상판 0.36·수면 -2.6과 게임 좌표·입력·전투 규칙은 바꾸지 않았다. 돌에는 별도 충돌체를 추가하지 않는다.

후속 작업에서 굽은 도로를 지형의 경사 경계마다 나누어 지면에 맞추었다. 경사 중간에서 흙길을 뚫고 보이던 잔디 삼각형이 사라지고, 연결부에서 원래 최대 약 0.103 높았던 도로 표면은 같은 표본에서 최대 0.016 높이로 낮아졌다. 도로 아래에 거의 붙어 있던 서쪽 포장석은 바탕 연결을 유지하면서 재배치해 겹친 면의 점선을 없앴다. 이는 메시와 게임 지면을 맞춘 작업이며 발 IK를 추가한 것은 아니다.

`npm run models:frontier-terrain`으로 [편집 원본](../art-source/defense/frontier-terrain.blend), [실시간 GLB](../public/defense/models/frontier-terrain.glb), 기존 공통 카메라 PNG·교량 PNG·WebP와 [해시/좌표 메타데이터](../public/defense/models/frontier-terrain.json)를 재생성한다. 이 WebP는 기존 참조·메뉴용이며 2.5D 캠페인의 새 배경으로 연결하지 않았다. 실시간 3D 변경 전장의 녹음 테마에서 GLB를 사용하고, 로딩 실패 시 기존 기본 3D 지형으로 복귀한다.

## 검증 범위

- `npm run models:frontier-terrain:check`: 42개 돌의 경계·최대 높이, 교차로의 장애물 부재, 기존 강·다리 높이, 단일 재질, 실제 카메라/영웅 위치 가림 표본 및 산출물 해시를 확인했다. 기존에 알려진 동북쪽 모바일 가림 1건은 그대로 남는다.
- 지형 GLB는 1메시·1재질을 유지하고 12,768→13,596삼각형, 795,640→866,080바이트다. 편집 가능한 지형은 430개 객체다.
- 전체 테스트 540개와 웹·모바일 빌드가 통과했다. PC 1440×900·가로 모바일 844×390 Chromium에서 실제 이동으로 다리를 건너고, 길 위 클릭·터치 좌표, 일시정지·2배속·동작 줄이기, 충격파 접촉 및 GLB 실패 폴백을 확인했다. 모바일 패키지와 작업실 회전·메시 보기, GLB와 PNG 동시 실패 안내도 확인했다. 모바일은 에뮬레이션이다.
- 같은 844×242 SwiftShader 장면의 짧은 단독 표본에서 드로콜 36→36, 전체 삼각형 45,874→46,702였다. 평균 프레임 시간 88.13→88.59ms, p95 100.1→100.1ms는 소프트웨어 렌더러의 표본이며 실기기 성능은 아니다. 기존 Three.js 그림자 설정 경고가 남아 있다.

위 수치와 성능 표본은 최초 접근로 작업의 기록이다. 후속 접지 작업의 메시 검사에서는 도로 삼각형 내부와 가장자리 1,068개 표본이 시뮬레이션 지형과 0.000001 이내로 맞았으며 GLB는 1메시·1재질, 13,612삼각형이다. 같은 844×242 SwiftShader 장면의 짧은 단독 비교에서는 드로콜 36→36, 장면 삼각형 46,702→46,718, 평균 프레임 시간 88.34→90.21ms였다. 모델 로딩 실패 시 기존 대체 지형도 정상 조작되지만 모바일 횡단 장면의 드로콜이 기준·변경 후 모두 189회로, 정상 로딩의 52회보다 높아 별도 최적화가 필요하다. 이는 실기기 성능이 아니다. 모든 지점의 발 접지·가림, 실제 Android/iOS GPU 성능, 사용자 플레이에서 길의 의미 전달은 후속 검증이 필요하다. 기존 전투 맵의 실제 확장이나 캠페인 전체 3D 전환은 아니다.

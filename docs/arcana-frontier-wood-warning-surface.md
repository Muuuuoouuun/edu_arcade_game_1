# 통나무 병사의 지형을 따르는 공격 예고

2026-11-10 · 기준 `65f9daacb3b64d3f93f53ff7fc57ff640e8b3950`. [통나무 병사 컨셉 비교](arcana-direction-loop/model-drafts/wood-log-compare-cycle34.webp), 서리 변경 전장과 기존 [몽둥이 공격](arcana-frontier-wood-strike.md)을 확인했다. 기존 예고는 중심의 접선 평면에 고정돼 다리 끝에서 수면 위에 뜨거나 상판에 가려질 수 있었다.

병사의 확정된 공격 방향·반경을 유지하면서 붉은 부채꼴을 지면·교량·수면에 투영한다. 평지는 기존 24구간이고 단차를 만나는 구간만 각도 2개×반경 4개로 세분한다. 꼭짓점·변·중앙의 높이를 확인해 단차를 가로지르는 면은 생략하므로 작은 틈이 남을 수 있다. 타격의 0.28초 경계, 사거리 2.2, 각도 0.65라디안, 피해·이동·보상은 변경하지 않는다. 기존과 같이 중심 반경 0.55 이내는 경고 부채꼴에서 비워 둔다.

하나의 공유 메시가 화면에 보이는 모든 예고를 그린다. 동시 예고 수에 따라 버퍼를 늘리고 재사용하며, 공격자·위치·방향·가시 목록이 바뀔 때만 다시 계산한다. 실제 3D 깊이 가림과 동작 줄이기의 정지 예고를 유지한다. 기존 통나무 병사의 편집 가능한 `.blend`, GLB와 베이크 및 캠페인 2.5D는 바꾸지 않았다.

## 검증

- 이동 가능한 다리 접근 상태(병사 `2.95, 3.1`, 영웅 `4.3, 2`)에서 기존 예고 정점 50개 중 13개가 표면에서 0.5 이상 떨어지고 최대 오차는 2.60이었다. 새 활성 정점의 최대 오차는 약 0.00000004였다. 이 위치는 고정 상태 재현이며, 별도의 실제 UI 조작에서도 이동과 적 준비·0.28초 접촉을 확인했다.
- 736개 이동 가능 위치·방향, 26,089개 표시 셀의 중심 검사는 표면 단차 오류 0이었다. 8방향 사거리·각도, 다리·강가·경사, 30개 동시 예고·제거·화면 밖 복귀, 정지 버퍼 재사용과 동작 줄이기를 검사했다. 표본은 모든 위치에서 틈이 없다는 뜻이 아니다.
- 실제 WebGL에서 예고 픽셀 `[152,68,50]`이 앞의 불투명 물체를 두면 `[255,0,255]`로 바뀌어 깊이 가림을 확인했다. PC 1024×576과 가로 모바일 844×390에서 실제 이동·일시정지·2배속·동작 줄이기와 모델 로딩 실패 대체를 확인했다. 모바일 배포 산출물에서도 타이틀→마을→전장→적 준비·접촉을 조작했고 전체 테스트 510개와 웹·모바일 빌드가 통과했다.
- 844×242 Chromium SwiftShader, 단차 근처에서 적이 준비하는 5초 단일 표본(순서 역전 재측정): 1명은 이전/이후 평균 85.08/86.62ms, 30명은 127.86/126.27ms였다. 호출 39회와 GPU 지오메트리 214개는 같았고, 30명 표본 삼각형은 63,284→69,892였다. 짧은 소프트웨어 측정으로 실제 기기 성능이나 개선을 보증하지 않는다.
- 경고 버퍼의 CPU 위치·인덱스 배열은 동시 예고 1개 용량 약 11.25KiB, 32개 용량 약 360KiB이며 GPU 복사본은 별도다. 용량은 더 커질 수 있고 화면 종료 시 해제한다.

급단차의 작은 경고 틈, 여러 예고의 모바일 혼잡도와 실제 Android/iOS GPU·발열은 후속 검증 대상이다. 부채꼴은 기존 게임 판정의 예고이며 몽둥이의 실제 메시 충돌을 추가한 것은 아니다.

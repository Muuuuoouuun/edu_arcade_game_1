### 2-2. 전투에 들어갈 때 미리 불러오는 그림

개발 통합 브랜치의 `preloadDefenseMotion`(`src/games/defense/art.ts`)이 전투 진입 때 불러오는 파일을 `git cat-file -s`로 쟀다.

| 묶음 | 파일 | 용량 | 비율 |
| --- | --- | --- | --- |
| 회화 시트 | `melee-motion` 539,174 · `ranged-motion` 707,842 · `tower-models` 571,594 · `monster-models` 594,058 · `boss-models` 531,906 (모두 `.webp`) | 2,944,574 B | 82% |
| Blender 몬스터 아틀라스 | 슬라임·돌·나무·얼음 4개 | 110,692 B | 3% |
| Blender 타워·드워프 렌더 | `*-game.webp` 16개 | 531,312 B | 15% |
| 합계 (상한) | | **3,586,578 B** | |

- Blender 몬스터 아틀라스 4개를 합쳐도 110 KB다. 같은 역할의 회화 시트 `monster-models.webp`는 594 KB다.
- `monster-models.webp`는 지금 **서리늑대 하나**와 대체 표시에만 쓰인다. 서리늑대가 Blender로 옮겨지면 **대체 표시 전용**이 된다.
- `tower-models.webp`는 Lv1 기본 타워 세 개에 쓰인다(Lv2부터는 Blender 렌더). Lv1이 Blender로 옮겨지면(3-1) 이것도 대체 표시 전용이 된다.

**제안**: 대체 표시 전용 시트는 **미리 불러오지 않는다.** Blender 렌더를 불러오지 못했을 때만 그 시트를 불러온다. 두 시트가 대체 전용이 되면 전투 진입 때 1,165,652 B(약 33%)를 덜 받는다. 화면은 바뀌지 않으므로 결정이 필요 없는 성능 작업이다. 인계 A에 넣는다. 실제 휴대폰 로딩 시간은 재지 않았다. 반영 후 같은 기기·같은 네트워크 조건에서 전후를 재야 한다.

### 2-3. Lv1 타워 — 강화하면 화풍이 바뀐다

`towerSpriteAsset`은 Lv2·Lv3에 Blender 렌더를, Lv1에는 회화 시트(`tower-models.webp` 첫째 열)를 쓴다. 회화 Lv1을 열어 보니 문제가 겹친다.

| 문제 | 내용 |
| --- | --- |
| 화풍 점프 | 회화(붓질, 굵은 윤곽) → 강화 순간 Blender 장난감 렌더로 바뀐다. 같은 타워가 다른 물건처럼 보인다. |
| 백합 문장 | Lv1 세 타워 모두 파란 깃발에 백합 문장. 실제 나라의 문장이라 아르카나의 것이 아니다(01·09회차). |
| 마법탑 색 | 마법탑 Lv1의 공격은 **불**(엔진: 분기 전 마법탑 = 불)인데 수정이 **파랑**이다. 이 게임에서 파랑은 얼음·물로 읽힌다(02회차 이안과 같은 문제). |

**제안**: Lv1 세 타워를 Lv2 Blender 모델과 **같은 기단**으로 만든다(3-1). 강화하면 기단 위에 분기 머리가 올라가는 모양이 되어, “쌓아 올린다”는 강화의 손맛도 생긴다. 깃발은 문장 자리를 비운 단색으로 둔다(수비대 문장이 정해지면 그때 넣는다). 마법탑 수정은 Lv2 화염탑과 같은 따뜻한 색 계열로 둔다. 기존 엔진 규칙(불)과 기존 Blender 화염탑의 색에 맞추는 일이라 새 결정이 필요 없다. 인계 A에 넣는다.

### 2-4. 원정 카드의 ‘갈 이유’ (PR #55)와 이 루프의 제안

PR #55는 원정 카드에 동료 합류, 다음 지역, 남은 퀘스트 중 하나를 ‘갈 이유’로 보여 준다. 03회차 등불 3개(클리어·추가 목표·정예)가 채택되면 **같은 자리**에 “정예 등불이 아직 꺼져 있어요” 같은 이유를 더할 수 있다. 05회차 ‘해결 이후 한 줄’은 결과 화면에, ‘갈 이유’는 원정 카드에 두어 역할을 나눈다. 두 루프가 같은 방향을 보고 있다는 확인이다.

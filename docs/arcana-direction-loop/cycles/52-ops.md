## 2. 등불 셋째 조건(정예 클리어)은 지금 기록되지 않는다

등불 3개(03회차, B 묶음 ④)는 클리어 · 추가 퀘스트 · **정예 클리어**다. 앞의 둘은 저장에 있다(`cleared`, `questClaimed`). 셋째는 없다.

`campaign.ts`를 확인한 것
- `normalize`는 저장을 **아는 필드만으로 다시 만든다.** 모르는 필드는 다음 저장에서 사라진다. 그래서 새 필드는 반드시 `normalize`에 같이 들어가야 한다.
- `completeRun`은 난이도를 보상 배율(정예 1.4배)에만 쓰고 기록하지 않는다. `processedRuns`에는 판 ID만 남는다.
- 그래서 **지금까지 깬 정예 판은 나중에 되살릴 수 없다.** 등불을 정하는 날까지 정예를 깬 플레이어는 셋째 등불을 처음부터 다시 따야 한다.

## 3. 제안 — 기록만 먼저 (결정 불필요, 인계 A)

등불 자체(화면·외형 보상)는 묶음 ④ 결정을 기다린다. **기록 필드만 먼저** 넣는다.
- 화면에 보이지 않는다.
- 보상과 진행을 바꾸지 않는다.
- 되돌리기 쉽다(필드를 읽지 않으면 그만이다).

| 항목 | 내용 |
| --- | --- |
| 필드 | `Campaign.eliteCleared: number[]` — 정예(`veteran`)로 이긴 스테이지 번호, 오름차순 |
| 버전 | `version: 1` 유지. 더하기만 하는 변경이고, 없으면 `[]`다 |
| `normalize` | `questClaimed`와 같은 방식이다. `cleared.filter(stage => incomingElite.includes(stage))`이고, 깬 적 없는 스테이지·잘못된 값은 버린다 |
| `completeRun` | `won && getDifficulty(state.difficulty)==='veteran' && !eliteCleared.includes(stage)`일 때만 더한다. 이미 처리한 판 ID는 지금처럼 아무것도 바꾸지 않는다 |
| 크기 | 최대 정수 8개(지금 저장 몇 KB에 비해 무시할 만함) |
| 확정 제약 | 재료와 상관없다. 승리·보상·진행의 관문이 아니다(기록일 뿐이다) |

**테스트**(`campaign.test.ts`, 지금 테스트 18개와 같은 형식)
1. 필드 없는 옛 저장을 읽으면 `eliteCleared: []`가 되고, 나머지 진행은 그대로다.
2. 손상된 값(문자열, 깬 적 없는 스테이지, 9 이상)은 버린다.
3. 정예로 이기면 더하고, 기본·여유로 이기거나 지면 더하지 않는다.
4. 같은 판 ID를 두 번 처리해도 한 번만 더한다.
5. 저장 → 읽기를 왕복해도 같다.

**하지 않는 것**
- 약점 명중 기록(48회차에서 두지 않기로 함)
- 배속(48회차 제안대로 기기별 설정, 캠페인 저장 아님)

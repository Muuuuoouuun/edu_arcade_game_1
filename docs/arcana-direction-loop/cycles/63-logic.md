## 2. 히트스톱 시계를 실제 엔진에 끼우면

47회차는 시계 함수(`advanceClock`·`stopAt`)를 혼자서만 시험했다. 이번에는 main 사본에 [`logic-drafts/battleClock.ts`](../logic-drafts/battleClock.ts)를 넣었다.
- 시계 함수 둘에 41회차 ‘큰 순간’ 판정 `bigImpact(prev, next)`(보스 처치, 필살기·충전 끊기, 영웅 근접의 무거운 적 처치)를 더했다.
- 실제 `stepDefense`로 전투를 끝까지 돌렸다.

**시험 방법** ([`logic-drafts/battleClock.test.ts`](../logic-drafts/battleClock.test.ts))
- 입력은 엔진 단계마다 같은 대본이다(건설 → 웨이브 시작 → 전직 → 적 5마리 이상이면 필살기, 테스트의 `campaignBattle`과 같은 방식).
- 실제 프레임 간격은 8~43ms로 무작위다.
- 큰 순간이면 50ms(보스 90ms) 멈추고, 큰 순간끼리는 엔진 시간 0.6초 대기를 둔다.
- 같은 대본을 멈춤 없이 돌린 판과 끝 상태를 비교했다.

| 스테이지 | 멈춤 | 엔진 단계 | 멈춘 동안 돈 단계 | 끝 상태(승패·마을·전초기지·처치·코인·판 시간·약점) |
| --- | --- | --- | --- | --- |
| 1-1 | 4번 | 5,126 | **0** | 멈춤 없는 판과 **같음** |
| 1-4 | 13번 | 8,678 | **0** | 같음 |
| 2-4 | 9번 | 10,964 | **0** | 같음 |

- 시계 단위 테스트도 통과한다. 멈춤 중 단계 0, 멈춤 뒤 첫 프레임 1단계 이하(몰아치기 없음).
- 이 사본의 엔진 테스트 53개도 그대로 통과한다(408번 줄 60Hz 루프 포함, 엔진 불변).

**하다가 찾은 것 — 필살기는 ‘단계’가 아니라 ‘입력’에서 생긴다**
- 필살기 효과는 `actDefense(skill)` 안에서 만들어진다. 그래서 단계 전후를 비교하는 `bigImpact`에는 잡히지 않는다(첫 시험에서 1-1의 멈춤이 0번이었다).
- UI 루프에서는 **필살기 입력이 받아들여진 프레임**에 멈춤을 걸어야 한다.
- 입력과 단계의 순서를 지키려면, 그 프레임의 단계를 마친 뒤 멈춘다(초안 테스트의 `skillUsed`).
- 사건 프레임은 바로 게시한다(47회차). 그래야 멈춘 그림이 필살기가 터진 그림이다.

## 3. 인계 (A ‘타격감 3단계’ ③에 덧붙임)

- 초안 파일 둘을 그대로 옮길 수 있다.
  - `logic-drafts/battleClock.ts` → `src/components/battleClock.ts`
  - 테스트 → `src/components/battleClock.test.ts` + `npm test` 목록
- `DefenseGame.tsx` 루프는 다음 순서로 바꾼다.
  1. `advanceClock`으로 단계 수를 받는다.
  2. 단계마다 `bigImpact`를 확인한다. 걸리면 `stopAt` 후 반복을 끊는다.
  3. 필살기 입력이 받아들여진 프레임은 그 프레임 단계 뒤 `stopAt`을 건다.
  4. 사건 프레임은 게시 제한 없이 게시한다.
- 완료 판단
  - 초안 테스트 2개와 엔진 테스트 전부 통과
  - 가로 844 × 390 영상에서 필살기·보스 처치에 멈춤이 보임
  - 동작 줄이기에서는 멈춤 길이 0(시계는 그대로)

## 1. 범위와 전제

### 1.1 이 규격이 다루는 것 / 다루지 않는 것

| 다룬다 | 다루지 않는다(6차 이후) |
|---|---|
| 영웅 모드 5개 스테이지(1-3·1-5·2-5·3-4·4-2)의 영웅 상태·이동·순찰·전투·스킬·쓰러짐 | 이탈 안개(`stray`), 측문 `G`, 보스 장막, 수레·거점 목표 `[RTS]` |
| 영웅 입력 API·스냅샷·이벤트·HUD 추가 요소 | 3D 모델·애니메이션 세부(13 소관) |
| E1~E4 적용 훅, 봇 시나리오 H1~H10 | 영웅 레벨업·성장(없음), 영웅 외형 선택 |

### 1.2 공통 전제

1. **결정론**: 영웅 로직은 난수를 쓰지 않는다(필요한 동률은 id·타일 인덱스로 깬다). 코어의 RNG 3개(`rng` 문제·봇 / `rngDraft` / `rngPerk`)를 하나도 소비하지 않는다. 그래서 `hero:'none'`은 4차 코어와 비트 단위로 같고(H8), `hero:'semi'`도 RNG 소비 열은 같다(영웅이 적을 먼저 흩어도 스폰 스케줄은 데이터로 고정이다).
2. **월드 틱 시간**: 이 문서의 모든 "틱"은 **월드 시간 0.1초**다. 코어는 `tick(dt)`에서 `dt *= S.timeScale`로 월드 시간을 만들고(드래프트 슬로우 ×0.3) 시간·타이머를 초(float)로 센다. 영웅 타이머도 같은 월드 `dt`로 `dt ÷ 0.1`틱씩 줄인다 → 슬로우 중에도 영웅 쿨다운·쓰러짐 대기가 월드와 같이 늦어진다. 표의 틱 수는 그대로 초 × 10이다.
3. **수치는 실수 허용**: 위치·빛·타이머는 실수. 비교는 ε = 1e-6. 이동은 `speed × worldDt`만큼만 전진한다(JS의 `+ − × ÷`는 결정적이므로 `Math.sin` 같은 초월함수만 쓰지 않으면 재현된다).
4. **모드 데이터는 `stages.json`**: `mode`, `heroEnabled`, `restSec`, `tutorialProtection`, `tutorialScript`, `starThresholds.star3.maxFalls`, `mapOverlay`만 읽는다(§2.1).
5. **영웅 피해는 카드 특성(A~D)의 영향을 받지 않는다**: 14 §5.1 확정. 영웅을 강화하는 것은 E 계열뿐이다.
6. **콤보 5 "전체 공격력 +30%"는 카드에만 적용한다** `[결정]`. 14 §4.3의 영웅 DP 환산(0.90)이 버프를 포함하지 않았다.

### 2.2 맵 레이어와 이동 가능 칸

08의 10×18 맵 위에 영웅 구역 오버레이를 얹는다(14 §4.2). 타일 종류는 `S T = o . x P`(14 §1.3 영웅 행).

| 종류 | 영웅이 걸을 수 있나 | 서 있기(순찰·귀환 후보) | 비고 |
|---|:-:|:-:|---|
| `x` 영웅 칸 | 예 | 예 | 맵 하반부(행 9 이상) 약 48칸(10 §4.3) |
| `P` 시작·부활 | 예 | 예 | 탑과 8방향으로 맞닿는 칸 1개 |
| `=` 길 | 예 | **자동 이동은 서지 않음** | 적과 같은 칸 → 접촉 피해 위험. 명령으로는 설 수 있다 |
| `o` 슬롯 | 아니오 | — | 카드 받침대 |
| `T` 탑, `S` 출발, `.` 장식 | 아니오 | — | 탑 탭 = 귀환 명령 |

- **고도**: 인접 칸 고도 차가 1을 넘으면 통행 불가(08은 ≤ 1을 보장). 도착 칸이 현재 칸보다 높으면 그 구간 속도 ×0.85.
- **대각 이동**: 8방향을 허용하되 두 직교 이웃이 모두 걸을 수 있을 때만(모서리 가로지르기 금지).
- **오버레이가 없을 때의 자동 유도 규칙**(오버레이 4벌이 제작되기 전 임시): ① `x` = 행 ≥ 9인 `.` 장식 칸 중 `P`에서 8방향으로 이어지는 것, ② `P` = 길의 마지막 칸(탑 직전)과 탑에 모두 8방향으로 맞닿는 비도로·비슬롯 칸 중 행이 큰 것, 동률이면 열이 작은 것, ③ `x`가 36개 미만이면 빌드 경고.
- 10 §4.3의 1-3 예시 맵에서 `X`를 길(`=`)로, `G`를 `x`로 바꾼 것이 영웅 모드 1-3 맵이다(14 §4.2). 이 맵의 영웅 칸은 50개(`x` 49 + `P` 1)다.

### 2.4 4차 코어(`prototype/core/sim.js`)와의 접속 메모

미커밋 사본(2026-10-28 23:40 시점)을 읽은 결과다. 코어가 바뀌면 이 표만 고친다.

| 항목 | 코어 현행 | 영웅·스테이지 연결 시 필요한 것 |
|---|---|---|
| 팩토리 | `createRun({region, subject, diff, seed, session, events, compat2D})` | `stage` 옵션 추가: `region = stage.mapId − 1`, `diff = stage.challengeTier`, 사용 슬롯 = `slotsEnabled`, 휴식 = `stage.restSec`(코어의 `prepSec`·`breakSec`), `hero` 옵션 |
| 웨이브 | `BALANCE.waveList[idx]` = 그룹 `{type, n, gap, at}`. **`at`이 없으면 직전 그룹이 끝난 뒤에 이어 붙는다** | `stages.json` 그룹을 `{type, n: count, gap: intervalSec, at: startSec}`로 바꾸되 **모든 그룹에 `at`을 명시**(03은 `+`로 이은 그룹을 동시에 시작한다). 왕 = `{type:'boss', n:1, gap:0, at: bossSpawn.startSec}` |
| 왕 HP | `enemyHp(type, waveIdx, diff)` = `BALANCE.enemies[type].hp × hpMult[w] × hpMultByDiff[diff]` | `boss`에 `× bossSpawn.fm ÷ rules.bossHp.fmRef(16)` 추가(15-6) |
| 시간 | `tick(dt)`: `dt *= S.timeScale`, 타이머는 초(float) | 영웅 타이머는 월드 `dt ÷ 0.1`틱씩 감소(§1.2-2) |
| 입력 | `answer(i)` `summon` `upgrade` `useUlt` `pickPerk` — **직접 호출, 틱 사이에 즉시 적용** | `heroMoveTo` `heroFocus` `heroRecall` `heroSkill` `heroSetOption` 동일 형태 |
| 정답 처리 | `answer(i)` 정답 분기: `addMana` → 읽기 하한(`S.qT < readFloorSec`이면 콤보 제외) → `comboReward` | 같은 분기에서 구슬 지급(`S.qT ≥ 1.0`일 때만, §7.3). 오답·회피 분기는 건드리지 않음 |
| 피해 | `damage(e, raw, ignoreArmor)` → 사망 시 `onKill(e)`(XP·처치 특성) | `damage(e, raw, false, 'hero')`처럼 **출처 인자**를 추가하고 `onKill(e, src)`가 영웅 처치(E3 크레딧, 통계)를 구분 |
| 탑 피해 | `towerHit(dmg)`: 보호막이 먼저 흡수 | 쓰러짐 벌칙은 `towerDirect(dmg)`(보호막 우회)를 새로 둔다(§8.1) |
| 단계 | `S.phase` = `'prep'`(첫 웨이브 전·웨이브 사이 휴식) / `'wave'` / `'result'` | 문서의 "휴식" = `'prep'`. hold 정지 조건 = `phase === 'prep'` |
| 스냅샷 | `snapshot()`: 재사용 객체 + 적 SoA(`flags` 1 둔화·2 피격·4 정예·8 보스) + `events` flush | `hero` 재사용 객체, 적 `flags` 16 = 눈부심(§11.3) |
| 이벤트 | `ev({k, ...})` | §11.4 |
| 맵 | `buildGeo(region, lift)` → `G.PTS` `G.SLOTS` `G.SEG` `G.pathLen` `G.posAt(dist, out)`. 적의 경로 진행 거리 = `e.dist` | 문서의 `s` = `e.dist`. 영웅 칸 오버레이·걷기 그래프를 `G`에 추가. 고도는 `MAPS`의 elev |
| 난수 | `rng`(문제·봇) · `rngDraft` · `rngPerk` | 영웅은 셋 다 소비하지 않음 |

## 3. 상태 머신

### 3.1 상태

| 상태 | 뜻 | 하는 일 | 못 하는 일 |
|---|---|---|---|
| `idle` 대기 | 서 있고, 사거리 안에 쏠 적이 없다 | 회복, 목표(goal) 평가, 스킬 시전 가능 | — |
| `move` 이동 | 목표 칸을 향해 걷는 중. `moveReason` = `order` `patrol` `chase` `retreat` `dash` | 스킬 시전 가능(돌진 중 제외) | 기본 공격(걷는 동안 쏘지 않음) |
| `combat` 전투 | 서 있고 사거리 안에 쏠 적이 있다 | 8틱마다 기본 공격, 스킬 | — |
| `down` 쓰러짐 | 빛 0. 부활 대기 | 명령 1칸 보관, 구슬 적립(문제는 정상) | 이동·공격·스킬. 적의 접촉·표적 대상에서 제외 |
| `revive` 부활 | `down`의 마지막 10틱. 탑 옆 `P`에서 일어나는 연출 | 명령 보관 | 이동·공격·스킬, 피해(무적) |

별도 플래그: `castLock`(스킬 2 시전 동작 3틱 동안 이동·기본 공격 불가), `dashLeft`(스킬 1 돌진 3틱, 접촉 무적). 12 §3.3 스냅샷의 `state`(대기·이동·공격·스킬) 가운데 "스킬"은 상태를 늘리지 않고 `casting` 필드로 따로 내보낸다.

### 3.2 전이표 (위에서 아래로, 처음 맞는 줄 하나만 적용. §4.2의 6c~6f에서 평가)

| # | 현재 | 조건 | 다음 | 부수 효과 |
|--:|---|---|---|---|
| 1 | 아무 상태 | 영웅이 없음(`hero:'none'`) | — | 영웅 갱신 전체 건너뜀 |
| 2 | `idle` `move` `combat` | 빛 ≤ 0 (T10에서 확정) | `down` | §8.1 |
| 3 | `down` | 남은 대기 > 10틱 | `down` | 카운트다운 |
| 4 | `down` | 남은 대기 = 10틱 | `revive` | 위치 = `P`, 빛 = 4칸, 무적 |
| 5 | `revive` | 남은 10틱 소진 | `idle` | 보관된 명령 1개를 6b에서 적용 |
| 6 | `idle` `move` `combat` | 후퇴 조건(§5.5) 성립 | `move`(retreat) | 명령 취소 |
| 7 | `idle` `move` `combat` | 스킬 1 시전(6b) | `move`(dash) 3틱 | 비용·쿨다운 확정, 접촉 무적 |
| 8 | `idle` `combat` | goal ≠ 현재 칸 | `move` | 사유 = goal 종류 |
| 9 | `move` | goal 도착(거리 ≤ 0.05) | `idle` 또는 `combat` | 명령이면 hold 시작 |
| 10 | `idle` | 정지 상태 + 사거리 안에 적 | `combat` | |
| 11 | `combat` | 사거리 안 적 0 | `idle` | |

- 6~8에서 `move`가 되는 목적지는 **goal 우선순위**(§4.2 6d)가 정한다. 후퇴 > 돌진 > 명령 > 추격 > 순찰 > 대기 위치. `combat` 중에도 더 좋은 goal이 생기면(§6.3 조건) 8번으로 이동한다.
- 걷는 중(`move`)에는 기본 공격을 하지 않고, 사거리 안에 적이 있어도 **목적지까지 멈추지 않는다**(순찰 칸은 이미 그 적을 잡으려고 고른 칸이다). 쿨다운은 걷는 동안에도 줄어서 도착하면 즉시 쏠 수 있다.

### 3.4 불변식 (테스트로 강제)

| # | 불변식 |

## 4. 틱당 처리 순서

### 4.1 전체 순서 (영웅 단계는 굵게)

4차 코어의 단계 이름이 다르면 **앞/뒤 관계만** 지킨다. T1~T3은 4차 코어에서 **틱 사이의 직접 호출**이다(§4.4).

| 단계 | 처리 | 영웅 관련 |
|---|---|---|
| T0 | 틱 증가, 이벤트 큐 비움, 이전 틱 스냅샷 보관 | — |
| T1 | 입력 소비(FIFO). 영웅 입력은 `inbox`에 적재만 | **`inbox` 적재** |
| T2 | 답 처리: 마나·콤보·XP·잠금·회피 | **구슬 지급**(§7.3) |
| T3 | 소환·강화·궁극기(궁극기 피해는 즉시) | — |
| T4 | 웨이브 감독: 스폰, 휴식 카운트, 방치 타이머, 튜토리얼 트리거 | 튜토리얼 보정(§8.3) |
| T5 | 적 이동·상태 갱신: 눈부심·둔화 타이머, 위치, 탑 도달(누수) | 눈부심이면 정지 |
| **T6** | **영웅 갱신(6a~6g, §4.2)** | **전부** |
| T7 | 카드 공격 | — |
| **T8** | **영웅 공격·스킬 판정**(카드 뒤) | **전부** |
| T9 | 처치 확정: XP·처치 특성·마나 | **영웅 처치 크레딧** |
| **T10** | **영웅 접촉 판정, 빛 0이면 쓰러짐 전이** | **전부** |
| T11 | 드래프트 큐 처리, 웨이브 종료·승패 판정, 통계 | 별 조건 통계 |
| T12 | 스냅샷·이벤트 확정 | 영웅 필드 |

- T8을 T7 뒤에 둔 이유: 같은 틱에 카드와 영웅이 같은 적을 때리면 카드가 먼저 깎고, 영웅은 마지막 타격을 **덜** 가져간다. E3(처치 마나)의 ME 4.0은 영웅 처치를 약 6마리로 잡은 값이라 보수적인 쪽이다.
- T6(영웅 이동)을 T5(적 이동) 뒤에 둔 이유: 영웅이 이번 틱의 적 위치를 보고 움직이고, T10 접촉 판정이 두 위치 모두 새 값을 본다.

### 4.2 T6 영웅 갱신 세부

| 단계 | 처리 |
|---|---|
| 6a | 타이머를 월드 `dt ÷ 0.1`틱만큼 감소: `cd1` `cd2` `atkCd` `hurtCd` `regenDelay` `castLock` `dashLeft` `focusLeft` `downLeft`. `order.holdLeft`는 도착 후이고 휴식 중이 아닐 때만 감소 |
| 6b | `inbox` 처리(§5.1). 도우미가 켜져 있으면 자동 시전 입력을 `inbox` 끝에 추가(§7.5). 스킬은 여기서 검증·비용·쿨다운을 확정하고 `pendingCast`로 남긴다(효과는 T8) |
| 6c | `down`/`revive` 진행(§8). 아니면 후퇴 조건 평가(§5.5), 만료된 `order`·`focus` 정리 |
| 6d | **goal 결정**(아래 우선순위) |
| 6e | 이동 1틱: 길찾기 경로를 속도 × 0.1만큼 전진(§5.3) |
| 6f | 표적 획득(§7.1)과 상태 결정: 정지 + 사거리 안 적 → `combat`, 정지 + 적 없음 → `idle`, 이동 중 → `move` |
| 6g | 회복(§7.6) |

**goal 우선순위(6d)**

| 순위 | goal | 조건 |
|--:|---|---|
| 1 | 후퇴 목표 `P` | `retreatLatch` |
| 2 | 돌진 종점 | `dashLeft > 0` |
| 3 | `order.tile` | `order`가 있고 아직 도착 전, 또는 도착 후 hold 중이면 그 자리 유지 |
| 4 | 추격 칸 | 고수 지점에서 `hero.leash` 안에서 표적을 사거리에 둘 수 있는 가장 가까운 비도로 칸(§5.4). 표적이 사거리 밖일 때만 |
| 5 | 순찰 칸 `patrolTile` | `autoPatrol` 켜짐 + `order` 없음(§6) |
| 6 | 대기 위치 `P` | 위협(길 위 적)이 없을 때 |

### 4.3 같은 틱 충돌 규칙

| 상황 | 규칙 |
|---|---|
| 같은 틱에 `heroMove` 여러 개 | 마지막 하나만 유효. 앞의 것은 `heroCmd{ok:false, reason:'replaced'}` 이벤트(로그용) |
| 스킬 시전과 쓰러짐 | 시전은 6b에서 확정되어 T8에서 효과가 난다. 쓰러짐은 T10이라 같은 틱 시전은 **유효** |
| 스킬 시전과 `down`/`revive` 진입 틱 | 진입한 틱은 T10 이후이므로 다음 틱부터 시전 거부(`down`) |
| 카드 처치와 영웅 처치 | T7이 먼저. 처치 크레딧은 **마지막 타격자** 1명 |
| 영웅 접촉과 적의 탑 도달 | 서로 독립. 도달한 적은 T5에서 이미 사라진다 |
| 눈부심과 둔화 | 눈부심 > 0이면 정지(둔화 무시). 끝나면 둔화 값으로 복귀. 눈부심 갱신은 `max(남은, 새 값)` |
| 후퇴와 플레이어 명령 | 명령이 이긴다. `retreatLatch` 해제, 다음 피해 때까지 재가동 안 함 |
| 부활 틱과 명령 | `revive`가 끝나는 틱의 6b에서 보관된 명령 1개를 적용 |

### 4.4 4차 코어 `tick(dt)`와의 대응

코어의 현행 순서는 `updateDraft` → 시간·자동 회복·콤보 버프 → `updateQuiz` → 준비/웨이브·스폰 → `updateEnemies`(끝에 `compact`) → `updateTowers` → `compact` → 패배·웨이브 클리어 판정이다. 영웅 단계 세 개를 끼운다. 답·소환·강화·궁극기는 틱 안이 아니라 **틱 사이의 직접 호출**이라 T1~T3은 "틱이 시작될 때 이미 끝나 있는 입력"이다.

| 이 문서 | 코어에서 | 영웅 삽입 |
|---|---|---|
| T0 | `tick()` 앞머리: `tickNo++`, 드래프트 갱신, `dt *= timeScale`, 시간·자동 회복·버프 타이머 | — |
| T1~T3 | 틱 사이 `answer` `summon` `upgrade` `useUlt` `pickPerk` 호출 | `answer()` 정답 분기에서 구슬 지급. `hero*` 호출은 `inbox`에 적재만 |
| T4 | `updateQuiz`, 준비/웨이브 단계, 스폰 | 튜토리얼 보정 |
| T5 | `updateEnemies(dt)`: 이동, 누수(`towerHit`), 끝에 `compact` | 눈부심 > 0인 적은 이동하지 않음(`enemySpeed`가 0) |
| **T6** | — | **`updateHero(dt)`**: `updateEnemies` 뒤, `updateTowers` 앞 |
| T7 | `updateTowers(dt)` | — |
| **T8** | — | **`heroAttack(dt)`**: `updateTowers` 바로 뒤 |
| T9 | `damage()` 안의 `onKill(e)` | 별도 단계가 아니다. T7·T8의 `damage()` 호출에서 즉시 확정되고 영웅 처치는 출처 인자로 구분 |
| **T10** | — | **`heroContact(dt)`**: `heroAttack` 뒤, 기존 `compact()` 앞(죽은 적은 `e.dead`로 제외) |
| T11 | `compact()`, `hp ≤ 0` 판정, 웨이브 클리어 판정 | 통계 갱신 |

- 영웅이 처치한 적은 `e.dead = true`로 표시만 하고 풀 반환은 기존 `compact()`가 맡는다.
- 영웅 때문에 `tick()` 호출 횟수나 기존 단계의 순서는 바뀌지 않는다(H8b의 전제).

## 5. 이동과 명령

### 5.1 입력 종류와 검증

모든 입력은 T1에서 `inbox`에 쌓이고 6b에서 순서대로 검증한다. 검증 실패는 상태를 바꾸지 않고 `heroCmd{ok:false, reason}` 이벤트만 남긴다.

| 입력 | 인자 | 효과 | 거부 사유 |
|---|---|---|---|
| `heroMove` | 타일 `{c, r}` | 이동 명령. 도착 후 hold | `unreachable`(걸을 수 있는 칸이 2.0 안에 없음), `noHero` |
| `heroFocus` | 적 `id` | 표적 지정 + 필요하면 접근 | `noTarget`(없거나 죽음) |
| `heroRecall` | — | `P`로 이동 명령(kind `recall`) | — |
| `heroSkill` | `i` ∈ {1, 2} | 스킬 시전 | `noOrbs` `cooldown` `locked`(castLock·돌진·`down`·`revive`) `noTarget`(스킬 2만) |
| `heroOption` | `key`, `value` | `autoPatrol` `safeRetreat` `assist` 토글 | `badKey` |

**`heroMove`의 칸 스냅**: 지정 칸이 걸을 수 있으면 그대로. 아니면 2.0 타일 안에서 걸을 수 있는 칸 중 유클리드 거리 최소(동률: 비도로 > 행 작은 쪽 > 열 작은 쪽). 없으면 `unreachable`. UI의 탭 우선순위(10 §5.3 #4: 팝업 바깥 → 슬롯 → 적 → 탑·수레·거점 → 빈 칸)는 **어댑터가 판정하고** 코어에는 결과 입력만 보낸다. 적 히트 반경은 0.6타일(20px ÷ 34px)이다.

**`heroFocus`**: `focusId`를 정하고 `focusLeft = 100`. 표적이 사거리 밖이면 순찰 점수식(§6.2)을 `lead = [그 적]`으로 한 번 돌려 얻은 칸으로 `order`(kind `move`)를 만든다. 표적이 죽거나 누수하면 `focus`와 그 `order`의 hold가 풀린다.

### 5.2 명령 큐 규칙 ("탭 이동 명령 큐")

| 규칙 | 내용 |
|---|---|
| 입력 경로 | 4차 코어는 입력 큐 없이 `run.answer(i)` 같은 **직접 호출을 틱 사이에 즉시 적용**한다. 영웅 호출(`run.heroMoveTo(tile)` 등)도 같은 형태이고 호출 순서대로 `inbox`에 쌓았다가 다음 틱 6b에서 처리한다. 06 §6.1의 큐(`{tick, action}`)로 재생하려면 호출을 큐 항목으로 감싸면 된다(§11.2). 헤드리스 봇도 같은 호출 |
| 병합 | 한 틱 안의 `heroMove`/`heroRecall`/`heroFocus`는 **마지막 하나만** 적용(앞의 것은 `replaced`) |
| 체인 없음 | 이동 명령은 대기열을 만들지 않고 **현재 명령을 대체**한다(웨이포인트 없음). `heroMove(tile, {queue:true})`는 이름만 예약 |

### 5.3 길찾기

- 그래프: §2.2의 걸을 수 있는 칸, 8방향, 비용 = 유클리드 길이(1 / 1.4142) + (자동 이동이면 도착 칸이 길일 때 `roadStepCost`).
- 알고리즘: A*(옥타일 휴리스틱). **동률 깨기**: f가 같으면 g가 큰 쪽, 그다음 타일 인덱스(`행 × 10 + 열`)가 작은 쪽. 경로는 명령·goal이 바뀔 때와 10틱마다 재계산한다(맵이 작아 비용은 무시할 수준).
- 이동: 경로의 다음 칸 중심을 향해 틱당 `speed × 0.1 × 구간 배율`만큼. 구간 배율 = 도착 칸이 더 높으면 0.85(후퇴 ×1.2 곱). 칸 중심에 도달하면 남은 거리를 다음 구간으로 넘기지 않는다(틱당 한 구간, 오차 < 0.3타일).
- **길 건너기 대기**(자동 이동 한정, 후퇴·돌진·플레이어 명령 제외): 다음 칸이 길이고 그 칸 중심 `crossGap`(1.2) 안에 살아 있는 적이 있으면 최대 10틱(`crossWaitTicks`) 제자리 대기한다. 대기 중에도 상태는 `move`(사유 유지)다. 10틱을 넘기면 그냥 건넌다(소프트락 방지).

### 5.4 고수(hold)·고삐(leash)·추격(chase)

| 항목 | 규칙 |
|---|---|
| hold 시작 | 명령 목표에 거리 ≤ 0.05로 **도착한 틱**에 `holdLeft = 80`. 이동 시간은 세지 않는다 `[결정]` |
| hold 중 | 순찰 중단. 사거리 안 적은 쏘고, 사거리 밖 적은 고삐 안에서만 추격 |
| hold 정지 | 웨이브 사이 휴식(`phase = rest`, 살아 있는 적 0) 동안은 `holdLeft`가 줄지 않는다. 플레이어가 고른 자리가 다음 웨이브까지 유지된다 `[결정]` |
| hold 만료 | 순찰 복귀. 순찰 칸이 현재 칸과 다르면 걸어간다 |
| 고삐 | 추격 칸은 고수 지점(`order.tile`, 순찰이면 `patrolTile`)에서 3.0타일 이내여야 한다. 표적이 사거리(2.0) 밖이면 그 안의 가장 가까운 비도로 칸으로 이동. 없으면 추격하지 않는다 |
| 추격 재평가 | 10틱마다. 표적이 이미 사거리 안이면 움직이지 않는다(떨림 방지: 사거리 1.8 안에 들어오면 멈춤) |

### 5.5 안전 후퇴

- 시작: `safeRetreat` 켜짐 + `light ≤ 2`(칸) + 영웅이 `down`/`revive`가 아님 → `retreatLatch = true`, 목표 `P`, 속도 ×1.2, `order`·`focus` 취소. 후퇴 중에도 접촉 피해는 받는다(10 §2.5).
- 해제: `light ≥ 4`(칸) 또는 플레이어 명령(이때는 다음 피해를 받을 때까지 재가동하지 않음). `P` 도착 후에는 회복하며 대기.
- 쓰러짐 진입 시 `retreatLatch`는 꺼진다.

## 6. 자동 순찰

목표: 조작이 없어도 쓸모 있고(10 §2.1-2), 예측 가능해서 플레이어가 "저기 서 있겠구나"를 읽을 수 있으며, 이리저리 떨지 않는 것.

### 6.1 후보 칸

- **서 있을 후보** = 영웅 칸 `x`·`P` 중 걸어서 닿을 수 있는 것. 길 칸은 후보가 아니다(I7).
- 후보에서 길 중심선까지 거리는 항상 ≥ 1.0이라 순찰만으로는 접촉 피해가 나지 않는다(접촉 반경 0.6).

### 6.2 점수식 (1초마다 재평가)

위협 열 `lead` = 살아 있는 **길 위** 적을 탑에 가까운 순(경로 진행 거리 `s` 내림차순, 동률 id 오름차순)으로 `leadCount`(3)마리. 왕은 다른 적과 같이 센다. `[RTS]` 이탈 안개·장막은 이 목록의 앞에 끼워 넣는 자리만 남긴다(10 §2.2 표적 순서).

후보 칸 `t`의 점수:

```
reach(t)  = 걷는 거리(hero→t) ÷ 3.0                         (초)
for e in lead:
    s'    = e.s + e.speed × (reach(t) + lookahead)           (도착 후 lookahead 초 뒤 적의 경로 위치, 현재 속도·눈부심 무시)
    hit   = 1  if 거리(t 중심, 경로의 s' 위치) ≤ 2.0 else 0
    gain += threatW[e.type] × (0.5 + e.s ÷ 경로길이) × hit    (탑에 가까운 적일수록 가중)
score(t)  = gain − travelPenalty × reach(t)
```

| 상수 | 값 |
|---|---|
| `leadCount` | 3 |
| `lookaheadSec` | 1.0 |
| `travelPenaltyPerSec` | 0.1 |
| `threatW` | normal 1.0 / fast 0.7 / tank 3.0 / boss 6.0 |
| `replanTicks` | 10 |
| `minStayTicks` | 30 |
| `switchRatio` / `switchBonus` | 1.25 / 0.2 |

최고 점수 칸을 고른다. **동률 깨기**: 걷는 거리 짧은 쪽 → 행 작은 쪽 → 열 작은 쪽.

### 6.3 히스테리시스 (떨림 방지)

현재 순찰 칸 `cur`을 바꾸는 조건은 모두 만족해야 한다.
1. 마지막 선택 후 `minStayTicks`(30틱) 지남.
2. `score(new) ≥ score(cur) × 1.25 + 0.2`, 또는 `score(cur) ≤ 0`(현재 칸이 더 이상 아무도 못 맞힘)이면서 `score(new) > 0`.

`order` hold 중에는 평가하지 않는다. 사거리 안에 적이 있어 `combat` 중이어도 조건 1·2를 만족하면 이동한다(위치를 옮겨 더 위협적인 적을 잡는다).

### 6.4 위협이 없을 때

- 휴식 중 또는 길 위 적이 0마리: 목표 = `P`(탑 앞, 10 §2.7). 회복하며 대기.
- 어떤 칸도 선두 적을 사거리에 두지 못하면(모든 점수 ≤ 0, 스폰 직후 선두가 경로 앞쪽에 있을 때) 현재 위치(대개 `P`)를 유지한다. 선두가 내려오며 점수가 양수가 되는 칸이 생기면 순찰 칸이 단계적으로 바뀐다(부록 A의 예).

### 6.5 성질 (테스트 가능한 보장)

| # | 성질 | 확인 |
|--:|---|---|
| P1 | 순찰 칸은 항상 비도로 영웅 칸 | I7, H9 |
| P2 | 같은 입력이면 같은 칸(결정론) | I5 |
| P3 | 선두 적이 한 정류 칸의 사거리를 지나는 동안(경로 약 3.5~5.5타일) 그 칸을 유지한다 | H9: 이동 틱 비율 ≤ 0.30 |
| P4 | 순찰만으로 영웅이 쓰러지지 않는다(접촉 0회) | H9 |
| P5 | 적이 한 마리뿐이어도 탑에 도달하기 전 최소 한 번은 사거리에 둔다 | 부록 A |

## 7. 전투, 스킬, 자원

### 7.1 기본 공격과 표적

- 발동: 상태가 `combat`(정지 + 표적이 사거리 2.0 안) + `atkCd = 0` + `castLock = 0` → T8에서 즉시 판정(히트스캔, 12 §3.2-6), `atkCd = 8`.
- **표적 우선순위**: ① `focusId`(살아 있고 사거리 안) ② `[RTS]` 이탈 안개 ③ `[RTS]` 장막 ④ 길 위 적 중 `s`가 가장 큰 것(동률: 남은 HP 비율 작은 쪽 → id 작은 쪽).
- **끈끈함**: 현재 `targetId`가 살아 있고 사거리 안이면 유지한다(적끼리 추월할 때마다 표적이 바뀌는 것 방지). `focus`가 생기거나 표적이 죽거나 사거리를 벗어나면 다시 고른다.
- 영웅은 **공격할 수 있는 적**만 본다: 길 위 적(`normal` `fast` `tank` `boss`). 탑에 이미 도달한 적은 사라져 있다.

### 7.2 피해식

```
raw  = 기본(20 / 스킬 값) × (1 + hero.dmgBonus) × roadMult            roadMult = 0.6 (길 위 적·왕), [RTS] stray 1.0, 장막 1.0·스킬별 배율
dmg  = max(1, round(raw − armor(target)))                              armor: tank 3, boss 5 (프로토 BALANCE.enemies)
```

- 예(보너스 0, 길 위): 기본 공격 안개 조각 12, 침묵 덩어리 9, 왕 7. E1(+0.4) 안개 조각 `round(20×1.4×0.6) = 17`.
- 영웅은 카드 특성의 방어 깎기(A3 등)·피해 +%(A·C·G)를 받지 않는다(§1.2-5).
- 콤보 5 버프(+30%)도 받지 않는다 `[결정]`.

| 쓰러짐 판정 | `light ≤ 0` → §8 |
| 회복 | `regenDelay = 0`이면 초당 +0.5칸. 펜타클 카드 중심 2.0 안이면 대기 없이 초당 +1.0칸(둘 중 큰 값 하나). 최대 6. `down`·`revive` 중 없음 |
| 펜타클 | 카드 Lv와 무관. 영웅-펜타클 연계는 "근처에 두기" 하나(10 §2.6) |

## 8. 쓰러짐과 부활

### 8.1 쓰러짐 진입 (T10)

1. `falls += 1`(튜토리얼 면제 쓰러짐은 `protectedFalls += 1`, `falls` 불변).
2. 구슬 `orbs = orbs − floor(orbs / 2)`(면제 쓰러짐은 손실 없음).
3. `down` 진입, `order` `focus` `targetId` `retreatLatch` 초기화. `inbox`는 보관 1칸만 남긴다.
4. `downTotal = hero.fall.downTicks[min(falls, 3) − 1]` (80 / 100 / 120). 면제 쓰러짐은 `downTotal = 10`(부활 연출만 = "즉시 부활").
5. **탑 벌칙**: 면제가 아닌 `falls ≥ 4`이고 `penalties < 3`이면 탑 HP −1, `penalties += 1`. 벌칙은 **펜타클 보호막을 우회**한다 `[결정]`. 이벤트 `towerPenalty{hp}`.
6. 이벤트 `heroDown{n, ticks, penalty}`.

| 쓰러짐 | 대기 | 탑 HP |
|--:|---|---|
| 1 | 80틱(8초) | 0 |
| 2 | 100틱 | 0 |
| 3 | 120틱 | 0 |
| 4 | 120틱 | −1 |
| 5 | 120틱 | −1 |
| 6 | 120틱 | −1 |
| 7~ | 120틱 | 0 (합계 상한 −3) |

### 8.2 대기와 부활

- `downLeft`는 매 틱 6a에서 감소. 남은 값이 10이 되는 틱에 `revive`: 위치 `P` 중심, `light = 4`, 접촉 무적.
- `revive` 10틱이 끝나면 `idle`. 6b에서 보관된 명령 1개를 적용하므로 플레이어가 대기 중에 미리 찍어 둔 자리로 바로 걷는다.
- 대기 중에도 문제·소환·강화·궁극기는 정상이고 구슬이 쌓인다(10 §2.5, 대기 시간이 문제 풀이 시간이 되도록 의도).
- 부활 위치 `P`에 적이 있어도 영웅은 무적이므로 충돌 처리는 없다.

### 8.3 튜토리얼 보호 (1-3, `tutorialProtection`)

| 키 | 효과 |
|---|---|
| `firstFallFree: true` | 첫 쓰러짐: 벌칙 없음, 구슬 손실 없음, `falls`에 세지 않음, 대기 10틱(즉시 부활) |
| `orbBoost: 2` | §7.3 |
| `straySpeedMultW2` | `[RTS]` 2-2 |

본 판(1-5부터)에는 보호가 없다.

### 8.4 별과의 연결

`stats.falls`(면제 제외)가 `starThresholds.star3.maxFalls = 2` 이하여야 ★3. `stats.penalties`는 결과 화면의 "탑을 지키지 못한 만큼" 설명에 쓴다.

## 11. API 초안

### 11.1 생성과 루프

```
run = createRun({ stage /* stages.json 항목: region = mapId−1, diff = challengeTier */,
                  seed, session, events,
                  hero: 'auto' | 'none' | 'semi',
                  heroOptions: { autoPatrol: true, safeRetreat: true, assist: false } })
  - hero 'auto'  : stage.heroEnabled ? 'semi' : 'none'
  - hero 'none'  : 스냅샷 hero = null, 영웅 입력은 noHero로 거부 (D16 "수비로 하기"가 이 값을 쓴다)

loop:  run.step(realDt)                // 코어 현행: 실제 시간을 쌓아 0.1초 틱으로 분할
       renderer.draw(run.snapshot(), run.alpha)   // snapshot().events 를 flush
       ui.update(run.state)            // HUD 값은 읽기 전용 run.state 와 snapshot().hero 에서
```

### 11.2 명령 (`run`의 직접 호출. 내부에서 `inbox`에 적재)

| 호출 | `inbox`/큐 항목 | 반환(동기, 상태 변경 없음) |
|---|---|---|
| `heroMoveTo(tile)` | `{type:'heroMove', c, r}` | `{ok, snapped:{c,r}\|null, etaTicks, reason?}` — 현재 상태 기준 미리보기 |
| `heroFocus(enemyId)` | `{type:'heroFocus', id}` | `{ok, reason?}` |
| `heroRecall()` | `{type:'heroRecall'}` | `{ok}` |
| `heroSkill(i)` | `{type:'heroSkill', i}` | `{ok, reason?}` — `noOrbs` `cooldown` `locked` `noTarget` |
| `heroSetOption(key, value)` | `{type:'heroOption', key, value}` | `{ok}` |
| `heroPreviewMove(tile)` | (큐 없음) | 위 `heroMoveTo`의 반환과 같은 순수 함수 |
| `heroSkillState(i)` | (큐 없음) | `'ready' \| 'noOrbs' \| 'cooldown' \| 'noTarget' \| 'locked'` |

- 반환값은 UI 피드백용이다. **실제 적용 여부는 6b에서 다시 검증**하므로 반환과 결과가 다를 수 있다(그 사이 틱에서 상태가 바뀜). 재현(replay)은 "틱 번호 + 호출 + 인자" 열만 있으면 된다(06의 `{tick, action}` 큐와 같은 정보).
- 어댑터의 탭 해석(10 §5.3 #4)은 `pickTile`/`pickEnemy` 결과로 위 래퍼 중 하나를 고른다. 코어는 화면 좌표를 모른다.

### 11.3 스냅샷 `snapshot().hero` (12 §3.3의 "영웅" 행을 구체화)

| `casting` | 0 \| 1 \| 2 | 시전 동작 중인 스킬(0 = 없음) |

### 11.4 이벤트 (렌더·사운드·도토 소비 전용)

코어의 관례를 따른다: `ev({k: 이름, ...})`가 `tick`을 자동으로 붙이고, 렌더는 `snapshot().events`를 읽어 비운다. 아래 `k` 이름은 영웅 모드 추가분이다. 06 §7 로그 스키마에는 같은 내용을 snake_case로 남긴다(예: `hero_down`).

| `k` | 페이로드 |
|---|---|
| `heroCmd` | `type`, `ok`, `reason`(`unreachable` `noTarget` `noOrbs` `cooldown` `locked` `noHero` `badKey` `replaced`) |
| `heroMove` / `heroArrive` | 목표 칸 `c`, `r`, 사유(`why` = `order` `patrol` `chase` `retreat` `dash`) |
| `heroAttack` | `id`, `dmg`, `kill` |
| `heroSkill` | `i`, 시작·종점 좌표, 맞은 `ids`, `combo`, `radius` |
| `heroHurt` | `dmg`(칸), `light` |
| `heroRetreat` | `on`(true/false) |
| `heroDown` / `heroRevive` | 쓰러짐 회차 `n`, 대기 `ticks`, 탑 벌칙 `penalty` |
| `towerPenalty` | 남은 탑 HP `hp` |
| `orb` | `d`(증감), `total`, `why`(`answer` `cast` `fall` `boost` `wasted`) |
| `heroCmdFlood` | (도토 힌트 1회) |
| `tutorialStep` | `step`, `pass` |
| `perkRejected` | `id`, `reason` |

## 12. 봇 시뮬 시나리오

06의 봇 프로필(`expert` 정답 95%/3초, `average` 80%/5초, `struggling` 55%/8초, `idle`)을 그대로 쓰고 영웅 파라미터를 더한다: `cmdPerMin`, `cmdPolicy`, `skillPolicy`, `autoPatrol`, `assist`, `heroOverheadSec`.

- `skillPolicy`: `none` / `greedy`(구슬이 차면 §7.5 규칙으로 시전) / `idle-try`(무풀이 시나리오용: 매 틱 시전을 시도해 코어가 거부하는지 본다).
- `cmdPolicy`: `none` / `anticipate`(15초마다 `lead[0]`이 6초 뒤 지나갈 위치를 사거리에 두는 정적 커버 최대 칸으로 `heroMove`) / `rush`(적 쪽 길 칸으로 돌진 — 쓰러짐 시나리오).
- **응답 주기 보정**: 봇이 문제 하나에 쓰는 시간 = `반응시간 + 3.0초`(피드백 1.0 + 지도 확인 2.0). 이 값으로 `average`가 8.0초/문항(03의 7.5문항/분)이 된다. 영웅 조작은 명령 1.0초, 스킬 1.5초, 상태 확인 2.0초를 주기에 얹는다(10 §6.2).
- 스테이지: 영웅 모드 5개(1-3 1-5 2-5 3-4 4-2). 시드 1000개(결정론). 비교 수비 모드는 같은 스테이지 데이터에 `hero:'none'`.

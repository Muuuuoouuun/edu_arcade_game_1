## 1. 학습 목표와 게임 행동의 매핑

### 1.1 과목별 학습 목표

| 과목 팩 | 핵심 학습 목표 | 주된 문항 유형 | 필요한 수행 특성 |
|---|---|---|---|
| 수학 연산·분수 | 사칙연산 유창성 + 분수 개념(통분, 역수, 나눗셈)의 절차적 이해 | mc, input, tf | 정확성 > 속도. 유창성(d1)만 속도가 의미 있음 |
| 영어 단어 | 뜻-철자 연결의 빠른 인출 | mc, input(영문 철자), tf | 속도와 정확성 모두 의미 있음(자동화) |
| 과학 개념 | 용어와 개념의 정확한 구분, 오개념 교정 | mc, tf, input(숫자) | 정확성, 이유 이해 |
| 한국사 연표 | 사건의 선후 관계와 시대 틀 형성 | mc, tf, order | 관계 파악, 순서 감각 |

### 1.2 게임 행동 → 학습 행동 매핑

| 게임 행동 | 강화되는 학습 행동 | 학습과학 근거 | 설계상 유의점 |
|---|---|---|---|
| 문제 카드를 풀어 마나 획득(마나의 유일한 원천) | 인출 연습(retrieval practice) | 다시 꺼내 쓰는 연습이 재독보다 기억에 유리 | 자동 회복은 소량(0.2/s)이라 풀지 않으면 진행 불가 |
| 정답 시 난이도별 마나 차등(+3/4/5 + 유형 가산) | 적정 난도에 도전 | 약간 어려운 과제가 학습에 유리(바람직한 어려움) | 마나는 풀이 시간과 무관(1.3 참조) |
| 콤보(3/5/8) | 연속 정확 수행, 집중 유지 | 목표 근접 동기, 유창성 | 찍기로 콤보를 쌓지 못하도록 5절 장치 적용 |
| 오답 → 봉인 카드 | 오류 지점의 기록·추적 | 오류 기반 학습, 형성평가 | 봉인은 처벌이 아니라 "복습 예약"으로 표현 |
| 해제 퀴즈(판 끝) + 시작 마나 보너스 | 간격 반복 재인출 | 분산 연습, 간격 효과 | 4절 규칙(1·3·7판) |
| 웨이브 사이 5초 휴식에 선행 풀이 | 분산 연습, 자기 속도 조절 | 짧은 분산 세션 | 휴식 중 문제는 정상 마나 지급 |
| 소환/강화 마나 배분 선택 | (직접 학습 아님) 인출 사이의 인지 휴식, 자기 조절 | 짧은 휴식이 지속 주의에 유리 | 문제 카드와 분리해 문제 풀이 UI를 가리지 않음 |
| 10초 방치 → "회피" 기록 | 메타인지 신호(모르겠음 vs 딴짓) 포착 | 형성평가의 진단 신호 | 처벌 아님. 교사 리포트에서 "회피 많은 주제"로 활용 |
| 판 끝 해설 모음 | 정교화 피드백, 오개념 교정 | 피드백 시점 연구 | 6절 |
| 별점(탑 HP·정답률·최대 콤보) | 정확도 중시 | 정답률이 별 평가에 포함되어 속도 편중 방지 | 정답률 가중치는 밸런싱 문서가 조정 |
| 메이저 아르카나(콤보 8) | 장기간 정확한 수행 | 연속 성공 보상 | 콤보는 정답에서만 증가 |

### 1.3 "빠르고 정확하게"가 해로울 수 있는 지점과 완화책

핵심 원칙(빠르고 정확할수록 강해짐)은 **암기·인출형(영어 단어, 한국사 연표, 과학 용어, 곱셈 구구)** 에서는 자동화를 촉진해 맞다. 그러나 **수학 사고력(다단계 연산, 분수 나눗셈의 의미, 문장제)** 에서는 다음 위험이 있다.

| 위험 | 설명 | 완화책 |
|---|---|---|
| 얕은 전략 유도 | 시간 압박 때문에 계산 대신 어림·끝자리 소거·찍기로 푼다 | (a) 마나가 풀이 시간에 의존하지 않음: 같은 문항은 3초에 풀든 9초에 풀든 같은 마나. 속도는 적의 진군을 통해서만 간접적으로 영향 (b) d3 수학은 보기 소거가 어려운 `input`형 비중을 높임 |
| 다단계 풀이 시간 부족 | 10초 방치 규칙이 다단계 문제에서 사고 시간을 끊을 수 있음 | "방치"를 **입력 없음**으로 정의해 키패드를 한 번이라도 누르면 타이머를 리셋. `skill:multi_step` 태그 문항은 15초로 늘리는 안을 제안(변경 제안 3) |
| 오답 콤보 단절 불안 | 어려운 문제를 피하거나 찍게 됨 | `skill:reasoning` 태그 문항의 오답은 콤보를 0이 아니라 **현재 콤보의 절반(내림)** 으로 낮춤. 단 회피로 콤보를 보호하는 우회는 웨이브당 1회까지(3.3) |
| 속도가 유창성만 보상 | 사고력 문항이 손해로 느껴짐 | d3 추론 문항의 마나(+5, input형은 +6)가 d1 유창성(+3)보다 큼. 난이도 적응이 d3 비중을 점진 상승 |
| 오답 이유를 못 봄 | 빠른 템포에서 "왜 틀렸는지"를 놓침 | 오답 직후 정답만 짧게 공개, 풀이 과정 해설은 휴식·판 끝에 제공(6절) |
| 속도 비교 압박 | 시간 기록 비교로 스트레스 | 난이도 적응(ELO)은 **지연 시간을 쓰지 않음**. 속도 지표는 교사 리포트에만 참고용으로 남김 |

문항 풀 구성 규칙(수학 팩): d1 유창성 문항은 한 판 출제의 40%를 넘지 않게 하고, `skill:reasoning` 문항은 숙련도가 오르면 자연스럽게 늘어나도록 3절 가중치를 사용한다.

## 2. 문항 유형, 입력 UI 제약, 마나 보상

### 2.1 마나 보상 표 (브리프 +3/+4/+5를 4지선다 기준값으로 두고 유형 가산을 얹음 — 확장)

| 유형 | d1 | d2 | d3 | 가산 근거 | 찍기 확률 |
|---|---|---|---|---|---|
| mc 4지선다 | 3 | 4 | 5 | 기준값(브리프와 동일) | 25% |
| tf 참/거짓 | 1 | 2 | 3 | 기준 −2(최소 1): 찍으면 50%라 보상을 낮춤. 대신 빠르고 짧아 콤보 쌓기용 | 50% |
| input 짧은 입력 | 4 | 5 | 6 | 기준 +1: 소거 불가, 인출 부담이 큼 | 거의 0 |
| order 순서 배열 | 5 | 6 | 7 | 기준 +2: 여러 항목 관계 이해, 시간이 더 걸림 | 3항목 17%, 4항목 4%, 5항목 1% |

권장 출제 비율(밸런싱이 조정): mc 40~50%, input 20~40%, tf 10~20%(연속 2회 초과 금지), order는 한국사 팩에서 10~20%.

### 2.2 유형별 입력 UI 제약 (모바일 한 손 조작, 세로 기준)

공통: 문제 카드는 화면 **하단 40%** 에 고정, 조작 버튼은 엄지 도달 영역(하단 중앙~우측)에 배치. 터치 목표는 **최소 48×48 CSS px, 간격 8px 이상**. 가로 모드는 문제 카드를 한쪽 절반으로 두고 같은 크기 규칙 유지. PC는 키보드 단축키(1~4, ←/→, 숫자·Enter)를 지원.

| 유형 | UI 규칙 |
|---|---|
| mc | 2×2 격자. 보기 한 칸은 높이 ≥ 56px, 보기 글자 20자 내외(2줄 허용, 스키마 상한 40자). 보기 순서는 매번 섞되 선택 후 위치 변동 없음. 탭 즉시 제출(확인 버튼 없음). 오탭 방지를 위해 선택 직후 120ms는 추가 입력 무시 |
| tf | 좌 ✕(거짓), 우 ○(참) 두 개의 큰 버튼(높이 ≥ 64px), **위치 고정(섞지 않음)** 으로 근육 기억 유도. 탭 즉시 제출 |
| input (number/fraction) | 앱 내장 키패드 4×4(숫자 0~9, `/`, `.`, ⌫, 확인). 키 ≥ 48×48px. OS 키보드는 쓰지 않음(문제 가림 방지). 입력창 최대 8자. 분수는 `a/b` 한 줄 입력이며 정답 목록에 동치 표기를 허용(예: `["2","2/1"]`). 정규화: 공백 제거, 앞의 0 제거 |
| input (word) | **영문 소문자 철자만** 허용(한글 단답은 프로토타입 범위에서 mc로 대체). 글자 수 칸(`_ _ _ _`)을 보여 길이 힌트 제공. 내장 QWERTY 3행(키 폭 ≥ 34px·높이 48px, 터치 영역 겹침 없이 키 미리보기 표시). 폭 34px는 44px 권장 기준 미만이므로 가로 모드나 태블릿에서는 확대, 오타 대비 ⌫ 길게 눌러 전체 삭제 |
| order | **탭하여 순서대로 담기** 방식(드래그 금지). 보기 칩을 섞어 세로 1열로 표시(최대 5개, 칩 높이 ≥ 52px), 탭한 순서대로 상단 슬롯 1~N에 채워짐. 담은 칩을 다시 탭하면 빠짐, `되돌리기`와 `확인` 버튼은 하단 우측 엄지 영역. 확인 전에는 자유롭게 재배치, 확인 후는 정답/오답만 판정 |

방치(10초) 타이머는 모든 유형에서 **마지막 터치 이후** 로 계산한다(입력 활동이 있으면 리셋).

## 3. 난이도 적응 (ELO 유사 규칙)

### 3.1 정의
- 문항 레이팅은 작성자가 정한 난이도에서 **고정 변환**: `B(d) = 1000 + 200·(d−1)` → d1=1000, d2=1200, d3=1400. (문항 레이팅은 런타임에 갱신하지 않음. 로그를 모아 작성자가 오프라인 보정)
- 플레이어 숙련도 `P`는 **플레이어 × 과목 팩** 단위로 저장. 초기값 `P0 = 1200`.
- 정답 기대확률: `E = 1 / (1 + 10^((B(d) − P) / 400))`
- 목표 정답 확률 0.75(너무 쉬우면 지루, 너무 어려우면 찍기 유발).

### 3.2 갱신식
- `P ← clamp(P + K·(S − E), 800, 1700)`
- `S`: 정답 1, 오답 0, 회피(첫 회피 제외, 3.3) 0
- `K`: 해당 팩 첫 20문항 32, 이후 16. 회피는 `K/2`.
- 예: P=1200, d2 정답 → E=0.5, ΔP=+16. d1 오답 → E=0.76, ΔP=−24.3.

### 3.3 출제 난이도 선택 (가중 무작위)
각 난이도 d의 가중치 `w_d = exp(−0.5·((E_d − 0.75)/0.15)²) + 0.05` (0.05는 어느 난이도도 완전히 사라지지 않게 하는 바닥값). 가중치 비율대로 d를 뽑고, 그 난이도 안에서 최근 10문항에 나오지 않았고 봉인되지 않은 문항을 유형 비율에 맞춰 무작위 선택.

| P | d1 | d2 | d3 |
|---|---|---|---|
| 1000 | 약 74% | 약 13% | 약 12% |
| 1200 (초기) | 약 75% | 약 21% | 약 4% |
| 1400 | 약 32% | 약 53% | 약 15% |
| 1600 | 약 19% | 약 30% | 약 51% |

(P=1000에서 d3가 12%로 d2와 비슷한 것은 바닥값 0.05 때문이며 의도된 "맛보기" 노출이다. 초기값 1200은 d1 위주로 시작해 첫 판 성공 경험을 확보하고, 정답이 쌓이면 d2·d3 비중이 커진다.)

### 3.4 프로토타입 구현 스케치 (약 14줄)

```js
const B = d => 1000 + 200 * (d - 1);                       // 문항 레이팅 1000/1200/1400
const expect = (P, d) => 1 / (1 + Math.pow(10, (B(d) - P) / 400));
function pickDifficulty(P) {                               // 목표 정답 확률 0.75
  const w = [1, 2, 3].map(d => Math.exp(-0.5 * ((expect(P, d) - 0.75) / 0.15) ** 2) + 0.05);
  let r = Math.random() * (w[0] + w[1] + w[2]);
  for (let i = 0; i < 3; i++) if ((r -= w[i]) < 0) return i + 1;
  return 3;
}
function update(player, d, outcome) {                      // outcome: 1 정답, 0 오답, 'avoid' 회피
  const avoid = outcome === 'avoid';
  const K = (player.n < 20 ? 32 : 16) * (avoid ? 0.5 : 1);
  const S = avoid ? 0 : outcome;
  player.P = Math.min(1700, Math.max(800, player.P + K * (S - expect(player.P, d))));
  player.n++;
}
```

### 3.5 보조 규칙
- 연속 오답 3회 → 다음 출제 난이도를 1단계 낮추고 "잠깐 숨 고르기" 문구(마나 변화 없음).
- 속도(지연 시간)는 갱신식에 사용하지 않는다(1.3).
- 해제 퀴즈(복습)는 ELO 갱신에 반영하지 않고 봉인 큐 규칙(4절)만 적용한다(복습 문항은 이미 노출된 문항이라 숙련도 추정이 편향됨).
- 첫 판은 P0=1200 그대로 시작하며, 튜토리얼 스테이지(웨이브 3개)는 d1 위주로 고정.

## 4. 봉인 카드(오답 복습) 큐

### 4.1 등록
- 오답이면 문항을 해당 팩의 봉인 큐에 `stage = 0`으로 등록한다. 봉인된 문항은 **일반 출제에서 제외**(같은 판에서 다시 만나지 않음).
- 같은 문항이 이미 큐에 있으면 중복 등록하지 않는다(stage만 0으로 되돌림, `lapse+1`).
- 한 판에서 새로 등록하는 봉인은 **최대 5개**. 초과 오답은 "흐린 봉인"으로 처리해 일반 출제 풀에 남기되 출제 가중치 ×2.

### 4.2 간격
판 수는 해당 팩의 **완료된 판(클리어·실패 모두)** 으로 센다. 복습 간격은 직전 사건(등록 또는 직전 복습)으로부터의 판 수이다.

| stage | 다음 복습까지 | 정답 시 | 오답 시 |
|---|---|---|---|
| 0 | 1판 뒤 | stage 1로 | stage 0 유지, `lapse+1` |
| 1 | 3판 뒤 | stage 2로 | stage 0으로 |
| 2 | 7판 뒤 | **해제**(stage 3, 일반 출제 풀 복귀, `mastered` 표시) | stage 0으로 |

즉 등록 후 1판, 그다음 3판, 그다음 7판 뒤에 확인한다(등록 시점 기준 누적 1·4·11판). 하루 3판 기준 약 4일에 해제.

### 4.3 해제 퀴즈 (판 끝)
- 판이 끝나면 복습 기한(`due`)이 도래한 봉인 중 **최대 3개** 를 출제. 우선순위: ① 기한 초과 판 수가 큰 것 ② stage가 낮은 것 ③ 난이도 높은 것.
- 보기 순서는 매번 섞는다(위치 암기 방지).
- 정답 시 **다음 판 시작 마나 보너스 +2/개(최대 +6)**. 오답이어도 추가 감점은 없다.
- `lapse ≥ 3`인 문항("집중 카드")은 출제 전에 해설 카드를 먼저 보여 준다(학습 후 인출).
- 오래 쉬었을 때(14일 이상 미접속): 모든 봉인을 due로 간주하되 한 판 최대 3개 원칙은 유지.

### 4.4 큐 상한
- 팩당 **최대 20개**. 가득 차면 새 오답은 봉인 대신 "흐린 봉인"(4.1)으로 처리하고, 큐 화면에 "먼저 해제해 봐요" 안내(오래된 항목을 밀어내지 않음: 거의 외운 카드를 버리지 않기 위함).
- 한 판에 3개씩 처리해도 3단계를 모두 거쳐야 해제되므로, 큐가 가득 찬 상태에서는 유입이 해제보다 빠르다. 이를 보완하는 확장(웨이브당 1장 인라인 복습, 판 끝 추가 해제 도전)은 변경 제안 5에 기록했다.

## 5. 회피(10초 방치)와 찍기(guessing) 억제

### 5.1 회피 처리
1. 마지막 터치 후 10초가 지나면 문제를 교체하고 `question_avoided`를 기록한다. 마나 변화 없음, 오답 봉인 아님.
2. 회피한 문항은 같은 판의 3~5문항 뒤에 **한 번 더** 출제(난이도 유지). 두 번째도 회피하면 오답으로 처리(봉인 등록, ELO S=0).
3. 첫 회피는 ELO를 `K/2`로 낮게 반영, 콤보는 유지하되 **웨이브당 1회까지만** 보호. 2회째부터는 콤보 리셋.
4. 연속 회피 3회면 자리를 비운 것으로 보고 게임을 **일시정지**하고 이어하기 확인 창을 띄운다(아이가 자리를 떠난 경우 탑 HP 보호).

### 5.2 찍기 억제 — 마나 기대값으로 본 이유
브리프는 오답에 마나 차감이 없다. 따라서 "시도당 마나 기대값"만 보면 찍기도 손해가 아니다(예: mc d2 찍기 = 0.25×4 = 1.0 마나로 0 이하가 아님). 찍기가 손해가 되는 이유는 **시간당 마나 기대값(기회비용)과 콤보 가치**이며, 이는 오답 직후 처리 규칙이 있어야 성립한다.

**오답 후 처리 규칙(확장)**: 오답이면 정답을 공개하는 1초 연출 후 문제 카드를 닫고, 새 카드가 나오기까지 **입력 잠금 2초**(같은 판에서 연속 오답이면 3초, 4초에서 상한). 소환·강화 조작은 잠금 중에도 가능하다(마나 차감이 아니라 문제 카드만의 짧은 대기).

가정: 찍기는 1.5초/시도, 성실 풀이 정확도 0.8·6초(mc), 자동 회복은 모두에게 0.2마나/초로 동일.

| 상황 (마나 m) | 시도당 시간 | 시도당 마나 | 마나/초 | 콤보 3 도달 확률 |
|---|---|---|---|---|
| mc d2 (m=4) 찍기 | 1.5 + 0.75×3 = 3.75s | 0.25×4 = 1.0 | 0.27 | 0.25³ ≈ 1.6% |
| mc d2 성실 풀이(정확도 0.8) | 6 + 0.2×2 = 6.4s | 0.8×4 = 3.2 | 0.50 | 0.8³ ≈ 51% |
| mc d2 두 보기 소거 후 추측(0.5) | 4 + 0.5×2.5 = 5.25s | 0.5×4 = 2.0 | 0.38 | 12.5% |
| tf d2 (m=2) 찍기 | 1.5 + 0.5×2.5 = 2.75s | 1.0 | 0.36 | 12.5% |
| tf d2 성실(정확도 0.9, 3초) | 3 + 0.1×2 = 3.2s | 1.8 | 0.56 | 73% |
| order 3항목 d2 (m=6) 찍기(1/6) | 3 + (5/6)×3 = 5.5s | 1.0 | 0.18 | 0.5% |
| order 3항목 d2 성실(0.8, 10초) | 10 + 0.2×2 = 10.4s | 4.8 | 0.46 | 51% |
| input | 찍기 성공 확률 ≈ 0 | ≈ 0 | ≈ 0 | ≈ 0 |

자동 회복(0.2/초)을 더한 총 마나 획득 속도는 mc d2 기준 **찍기 약 0.47 vs 성실 약 0.70 마나/초**. 여기에 콤보(3: 소환 할인, 5: 공격 버프, 8: 궁극기)를 얻는 확률이 찍기는 0에 가깝다. 그리고 오답 75%는 봉인 큐를 채워 판 끝 복습 부담으로 돌아온다. 따라서 찍기는 마나 차감 없이도 "느리고, 콤보가 없고, 복습 숙제가 쌓이는" 선택이 된다. 절반 지식으로 소거 후 추측하는 것은 합리적 전략이며 그 자체로는 막지 않는다(0.38/초로 성실 풀이보다 낮음).

**유의(밸런싱 필수 조건)**: 잠금 시간을 0으로 두고 1초 안에 찍는다면 mc 찍기가 1.0마나/초가 되어 성실 풀이(0.5)를 이긴다. 따라서 ① 오답 잠금 ≥ 2초, ② 아래 "읽기 하한" 규칙은 유지해야 한다.

**보조 장치**
- 읽기 하한: `0.8s + 0.04s × 문제글자수` 이내에 제출된 답은 "찍기 의심" 플래그를 달고 **콤보 증가에서 제외**(마나는 지급, 정답을 아는 아이를 처벌하지 않기 위함). 로그로 교사 리포트에 집계.
- tf 유형은 마나를 낮추고(2.1), 연속 출제를 2회로 제한.
- 난이도 적응이 연속 오답에서 쉬운 쪽으로 이동(3.5)하여 좌절성 찍기를 줄임.
- 문항 작성 지침: 오답 보기는 유형별 오개념을 반영(`misconception:*` 태그)하여 "그럴듯한 오답"이 되도록 한다.

## 6. 오개념 피드백 시점 결정

**결정: 3단 분리**
1. **즉시(오답 직후, 약 1초)**: 정답만 공개한다(mc는 정답 보기 강조, input은 `정답: 3/4`). 해설 문장은 보이지 않는다.
2. **웨이브 사이 5초 휴식**: 직전 웨이브의 오답 중 최대 1개의 해설 1줄을 하단에 슬라이드로 띄운다(탭으로 닫기, 안 닫아도 자동 사라짐, 문제 풀이를 막지 않음). 오개념 태그가 있는 문항을 우선.
3. **판 끝 모아보기**: 봉인 카드 정리 화면에서 오답 전체의 정답 + 1줄 해설을 보여 준다. 이 화면이 해제 퀴즈 직전 단계이므로 "읽고 → 곧바로 재인출"로 이어진다.

**근거**
- 아케이드 템포: 해설을 오답 직후마다 띄우면 적 진군 중 문제 카드가 멈추는 시간이 늘어 몰입을 해치고 아이들이 해설을 건너뛰게 된다.
- 즉시 정답 공개는 잘못된 답이 굳기 전에 올바른 답을 보게 하는 최소 장치다(교정 없이 오답이 반복되는 것을 방지).
- 지연 피드백은 간격·재인출과 결합될 때 유지에 불리하지 않고, 판 끝 해설은 다음 판 해제 퀴즈와 연결해 효과를 보강한다.
- 수학 절차 오류처럼 즉시 교정이 필요한 경우는 휴식 구간 해설(2)이 가장 이른 안전한 창구다.
- 튜토리얼 스테이지에서는 예외로 오답 직후 해설을 바로 보여 준다(처음 규칙을 익히는 단계라 템포 압박이 낮음).

## 7. 교사/보호자 리포트용 로그 이벤트 최소 목록

공통 필드: `event`, `ts`(ISO), `player_id`(가명 ID), `session_id`, `pack_id`, `pack_version`. 개인정보(실명, 연락처)는 저장하지 않는다. 수집은 보호자 동의 후, 기기 내 저장을 기본으로 한다.

| 이벤트 | 핵심 필드 | 리포트 활용 |
|---|---|---|
| `session_start` | `subject`, `stage_id`, `rating_P`, `start_mana_bonus` | 플레이 빈도·시간대 |
| `question_shown` | `item_id`, `type`, `difficulty`, `source`(stream/release/retry), `rating_P` | 노출량, 난이도 분포 |
| `answer_submitted` | `item_id`, `response`(보기 인덱스·순서 배열·입력 최대 20자), `correct`, `latency_ms`, `suspected_guess`, `combo_before`, `mana_gain` | 정답률, 주제·태그별 약점, 오개념 패턴, 찍기 의심 비율 |
| `question_avoided` | `item_id`, `shown_ms`, `avoid_count_in_session` | 어려워하는 주제, 집중 이탈 |
| `seal_changed` | `item_id`, `action`(created/promoted/reset/released/blurred), `stage_before`, `stage_after`, `lapse` | 복습 진행, 정착 속도 |
| `release_quiz_result` | `item_id`, `stage`, `correct`, `games_since_seal` | 간격 반복 성과, 해제율 |
| `explanation_viewed` | `item_id`, `where`(rest/end), `dwell_ms` | 해설을 읽는지 여부 |
| `rating_update` | `P_before`, `P_after`, `n` | 숙련도 추이 |
| `session_end` | `result`(clear/fail/quit), `stars`, `tower_hp`, `accuracy`, `max_combo`, `questions`, `avoids`, `duration_s` | 판 요약, 하루 학습 시간 |
| `pause_idle` | `reason`(3연속 회피), `duration_s` | 자리 비움 구분 |

리포트 지표 예: 주간 플레이 시간, 팩·태그별 정답률, 회피 비율 상위 태그, 반복 오답 문항과 `misconception:*` 태그, 봉인 해제율, 숙련도 `P` 추이, 찍기 의심 비율.

## 변경 제안

1. **마나 유형 가산 표**
   - 무엇을: 정답 마나를 mc 3/4/5 기준으로 tf −2(최소 1), input +1, order +2로 차등한다.
   - 왜: 찍기 확률이 다른 유형 사이의 보상 균형, 순서 배열·입력의 높은 인지 부담 보상.
   - 영향 범위: 브리프 4절 정답 마나 표, 밸런싱 문서(평균 마나 유입량), 출제 비율.

2. **오답 후 문제 카드 입력 잠금 2초(연속 3·4초)와 "읽기 하한" 콤보 제외**
   - 무엇을: 마나 차감 없이 오답 직후 문제 카드만 잠그고, 너무 빠른 제출은 콤보 증가에서 제외한다.
   - 왜: 마나 차감 없이 찍기를 시간당 기대값에서 손해로 만들기 위함(5.2).
   - 영향 범위: 브리프 3절 루프 2번, UI/UX 문서, 밸런싱(잠금 ≥ 2초 유지 필수).

3. **방치 정의 변경(입력이 있으면 10초 타이머 리셋)과 다단계 문항 15초**
   - 무엇을: "방치"를 마지막 터치 이후 경과로 정의하고, `skill:multi_step` 문항은 15초로 한다.
   - 왜: 수학 다단계 풀이를 끊지 않기 위함.
   - 영향 범위: 브리프 4절 마지막 항목, 프로토타입 타이머, 팩 태그 규약.

4. **회피 처리: 첫 회피는 재출제, 두 번째는 오답 처리, 콤보 보호는 웨이브당 1회, 3연속 회피는 일시정지**
   - 무엇을: 회피를 오답 봉인과 구분하고 어려운 문제 회피 전략을 차단한다.
   - 왜: 회피로 콤보를 지키는 우회와 자리 이탈 시 탑 HP 손실 방지.
   - 영향 범위: 브리프 4절 회피 규칙, 로그 이벤트, 밸런싱.

5. **봉인 큐 보완(상한 20, 판당 신규 5, 인라인 복습과 추가 해제 도전)**
   - 무엇을: 큐가 가득 차면 새 오답은 "흐린 봉인"으로 처리하고, 웨이브당 1장의 due 카드를 일반 문제처럼 섞어 내며(정답 시 복습 통과 인정), 판 끝에 선택형 추가 해제 도전 최대 3개(보너스 대상은 첫 3개만)를 둔다.
   - 왜: 판당 해제 퀴즈 3개로는 유입(판당 수 개의 오답)을 처리하지 못해 큐가 정체된다.
   - 영향 범위: 브리프 3절 6번(복습 루프), 메카닉 문서(웨이브 문제 스트림), 세이브 데이터 구조.

6. **순서 배열형 부분 정답 로그와 보기별 오개념 태그**
   - 무엇을: 순서 배열 오답 시 인접 쌍 정확도를 로그로 남기고(마나는 지급 안 함), 스키마에 보기별 오개념 코드 필드(`distractor_tags`)를 추가하는 안.
   - 왜: 한국사 연표에서 어느 시대를 혼동하는지, 수학에서 어떤 오개념인지 교사 리포트에 정확히 전달하기 위함.
   - 영향 범위: `content/pack_schema.json`(필드 추가), 로그 스키마, 문항 제작 가이드.

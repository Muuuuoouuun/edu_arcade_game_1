## 컨셉 대비 개선

`art-source/defense/atlases/tower-models.png`의 관통 석궁은 큰 활대·팽팽한 시위·긴 관통탄과 오크·황동·청록 깃발로 역할을 구분한다. 기존 전투에서는 석궁 그림이 옆을 향한 채 위쪽 적에게 발사하고, 반동 때 석재 기초까지 움직였다. 실제 PC·390px 전장에서 건설/강화한 화면과 동일 위치의 북쪽 발사 상태를 비교했다.

기존 `towers.blend`의 실루엣과 재질을 보존하면서 **상부 회전, 좌우 활대 관절, 두 시위 구간, 장전탄**을 분리했다. 실제 발사 때 활대와 시위가 풀리고 탄이 레일에서 사라진다. 시위를 다시 당긴 뒤 새 탄이 레일에 놓인다. 석재·오크 기초와 깃발은 움직이지 않는다. Lv.2와 Lv.3 모두 적용하며 최종 강화의 금장·부채꼴 탄 구조를 유지한다. Lv.3의 여러 장전탄은 기존 외형 표현이며 추가 피해나 다중 투사체 규칙을 만들지 않는다.

전투는 실제 모델을 베이크한 2.5D이고 작업실만 실시간 3D다. 연속 회전이나 모든 타워의 동작을 완료한 작업은 아니다.

## 제작 및 재생성

```bash
npm run models:ballista-action
npm run models:ballista-action-lv3
# 렌더 없이 방향별 경계와 시위 끝점 확인
blender --python-exit-code 1 -b --python tools/blender/build_ballista_action.py -- --check
blender --python-exit-code 1 -b --python tools/blender/build_ballista_action.py -- --level 3 --check
```

- 제작 코드: `tools/blender/build_ballista_action.py`
- 편집 원본: `art-source/defense/piercing-ballista-action.blend`, `piercing-ballista-lv3-action.blend`. 기존 `towers.blend`는 보존한다.
- 원본 렌더: 같은 이름의 `art-source/defense/` 폴더 두 곳, 각 640×640 PNG 32개. 8방향 × 장전/발사/시위 당김/재장전 4포즈, Cycles CPU 96샘플.
- 전투: `public/defense/models/ballista-action-{0..7}-atlas.webp`, `ballista-lv3-action-{0..7}-atlas.webp`. 각 1024×256, 256px 셀 4개. Lv.2 합계 313,174바이트, Lv.3 합계 367,120바이트다.
- 실제 3D: `piercing-ballista-action.glb`, `piercing-ballista-lv3-action.glb`. `ballista-release` 0.4초 클립에 활대·시위·탄의 5관절이 들어간다. 120Hz로 시위 끝점을 계산해 포즈 사이의 벌어짐을 줄인다. 작업실의 관통 발리스타/최종 강화 항목에서 재생·복귀·메시 보기·다운로드를 제공한다.
- JSON 두 개에 기준/편집 원본 해시, 납품물 해시, 방향·포즈 경계, 투영된 발사점, 샘플 수·메시/삼각형 수와 재생성 명령을 기록한다. `ballistaMuzzles.ts`, `ballistaLv3Muzzles.ts`도 같은 카메라에서 생성한다.

카메라 `(9,-12,12)`, 목표 `(0,0,2.35)`, 정사영 배율 7.5를 유지한다. 원본 자르기 `(32,24,576,576)`을 전투 셀의 `(12.8,9.6,230.4,230.4)`로 동일하게 줄인다. 방향/포즈별 확대나 기초 반전은 없다. Lv.2 표시 배율 1.16, Lv.3는 1.16×1.025다. 두 등급의 RGBA 픽셀 합은 **16MiB**로, 384px 셀 납품 시 36MiB보다 작다. 실제 기기 GPU 메모리를 측정한 수치는 아니다.

GLB 크기는 Lv.2 1,152,848바이트 / Lv.3 1,336,720바이트다. 삼각형은 23,958 / 27,634개, 메시 27 / 29개, 재질은 각 13개다. 이 비용은 단일 장면의 작업실에만 발생한다.

원본의 전체 배율을 새 관절·활대 끝·탄두 위치에도 적용한다. 원본 좌표를 그대로 월드 좌표로 쓰면 시위가 활대에서 떨어지므로 재생성 검사에서 실제 끝 고리 메시와 시위 끝점이 일치하는지 확인한다. 기존 메시를 강체 관절로 묶었으며 천·시위 물리 시뮬레이션이나 스킨 리그는 아니다.

## 전투 시간과 발사점

기존 `tower.aim`으로 8방향을 고른다. 준비 중에는 장전 포즈를 유지하고, 엔진이 실제 투사체를 생성해 `recoil=.24`를 기록한 뒤에만 발사 포즈를 쓴다. 남은 반동 시간이 `.16` 초과면 발사, `.08` 초과면 시위 당김, 그 이하면 재장전이며 0에서 장전 자세로 돌아온다. 일시정지와 배속은 기존 시뮬레이션을 따른다. 동작 줄이기에서도 조준·발사 단서는 유지하고 관절 포즈 변화는 끈다.

발사 순간 움직인 표적의 위치로 관통 타워의 **표시용 조준**을 갱신하고, 투사체에 `launchAim`을 복사한다. 화살의 기존 추적 `to`는 비행 중 계속 바뀌므로 이 값으로 출발점을 다시 계산하지 않는다. 기존 `sourceLevel`과 새 `launchAim`으로 발사 당시 탄두 위치를 유지한다. 강화·판매·표적 이동이 이미 발사된 화살의 시작점을 바꾸지 않는다.

화살 화면 보정은 기존 `projectileScreenPosition`에서 진행률에 따라 0으로 줄어든다. 출발점 보정이 끝난 뒤에도 계속 날아가는 관통 화살은 실제 속도 방향을 따르도록, 소멸한 보정의 기울기도 제거한다. 실제 충돌 좌표·추적 속도·사거리·피해·관통 수·보상은 바꾸지 않는다. 이전 투사체에 `launchAim`이 없으면 기존 표시를 유지한다.

클립만 수정할 때는 `npm run models:ballista-action -- --reuse-renders` 또는 `npm run models:ballista-action-lv3 -- --reuse-renders`로 기존 렌더를 재사용할 수 있다. 원본 해시·샘플 수와 모든 포즈 경계/발사점이 일치해야 한다. 재질이나 형상을 바꿀 때는 이 옵션 없이 새로 렌더한다.

각 등급의 기본 렌더와 해당 동작 아틀라스 8개가 모두 준비돼야 새 세트를 쓴다. 하나라도 실패하면 그 등급의 기존 모델로, 기본 모델도 실패하면 기존 대체 렌더/삽화로 돌아간다. 한 등급의 실패가 다른 등급이나 물폭탄포 동작을 끄지 않는다. 전투 로더는 GLB를 요청하지 않는다.

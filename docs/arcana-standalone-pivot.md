# 아르카나 독립 모바일 게임 전환

2026-11-09. 사용자 방향은 교육 게임이 아닌 **독립 모바일 판타지 게임**이다. 재미와 조작·전투 피드백, 캐릭터·마을의 시각적 완성도를 먼저 평가한다. 학습·계산·속성은 세계를 이해하는 짧은 개념으로만 녹이며 문제 풀이·암기·수업형 설명을 진행 조건으로 삼지 않는다.

## 실제 전환

- 기본 `/`는 `ArcanaApp`: 전용 키아트 타이틀, 시작/이어가기, 효과음·진동 설정. 교육 허브 헤더·프로필·학습 게임 선택은 없다.
- 마을 → 동료/성장/원정 → 전장 흐름은 기존 캠페인을 이용한다. 동료 카드6종과 해금 조건, 상세 초상·역할·필살기, 무료 편성 확정을 추가했다. 미리보기·취소는 선택을 저장하지 않는다.
- 스테이지 카드에 이름·기후·해금 조건, 난이도에 짧은 설명을 추가했다. 강화 비용·전투 판정·퀘스트 자동 지급은 바꾸지 않았다.
- 기존 관찰노트는 접힌 **전술 힌트**가 된다. 첫3가지 약점과 개념 한 줄을 보여 주고 나머지는 선택적으로 펼친다. 배율·연쇄는 게임 규칙임을 구분한다.
- 기존 허브는 `/arcade.html`, 제작용 모델 작업실은 `/model-lab.html`에 보존한다. 게임 소스 저장소는 `edu_arcade_game_1` 그대로다. 별도 국방 데이터 서비스인 `defense_atlas`에는 변경하지 않았다.

## 모바일 설치판과 저장

`build:mobile`은 아르카나 앱과 별도 3D 변경 훈련 전장을 `dist-mobile`에 생성한다. `android:sync`는 이 결과만 패키징한다. 다른 미니게임의 진입점·코드와 race/art/flags 이미지, 제작 작업실 전용 GLB·모델 시안은 모바일 출력에서 제외한다. 전장 PNG/WebP 아틀라스·폰트와 변경 전장에 필요한 GLB 및 대체 모델은 로컬 패키지에 포함한다.

앱 이름은 아르카나 수비대, 출시 후보 applicationId는 `io.github.muuuuoouuun.arcana`, 디버그는 `.debug`다. 기존 Java namespace는 `.arcade`를 유지하며 실제 MainActivity 클래스와 일치한다. 런처·스플래시는 방패 문장으로 교체했다. 현재 산출물은 개발용 디버그 APK이며 스토어 출시 서명본이 아니다.

동일 웹 주소에서 `playground:defense:v1`·테마·설정·기존 기록을 이어 읽는다. **새 Android 앱은 기존 arcade 설치판과 패키지가 달라 저장을 자동 이전하지 않는다.** 앱 간 이전·클라우드 저장은 미구현이며 앱 삭제·데이터 초기화 시 기록을 잃을 수 있다. 기존 앱을 삭제하거나 데이터를 초기화하는 작업은 수행하지 않았다.

Claude 첫 모델링 요청은 추론만으로 토큰 한도에 도달했다. 설정을 조정한 후 유효한 동작 권고를 받았으며 두 번째 응답도 한도 종료였지만 실제 적용한 권고 본문은 기록에 남아 있다. API가 직접 앱을 실행했다고 주장하지 않는다. 키는 제작 환경에서만 읽었고 프런트엔드나 앱에 넣지 않았다.

타이틀 그림 속 열대 절벽은 향후 세계관 분위기다. 플레이 가능한 지역이 열대까지 늘었다는 의미는 아니다. [원본 생성물과 메타데이터](../art-source/defense/concepts/2026-11-09/pivot/manifest.json), [실제 브론 동작 원리](model-lab-motion/README.md)를 참조한다.

## 2026-11-09 검증과 판단

아래 검사는 독립 앱 전환 당시의 결과다. 2026-11-10 통합 후 모바일 출력은 별도 3D 변경 전장과 필수 GLB를 추가로 포함한다.

- 전체170개 테스트, TypeScript/Vite 웹·모바일 빌드, Android `assembleDebug`·`lintDebug` 통과.
- 360·390·844·1440px에서 타이틀/선택창 가로 넘침 없음. 세로·가로 영웅 확인창, 설정, 마을, 전장, 일시정지 화면을 직접 검토.
- 기존 저장 fixture(1·2클리어,300G)를 사용해 이어가기, 영웅 미리보기·취소 무변경, 무료 출전 확정, 강화 취소/확정과200G 잔액 유지 검증. 이는 자연 플레이 성과가 아니다.
- 네이티브 뒤로가기 전달을 브라우저에서 모의: 대화창 닫기 → 거점에서 타이틀, 전장에서는 일시정지. 백그라운드 신호 후 명시적으로 재개하기 전까지 정지. 실제 기기 버튼 검증과 구분한다.
- 모바일 배포 출력만 별도HTTP로 제공해 타이틀→마을→전장을 실행. 네트워크/이미지 오류 없음. APK 내부의 HTML은 index 하나이며 GLB·허브/제작 페이지·다른 미니게임 이미지가 없음.
- 브론 작업실은 실제 관절 변화·발 고정·정확한 원위치 복구, 반복 공격, 모델 변경, 작은 화면, 동작 줄이기 시 정적 포즈를 확인. 녹화는 실제 Three.js 브라우저 실행이다.
- Opus의 전투 뒤로가기 가설: `DefenseGame`은 battle의 Escape를 항상 `preventDefault`한다. 실제 준비 상태·일시정지/복귀 통합 검사도 통과했으므로 별도 플래그를 만들지 않았다. 모바일 Three 청크 가설도 빌드 출력에 해당 청크가 없어 반려했다.
- 모델 디렉터리 누락 시 빌드 실패는 누락된 필수 게임 자산을 숨기지 않으므로 유지했다. 당시 모바일 원정은 GLB를 요청하지 않았다.

연결된 Android 실기기는 없었다. APK 빌드와 lint가 실제 설치·성능·발열·장시간 안정성을 증명하지는 않는다. 전장 전체 플레이의 난이도·재미, 진행 중 전투 저장, 앱 간 세이브 이전, 스토어 배포는 후속 범위다.

## 다음 개발 기준

1. 실기기 APK 설치 후 세로/가로, 뒤로가기, 백그라운드 복귀, 저장, 터치와 프레임을 확인한다.
2. 첫10분의 재미를 점검한다: 짧은 첫 방어 → 첫 동료의 방문 → 첫 강화 → 넓어진 방어 영역. 학습 미션·정답 보상을 추가하지 않는다.
3. 브론 모션을 실제 전장 크기에서 읽을 수 있도록 아틀라스로 굽거나 렌더 경로를 결정한 후 전투 타이밍과 함께 통합한다.
4. 촌장·전령·보관인, 신규 지역·타워·보스는 현재 구조에 맞춰 하나씩 출시 가능한 단위로 확장한다. 가방·유물은 저장/경제 계약부터 구현한다.

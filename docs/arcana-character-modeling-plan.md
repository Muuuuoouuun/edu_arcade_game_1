# 아르카나 수비대 캐릭터·모델링 제작 기획

2026-11-09. 범위는 현재 숲·설산 8스테이지와 여섯 영웅이다. [전체 이미지 목록](arcana-image-inventory.md)의 프로젝트 이미지 53개, 생성 보관함 이미지 40개와 이전 Higgsfield 시안 4개를 검토하고 실제 아트 매핑 및 전투 코드를 대조했다. 아래의 새 의상·제작 순서는 **제안**이며, 미구현 지역·캐릭터를 확정하거나 기존 전투 규칙을 바꾸지 않는다.

## 결론과 현재 상태

게임에서 중요한 것은 작은 전장에서도 영웅·적·역할과 공격 예고가 구분되는 것이다. 실제 전투는 2.5D 스프라이트이며 그림자·이펙트·투사체는 코드가 그린다. 카메라에서 회전하는 3D 캐릭터가 아니라 **Blender에서 만든 모델을 동일한 정사영 계열의 2D 포즈로 내보내는 방식**을 우선한다. 3D 원본은 편집과 포즈 생성에 사용하고 게임 화면은 기존 방식을 유지한다.

- 이미 있는 것: 여섯 영웅과 늑대의 대기 이미지, 7종의 준비·타격·회복 이미지, 4종 일반 적의 보행/피격 이미지, 보스 2종의 4상태 이미지, 9종의 전투 타워 이미지. 프레임 매핑은 `src/games/defense/art.ts`다.
- 아직 없는 것: 현재 코드에서 쓰는 전신 3D 영웅·캐릭터 리그, 게임에 연결된 3D 무기, 3D 원본에서 일괄 생산한 일관된 영웅 스프라이트. `hero-armory.blend`는 **받침이 붙은 정적 무기 원형**이며 전신 캐릭터가 아니다. 타워·서리 모델도 현재 게임에 직접 연결되지 않았다.
- 장면 제약: 기존 렌더러는 전장 900×600, 영웅 기본 크기 84 월드 단위, 승급 94, 늑대 73을 사용한다. 기존 모바일 배치 계산에서 영웅은 390px 폭 약 35px, 320px 폭 약 28px이다. 이는 목표용 화면 크기이며 실제 기기·배치에 따라 달라진다.
- 현재 걷기는 대기 그림에 이동·기울기·상하 움직임을 합성한다. 공격은 준비/타격/회복의 3포즈이며, 새 보행 프레임을 만들면 매핑과 테스트를 별도로 추가해야 한다. 좌우는 이미지 반전으로 처리하므로 비대칭 의상·무기·문양의 반전도 검토해야 한다.

## 관찰한 화풍과 개선 과제

1. **유지할 것**: 큰 머리와 손·무기, 선명한 외곽, 3/4에 가까운 시점, 따뜻한 금색 금속, 굵은 재질 덩어리와 포화된 속성색. 숲은 올리브·갈색·금색, 설산은 청백색·남색에 금속 대비가 뚜렷하다. 허브의 둥근 3D 마스코트와 레이스 아트는 별도 게임의 톤으로 참고한다.
2. **우선 해결할 것**: 원본 아틀라스는 손그림처럼 복잡한 반면 새 3D 무기·타워 원형은 매끈하고 단순하다. 실루엣과 큰 명도 덩어리를 먼저 맞추고, 손으로 조정한 마모·각진 모서리·재질 구분을 더한다. 절차적 노이즈만 늘려 축소 시 알아보기 어려운 표면을 만들지 않는다.
3. **혼동 위험**: 브론과 카르는 모두 붉은 수염·망치를 가진다. 브론은 공병의 작은 망치·고글·공구, 카르는 큰 전투 망치·넓은 어깨·털 장식으로 차별한다. 이는 실제 작은 화면에서 검증할 가설이다.
4. **속성 혼동**: 이안의 기본 피해는 불인데 이미지의 주색은 청색이다. 파란 모자·수정은 정체성으로 유지하고 불 공격의 준비/타격 이펙트에 따뜻한 색을 분리해 표현한다. 루나의 녹색 마법은 기본 물리 피해와 별도 시각 테마다. 색 자체를 새로운 피해 속성으로 표기하지 않는다.
5. **출처 구분**: 생성 보관함에는 배포본과 동일한 파일 외에 이전 변형·화면 시안이 있다. 18개 비일치 파일은 미사용으로 단정하지 않는다. Higgsfield 결과는 불투명 배경의 콘셉트이며 전투용 프레임이나 동일한 디자인의 증거가 아니다.

## 몬스터·보스와 타워

- **일반 적**: 나무·빙결 기사·돌 갑옷병·서리늑대의 기존 두 보행과 피격 포즈를 기준으로, 먼저 동일 개체의 체격·발 위치·무기 길이를 통일한다. 새싹·금속·절연체는 기본 아틀라스를 사용하므로 별도 모션이 필요할 때만 후속으로 제작한다.
- **고목왕**: 뿌리 다리, 넓은 수관과 보라색 중심부가 기본 식별자다. 체력 절반 이하 돌진과 피해 포즈를 구분하되 게임상 가속 타이밍을 바꾸지 않는다.
- **서리군주**: 왕관·흰 수염·청색 얼음 검·금속 갑옷·망토를 보존한다. 정지/충전/피격/쓰러짐의 높이 차이가 HP 바와 겹치지 않게 한다. 눈보라 충전은 현재 로직의 충전·중단과 맞춰 검토한다.
- **타워**: 기존 9종 2D 아틀라스를 기준으로 3D 화염·관통·물폭탄포와 대조한다. 3D 없는 연발·뇌전·파쇄는 기본 3종의 차이를 유지해 후속으로 설계한다. 서리 수호탑은 독립 콘셉트이며 현재 플레이 분기나 공격 속성이 아니다.

## 제작 순서와 완료 기준

### 0. 기준 확정

- 실제 `atlas.png`, `ranged-motion.png`, `melee-motion.png`, 게임 화면의 이안 포즈를 나란히 보고 카메라·실루엣·손과 무기 위치의 기준을 기록한다.
- 화면 캡처는 같은 3/4 각도·광원·배율에서 하고, 390px과 320px 화면에 실제 크기로 배치한다. 진짜 모바일 기기에서의 성능·터치·명암은 별도로 확인한다.
- 이미지·모델 출처와 사용 권한을 정리하고, 확정 전 생성 시안은 원본을 덮어쓰지 않는다.

### 1. 이안 전신 시범

- Blender의 개별 메시·재질, 손과 지팡이 연결점, 간단한 편집 가능한 리그를 만든다. 기존 무기 원형의 받침과 지지대는 분리한다. 고정된 피부·천·가죽·금속·수정 재료를 분리하고 낮은 화면 크기에 필요한 큰 명암을 우선한다.
- 대기와 기존 3개 공격 포즈를 먼저 내보낸다. 새 걷기 2포즈는 별도 실험으로 만들고, 엔진과 연결하기 전 코드 지원 여부를 결정한다. 프레임에는 투명 배경, 동일 카메라, 발 기준점, 공통 픽셀/월드 배율, 무기 흔들림 여백과 메타데이터를 제공한다. 필요하면 폭이 다른 프레임을 쓰되 몸 크기는 바꾸지 않는다.
- 수락 기준: ① 28–35px 화면에서 기존 이안과 식별 가능 ② 원본 대비 손·지팡이 연결과 발 위치 유지 ③ 준비/타격/회복의 정렬·잘림 없음 ④ 불 이펙트와 발사 타이밍 일치 ⑤ 모바일/데스크톱·일시정지·배속·동작 줄이기에서 오류 없음. 우선 기존 아트와 스위치 가능한 시험 화면에서만 비교한다.

### 2. 공통 제작 규격

- 이안 결과가 수락되면 인간형 골격·재질·내보내기 설정을 공통화한다. 귀·망토·모자·수염·장비는 실루엣별로 조정하며 같은 체형을 강제하지 않는다.
- 각 캐릭터의 `.blend`, 투명 포즈 PNG, 프레임 좌표·기준점·해상도·정면 방향·속성·원본 경로와 버전을 기록한다. 장면용 받침·카메라·조명은 최종 캐릭터 GLB에서 분리한다.
- 품질 확인은 ① Blender 원본 재열기 ② GLB의 내장 재질·연결점 확인 ③ 실제 축소 이미지와 배경 대비 ④ 아틀라스 좌표·인접 프레임 누출 ⑤ 전투에서 이펙트·HP바·그림자와의 겹침 순으로 한다. 삼각형·메모리 한도는 기기 측정 후 정한다.

### 3. 나머지 영웅과 영물

- 브론·카르를 한 쌍으로 제작해 망치와 체형 구분을 검증하고, 리엘의 활·청운의 검과 부적·루나와 늑대를 순서대로 이식한다. 순서는 자산 의존성과 중복 위험을 고려한 제안이다.
- 영웅 무기에는 손 연결점을 정의하고, 늑대는 별도 좌표·별도 공격을 유지한다. 캐릭터별 프레임을 서로 같은 파일 크기나 포즈로 억지 통일하지 않는다.
- 기존 프레임과 새 프레임의 모습이 비슷한 시점·체형·발 기준을 유지해야 하며, 모든 무기를 개별 3D 소품으로 게임 중 렌더링하는 것은 이 단계의 전제가 아니다.

### 4. 적·보스·타워

- 일반 적 4종의 포즈 정렬을 마친 뒤 보스 충전·타격·사망을 제작한다. 충전 표시와 HP 바는 화면 레이어와 함께 확인한다.
- 타워는 각 분기의 실루엣과 발사 방향을 맞춘 뒤 필요할 때만 기존 아틀라스의 선택 프레임을 교체한다. 지면 기준·이웃 프레임·탄환 시작 위치·타워 동결 표현을 확인한다.
- 기존 8스테이지 전투, 저장·보상·해금·브라우저 성능을 회귀 확인한다. 실제 사용자가 재미와 가독성을 확인하기 전까지 결과를 플레이 검증 완료라고 부르지 않는다.

## API와 검토 비용

이번 문서에서는 기존 이미지 6장을 Claude Haiku 4.5로 독립 검토했다(입력 9,456토큰, 출력 1,300토큰). 응답이 출력 한도에서 잘렸고, 실제 없는 이안 설산 버전과 청운의 부채 등을 주장해 해당 내용을 제외했다. 시각 판정과 기준은 원본 이미지와 코드에서 재확인했다. 실제 달러 청구액은 확인하지 못했다. 이번 단계에서 Higgsfield 신규 생성은 하지 않았다.

후속 제작에서 Higgsfield를 쓴다면 이미지 1회당 먼저 견적을 확인하고, 기존 이미지 참조 가능 여부와 모델의 출력·배경을 명시한다. 시안으로 승인된 다음에도 이미지 자체를 애니메이션·3D 모델·게임 아틀라스로 간주하지 않는다.

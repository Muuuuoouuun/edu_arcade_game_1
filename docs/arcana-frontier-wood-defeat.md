# 변경 전장 · 통나무 병사의 처치 반응

녹음 숲 원본과 실제 가로 전장을 비교했다. 치명타 전에는 무게감 있는 목재 병사가 화면에 있지만, 타격한 프레임에 바로 사라져 공격의 결과가 끊긴다. 연결된 OpenAI 이미지 도구로 만든 충격→기울기→착지 참고 보드에서 뒤로 쏠리는 실루엣을 검토했다. 참고 보드는 3D 자산이나 실제 게임 화면이 아니다.

기존 통나무 병사의 관절 GLB와 폴백을 단일 장면의 공유 인스턴스로 재사용한다. 치명타의 실제 위치·피해 원점 방향과 당시 자세를 남겨, 시뮬레이션 시간 0.6초 동안 피격 방향으로 기울고 지면에 닿은 뒤 작아져 사라진다. 평지·경사·교량·수면의 실제 표면 높이를 표본으로 참조한다. 절차적 시각 연출이며 새로운 강체 충돌이나 넉백 이동은 아니다. 기존 편집 `.blend`, GLB, 공통 카메라 렌더 및 WebP는 바뀌지 않았다.

대상은 치명타 즉시 기존처럼 전투 목록에서 제거되고 경험치와 금화를 한 번만 지급한다. 쓰러진 몸은 공격·피해·타깃·건설·이동 판정에 참여하지 않는다. 잔상은 최대 32개로 제한하며 화면 밖에서는 자세를 계산하지 않는다. 일시정지에서는 멈추고 2배속에서 시뮬레이션과 함께 진행한다. 동작 줄이기에서는 쓰러짐을 생략한다. 모델 로딩 실패 시에도 기본 입체 병사에 같은 처리를 적용한다.

## 검증

- 4방향·5개 지형 표본·5개 시점에서 원본/폴백 모델의 지면 접촉, 반대 방향으로 넘어짐, 일시정지 반복의 안정성을 확인했다. 수면·급격한 경계에서의 모든 자세를 보증하는 검사는 아니다.
- 근접·충격파와 발리스타의 실제 치명타, 공격 중 처치, 즉시 대상 제거, 중복 보상 방지, 동시에 40명 처치 시 잔상 32개 제한, 일시정지와 배속을 검사했다.
- PC 1024×576 키보드 및 가로 모바일 844×390 터치에서 실제 진입·이동·스킬·강타·처치·일시정지·2배속·동작 줄이기를 조작했다. GLB 요청 실패 시에도 같은 흐름을 확인했다. 모바일 빌드 결과물에서도 타이틀→거점→솔로 전장 진입과 같은 실제 처치·정지·배속 흐름을 확인했다. 모바일은 Chromium 에뮬레이션이다.
- 실제 WebGL에서 쓰러진 모델이 불투명한 물체 뒤에 가려지는 것을 픽셀로 확인했다. 같은 844×242 Chromium SwiftShader 장면에서 쓰러짐 이전 구현(몸 없음)과 동시에 쓰러진 병사 8개를 각각 3초 예열 후 5초 표본으로 비교한 결과 드로콜 36→45, 삼각형 45,874→54,162, 평균 프레임 간격 80.6→97.0ms, p95 100→116.7ms였다. 표현을 추가한 비용이 있는 소프트웨어 표본이며 실제 휴대기기 성능을 보장하지 않는다.

콘솔에는 기존 Three.js 그림자 모드 대체 경고가 나오며, PC SwiftShader에서는 ReadPixels 동기화 경고도 관찰됐다. 두 경고 모두 수정 전 기준 커밋에서도 재현됐고 이번 범위에서 변경하지 않았다. 페이지 오류와 프레임워크 오류 화면은 없었다.

기존 2.5D 캠페인에는 연결하지 않았다. 혼잡한 화면에서 가려진 쓰러짐의 가독성, 극단적인 단차에서의 자세와 실제 Android/iOS GPU 측정은 후속이다.

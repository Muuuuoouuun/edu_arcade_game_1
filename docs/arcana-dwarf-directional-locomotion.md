## 컨셉과 실제 화면의 차이

`art-source/defense/atlases/melee-motion.png`의 브론은 넓은 어깨, 주황 수염, 큰 망치로 방향과 무게를 보여준다. 기존 전투는 공격만 8방향이고 보행은 한 방향을 좌우 반전했다. 실제 PC·390px 전장에서 북쪽으로 걸어도 얼굴이 측면을 향하고, 공격할 때 갑자기 몸과 망치가 돌아갔다.

기존 강체 관절 보행을 실제 모델의 8방향으로 렌더했다. 위로 걸으면 등과 망치 뒷면, 아래로 걸으면 수염과 가슴이 보인다. 망치·방패 손을 반전하지 않는다. 방향별 중립 자세도 추가해 정지하면 마지막 이동·타격 방향을 유지한다. 기존 체형·재료·공격과 보행 관절 원본을 보존한 **동작 연결 작업**이며, 새 체형이나 스킨 리그 제작은 아니다.

## 재생성과 산출물

```bash
npm run models:dwarf-locomotion
# 렌더 없이 모든 방향의 카메라 경계 검사
blender --python-exit-code 1 -b --python tools/blender/build_dwarf_locomotion.py -- --check
```

- 제작 코드: `tools/blender/build_dwarf_locomotion.py`
- 편집 원본: `art-source/defense/dwarf-locomotion.blend`; 기준 `dwarf-walk.blend`와 `dwarf.blend`는 그대로 둔다.
- 공통 카메라 렌더: `art-source/defense/dwarf-locomotion/`, 384×384 PNG 72장(8방향 × 보행 8 + 중립 1).
- 전투: `public/defense/models/dwarf-locomotion-{0..7}-atlas.webp`, 각각 2304×256, 합계 **392,054바이트**.
- 실제 3D: `dwarf-locomotion.glb`, **1,327,136바이트**, `dwarf-walk` 0.8초 반복 클립. 몸·두 팔·두 다리의 5개 관절 노드가 움직인다.
- 메타데이터: `dwarf-locomotion.json`, 원본/납품물 해시·방향 회전각·포즈 경계·카메라·재생성 명령. 작업실 대체 렌더는 `dwarf-locomotion.png`다.
- 작업실: `/model-lab.html?model=dwarf-locomotion`, 실제 GLB 보행 재생/정지·회전·메시 보기·다운로드. 기존 브론 공격 항목도 유지한다.

기존 방향 공격과 동일한 정사영 배율 6.8을 쓴다. 원본 지면 (192,330), 전투 지면 (128,220), 표시 배율 `1.2 × 6.8 / 5.8`로 같은 지면·몸 크기를 유지한다. 전투에서는 256px 셀로 줄여 8아틀라스의 RGBA 픽셀 합이 **18MiB**다(384px 납품 시 40.5MiB). 이는 픽셀 계산이며 실제 기기 GPU 메모리 측정은 아니다. GLB는 23,190삼각형, 내보내기 기준 55메시/18재질이며, 작업실의 glTF primitive 기준 표시는 56메시다.

## 전투 연결과 대체 동작

`Locomotion.heading`은 실제 이동 벡터를 정규화해 보관하고 정지해도 유지한다. 공격 준비와 실제 발사/타격 때 갱신하므로 준비 중 표적이 이동해도 최종 공격 방향을 정지 자세가 이어받는다. 영웅과 브론 용병 모두 같은 경로를 쓴다. 공격은 기존 `CombatAttack.from/to`와 `hitAt`을 따른다. 피해·사거리·이동 속도·공격 주기·보상은 바꾸지 않는다.

보행 프레임은 기존 64 논리 단위의 이동 거리 주기를 따른다. 공격이 보행보다 우선하며 추가 몸 튀기기나 기울이기를 겹치지 않는다. 일시정지는 거리·방향·공격을 함께 고정하고, 배속은 시뮬레이션을 따른다. 동작 줄이기는 방향을 유지한 중립 자세로 이동을 표시한다. 스킬·돌진은 기존 표시를 유지한다.

새 이미지 8개와 기존 기본 모델 전체가 준비됐을 때만 새 세트를 쓴다. 하나라도 실패하면 기존 8포즈 보행/대기, 기본 모델도 실패하면 기존 삽화로 대체한다. 전투는 베이크 기반 2.5D이고 GLB나 유닛별 WebGL 렌더러를 로드하지 않는다.

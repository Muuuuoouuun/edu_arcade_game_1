# 브론의 8방향 망치 공격

2026-11-06. 컨셉 기반 반복 개발 두 번째 구현 단위다. 원격 main `183f918`의 지역 컨셉과 동료 특성 UI를 통합 개발 브랜치에 보존하고, Claude 기획 `a8d95fe`와 기존 모델·움직임 규격을 참고했다.

## 해결한 차이

`art-source/defense/atlases/melee-motion.png`의 브론은 낮고 넓은 몸과 큰 망치로 준비·타격·복귀를 구분한다. 기존 Blender 모델은 이 동작과 강철·청동 재료를 갖췄지만, 전투에서는 적이 위·아래에 있어도 측면 포즈를 좌우 반전했다. 그러면 타격 궤적과 몸이 보는 방향이 어긋나고 비대칭 망치·방패의 손도 뒤집힌다.

이번 변경은 기존 모델의 실제 방향을 8개로 돌려 각 방향에서 준비·타격·복귀를 렌더링한다. 동쪽부터 화면 시계 방향으로 45도씩 고른다. Blender 지면의 방향은 고정 카메라 투영을 역산하므로 화면 북쪽과 모델의 전방이 맞는다. 새 메시나 스킨 리그를 제작한 작업은 아니다. 기존 컨셉의 주황 수염·큰 망치와 현재 모델의 재료 구분을 유지한다.

## 제작과 전투 연결

```bash
npm run models:dwarf-directions
# 렌더링 없이 24포즈 카메라 여유 확인
blender -b --python tools/blender/build_dwarf_directions.py -- --check
```

- 제작 코드: `tools/blender/build_dwarf_directions.py`
- 편집 원본: `art-source/defense/dwarf-directions.blend`; 원래 `dwarf.blend`와 공격 클립을 보존한다.
- 원본 렌더: `art-source/defense/dwarf-directions/`, 640×640 PNG 24개.
- 전투용: `public/defense/models/dwarf-attack-{0..7}-atlas.webp`, 1152×384 아틀라스 8개. 합계 228,466바이트.
- 메타데이터: `dwarf-directions.json`, 기준 원본 해시·방향 벡터·회전각·포즈 경계·카메라·산출물 해시.
- 실제 3D: 기존 `dwarf-guardian.glb`와 `dwarf-hammer-attack` 클립을 그대로 사용하며 `/model-lab.html?model=dwarf-guardian`에서 확인한다.

모든 방향의 원본 지면 기준은 (320,550), 전투 이미지에서는 (192,330)이다. 카메라 배율을 5.8에서 6.8로 넓혀 뒤쪽 준비 자세까지 담고, 런타임 표시 배율도 같은 비율로 보정해 기존 몸 크기를 유지한다. 포즈별 자르기·확대는 하지 않는다. 384px 전투 납품물의 RGBA 픽셀 합은 약 14.2MB로, 640px 24포즈의 약 39.3MB보다 작다. 이는 픽셀 계산이며 실제 GPU 메모리·프레임 시간 측정은 아니다.

전투에서는 `CombatAttack.from/to`로 방향을 고르고 기존 `hitAt`을 기준으로 포즈를 바꾼다. 피해·사거리·공격 간격은 바꾸지 않는다. 새 이미지에는 좌우 반전과 추가 몸 기울이기·튀기기를 적용하지 않아 공통 발 기준을 지킨다. 이동 중 공격도 같은 원칙을 따른다. 스킬·돌진·보행은 기존 표시를 유지한다.

기본 모델과 방향 이미지 8개가 모두 로딩됐을 때만 새 세트를 사용한다. 하나라도 실패하면 기존 모델 포즈로, 기본 포즈도 실패하면 기존 삽화로 대체한다. 동작 줄이기에서도 공격 방향과 준비/타격 표시는 유지하되 추가 흔들림은 넣지 않는다. GLB를 전투에서 로딩하거나 유닛마다 WebGL을 생성하지 않는다.

## 검증과 남은 범위

자동 검사에서 8방향·수직 방향·좌표 오류, 공통 배율·지면, 일부 이미지 실패 시 전체 세트 대체를 확인했다. 전체 166개 중 165개 통과, 기존 수학 엔진 `(3 × 7) ÷ 5`의 4/4.2 불일치 1건은 남아 있다. 최종 에셋 규격 변경 후 관련 29개 검사와 프로덕션 빌드도 통과했다. 24원본의 투명 경계, 8아틀라스의 크기·해시, 편집 원본 재열기와 공격 관절 클립을 확인했다.

Chromium의 실제 앱과 별도 고정 전투 상태를 함께 검토한다. 고정 상태에서 모든 8방향×3포즈, 이동 중 공격의 추가 몸 변형 억제, 부분 로딩 실패와 동작 줄이기를 확인했다. 이 상태는 비교용이며 실제 플레이 결과로 표시하지 않는다. 실제 전투에서는 PC·모바일 각각 브론 해금/선택 → 전장 입장 → 이동 → 웨이브 시작 → 일시정지/재개 → 1배속/2배속의 준비·타격·복귀를 확인했고 앱 오류는 없었다. 3D 작업실의 망치 강타 재생/복귀도 통과했다. Browser 스킬의 실행 도구가 제공되지 않아 기존 허용된 Playwright/Chromium을 사용했다. 1440×900 및 390×844, 부분 로딩 실패와 동작 줄이기를 포함한다. 실제 모바일 기기 GPU 성능은 미검증이다.

걷기/대기에서 공격으로 넘어갈 때의 연속 회전, 방향별 보행, 어깨·허리의 추가 준비 동작은 후속 범위다. 현재는 기존 3포즈를 방향별로 연결한 2.5D 전투이며 연속 3D 전투나 24프레임 연속 공격 애니메이션은 아니다. 다음 후보는 포탑 재조준·반동과 실제 발사 시점의 연결이다.

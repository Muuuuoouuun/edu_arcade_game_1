# 변경 전장 카르의 경사 접지

녹음 협곡 경사에서 카르의 발은 가장 낮은 점만 지형에 맞췄기 때문에 발바닥 한쪽이 떠 있었다. 기존 동작과 망치 소켓은 유지하고, 접지한 발바닥 면을 실제 높이장의 기울기에 맞춘다. 들린 발에는 원래 포즈를 돌려주고 경사 끝과 교량 단차에서는 보정을 부드럽게 줄인다. 교량 가장자리에 발이 걸칠 때는 발 전체 정점을 검사해 갑판 관통도 방지한다.

기존 모델에서는 발과 종아리가 한 관절에 묶여 있다. 이 관절을 통째로 회전하면 종아리가 몸에서 벌어지므로, 발바닥 면에 전단 변형을 적용해 종아리의 세로축과 상단 연결 위치를 보존한다. 매 프레임 원본 자세를 복원한 뒤 시뮬레이션 상태로 다시 계산하므로 정지 중에 보정이 누적되지 않는다. 무릎과 발목을 각각 푸는 IK는 아니며 매우 급한 절벽이나 임의의 지형에서 모든 자세가 자연스럽다고 보장하지 않는다.

변경은 실시간 3D 변경 전장에 적용된다. 기존 2.5D 캠페인 스프라이트나 전투 판정은 수정하지 않았다. 새 모델이나 베이크를 만들지 않았으며 [기존 카르의 편집 원본과 재생성 명령](arcana-frontier-kar-model.md)을 그대로 사용한다.

## 검증

- 실제 전장 GLB와 협곡 경사의 여덟 방향 정지 자세에서 발바닥 지면 높이 차이의 최댓값은 0.354726에서 0.016780 전장 단위로 감소했다. 여덟 방향 보행의 지지 구간에서 발바닥 중심의 최대 월드 이동은 약 0.000000033 단위였다.
- 교량 양 끝과 옆면의 3,936개 방향·걸음 표본에서 발 전체 정점이 갑판을 관통하지 않았다. 회전 방식의 초기 시안에서 다리가 분리되는 문제가 확인되어 전단 방식으로 교체하고 다리 상단 위치 보존 회귀 검사를 추가했다.
- 경사·단차 연결, 동작 줄이기, 반복 정지 프레임, 망치 소켓, 공격 및 기존 영웅 동작은 `src/games/frontier/heroView.test.ts`에서 검사한다. `npm test`, `npm run build`, `npm run build:mobile`, `npm run models:frontier-kar:check`로 전체 테스트·웹/모바일 빌드·기존 Blender 원본과 GLB를 확인한다.
- 실제 PC와 가로 모바일 전장에서 경사 이동, 일시정지, 배속, 동작 줄이기, 스킬 타격 시점을 조작했다. 모델 로드 실패 시 대체 모델과 조작도 검사했다. 실제 Android 기기에서의 성능은 아직 측정하지 않았다.
- 소프트웨어 WebGL의 가로 844×390 화면에서 적 12명과 보행 영웅을 둔 짧은 비교는 전후 모두 단일 캔버스·45회 렌더 호출·59,150 삼각형, 평균 프레임 간격 약 116ms였다. 이는 기기 성능 수치가 아니라 같은 환경에서 추가 렌더러나 뚜렷한 변화가 없는지 확인한 표본이다.

# 브론의 8단계 망치 공격과 실제 망치 궤적

2026-11-07 KST, `codex/arcana-stage-experience-20261106`의 `1fbe476`에서 이어갔다. main `785154a`의 슬라임 식별 개선을 개발 브랜치에 병합해 보존했다. Claude `c03beb5`의 44회차 결과 화면 기획도 확인했으며 이번 시각 단위와 별도 후속 범위다.

## 컨셉에서 전투로

`art-source/defense/atlases/melee-motion.png`의 브론은 넓은 발로 버티고 망치의 준비·내려치기·회수로 무게를 전달한다. 기존 모델과 방향별 공격은 이미 구현돼 있었지만, 전투에서는 시작 즉시 머리 위 준비 자세가 되고 세 포즈만 거쳐 중립 자세로 급히 돌아왔다. 실제 전장 비교에서 범용 파란 공격 호도 모델의 망치보다 멀리 떨어져 그려졌다.

기존 강철·청동·청록 천·수염·방패의 형태와 재질을 유지하고 **준비와 복귀 사이의 움직임**을 제작했다. 몸통의 작은 하강·전후 이동과 팔꿈치·손목·고개·방패팔의 움직임을 조합한다. 발과 다리 갑옷은 고정한다. 새 보행이나 스킨/IK 리그를 구현한 작업은 아니다.

여덟 방향 모두 실제 원본을 회전해 베이크한다. 망치·방패 손을 반전하지 않고 이전 보행과 같은 카메라·확대율·발 기준을 유지한다. 영웅과 용병 브론에 적용하며, 필살기·대시는 기존 우선순위를 유지한다.

## 전투와 타격 연출

`dwarfHammerFrame`은 기존 공격의 `elapsed`, `hitAt`, `duration`으로 포즈를 고른다. 준비 구간과 타격 이후 구간을 각각 정규화하므로 실제 피해 시점 전에 contact가 나오지 않는다. 첫 구간과 회복 끝에는 중립 프레임을 둔다. 보행 중 어느 발을 내밀었는지에 따른 전신 자세 보간은 후속 범위다.

전투 프레임은 원본의 대표 포즈를 구간별로 보여 주는 2.5D다. 작업실은 0.52초 클립을 보간하는 실제 3D다. 둘이 연속 렌더 방식까지 같다는 뜻은 아니다. GLB는 한 작업실 장면에서만 로드한다.

잔상은 같은 카메라에서 0.19~0.24초의 **망치 돌 중심을 7점 투영**해 만든다. contact 포즈에서만 짧게 표시하고 현재 영웅/용병 위치, 승급 크기, 모바일 유닛 배율을 따른다. 기존 큰 범용 호는 새 세트가 준비됐을 때 끈다. 적 위치의 충격 고리·실제 피해·충돌·범위·넉백·보상은 그대로다. 망치 궤적은 피해 판정이 아니다.

일시정지는 기존 시뮬레이션을 멈추고 배속은 시뮬레이션 시간을 늘린다. 동작 줄이기는 중립/타격 단서만 남기고 새 관절 순환과 잔상을 끈다. 기본 모델과 새 8방향 아틀라스가 모두 준비돼야 교체한다. 새 이미지 하나라도 실패하면 기존 3포즈 방향별 공격을 쓰고, 기본 모델도 실패하면 기존 삽화로 돌아간다.

## 원본·납품·재생성

```bash
npm run models:dwarf-hammer
npm run models:dwarf-hammer -- --check
```

- 제작 코드: `tools/blender/build_dwarf_hammer.py`
- 기준 원본: `art-source/defense/dwarf.blend` — 기존 공격·보행 원본과 납품물은 보존한다.
- 편집 원본: `art-source/defense/dwarf-hammer-sequence.blend`
- 공통 카메라 렌더: `art-source/defense/dwarf-hammer-sequence/`, 384×384 투명 PNG 64장, Cycles CPU 64샘플.
- 전투: `public/defense/models/dwarf-hammer-{0..7}-atlas.webp`, 각 2048×256, 256px 셀 8개. 합계 353,380바이트.
- 작업실: `dwarf-hammer-sequence.glb`, 같은 카메라의 `dwarf-hammer-sequence.png`. 기존 `dwarf-guardian` 항목에서 재생·복귀·메시 보기·다운로드한다.
- 규격·원본/납품물 해시·포즈 경계·궤적: `public/defense/models/dwarf-hammer-sequence.json`
- 전투 궤적 데이터: `src/games/defense/dwarfHammerTrail.ts` — 생성 코드가 같은 좌표에서 재생성한다.

정사영 배율 6.8, 원본 발 기준 `(192,330)`, 전투 셀 `(128,220)`, 표시 배율 `1.2×6.8/5.8`이다. 포즈별 자르기나 크기 보정은 없다. 새 전투 아틀라스의 RGBA 픽셀 합은 16MiB이며 기존 대체 이미지 세트도 로드한다. 실제 기기의 GPU 메모리 측정값은 아니다.

GLB는 1,332,076바이트, 내보내기 메시 객체 48개·23,190삼각형·18재질이며 몸통·고개·상완·팔꿈치·손목·방패팔 6관절의 실제 변환 클립을 포함한다. 원본 전체 FPS는 100, 프레임 1~53이다.

- `.blend` 재열기와 GLB 재가져오기: 고정 발·다리 메시 22개의 변환 오차 0, 시작/끝과 기존 원본 중립 자세의 차이 0. 전 프레임의 최저 꼭짓점은 지면 위 약 0.005 모델 단위였으며, 원본과 GLB의 관절 행렬 차이는 최대 약 0.00000048이었다.

- 제어 상태에서는 영웅/용병 × 8방향 × 9시점 × PC·모바일·동작 줄이기·동작 이미지 실패·기본 이미지 실패 **720조합**을 검사했다. 전체 몸을 중복 흔들거나 손을 반전하지 않는 것, 보행 유지, 스킬/대시 우선순위, 대체 이미지와 GLB 미요청을 확인했다.

- 작업실에서 PC/모바일 실제 GLB 재생·복귀·메시 보기·내려받기·동작 줄이기·GLB 실패 시 PNG 대체를 확인했다. 브라우저에서 49개 메시로 집계되는 것은 다중 재질 primitive 분리 때문이며 삼각형은 23,190개로 같다. 페이지 오류와 가로 넘침은 없었다. 0.24초 부근의 화면은 렌더 주기 때문에 직전 자세가 남을 수 있어 시간별 캡처로 실제 내려치기와 복귀도 확인했다.

모바일은 에뮬레이션이며 실제 Android 기기 성능 검증은 아니다. 첫 자동 검사의 배속 가정과 실패 대체의 선택자 오류는 검사 코드를 수정해 재실행했으며, 초기 로그는 최종 통과 로그와 구분해 남겼다.

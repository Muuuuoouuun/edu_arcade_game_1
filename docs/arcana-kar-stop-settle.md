## 컨셉과 범위

`art-source/defense/atlases/melee-motion.png`의 큰 양손 망치, 흰 모피와 붉은 수염, 넓게 딛는 발을 실제 PC·모바일 화면과 비교했다. 서리늑대 보행·접지, 영웅 방향별 공격·주요 포탑 반동·지형·성문은 기존 완료 작업이다. 카르의 강타 진입·이동 복귀·제자리 회수도 보존하고 **걷다 멈출 때 마지막 걸음에서 즉시 대기로 바뀌는 차이**를 선택했다. 기존 체형·재질 위에 실제 관절 움직임을 제작했다.

시작 작업트리는 깨끗했고 활성 중복 편집은 없었다. 원격 main `2499225`, Claude nice `bf7c1c6`, wizard `e9c1bef`를 확인했다. main의 개별 컨셉 커밋 `c43a0f4`를 `3df3525`로 적용해 영웅·보스·몬스터·전장 원본 6종과 기획을 보존했다. 이 PNG를 3D 모델이나 신규 전장 구현으로 표시하지 않는다. Claude 59회차의 JSON 저장 왕복 검증은 문서 제안으로 검토했다. 기존 Android·모바일 기준 브랜치는 통합 계보에 이미 포함되어 있다. 자동 main 병합은 하지 않았다.

## 실제 동작과 연결

- `kar-stop-0`~`kar-stop-7`: 원래 여덟 보행 자세 각각에서 시작해 기존 대기로 끝나는 0.24초·100fps·11관절 GLB 클립.
- 들린 발을 먼저 옮기고 첫 0.12초와 다음 0.12초의 지지 발을 번갈아 고정한다. 발은 낮은 호로 이동하며 몸통은 지지 발 쪽으로 무게를 받는다.
- 몸통·머리는 0.16초에 안정된다. 망치·모피·수염은 0.035초 늦게 복귀를 시작하고 작은 후속 회전을 남긴다. 출발 자세가 대기에 가까울 때에도 몸보다 늦게 멈춘다.
- 각 시점에 실제 망치의 양손 그립에서 어깨·팔꿈치·팔 길이를 다시 계산한다. 원본 보행·대기 끝점과 양손 연결을 검증한다.
- 영웅·용병의 마지막 걸음과 방향을 시뮬레이션 상태에 저장한다. 용병이 움직이는 주인을 매 틱 따라잡아도 실제 이동량이 있으면 보행을 유지하고, 이동이 멈춰야 정지를 시작한다.
- 전투는 0~0.08초 저장된 마지막 보행, 0.08~0.16초 첫 발 베이크(0.08초), 0.16~0.24초 두 번째 발 베이크(0.20초), 이후 기존 대기를 표시한다. 연속 관절 보간은 실시간 3D 작업실에서 제공한다.
- 재이동·돌진·공격·필살기가 우선한다. 동작 줄이기와 정지 세트 로딩 실패에는 기존 표현을 사용하며 기존 보행·공격 세트의 가용성을 유지한다.

발 고정은 모델 평면 기준이며 지형 IK가 아니다. 기존 0.28초 강타·0.56초 공격, 실제 위치·체력·피해·보상 규칙을 유지한다. 전투는 베이크 2.5D, 작업실은 단일 Three.js 장면이다.

## 산출물과 재생성

```bash
npm run models:kar-stop
npm run models:kar-stop:pose-check
npm run models:kar-stop:check
```

Blender 4.3.2·Cycles CPU 64샘플·FFmpeg. `kar-barbarian-walk.blend`와 `kar-barbarian.blend`를 읽는다.

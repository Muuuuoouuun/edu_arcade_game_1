# 루나의 마지막 걸음에서 접지된 지팡이 시전으로

2026-11-08 · 컨셉 개발 49회차. 기준 `3bcb659`, 브랜치 `codex/arcana-stage-experience-20261106`.

## 컨셉과 선택

`art-source/defense/atlases/ranged-motion.png` 넷째 행의 큰 여우 귀·구리색 머리·초록 망토·가지 지팡이와 현재 PC/모바일 화면을 직접 비교했다. 서리늑대 체형·보폭·피격, 브론/리엘/이안/청운의 전환은 이미 제작됐다. 루나는 걷던 발과 지팡이가 곧바로 고정된 준비 자세로 바뀌어 무게를 받는 과정이 없었다. 이번에는 원래 체형·재료를 유지하고 **보행→시전 준비**를 실제 관절로 연결한다.

작업 시작 때 작업트리는 깨끗했고 다른 활성 작업은 없었다. main `2eabc76`, Claude nice `bf7c1c6`, wizard `d6e3b6c`는 이전 회차와 같았다. 최근 Claude 56회차는 기존 보상 안내의 정정 기록이다. 열린 PR 81의 번개 표적 변경은 별도 범위다. 기존 지형·성문·브론·통나무 병사·청운 정지를 포함한 통합 계보와 실행 중 Vite를 보존했다. 세계관 제작 명세의 발 접지·공격 시점·시뮬레이션 시간 규칙을 적용했다.

## 실제 동작과 전투 연결

- `luna-entry-0`~`luna-entry-7`: 여덟 보행 자세에서 시작하는 **0.33초·100fps·17노드** 실제 GLB 클립이다. 첫 0.10초를 새로 연결하고 이후 시전은 기존 원본과 일치한다.
- 먼저 옮길 발을 출발 높이·전후 위치로 선택한다. 첫 0.05초는 반대 발을 고정하고, 다음 0.05초는 내려놓은 발을 고정한 채 나머지 발을 정리한다. 몸은 지지 발 쪽으로 체중을 받는다.
- 몸·머리·여우 귀·머리카락·잎 망토·앞자락·양팔·지팡이를 같은 시작 자세에서 잇는다. 양팔은 공통 어깨·팔꿈치·손 끝점으로 다시 계산해 소매와 손이 벌어지는 문제를 방지한다.
- 가지 지팡이의 실제 `cast-socket`을 8방향×8출발 걸음×3시점으로 투영한 **192개 소켓**을 준비 광원에 사용한다. 발사 소켓·0.15초 발사·0.33초 공격 길이는 기존 값을 유지한다.
- 공격을 시작할 때 영웅/용병의 보행 프레임을 한 번 저장한다. 0~0.025초는 저장된 보행, 0.025~0.065초는 0.04초 베이크, 0.065~0.10초는 0.08초 베이크, 이후 기존 시전으로 이어진다.
- 용병이 주인을 따라잡는 틱에도 실제 이동량이 있으면 보행으로 기록한다. 준비 화면에서 정지한 뒤에는 시각 속도를 0으로 정리하고 불필요한 시뮬레이션 갱신을 멈춘다.
- 제자리 시전·필살기·돌진·동작 줄이기는 기존 표현을 따른다. 새 진입 이미지 실패에는 기존 시전/보행을 사용한다. 기본 시전·보행 세트 실패는 기존 삽화 대체를 유지한다. 기존 이동 명령의 미발사 공격 취소 규칙도 유지한다.

모델 평면 기준 발 접지이며 월드 좌표 발 고정·지형 IK가 아니다. 영웅 이동을 멈추거나 발사 시간을 늦추지 않는다. 전투는 베이크 2.5D이며 작업실은 단일 실시간 3D 장면이다. 지팡이 회수→현재 걸음과 연속 방향 전환은 후속 범위다.

## 검증과 한계

외부 증거 `/tmp/arcana-hourly-20261108-1739/`에 편집 전 기준·소유 브랜치·범위·수용 기준·미완료 기록부터 남겼다.

- 전체 322개 중 321개 통과. 기존 수학 게임 `(3×7)/5`의 4/4.2 실패는 기준 커밋에서도 재현했다. 타입 검사·프로덕션 빌드 통과.
- 초기 기존 루나 테스트가 기본 16장과 선택적 진입 8장을 함께 세었다. 기본 cast/walk만 검사하도록 분류를 바로잡고 별도 진입/실패 테스트를 추가했다. 새 회귀는 없다.
- GLB 저작 272시점·보간 1,064시점에서 보행 시작 오차 최대 `5.97e-8`, 기존 시전 오차 `9.93e-8`, 지지 발 오차 `1.12e-16`, 발사 소켓 오차 `8.83e-8`, 최소 발바닥 높이 약 `0.005`를 확인했다. 양팔 연결 최대 오차 `0.00156`은 공통 렌더 기준 0.09px 미만이다. 144개 해시 통과.
- `.blend` 재열기에서 153메시×8시작/끝의 월드 변환이 원본과 정확히 일치했다. PNG 128장·WebP 128셀의 최소 투명 여백은 14px이고 빌드 파일 11개가 원본과 동일하다.
- 스테이지 1·4·5·8×영웅/용병 8게임·14,400스텝에서 용병의 시각 속도와 루나 공격/투사체의 `walkEntry`만 제외한 상태가 기준 엔진과 동일했다. 체력·피해·보상·공격·이동·동료 늑대·배속·일시정지·돌진·필살기를 포함한다.
- 실제 PC 1440×900·390×844 터치 UI로 지역·스테이지 선택, 이동·웨이브·자연 이동 시전, 1/2배속, 일시정지·동작 줄이기·복원·재개를 조작했다. 여덟 보행 프레임·진입·발사·회수를 관측했고 오류·가로 넘침·진입이 발사와 겹치는 현상은 없었다. 첫 자동검사는 방문자 안내를 아직 보지 않은 저장 상태 때문에 중단됐다. 전투 검사에 맞게 모두 확인한 저장 상태로 다시 실행했으며 게임 코드는 바꾸지 않았다.
- 작업실의 잘못된 접근성 이름을 `시전 진입 출발 걸음`으로 수정했다. PC 8클립, 390/320px 각 3클립의 실제 재생 전후 캔버스 변화·끝 자세·메시 보기·회전·시점 초기화·동작 줄이기·단일 캔버스가 통과했다. GLB 실패 시 PNG를 렌더 이미지로 표시하고 재생을 끄며 기존 이안 정지도 유지한다.
- 컨셉·공통 렌더·동일 조건 PC/모바일 전후 화면·실제 모바일 전투·모바일 작업실을 직접 확인했다. 모바일은 Chromium 터치 에뮬레이션이다.

- 실제 `DefenseBoard`에서 영웅/용병×8방향×8출발 걸음과 준비·발사·회수 시점을 PC·390/320px·동작 줄이기·진입/기본 시전/보행/다른 영웅 정지 이미지 실패로 검사한 **3,072조합**이 최종 통과했다. 실제 광원 위치도 메타데이터 소켓과 일치하며 페이지 오류·가로 넘침·전투 GLB 요청은 없었다.
- 첫 화면 조합 실행은 작업실 코드 수정에 따른 개발 서버 새로고침으로 중단됐다. 소스 수정이 끝난 뒤 전체 3,072조합을 다시 실행했고 통과했다. 초기 로그와 최종 로그를 함께 보존했다.

지팡이 시전에서 현재 보행으로 복귀, 제자리 회수, 연속 방향 전환, 월드 좌표 발 고정과 실제 Android 성능은 남아 있다. 다음 후보는 루나의 시전→보행 복귀다. 예약 설정 조회·변경 및 Claude API 호출은 하지 않았다.

원격 main `2eabc76`, Claude `bf7c1c6`·`97ef02c`와 진행 작업을 확인했다. 통합 계보의 지형·성문·브론·통나무 병사·늑대와 완료된 영웅/포탑 동작을 보존했다. PR #81의 번개 표적/연쇄 작업은 이번 범위와 분리되어 있다.

## 컨셉 대비 개선

[원본 컨셉](../art-source/defense/atlases/ranged-motion.png)의 큰 모자·남색 코트·금장 장화·수정 지팡이를 현재 PC/모바일 전투와 비교했다. 체형을 다시 만드는 대신, **걷다가 멈추면 발이 곧바로 대기 위치로 바뀌던 문제**를 선택했다. 기획의 이동→정지 발 접지 원칙을 실제 관절 동작으로 연결한다.

기존 보행의 8개 자세 각각에서 시작하는 0.24초 정지 클립을 만들었다. 떠 있는 발(양발 접지 시 뒤쪽 발)을 먼저 내려놓고, 그 발로 지지하면서 반대 발을 대기 위치로 옮긴다. 몸통은 지지 발 쪽으로 체중을 정리하고 팔·망토는 기존 보행 위치에서 대기로 돌아온다. 발을 옮기는 동안 반대 발의 위치는 고정한다. 기존 메시·재질·보행·시전 원본을 덮어쓰지 않는다.

전투에서는 마지막 **시뮬레이션 보행 위상**을 잡아 0–80ms 동안 기존 보행 이미지를 유지하고, 80–160ms/160–240ms에 두 중간 자세를 표시한 뒤 기존 대기로 복귀한다. 8방향·영웅/고용 동료를 지원한다. 벽시계 대신 시뮬레이션 상태를 사용하므로 일시정지와 배속에 따른다. 준비 화면의 유휴 최적화에서도 정지 상태만 마저 진행한다. 재이동·돌파·공격·필살기가 우선하며, 동작 줄이기나 불완전한 이미지 로딩에서는 기존 대기를 사용한다. 이동 좌표·속도·공격 시점·피해는 바꾸지 않는다.

## 산출물과 재생성

- [편집 원본](../art-source/defense/ian-stop.blend): 기존 개별 메시·재질·베벨과 8개 관절의 8가지 액션 세트. `Ian stop N / 관절 이름`을 같은 N으로 지정해 편집한다. 기본 N=0, 모든 세트는 fake user로 보존한다.
- [실제 GLB](../public/defense/models/ian-stop.glb): `ian-stop-0`…`ian-stop-7`, 각각 100fps·25키 시점·0.24초. 21,122 삼각형·36 묶음 메시(작업실에서는 37개 메시 프리미티브)·14 재질. 8개 클립이 하나의 메시 집합을 공유한다.
- [공통 카메라 PNG](../public/defense/models/ian-stop.png), [128개 원본 PNG](../art-source/defense/ian-stop-frames/): 384×384, 정사영 6.8, 지면 (192,330).
- 전투 `ian-stop-{0..7}-atlas.webp`: 방향마다 8출발 자세×2중간 자세, 3072×192, 셀 192×192, 지면 (96,165). 기존 이안과 표시 배율 동일. 파일 합계 약 495KB, RGBA 디코드 픽셀 합 18MiB. 실제 모바일 GPU 측정값은 아니다.
- [메타데이터](../public/defense/models/ian-stop.json): 원본·컨셉·생성기 및 산출물 해시, 렌더 설정, 클립, 방향별 자세 경계, 실제 장화 밑창 높이·지지 발 이동량.
- [생성기](../tools/blender/build_ian_stop.py): `npm run models:ian-stop` — Blender 4.3+, ffmpeg. 렌더 없이 원본 접지 검사: `npm run models:ian-stop -- --check`. 내보낸 실제 GLB의 시작/끝/접지 검사: `npm run models:ian-stop:check`.
- 모델 작업실의 **이안 · 발 디디며 멈추기**에서 출발 걸음 1–8을 선택하고 재생한다. 기존 단일 WebGL 장면을 사용한다. GLB 실패 시 PNG라고 표시하고 재생을 비활성화한다.

## 검증

- Blender 8클립×25시점: 지지 발 이동량 0, 장화 밑창 최소 Z 약 0.005. 모든 베이크의 화면 경계 검사.
- Three.js로 실제 GLB 200시점 검사: 8클립 시작은 기존 보행의 각 자세, 끝은 기존 시전 원본의 중립과 일치. 지지 발 고정·밑창 비관통 확인.
- 전체 테스트 246개 중 245개 통과. 유일한 실패는 기준 커밋에서도 동일하게 재현되는 수학 게임 `4 !== 4.2`. 디펜스 관련 신규/기존 검사는 통과한다. TypeScript 및 프로덕션 빌드 통과.
- 기준 엔진과 2스테이지×3난이도×1,800스텝 비교: 새 정지 표시 상태만 제외하면 이동·피해·탄·자원 등 상태가 동일하다.
- 실제 Chromium PC 1440×900 / 터치 모바일 390×844 조작: 보행 8프레임, 정지 3단계, 일시정지, 1·2배속, 재이동, 시전 타격 시점, 동작 줄이기, 재시작 확인. 정지 표시 구간 관측 PC 약 260/138ms, 모바일 약 227/140ms(1배/2배, 화면 게시 시점 포함).
- 실제 DefenseBoard에서 영웅/동료×8방향×8출발 자세, 공격·필살기·돌파 우선순위와 부분 이미지 실패 대체를 확인했다. 작업실은 PC/모바일 8클립 선택·재생·중립 유지·동작 줄이기·GLB 실패 대체를 확인했다.
- 전후 화면·원본 비교·검사 로그는 저장소 밖 `/tmp/arcana-hourly-20261107-1938/`에 있다. 모바일 검사 초기 시간 초과는 건설 선택 영역을 누른 테스트 경로와 개발 서버 갱신을 분리해 재검사했다. 제품 코드 회귀로 집계하지 않는다.

## 남은 범위

전투는 3단계 베이크여서 연속 관절 보간은 아니다. 출발 자세는 마지막 시뮬레이션 위상이며 30Hz 화면 게시 직전 자세와 한 단계 차이가 날 수 있다. 장화와 다리는 기존 강체 관절 구조를 유지하며 무릎 IK를 추가하지 않았다. 보행 중 공격으로 넘어갈 때의 전신 연결과 다른 영웅의 정지 동작은 후속 후보다. 실제 Android 기기 성능 검증은 미실행이다.

이번 실행은 개발 루프 1회이며 예약 생성·변경, Claude API 호출, main 병합, 서비스 배포를 하지 않았다.

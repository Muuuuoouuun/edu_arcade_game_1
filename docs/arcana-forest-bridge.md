# 숲 마을 교량의 석조 아치와 전경 가림

2026-11-06 컨셉 개발 다섯 번째 회차. 기준은 `ed6ded1`이며 원격 main `40d2289`와 Claude `22fe3ac`의 42회차 기획을 확인했다. 나무·서리늑대 보행, 브론 방향별 공격, 물폭탄포 Lv.2/3 조준은 통합 브랜치의 완료 작업으로 보존한다. Claude의 main 기준 4프레임 보행 제안을 이미 완성한 8단계 보행에 덮어쓰지 않는다.

## 컨셉과 구현

`art-source/defense/concepts/2026-11-06/verdant-heart.png`의 작은 다리는 두꺼운 석조 아치와 받침으로 무게를 전달한다. 기존 전장의 다리는 얇은 목재 판과 별도 SVG 앞 난간이었다. 같은 통로 위치에 석조 교대 2개, 실제 구멍이 있는 아치, 목재 하중 보·상판·기둥·대각 버팀대를 제작했다. 기존 목재의 성격은 유지하면서 석재와 지지 구조를 추가했다. 미세 장식을 늘리기보다 상판 아래의 빈 공간과 두꺼운 받침이 읽히게 했다.

앞 난간은 같은 Blender 메시와 카메라로 따로 렌더한다. 유닛과 같은 Y 정렬에 넣어 발 위치가 난간 뒤/앞으로 이동할 때 가림 순서가 바뀐다. 두 숲 지형에서 사용하고 설산 지형은 그대로 둔다. 강 아래의 기존 도로 이미지 일부를 제거해 아치 구멍으로 배경 물이 보인다. 새 지형과 전경이 모두 로드돼야 전환하며, 하나라도 실패하면 기존 베이크 지형과 SVG 난간으로 돌아간다. 기존 지형도 실패하면 원래 벡터 도로·교량 삽화를 사용한다.

이 작업은 시각적 지형 개선이다. 경로·영웅 이동·공격·충돌·보상은 바꾸지 않았다. 영웅의 자유 이동을 교량으로 제한하거나 강을 통행 금지로 만드는 규칙은 별도 작업이다. 전투는 계속 2.5D이며 교량 GLB는 작업실에서만 로드한다.

## 제작과 납품

```bash
npm run models:bridge
```

- 제작: `tools/blender/build_terrain.py --bridge`, `forest_bridge.py`, `export_bridge.py`.
- 편집 원본: `art-source/defense/forest-bridge.blend`, `terrain-forest-{single|expanded}-bridge.blend`.
- 공통 카메라 PNG: 위 이름의 PNG와 `forest-bridge-front.png`.
- 전투: `public/defense/terrain/forest-{single|expanded}-bridge.webp`, `forest-bridge-front.webp`, `bridge-manifest.json`.
- 작업실: `public/defense/models/forest-bridge.glb/.png/.json`, `/model-lab.html?model=forest-bridge`.
- 기존 지형 `.blend`·PNG·WebP·manifest는 대체 표시와 재현 기준으로 보존한다.

카메라 `(0,-900,1200)`, 목표 원점, 정사영 폭 900, 원본 1800×1200을 유지한다. 상판의 논리 중심 Y는 430/235이며 실제 경로 좌표와 동일하다. 높은 부품은 상판을 기준으로 수직으로 쌓아 기둥과 받침이 기울지 않게 했다. 전경은 원본에서 `(1192,768,328,200)`을 잘라 논리 좌표 `x=596, y=교량중심-46, 164×100`에 배치한다. 정렬 기준은 `교량중심+25`다. 포즈별 재자르기나 별도 카메라를 사용하지 않는다.

원본은 120개의 편집 가능한 메시다. GLB는 재질·앞뒤 묶음으로 합쳐 14개 glTF 메시, 10,104삼각형으로 내보낸다. 작업실에서 재질별 프리미티브가 나뉜 측정값은 Three.js 메시 18개·재질 5개·그리기 호출 38회다. 이는 실기기 프레임 성능 보증이 아니다. 작업실은 정적 구조물에 공격 재생 버튼을 표시하지 않으며 회전·메시 보기·다운로드를 제공한다. Blender의 절차적 나뭇결은 원본과 전투 이미지에 남고, GLB에는 기본색·거칠기를 갖는 PBR 재질을 사용한다. 소스 원본의 재질 노드는 지우지 않는다. 최종 GLB는 601,476바이트, 전경 WebP는 4,712바이트이며 숲 지형은 단일 54,944·두 갈래 90,780바이트다.

## 검증

- 4종 기존 지형과 새 숲 지형의 경로 좌표, 파일 해시, 카메라·전경 배치 계약을 확인한다. 새 아치의 중앙은 실제 광선 검사에서 비어 있고 교대와 윗돌은 막혀 있다. GLB 재가져오기, 원본 120/전경 20개 메시, 카메라 안의 전체 정점, 정적 GLB의 애니메이션 없음도 검사한다.
- 전체 자동 검사 174개 중 173개 통과. 기존 수학 엔진의 `(3×7)÷5` 정답 4/4.2 오류 1건은 남아 있다. 교량 검사 4개와 프로덕션 빌드 통과.
- Playwright/Chromium의 PC 1440×900·모바일 390×844에서 앞뒤 가림, 논리 좌표 클릭/터치, 단일/두 갈래 숲·설산 전환, 늦게 도착한 이미지, 전경/지형/전체 이미지 실패를 확인한다. 실제 전투에서는 건설·웨이브·브론 교량 횡단·일시정지/재개·배속을 조작한다. 모바일 확대 상태의 화면 밖 목적지는 전체 보기로 전환한 뒤 누른다.
- 실행 중 동작 줄이기 변경에서 MediaQueryList의 상태는 바뀌어도 이벤트가 전달되지 않는 경우를 재현했다. 작업실 렌더 루프도 설정 변화를 확인해 자동 회전과 버튼 상태를 동기화한다. 정적 구조물에 가짜 반동을 추가하지 않는다. 교량에서 물폭탄포로 전환한 뒤 발사/복귀, 설정을 양방향으로 변경한 뒤 버튼 상태 복구, GLB 실패 시 PNG 렌더로 명시된 대체 표시도 확인했다.
- 제작 중 교대와 상판의 겹친 면이 검게 보이는 문제, GLB의 절차적 재질이 흰색으로 빠지는 문제를 수정했다.

실제 Android GPU 성능·촉감과 사용자 재미는 검증하지 않았다. 다음 건축 후보는 마을 성문 앞 진입부의 크기·조명·유닛 가림이며, Claude의 몬스터 쓰러짐 포즈는 별도 동작 후보로 남긴다. 예약 설정은 이번 회차에서 변경하지 않았고 Claude API 호출도 하지 않았다.

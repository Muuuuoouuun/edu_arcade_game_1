원격 main `2eabc76`, Claude `bf7c1c6`·`d0484f2`, 깨끗한 단일 작업 트리와 실행 중인 작업을 확인했다. Claude 52회차의 정예 클리어 저장 기획과 PR #81의 번개 표적 작업은 별도 범위다. 통합 지형·성문·통나무 병사·영웅 전환, 기존 서리늑대의 체형·접지 보행·일반 피격·쓰러짐을 보존했다.

## 선택한 차이와 실제 동작

[은서리 늑대 컨셉](../art-source/defense/concepts/2026-10-29/beasts/silverfrost-wolf.png)의 긴 주둥이·회백색 갈기·짙은 발과 실제 PC/모바일 화면을 비교했다. 보행·일반 피격·쓰러짐은 방향을 유지하지만, **넉백 중에는 고정 옆모습으로 바뀌고 전체 이미지가 기울어 발이 뜨는 차이**가 남아 있었다.

기존 여덟 보행 자세에서 시작하고 같은 자세로 복귀하는 실제 0.54초 관절 클립을 만들었다. 몸통을 낮추고 뒤로 체중을 옮기며 앞발은 앞으로, 뒷발은 뒤로 조금 넓혀 버틴다. 들려 있던 발은 낮아지고 무릎·발목이 굽혀지며 발바닥은 평평함을 유지한다. 목·머리·턱·꼬리가 함께 반응하고, 힘이 줄어들면 원래 걸음으로 돌아온다. 기존 실루엣과 재질을 사용한다.

첫 GLB의 100fps 선형 보간에서는 발 목표 오차가 0.00237까지 커져 검사를 실패했다. 관절 키를 200fps로 촘촘하게 만들어 최대 오차를 0.000635 미만으로 줄였다. 허용치 0.001은 늘리지 않았다. 접지는 모델 내부의 평면 기준이며 전장 좌표에 발을 고정하는 IK는 아니다.

## 전투 연결

엔진이 이미 넉백 중 유지하는 `walkHeading`과 `walkCycles`를 그대로 사용한다. 개체별 위상과 모바일 크기를 기존 방향 보행 함수로 계산한다. 별도 타이머나 전투 상태 필드를 추가하지 않고 현재 `knockVelocity`에 따라 자세를 선택한다.

| 현재 넉백 속도 | 전투 자세 | GLB 베이크 시점 |
| --- | --- | --- |
| 65 초과 | 낮은 몸으로 강하게 버티기 | 0.10초 |
| 22 초과–65 이하 | 무릎과 목을 펴며 힘 완화 | 0.30초 |
| 7 초과–22 이하 | 원래 걸음에 가까워지는 복귀 | 0.46초 |
| 7 이하 | 기존 보행/일반 피격 규칙 | 기존 이미지 |

속도는 기존 엔진의 감쇠를 따르므로 약한 넉백은 중간/복귀 자세부터 시작한다. GLB의 0.54초를 전투 타이머로 강제하지 않는다. 피해·진행 거리·마찰·넉백 면역·공격 시점·보상은 그대로다.

8방향의 렌더를 사용하고 전체 이미지 기울기·흔들림·중복 확대·좌우 반전을 제거했다. 빠른 밀림의 지면 잔상도 같은 방향을 따른다. 보행과 카메라·크롭·지면 기준·표시 배율을 공유하며 체력바 위치를 유지한다. 동작 줄이기는 밀리는 동안 같은 방향의 원래 걸음 자세로 고정하고 잔상을 숨긴다.

새 버티기 이미지가 실패하면 기존 넉백 표현으로, 방향 보행이나 기본 모델이 실패하면 기존 단계별 대체 이미지로 돌아간다. 새 이미지 실패가 일반 피격·쓰러짐을 막지 않는다. 전투는 베이크 2.5D이며 GLB 요청이나 유닛별 WebGL을 추가하지 않았다.

## 산출물과 재생성

- [편집 원본](../art-source/defense/frost-wolf-brace.blend): 기존 66메시·재질, 17개 애니메이션 관절. 각 관절에 같은 N의 `Frost wolf brace N / 관절 이름` 액션을 지정한다. N=0–7이며 모두 fake user로 보존한다.
- [실제 GLB](../public/defense/models/frost-wolf-brace.glb): 메시 집합을 공유하는 `frost-wolf-brace-0`…`frost-wolf-brace-7`, 각각 0.54초·200fps·109키 시점. 66메시·2,300삼각형·6재질, 599,864바이트. 정지 이미지 평면 모델이 아니다.
- [공통 카메라 렌더](../public/defense/models/frost-wolf-brace.png), [원본 PNG 192장](../art-source/defense/wolf-brace/): 8방향×8걸음×3자세, 384×384. 기존 접지 보행과 같은 조명·카메라다.
- `frost-brace-{0..7}-atlas.webp`: 방향마다 8열×3행·1536×576. 가로는 출발 걸음, 세로는 버티기 단계. 셀 192×192, 크롭 (4,20,184,152). 합 654,108바이트, 디코드 RGBA 픽셀 합 27MiB. 실제 GPU 메모리 측정값은 아니다.
- [메타데이터](../public/defense/models/frost-wolf-brace.json): 제작 872시점의 발 목표/바닥 높이, 클립·속도 경계·카메라·지면·방향별 경계, 원본/생성기/산출물 해시.
- 작업실 `/model-lab.html?model=frost-wolf-brace`: **서리늑대 · 밀림 버티기**, 출발 걸음 1–8·재생·복귀 자세 유지. 기존 단일 3D 장면과 GLB 실패 시 PNG 대체를 사용한다.

```bash
npm run models:wolf-brace             # Blender 4.3+, ffmpeg, 전체 재생성
npm run models:wolf-brace:pose-check  # 렌더 없는 관절/접지 검사
npm run models:wolf-brace:check       # 납품 GLB 보간·시작/복귀·해시 검사
```

## 검증

- GLB 1,736시점: 시작/복귀의 기존 보행 메시 변환 오차 최대 6.32e-7, 발 목표 오차 0.000635 미만, 발 기울기 5.80e-7라디안 미만. 보간 중 최소 메시 높이 -0.000207로 0.001 허용치 안이다. 제작 872키 시점에서도 발/전체 메시 검사를 수행했다.
- `.blend` 재읽기: 66메시×8시작/복귀 자세가 각각 원래 보행과 최대 2.39e-7 이내로 일치한다. 206개 해시·PNG 192장·WebP 192셀의 크기/투명 경계/크롭·dist 11파일 일치 검사 통과. 최소 알파 크롭 여백 1픽셀.
- 아트 테스트 95개 통과. 전체 276개 중 275개 통과. 실패 1건은 기준 커밋 복사본에서 재현된 수학 게임 `(3×7)/5`의 `4 !== 4.2`다. 타입 검사·프로덕션 빌드 통과.
- 스테이지 1·4·5·8×영웅/용병, 총 14,400스텝의 상태 전체가 기준 커밋과 동일했다. 비교에서 제외한 필드는 없다.
- 60Hz의 2/4/6틱 화면 게시와 모든 시작 오프셋에서 강한 넉백의 세 단계가 표시된다. 임의 프레임 저하에서 모든 자세가 표시된다는 보장은 아니다.
- 실제 DefenseBoard PC 1440×900·터치 390×844·320×844, 동작 줄이기, 버티기/보행/기본 이미지 실패를 포함한 3,136시점 검사 통과. 8방향·8걸음·속도 경계·고정 체력바·페이지 예외/전투 GLB 요청 0건·가로 넘침 없음 확인.
- 작업실 PC 8클립·390/320px 각 3클립: 걸음 선택·실제 재생·복귀 자세·메시 보기·회전·시점 복귀·동작 줄이기·GLB 실패 시 PNG 대체 확인. 기존 이안 정지 선택 정상이며 캔버스는 하나다.

- PC/390px 실제 설산 전투에서 브론·훈련 0 저장 데이터로 입장·웨이브 시작·일시정지/재개·1/2배속·동작 줄이기를 조작했다. 두 화면 모두 보행 8포즈·브론의 준비/타격/회수·각 배속의 버티기 0/1/2단계를 관측했다. 버티기 중 일시정지하면 전장 DOM이 유지되고, 동작 줄이기를 켜면 원래 방향 걸음(표시 단계 3)으로 바뀐다. 다시 끄면 정지 당시 자세와 시뮬레이션 시간이 유지된다.
- 실제 전투 자동화에서 빠른 일시정지 클릭의 경합과 모바일 늑대 터치가 인접 건설 패널을 여는 상황을 분리했다. 최종 실행은 가상 시계로 프레임을 제어하면서 실제 UI 버튼을 조작하고 자연 발생하는 브론의 공격을 관측했다. 패널이 열린 채 멈춘 결과를 배속 통과로 계산하지 않았다.

# 루나의 실제 모델과 방향별 지팡이 시전·보행

2026-11-07 KST, `codex/arcana-stage-experience-20261106`의 `b00d70c`에서 이어갔다. 작업 트리는 깨끗했고 겹치는 로컬 작업·다른 에이전트·열린 PR은 없었다. 원격 Claude `42728f7`/`bf7c1c6`는 이전 회차와 같았다. main은 PR #78의 물·번개 색 구분이 병합된 `2574ea1`로 진행돼 **main을 개발 브랜치로 가져왔다**. main 자체에 이번 개발을 병합하거나 배포하지 않는다.

## 컨셉과 구현

실제로 열어 본 `art-source/defense/atlases/ranged-motion.png`의 네 번째 줄은 루나의 큰 여우 귀·구리빛 머리·초록/상아색 옷·잎 고리와 녹색 수정 지팡이를 보여준다. 기존 전투는 세 삽화를 좌우 반전했다. 이번에는 같은 몸과 같은 손의 장비가 여덟 방향에서 유지되는 첫 실제 루나 모델을 제작했다.

귀 바깥 털과 안쪽 상아색 털·따뜻한 속귀를 두께가 있는 구조로 나눴다. 머리는 가르마·긴 옆머리·등 뒤 머리로 구분했다. 첫 렌더에서 둥근 머리 가닥이 덩어리처럼 보여, 길게 굽고 끝이 가늘어지는 메시로 바꿨다. 작은 화면에서 보이는 잎 장식과 금장, 상아색 앞자락, 초록 안쪽 옷, 물결 모양 망토, 가죽 장화를 제작했다.

지팡이는 꺾인 목재 자루·금장 결속·열린 가지 고리·잎·면으로 구분되는 녹색 수정으로 구성한다. 평면 이미지로 세운 모델이 아니다. 원본 삽화의 세밀한 잎무늬·표정·천 주름은 축소 화면에 맞게 단순화했다. 초상화·선택 화면과 별도로 싸우는 기존 동료 늑대는 유지한다.

## 시전과 보행

| 클립 | 실제 원본 | 전투용 표현 |
| --- | --- | --- |
| `luna-cast` | 0.33초, 대기→지팡이 모으기→들기→0.15초 앞으로 내밀기→반동→회수 | 8방향 대기·준비·발사·회수 4포즈 |
| `luna-walk` | 0.8초, 양발 지지/회수와 반대 팔·머리·귀·옷자락 | 8방향 이동 거리 기준 8포즈 |

몸·머리·머리카락·망토·양다리·앞자락 두 개·귀 두 개·양쪽 상완/전완·손·지팡이의 **17개 변환 노드**를 움직인다. 손과 팔꿈치 위치로 상완·전완의 길이와 방향을 같은 프레임에서 계산해 손·소매 연결을 유지한다. 100fps의 매 프레임을 계산하며 시전 중 발과 다리는 고정한다. 피부 변형 리그나 지형 발 IK는 아니다.

기존 전투의 `hitAt=0.15`, `duration=0.33`을 유지한다. 실제 수정 끝의 `cast-socket`을 공통 카메라로 투영해 준비 광원과 마법탄 출발점을 연결한다. 발사 때의 방향 `launchAim`과 몸 크기 `sourceSize`를 기록해 표적 추적·영웅 이동·승급 후에도 이미 발사된 탄의 시작점을 보존한다. 영웅/용병과 모바일 배율을 반영한다.

대기·보행·시전·돌진·필살기에 같은 모델 몸을 사용한다. 새 16장 세트가 완전히 로드됐을 때만 전환하며 한 장이라도 실패하면 루나 전체가 기존 삽화로 돌아간다. 다른 완료 모델은 유지한다. 완성된 모델에는 기존 몸 흔들기나 고정된 손 위치의 마법 입자를 겹치지 않는다. 동작 줄이기는 대기/발사 단서만 남기고, 일시정지·배속은 기존 시뮬레이션 시간을 따른다.

## 최신 main 통합

main의 물 효과는 청록색, 번개는 노랑·흰색으로 구분한다. 통합 중 `DefenseBoard.tsx`의 충돌은 기존 방향별 모델·망치 궤적·모델 소켓·포구 위치를 보존하고 새 색만 해당 위치에 적용하는 방식으로 해결했다. 청운의 실제 부적 준비 광원도 새 번개 탄과 같은 `def-spark-core`로 맞췄다. 루나는 기존 녹색 마법 표현을 유지한다. 피해·추적·충돌·이동·보상·승패·동료 늑대 규칙은 바꾸지 않았다.

## 재생성과 산출물

```bash
npm run models:druid
npm run models:druid -- --check
npm run models:druid -- --preview
```

Blender와 FFmpeg를 사용한다. `--check`는 포즈별 카메라 경계를 확인하며 `--preview`는 0·1방향의 네 시전 포즈를 `/tmp/arcana-druid-preview-{direction}-{pose}.png`로 출력한다.

- 제작 코드: `tools/blender/build_druid.py`
- 편집 원본: `art-source/defense/luna-druid.blend`, `luna-druid-walk.blend`
- 공통 렌더: `art-source/defense/luna-druid/`, 384×384 투명 PNG 96장, Cycles CPU 64샘플
- 전투: `public/defense/models/luna-cast-{0..7}-atlas.webp`, `luna-walk-{0..7}-atlas.webp`, 256px 셀 4개/8개
- 작업실: `public/defense/models/luna-druid.glb`, `luna-druid-walk.glb`와 같은 카메라 PNG. `/model-lab.html?model=luna-druid` 및 `?model=luna-druid-walk`
- 메타데이터: `public/defense/models/luna-druid.json`, 컨셉 경로/해시·카메라·포즈 경계·소켓·클립·납품 파일 해시
- 생성 좌표: `src/games/defense/druidSockets.ts`, 위 명령으로 함께 재생성

기존 영웅의 정사영 배율 6.8, 원본 지면 `(192,330)`, 전투 셀 지면 `(128,220)`, 표시 배율 `1.2×6.8/5.8`을 사용한다. 포즈마다 자르거나 확대율을 바꾸지 않는다. 편집 원본은 개별 부품이고 GLB만 관절/재질별로 묶는다.

GLB는 시전 1,636,208바이트, 보행 1,651,068바이트다. 각각 **24,384삼각형·51 GLB 메시·15재질**이며, 여러 재질을 쓰는 메시가 분리되므로 Three.js 작업실에는 **52개 메시 노드**로 표시된다. 새 전투 WebP 합은 543,294바이트, 디코딩한 RGBA 픽셀 합은 **24MiB**다. 기존 대체 이미지도 함께 로드하므로 추가 메모리가 필요하다. 이 값은 실제 기기의 GPU 메모리 측정값이 아니다.

전투는 기존 베이크 기반 2.5D이고 GLB를 요청하지 않는다. 작업실만 실시간 3D다. 유닛별 WebGL 렌더러를 추가하지 않았다.

## 검증

증거·전후 화면·검사 코드·초기 미완료부터 갱신한 상태는 저장소 밖 `/tmp/arcana-hourly-20261107-0739/`에 남겼다.

- 전체 테스트 **211개 중 210개 통과**, 타입 검사·프로덕션 빌드 통과. 추가한 방향별 포즈·로딩 실패·투영·발사점 보존 테스트도 통과했다. 기존 수학 게임 `(3 × 7) ÷ 5` 정답 4/4.2 불일치 1건은 남아 있다.
- 기준 엔진과 스테이지 1·4·5·8 × 강화/판매 유무의 8게임을 매 프레임 비교했다. 게임마다 루나 탄 61~153발을 관측했고 새 시각 기록 두 필드를 제외한 전투 상태가 일치했다. 동료 늑대 상태도 비교에 포함했다.
- `.blend` 재열기·GLB 재가져오기 통과. 시전의 고정 다리/장화 메시 10개 변환 차이 0, 발바닥 최저 높이 약 0.005 모델 단위, 보행 때 한쪽 발이 지지하고 반대쪽 최고 높이는 약 0.125다. 루프 시작/끝 차이는 0.000001 미만, 원본/GLB 관절 행렬 차이는 최대 약 0.00000048다. 모든 원본 프레임의 상완/전완/손 연결도 검사했다.
- PNG 96장·WebP 16장의 크기·알파 경계·잘림·해시와 실제 GLB 클립 이름·길이·이미지 미사용 검사 통과.
- 영웅/용병 × 8방향 × (대기·공격 7시점+보행 8포즈) × PC·모바일·동작 줄이기·시전 이미지 실패·보행 이미지 실패 **1,200조합** 통과. 돌진/필살기 몸 유지, 중복 몸 변형 없음, 전투 GLB 요청 없음도 확인했다.
- 수정의 준비 광원/탄 시작점은 영웅/용병·승급 유무·8방향·PC/모바일/동작 줄이기/실패 대체 **256조합** 통과. 원본 투영과 화면 오차는 최대 약 0.000033px였다.
- Chromium **1440×900 / 390×844 터치 뷰포트**에서 입장→이동→정지→웨이브→시전→일시정지/재개→2배속을 실제 조작했다. 8개 보행 포즈, 시전 준비·발사·회수, 발사 전 strike 없음, 동작 줄이기의 대기/발사를 확인했다. 관측 시전 구간은 PC 389/166ms, 모바일 334/167ms(1배속/2배속)로 브라우저 관측 간격을 포함한다. 모바일 기본 확대에서도 실제 시전을 확인했다.
- 작업실 PC/모바일에서 GLB 시전/복귀·보행 재생/정지·회전·메시 보기·다운로드 링크·동작 줄이기·GLB 실패 시 PNG 대체를 확인했다. 실제 작업실과 전후 고정 상태의 전장 화면을 직접 열어 비교했다. 페이지 오류·가로 넘침은 없었다.
- main 색상 통합은 PC/모바일에서 청운의 모델 준비 광원·번개 탄, 물/번개 탄 및 명중·연쇄·스킬의 구분을 검사했다. 처음 검사 도구가 물 입자 세 개를 한 개로 읽으려던 선택자 오류는 수정 후 통과했다. 최초 실제 UI 시도는 테스트용 저장 데이터의 미확인 동료 안내가 입장을 가렸다. 방문/확인 기록을 일치시킨 뒤 실제 조작을 다시 수행해 통과했다. 초기 로그도 보존했다.

## 남은 차이와 다음 후보

귀·긴 머리·잎 지팡이의 입체 실루엣과 방향별 동일 장비, 실제 수정 발사점으로 기존 삽화 반전의 차이를 줄였다. 컨셉의 부드러운 머리 곡선·섬세한 천·표정과 몸 전체의 무게 이동은 더 다듬어야 한다. 보행→시전의 전신 자세 보간, 연속 회전과 실제 Android 메모리·성능은 미완료다. 모바일 검증은 Chromium 에뮬레이션이다.

실제 화면에서는 기존 동료 늑대 삽화가 새 루나 모델보다 크게 보이는 비율 차이가 남았다. 다음 후보는 **동료 늑대의 별도 모델·크기와 주인 옆 가독성**, 영웅 보행→공격 발 전환, 남은 성 테마의 입체 건축이다. 적 서리늑대의 완료된 체형·보행을 다시 만드는 작업과 구분한다.

이번 회차는 예약 상태를 조회·변경하지 않았고 Claude API도 호출하지 않았다. 원격 main을 개발 브랜치로 통합한 것과 개발 브랜치를 main에 병합·배포하는 것은 구분한다. 후자는 수행하지 않았다.

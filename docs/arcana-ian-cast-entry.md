# 이안의 걸음에서 접지된 시전으로

2026-11-08 · 컨셉 개발 41회차. 기준 `3b0ac21`, 개발 브랜치 `codex/arcana-stage-experience-20261106`.

## 컨셉과 이번 차이

`art-source/defense/atlases/ranged-motion.png` 첫 행의 꺾인 모자·남색 코트·수정 지팡이, 발을 벌리고 버티는 시전 자세를 기준으로 삼았다. 기존 전장에서는 걷던 이안이 공격을 시작하면 발과 지팡이가 바로 준비 자세로 바뀌었다. 이번에는 마지막 걸음에서 한 발씩 짚고 몸의 무게를 정리하며 지팡이를 들어 올린다. 체형·재질을 새로 만든 작업이 아니라 기존 실제 모델의 관절 동작을 연결한 작업이다.

서리늑대의 방향별 보행·피격·넉백·쓰러짐과 리엘의 보행→정지는 앞 회차 완료 범위다. 원격 main `2eabc76`, Claude `nice-meitner`의 `bf7c1c6`, `wizardly-shannon`의 `c0d0367`을 확인했다. Claude 54회차는 이안 초안으로 시험한 리엘 망토 밝기 제안이며, 통합 개발 브랜치에는 이미 실제 리엘 모델이 있다. 이 제안을 새 모델 부재로 해석하거나 이번 동작에 일괄 적용하지 않았다.

## 실제 동작과 전투 연결

- 실제 `ian-entry-0`~`ian-entry-7` GLB 클립, 각 0.33초·100fps·8개 관절이다. 시작은 기존 여덟 보행 자세와 일치한다.
- 처음 0.05초에 들린 발을 내려놓고, 다음 0.05초에 다른 발을 정리한다. 지지 발은 모델 평면에서 고정한다. 몸통은 지지 발 쪽으로 살짝 무게를 옮기고 지팡이·반대팔·머리·망토가 준비 자세로 이어진다.
- 0.10초부터 모든 관절과 지팡이 소켓은 기존 시전과 같다. **0.15초 발사, 전체 0.33초 공격, 기존 투사체 출발점·피해·이동 판정은 유지한다.**
- 전투는 시작 보행 이미지 → 0.04초 첫 디딤 렌더 → 0.08초 두 번째 디딤 렌더 → 기존 시전을 사용한다. 표시 경계는 0.025/0.065/0.10초다. 2배속 게시 간격에서도 두 번째 준비 자세가 표시된다.
- 준비 광원은 각 방향·걸음·표시 자세의 실제 수정 끝 소켓을 따른다. 기존 발사 소켓을 준비 자세에 고정하지 않는다. 소켓은 영웅/용병 및 기본/승급 표시 크기에 비례한다.
- 엔진의 기존 시각 필드 `walkEntry`를 이안 공격에도 기록한다. 동료 이안이 매 틱 주인을 따라잡아 이동 중인데도 속도 0으로 표시되던 문제를 실제 이동량으로 판정하고, 준비 화면의 정지 완료 처리도 연결했다.
- 필살기·돌진이 우선한다. 정지 상태에서 시작한 시전과 동작 줄이기는 기존 시전을 유지한다. 새 이미지 하나라도 실패하면 새 전환만 끄고 기존 시전/보행 세트를 쓴다. 기존 시전/보행 세트의 실패 대체 규칙도 유지한다.

전투는 WebP 기반 2.5D다. GLB는 모델 작업실의 단일 실시간 3D 장면에서 재생한다. 유닛별 WebGL 렌더러는 추가하지 않았다.

## 원본과 재생성

```bash
npm run models:ian-entry
npm run models:ian-entry:pose-check
npm run models:ian-entry:check
```

전체 재생성은 기존 `ian-mage-walk.blend`와 `ian-mage.blend`를 읽으며 해당 원본을 덮어쓰지 않는다. Blender·FFmpeg가 필요하다. 이번 납품은 Blender 4.3.2, Cycles CPU 48샘플이다.

| 산출물 | 위치·규격 |
| --- | --- |
| 제작 코드 | `tools/blender/build_ian_entry.py` |
| 편집 원본 | `art-source/defense/ian-entry.blend`, 기존 메시 135개와 관절별 `Ian entry N / JOINT` 액션 |
| 실제 3D | `public/defense/models/ian-entry.glb`, 8클립, 1,470,932바이트 |
| 공통 카메라 렌더 | `art-source/defense/ian-entry-frames/`, 384×384 PNG 128장 |
| 전투용 베이크 | `public/defense/models/ian-entry-{0..7}-atlas.webp`, 3072×192, 방향마다 16셀 |
| 메타데이터·미리보기 | `public/defense/models/ian-entry.json`, `ian-entry.png` |

정사영 배율 6.8, 원본 지면 `(192,330)`, 전투 셀 지면 `(96,165)`를 공유한다. 포즈마다 자르거나 확대하지 않는다. 작업실 경계 맞춤 카메라만 확대 검토에 사용한다. GLB는 21,122삼각형·14재질이며 로더에서 37개 메시로 표시된다. 전투 WebP 합은 508,936바이트, 추가 RGBA 픽셀 합 추정은 **18MiB**다. 실제 기기의 GPU 메모리 측정값은 아니다.

## 검증

증거 폴더: `/tmp/arcana-hourly-20261108-0939/`. 시작 시 기준·소유 브랜치·수용 기준·미완료 상태를 기록했다.

- 전체 테스트 **292개 중 291개 통과**, 엔진 65개 통과, 타입 검사·프로덕션 빌드 통과. 실패 1건은 기준 커밋에서도 재현한 기존 수학 게임 `(3×7)/5`의 4/4.2 불일치다.
- 납품 GLB를 Three.js로 읽어 저작 시점 272개·보간 시점 1,064개를 확인했다. 기존 보행 시작 오차 최대 약 `1.39e-7`, 기존 시전 일치 오차 `1.20e-7`, 지지 발 이동 약 `1.11e-16`, 발바닥 최저 높이 약 `0.005`다. 0.10초 이후 소켓 오차는 `9.86e-8` 이하다. 원본·생성기·산출물 해시 144개 통과.
- `.blend` 재열기에서 메시 135개×8개 시작/끝 자세의 변환 차이 0. 실제 카메라로 192개 수정 끝을 다시 투영한 오차는 192px 기준 약 `0.000015px` 이하다.
- PNG 128장·WebP 128셀의 해상도·알파 경계를 확인했다. 최소 투명 여백 15px, 빌드 배포 파일 11개가 원본과 일치한다.
- 스테이지 1·4·5·8, 영웅/용병의 8게임·14,400스텝에서 기준과 현재 게임 상태를 비교했다. 이안의 공격/투사체 `walkEntry`, 동료 이안의 표시용 `speed`/`settle`만 제외하고 상태가 일치했다. 배속·일시정지·재개·스킬·돌진·강화가 포함된다.

## 남은 차이와 다음 후보

지지 발 고정은 모델 내부 평면 기준이다. 전장 좌표 이동·경사 지형에 맞춘 IK나 연속 방향 회전은 구현하지 않았다. 보행 방향과 공격 방향이 다르면 기존 8방향 선택 규칙을 따른다. 준비 이후 시전→현재 보행 복귀도 다음 후보이며, 실제 Android 메모리·프레임 성능은 미검증이다. 이번 회차는 Claude API를 호출하거나 예약 설정을 조회·변경하지 않았다.

# 서리 협곡 근접 물기의 가독성

[은서리 늑대 컨셉](../art-source/defense/concepts/2026-10-29/beasts/silverfrost-wolf.png)은 머리와 주둥이가 방향을 분명히 드러낸다. 기존 실시간 전장에서는 [접지된 물기](arcana-frontier-wolf-bite.md)가 영웅에게 겹치면 목과 턱이 가려졌다. 영웅의 몸을 잘라내는 시안은 몸통에 빈 구멍이 보여 폐기했다.

서리 협곡에서 영웅을 향한 물기 중 주둥이 아래 또는 위가 영웅 뒤에 있으면 기존 GLB의 움직이는 머리와 턱 메시를 같은 3D 장면에서 옅은 서리색으로 한 번 더 그린다. [물기 체중 이동](arcana-frontier-wolf-bite-brace.md) 후 윤곽 가장자리에서도 동작이 보이도록 두 지점을 검사한다. 피해 전의 가장 진행된 물기를 우선해 한 마리만 표시하며, 걷기·성문 공격·쓰러진 적에는 표시하지 않는다. 기존 공격 예고, 발 접지, 피해와 조작은 유지된다.

## 2026-11-11: 영웅으로 가려진 픽셀만 표시

첫 중첩은 깊이만 검사해 앞의 벽이나 다른 적의 표면에도 늑대 머리가 비칠 수 있었다. 이제 불투명 지형과 유닛을 먼저 그린 뒤 실제로 보이는 영웅 표면이 스텐실 버퍼의 한 비트를 기록한다. 늑대의 기존 머리·턱은 그 비트가 있는 픽셀에서만, 영웅보다 뒤에 있을 때 그린다. 영웅의 색과 깊이 기록은 바꾸지 않으며 스텐실 속성과 렌더 순서는 물기 종료·모델 교체·장면 정리 때 복원한다. 불투명 성문이나 절벽이 영웅 앞을 가리면 표시도 함께 가려져, 기존의 성문 주변 4단위 일괄 제한을 없앴다.

스텐실은 서리 협곡의 영웅이 있는 모드에서만 요청한다. 지원되지 않으면 안전하게 중첩을 생략하고 기존 공격 예고와 전투를 유지한다. 여전히 위협 한 마리만 선택하며 가장 우선한 늑대가 가려지지 않았다면 다른 늑대로 대체하지 않는다. 투명한 물체와 이펙트의 겹침 및 실제 Android/iOS GPU는 후속 검증 대상이다. 동작 줄이기는 기존 정적 물기 자세를 유지한다. 새 모델이나 Blender 모션은 만들지 않았으며 기존 [편집 원본·공통 렌더·GLB·전투 WebP와 재생성 명령](arcana-frost-wolf-grounded-stride.md)을 사용한다. 캠페인 전투는 기존 2.5D다.

## 검증

- 실제 전장과 같은 카메라의 통제된 3D 물기 장면에서 영웅 앞에 불투명 벽을 놓았다. 중첩을 끈 벽 화면과 비교했을 때 벽 위에 달라진 픽셀이 PC는 이전 892개에서 0개, 가로 모바일은 112개에서 0개가 됐다. 벽을 제거하면 영웅 위의 물기 중첩은 유지된다.
- `tools/tests/bite-stencil-depth-browser.cjs`는 실제 WebGL 픽셀로 영웅 위 중첩, 영웅 옆 벽, 영웅 앞 기둥의 가림을 검사한다. `npm test`에는 재질·렌더 순서 복원과 비동기 모델 교체 검사를 포함한다.
- PC와 가로 모바일에서 물기·일시정지·1/2배속·동작 줄이기, 스텐실 미지원, 실제 UI·모델 실패 및 맵 전환을 검증한다. 브라우저의 모바일 화면과 소프트웨어 렌더러 측정은 실제 휴대기기 GPU 검증을 대신하지 않는다.
- 844×390 Chromium SwiftShader에서 1/30마리의 공격 중 드로우콜은 전후 모두 49회, 삼각형은 각각 32,456/99,504개였다. 3초 평균 프레임 간격은 1마리 90.2→91.9ms, 30마리 138.6→138.2ms다. 스텐실 버퍼 비용은 남으며 짧은 소프트웨어 표본이므로 실기기 합격이나 성능 향상을 뜻하지 않는다.

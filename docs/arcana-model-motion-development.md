## 이번에 구현한 것

나무 병사는 실제 Blender 메시와 강체 관절 계층으로 제작한다. 나이테는 이미지가 아닌 메시이고, 발·팔·머리·등 잎을 따로 움직인다. 한 주기 1초의 GLB 보행 클립과 같은 동작의 8단계 전투용 WebP를 출력한다. 디딘 발은 지면에 맞추고 반대쪽 발을 들어 옮기며, 팔은 다리와 반대로 움직이고 잎은 조금 늦게 따라온다. 스킨 리그나 지형을 읽는 실시간 IK는 아니다.

전투에서는 나무 병사가 52 논리 단위를 이동할 때 8프레임을 한 번 순환한다. 이동 거리와 속도는 시뮬레이션 상태에 기록한다. 둔화·물길·얼음·일시정지를 그대로 따르고, 넉백 속도 7 초과일 때는 보행보다 버티는 동작을 우선한다. 뒤로 밀리는 거리는 보행에 더하지 않으며 몸은 길의 진행 방향을 유지한다. 완성된 보행에는 기존 전체 몸체의 추가 튀기기를 겹치지 않는다.

보행 아틀라스를 못 불러오면 같은 모델의 기존 3포즈로 대체한다. 기본 모델 아틀라스까지 실패하면 삽화 세트로 대체한다. 동작 줄이기에서는 새 보행 순환을 끈다. 피해·공격 속도·적 이동 속도·보상은 이번 모델/보행 변경에서 조정하지 않았다.

실제 게임 전투는 **3D 원본을 베이크한 2.5D**다. 모델 작업실은 **실시간 3D**로, `/model-lab.html?model=wood-soldier`에서 보행 재생/정지, 회전, 메시 보기, GLB 내려받기를 제공한다. 전체 전투를 실시간 3D로 전환했다고 보지 않는다.

## 재생성과 납품물

```bash
npm run models:wood
```

- 제작 코드: `tools/blender/build_wood.py`
- 편집 원본과 고정 카메라 렌더: `art-source/defense/wood-soldier.blend`, `art-source/defense/wood-frames/`
- 3D 검토: `public/defense/models/wood-soldier.glb`와 미리보기 PNG
- 전투: `wood-soldier-atlas.webp`(3포즈, 약 31KB), `wood-soldier-walk-atlas.webp`(8포즈, 약 76KB)
- 규격·클립·해시: `public/defense/models/wood-soldier.json`

블렌더의 공통 384px 카메라, 지면 기준 (192, 317.61), 동일 배율을 유지한다. 보행 전체 메시가 카메라 안에 있는지 생성 시 검사한다. GLB는 약 539KB이며 전투 이미지 로더는 내려받지 않는다. GLB의 실제 렌더 비용은 작업실에서만 발생한다.

## 검증과 다음 범위

엔진 검사에서는 순방향 거리 누적, 역밀림 때 보행 정지, 길을 향하는 방향, 둔화 비율, 일시정지, 시간 분할 일관성과 이전 상태 불변성을 확인한다. 이미지 검사에서는 8포즈의 동일 지면·크기, 아틀라스 경계와 부분 로딩 실패를 확인한다. Blender 원본 재열기·GLB 재가져오기, Chromium의 실제 전투와 작업실 재생도 확인한다.

이번 확인 결과:

- Claude 30회차의 동일한 64px 비교 도구에서 돌·나무 기본 포즈의 실루엣 겹침은 0.70 → 0.58, 새 보행 8포즈는 0.50~0.59였다. 해당 도구의 잠정 혼동 기준 0.65 아래다. 자동 실루엣 측정이며 사용자 인지 실험을 대신하지 않는다.
- 전투·보행·에셋 검사 74개 통과, 전체 검사 162개 중 161개 통과. 기존 수학 엔진의 `(3 × 7) ÷ 5` 정답 4/4.2 불일치 1건은 남아 있다. 프로덕션 빌드 통과.
- `http://localhost:3100/` 및 `/model-lab.html?model=wood-soldier`, Chromium 1440×900 / 390×844에서 확인했다. 연결형 Browser 실행 도구가 없어 설치된 Playwright·Chromium을 사용했다.
- 실제 웨이브에서 8포즈 순환, 일시정지/재개, 이미지 요청 실패 시 기존 2포즈 보행, 동작 줄이기의 고정 포즈를 확인했다. 작업실은 보행 재생/정지·메시 보기·동작 줄이기·브론 공격/화염탑 전환을 확인했다. 빈 화면·프레임워크 오류 화면·가로 넘침·예상하지 않은 콘솔 오류는 없었다.
- 작업실의 나무 병사는 GLB 로딩 후 6,884 삼각형, 92 메시, 9재질로 측정됐다. 이 수치는 전투 WebGL 예산을 충족했다는 의미가 아니며, 실제 전투는 해당 GLB를 로딩하지 않는다.

다음 모델 묶음은 서리늑대의 웅크림·도약·착지와 영웅의 방향별 공격이다. 모든 적을 한 번에 같은 몸 튀기기로 처리하지 않고 체형별 걸음과 무게를 분리한다. 완전한 3D 전투 전환은 단일 장면 렌더러에서 지형 가림·화면 좌표 입력·유닛 수별 성능을 검증한 뒤 확장한다. 실제 Android 기기 성능과 사용자 재미 검증은 별도다.

[빙결 기사 행군](arcana-ice-knight-walk.md)은 기존 얼음 갑옷·검을 유지하고 발목 관절과 정강이 접지를 보정한 1초 3D 보행이다. 공통 카메라의 8포즈를 실제 이동 거리와 모바일 표시 크기에 맞춰 2.5D 전투에 연결하고 피격·붕괴와 기준점을 맞춘다. `.blend`, GLB, 원본 PNG, WebP, 메타데이터와 재생성 명령을 제공한다. 대각선 월드 좌표 발 고정과 Android 실기기 성능은 후속이다.

## 91회차 · 기본 포격탑의 조준과 반동

기존 Lv.1 포격탑의 단일 그림 대신 낮은 오크·석재 포대와 철제 포신을 실제 3D로 구성했다. 고정된 기초 위의 포대가 여덟 방향으로 조준하고, 0.28초 발사 직후 포신이 뒤로 밀렸다가 복귀한다. 전투는 공통 카메라의 방향별 네 포즈와 발사 당시 포구를 사용하며 판정·피해는 변경하지 않는다. `npm run models:base-cannon-action`으로 편집 `.blend`, 애니메이션 GLB, 640px 원본 PNG, 192px 전투 WebP와 메타데이터를 재생성한다. 동작 줄이기에서는 조준 자세를 유지하고, 방향 이미지 하나라도 실패하면 기존 포탑 그림을 사용한다. 실제 모바일 GPU 성능과 포탄·포신 사이의 동적 강체 충돌은 후속 검증이다.

## 92회차 · 기본 석궁탑의 조준과 시위 발사

기본 석궁탑의 정적인 그림 대신 청색 깃발·목재 활대·짧은 화살을 실제 3D로 구성했다. 석재·목재 기초는 고정하고 8방향 상부 활대와 양쪽 시위를 움직인다. 전투 판정의 0.1초 발사에 맞춰 화살을 내보내며, 화살촉이 발사 당시 모델의 실제 끝점에서 출발하고 장전 자세로 복귀한다. 편집 원본·애니메이션 GLB·공통 카메라 원본 PNG·192px 전투 WebP·메타데이터는 `npm run models:base-crossbow-action`으로 재생성한다. 동작 줄이기는 조준 자세를 유지하고, 일부 방향 이미지가 실패하면 기존 그림으로 돌아간다. 실제 Android GPU 성능과 활대의 연속 회전은 미검증이다.

## 93회차 · 금속 병사의 무거운 행군

두 자세를 교대하던 금속 병사에 발목 관절을 추가해 둥근 철제 갑옷과 주황색 투구를 유지하면서 양발이 번갈아 지면을 지지하는 1초 3D 행군을 만들었다. 팔과 몸도 체중 이동을 따르며, 공통 카메라의 8포즈를 실제 이동거리와 표시 크기에 연결한다. 표시 크기 68 기준 지지 발의 투영 이동으로 한 주기를 24.69776 보드 단위로 맞췄고, 8개 포즈를 유지하는 동안 지지 발의 수평 흔들림은 표본 기준 5.3단위 미만이다. 기존 피격·처치와 체력 막대 앵커 및 게임 판정은 유지한다. `npm run models:metal-walk`로 편집 `.blend`, GLB, 원본 PNG, 전투 WebP, 메타데이터를 재생성한다. 보행 이미지나 기존 금속 모델 로딩이 실패하면 원래 동작 또는 삽화를 사용한다. 세로·대각 이동의 월드 좌표 발 고정과 실제 Android 성능은 아직 검증하지 않았다.

## 94회차 · 기본 마법탑의 충전과 발사

기존 기본 마법탑의 정적 파란 수정을 기준으로, 돌 기초와 금속 고리·두 지지구·청색 깃발을 편집 가능한 실제 메시로 구성했다. 기초는 고정하고 수정과 고리가 충전·발사·복귀하는 0.39초 동작을 만든다. 공통 카메라의 6개 자세를 기존 공격의 0.15초 발사 시점에 맞춰 2.5D 전투에 연결하고, 투사체는 실제 수정 꼭대기 소켓에서 출발한다. 상위 화염·번개 강화 외형과 피해 판정은 유지한다. `npm run models:base-magic-action`으로 `.blend`, 애니메이션 GLB, 원본 PNG, 전투용 WebP와 좌표·해시 메타데이터를 재생성한다. 모델 작업실에서는 GLB를 재생하고, 동작 줄이기는 정지 자세를, 이미지 로딩 실패는 기존 탑을 사용한다. 고리와 수정의 표면 관통은 40개 표본에서 검사했다. 실제 Android GPU와 동적 강체 충돌은 검증하지 않았다.

## 95회차 · 녹음 협곡의 숲 경계

[녹음 숲 컨셉](../art-source/defense/concepts/2026-11-06/verdant-heart.png)과 실제 가로 전장을 비교해 원뿔 나무를 가지와 두 개의 넓은 수관을 가진 실제 3D 메시로 교체하고 풀밭의 반복 격자를 완만한 녹음 색면으로 바꿨다. 동쪽 수관은 플레이 영역 밖의 지면과 기초 위에 두어 근접 카메라에서 영웅을 가리지 않게 했다. 이동 가능한 영역·적 경로·지형 높이와 강·다리의 입력 및 판정은 유지한다. 기존 64×64 플레이 영역은 확장하지 않았으며, 바깥쪽 지면은 시각적 배경이다.

`npm run models:frontier-terrain`은 28그루의 편집 가능한 원본, 단일 표면 GLB, 두 공통 카메라 PNG, 메뉴용 WebP와 메타데이터를 재생성한다. `npm run models:frontier-terrain:check`는 높이·다리·색·메시 예산과 162개 카메라/영웅 위치의 중심 가림을 검사한다. 샘플 기준 기존 가림 6개 중 1개가 남으며 새 가림은 없었다. GLB는 11,508→12,768삼각형이고 지형 draw call은 하나다. 모든 위치·카메라 각도의 가림과 실제 Android GPU 성능은 미검증이다. 캠페인은 기존 2.5D다.

## 96회차 · 녹음 성문의 목재 양문

[녹음 숲 컨셉](../art-source/defense/concepts/2026-11-06/verdant-heart.png)의 보강 목재 문과 실제 3D 변경 전장의 열린 아치를 비교했다. 기존 석조·덩굴·초록 지붕을 보존하면서 아치에 맞춘 8개 널판, 철띠·리벳·맞댐목과 양쪽 경첩을 실제 메시로 제작했다. 성문 피해가 발생한 시뮬레이션 시점에 문짝이 밀렸다 돌아오며, 지휘·솔로에서는 열린 통로를 유지한다. 열린 문이 카메라와 영웅 중심 사이에 있을 때만 문을 반투명하게 하여 모바일 측면 가림을 줄인다. 판정·이동·보상은 바꾸지 않았다.

`npm run models:frontier-forest-doors`로 편집 `.blend`, 두 문짝과 실제 0.55초 클립을 담은 GLB, 기존 공통 카메라 4포즈 PNG·WebP·해시 메타데이터를 만든다. 모델 작업실에서는 문짝 GLB를, PNG 대체 이미지는 아치와 문짝을 함께 보여 준다. WebP는 보존용 베이크이며 기존 캠페인 2.5D에 새로 연결하지 않았다. `npm run models:frontier-forest-doors:check`는 34개 시간 표본의 고정 석조·경첩·접지·해시와 GLB 동작을 검사한다. 숲 전장 GLB 실패 시 기본 입체 문을 사용하며 동작 줄이기에서는 정지 자세와 피해 고리만 남긴다. 문짝 간/석조 간 동적 강체 충돌과 실제 Android GPU 성능은 후속이다.

[지원병 모델](arcana-frontier-squad-model.md)은 42개 편집 메시를 실제 4표면·1,060삼각형 GLB로 묶고 양발과 양손에 든 석궁을 기존 거리 기반 보행·발사 방향과 연결한다. 발사선은 무기 끝 소켓을 사용하며 기존 피해와 캠페인 2.5D는 유지한다. 팔꿈치 IK·시위 장전·급회전 발 고정과 실기기 성능은 후속이다.

## 107회차 · 수정 원정의 회복 수정

[회복 수정](arcana-frontier-recovery-crystal.md)은 청록 결정과 어두운 석재 받침을 실제 메시로 만들어 눈밭의 실루엣을 분리한다. 기존 수집 거리와 즉시 회복을 유지하고 지형을 따르는 접근 표시·시뮬레이션 시간 기반 수집 반응을 연결한다. 편집 가능한 원본과 GLB·공통 렌더·베이크·재생성 명령을 제공한다. 기존 캠페인 2.5D 연결과 실기기 GPU 검증은 범위 밖이다.

## 108회차 · 통나무 병사의 처치 반응

[통나무 병사의 접지된 쓰러짐](arcana-frontier-wood-defeat.md)은 기존 3D 관절 모델을 치명타 방향과 지형에 맞춰 시뮬레이션 시간 동안 기울이고 줄여 없앤다. 처치 시 대상·공격·보상은 기존처럼 즉시 확정하며 렌더 잔상은 게임 판정에 참여하지 않는다. 새 Blender 모델·GLB·전투 베이크는 제작하지 않았다.

## 109회차 · 카르의 실제 돌진 구간

[돌진 흔적](arcana-frontier-dash-trace.md)은 이미 검증된 시작·도착점 사이에 지형을 따르는 짧은 3D 바람과 접지 파편을 공유 인스턴스로 표시한다. 위치 이동은 기존 즉시 판정을 유지하며, 새 Blender 모델이나 실제 관절 대시 클립은 만들지 않았다. 실기기 성능과 실제 시간에 걸친 대시는 후속이다.

## 110회차 · 실제 이동하는 카르 돌진

[시간 기반 돌진](arcana-frontier-timed-dash.md)은 기존 카르 GLB의 보행과 몸 기울기를 실제 0.2초 이내의 게임 좌표 이동에 연결한다. 지형 경계·발 접지·정지·배속·동작 줄이기를 검사한다. 새 Blender 모델이나 관절 대시 클립을 제작하지 않았다.

## 111회차 · 카르의 돌진 버팀 자세

[돌진 버팀 자세](arcana-frontier-dash-brace.md)는 기존 카르 GLB의 보행·대기 클립과 양발 관절을 실제 돌진 진행도에 맞춰 혼합한다. 지면에 닿는 발과 양손의 망치 연결, 서기/보행 출발과 착지를 확인한다. 새 Blender 원본·GLB·베이크나 손으로 제작한 돌진 클립은 없다.

## 112회차 · 카르의 공격 취소와 돌진 연결

[공격 취소 연결](arcana-frontier-cancel-pose.md)은 기존 카르 공격·회수 관절 포즈를 돌진 버팀으로 최대 0.05초에 혼합하고 어깨·팔꿈치·그립과 발을 재연결한다. 실제 판정은 즉시 취소되며, 새 Blender 모델이나 관절 클립을 제작하지 않았다.

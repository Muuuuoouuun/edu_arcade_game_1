# 변경 지휘 지원병의 이동과 발사 방향

2026-11-10 UTC · 컨셉 개발 82회차 · 기준 `86ec46c71d82ecac0577a0f06c448aa1a9f9ddcb`.

[녹음의 심장 원본](../art-source/defense/concepts/2026-11-06/verdant-heart.png)과 실제 가로 지휘 전장을 비교했다. 컨셉은 발로 땅을 지지하며 무기와 몸이 동작 방향을 전달하지만, 변경 지휘의 지원병 셋은 기존 단순 입체 모형이 정지 자세로 미끄러지며 영웅의 방향만 복사했다. 서리늑대 보행·영웅의 방향별 공격·기본 포탑 조준은 이미 구현돼 있어 반복하지 않았다.

기존 입체 병사의 좌우 발과 무기 메시를 움직인다. 병사마다 실제 이동 거리를 기록해 1.2 전장 단위마다 양발의 지지·회수를 교대하고, 지지 발은 직선 이동에서 병사 이동만큼 뒤로 이동한다. 각 발의 위치는 경사·다리 높이를 참조하며 정지 후 0.16초에 양발 자세로 돌아간다. 병사는 자신의 실제 진행 방향을 보고, 공격이 즉시 적용된 시점부터 0.18초 동안 그 공격의 표적 방향을 바라보며 무기를 짧게 거둔다. 동작 줄이기에서는 양발을 지면에 두고 무기 반동을 생략하지만 발사 방향은 보존한다. 방향 전환이나 발사 중에는 지지 발이 월드 좌표에 완전히 고정되는 기능은 아니다.

움직임은 시뮬레이션 상태의 위치·시간을 사용한다. 일시정지에서 멈추고 2배속에서는 이동과 함께 진행한다. 발사·피해·이동·보상·경로 판정은 바꾸지 않았다. 2.5D 캠페인, 저장, 기존 지형 및 모델 작업실은 바꾸지 않았다. 원래 전장에 있던 단순한 입체 박스·구체를 재사용한 절차적 관절 표현이며 새 모델, `.blend`, GLB나 렌더 아틀라스 제작은 아니다. 유닛별 렌더러를 만들지 않는다.

## 검증

- 8방향·8보행 위상, 경사·다리·상판 경계에서 두 발의 네 모서리가 표면보다 아래로 들어가지 않는지 확인했다. 이산 표본이며 급격한 지형의 모든 가능한 위치·회전에서 접지를 보장하지 않는다. 직선 평지의 지지 발 좌표와 이동 거리, 시작 정지·0.16초 복귀, 동작 줄이기와 발사 방향·즉시 피해, 일시정지·2배속을 테스트한다.
- 이전 구현과 방어·지휘·솔로 각각 6,000회 시뮬레이션 호출을 비교했다. 실제 활성 단계는 각각 1,591·1,420·164회였으며 표현용 분대 필드를 제외한 전체 게임 상태가 같았다. 장시간이나 모든 플레이에 대한 동등성 증명은 아니다.
- 실제 PC 1024×576 및 가로 모바일 844×390 브라우저에서 훈련 시작, 분대 이동, 일시정지, 2배속, 동작 줄이기와 실제 발사를 조작했다. 모바일은 터치 에뮬레이션이다. 모바일 빌드에서 타이틀→캠프→지휘 전장과 이동·일시정지를 확인했다. 영웅·지형 GLB를 차단한 대체 입체 장면에서도 분대가 이동했다.
- 전체 테스트 515개, 웹 빌드·모바일 빌드 통과. `node --experimental-strip-types --test src/games/frontier/squadView.test.ts`로 관련 검사 5개를 재실행한다.
- 844×242 Chromium SwiftShader, 지원병 3명 표본 5초씩: 이전/이후 평균 프레임 간격 78.52/80.37ms, p95 100/100ms, 드로 호출 56/56, 삼각형 46,396/46,396, GPU 지오메트리 247/247, 캔버스 1개. 짧은 소프트웨어 측정은 실제 Android/iOS GPU 성능이나 개선을 입증하지 않는다.

후속은 컨셉에 맞는 편집 가능한 지원병 전용 모델·관절과 팔/무기 연결, 방향 변경 중 발 고정, 화면 크기에서의 구별성, 실제 기기 성능이다. 이번에는 기존 모형의 단순한 몸통과 떠 있는 무기 형태가 남는다.

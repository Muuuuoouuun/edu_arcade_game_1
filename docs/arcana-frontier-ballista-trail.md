# 변경 전장 발리스타의 비행 방향

2026-11-10. [발리스타·착탄 컨셉](../art-source/defense/concepts/2026-11-09-openai/ballista-impact-reference.png)과 실제 PC/가로 모바일 서리 전장을 비교했다. 기존 3D 볼트는 발사 소켓과 목표 사이를 실제로 이동하지만 작고 얇아 밝은 바닥에서 방향을 읽기 어려웠다.

볼트 꼬리에서 뒤쪽으로 좁아지는 짧은 호박색 입체 흔적을 추가했다. 매 순간 실제 볼트의 직전 위치와 현재 위치로 방향을 정하고, 발사 이후의 실제 이동 거리가 볼트 길이를 넘은 만큼만 흔적을 늘린다. 최대 길이는 2.4 전장 단위다. 발사 직후에는 포탑 뒤로 나타나지 않고, 명중·대상 소멸로 볼트가 제거되면 흔적도 제거된다. 벽과 지형은 깊이 버퍼로 흔적을 가린다. 볼트가 없는 곳에 과거 궤적을 남기지 않는다.

흔적은 별도의 물리 물체가 아닌 시각 효과다. 기존 볼트의 유도 이동·속도, 발사/도착 시각, 피해·보상과 착탄 파편은 변경하지 않는다. 일시정지와 배속은 기존 시뮬레이션 시간을 따르며, 동작 줄이기는 중요한 볼트와 피해를 유지하고 흔적만 생략한다. 포탑 GLB가 실패해도 기존 입체 대체 포탑에서 같은 효과가 동작한다. 단일 Three.js 장면 안에 최대 64개의 흔적을 하나의 공유 `InstancedMesh`로 그린다. 새 모델이나 Blender 동작, 캠페인 2.5D 이미지를 제작한 것은 아니다. 기존 편집 원본과 GLB·공통 카메라 렌더·재생성 명령은 [발리스타 기록](arcana-frontier-ballista.md)을 따른다.

## 검증과 한계

- `npm test`의 볼트/포탑·충격·기존 게임 테스트, `npm run build`, `npm run build:mobile`을 확인했다. 단위 검사는 방향·길이·발사 전 표시 금지·64개 상한·리소스 해제·일시정지·배속·도착 피해를 다룬다.
- Chromium PC 1440×900과 가로 모바일 844×390에서 실제 포탑 건설·발사와 전후 화면을 확인했다. 가로 모바일에서는 일시정지/재개·2배속·동작 줄이기·발리스타 GLB 실패와 착탄을 확인했다. 별도의 WebGL 픽셀 검사 `tools/tests/bolt-trail-depth-browser.cjs`는 앞에 있는 불투명 벽이 흔적을 가리는지 확인한다.
- 844×242 Chromium SwiftShader 단일 표본, 동일 12적·8개 비행 볼트를 인위적으로 유지한 2초: 변경 전 평균 68.95ms/p95 83.4ms·28호출·35,186삼각형, 변경 후 평균 71.78ms/p95 99.9ms·29호출·35,314삼각형. 표본이 짧고 소프트웨어 렌더이므로 실제 모바일 GPU 성능이나 프레임 합격을 뜻하지 않는다.
- 화면 증거와 원격 기준은 `/workspace/arcana-loop-evidence-20261110-1240/`에 기록했다. 실제 Android/iOS 기기, 긴 전투의 발열·배터리, 지형과 볼트의 물리 충돌·중력 궤도는 검증하거나 구현하지 않았다.

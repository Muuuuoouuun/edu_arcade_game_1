# 아르카나 수비대: 조작·난이도·성능 개선

2026-10-28. 기존 2.5D 그림체, 8개 스테이지, 영웅·용병·타워 성장을 유지한 전투 개선입니다.

## 조작과 물리

- 빈 땅을 누르면 영웅이 이동합니다. 전장에 키보드 초점을 두고 방향키를 눌러도 이동합니다.
- 전투 중 `돌진` 또는 Shift로 위치 선택을 켠 다음 목적지를 누릅니다. 최대 200거리, 속도 750거리/초, 재사용 5초입니다. 돌진 자체는 피해를 주지 않습니다.
- 일반 이동은 최고 속도 230거리/초에 가속·제동을 적용합니다. 순간이동과 목표점 초과를 막으며, 돌진 중 추가 이동 명령으로 거리를 늘릴 수 없습니다.
- 돌진은 공격 준비를 취소합니다. 웨이브가 끝나면 진행 중 돌진을 멈추며, 일시정지·전직·결과 화면에서 재사용 시간이 흐르지 않습니다.
- 포탄 높이는 `4 × 최고높이 × 진행률 × (1 − 진행률)`인 포물선입니다. 절반 지점이 정점이며, 조준한 땅에 닿기 전에는 폭발 피해가 발생하지 않습니다.
- 충격에 의한 밀림은 몬스터 질량을 따릅니다. 지수 감쇠를 적분해 10Hz와 60Hz 계산 간 넉백 거리 차이를 줄였습니다. 연속 밀림 면역은 유지합니다.

게임의 좌표와 중력은 연출용 단위입니다. 일반 강체 물리 엔진이나 지형 충돌 시뮬레이터를 추가한 것은 아닙니다.

## 난이도와 전투 판단

| 원정 | 적 체력 | 적 속도 | 출현 간격 | 시작 코인 | 승리 기본 보상 |
|---|---:|---:|---:|---:|---:|
| 여유롭게 | 80% | 90% | 115% | +70 | 100% |
| 기본 원정 | 100% | 100% | 100% | 기존 | 100% |
| 정예 원정 | 130% | 112% | 78% | 기존 | 140% |

정예는 웨이브마다 빠른 증원을 2·3·3·4마리 추가합니다. 각 지역 보스는 마지막에 등장합니다. 정찰 패널은 실제 생성에 쓰는 편성표를 공유하며 적 수·상성·보스 출현과 전투 중 남은 적을 표시합니다.

난이도는 거점에서 선택하고 원정 중 고정됩니다. 기존 저장은 기본 원정으로 이어집니다. 추가 퀘스트는 난이도와 관계없이 스테이지당 한 번만 지급하며, 실패 보상은 늘리지 않습니다. 최근 플레이 기록에 난이도와 지역을 함께 저장합니다.

## 재현 가능한 밸런스 비교

Node 22에서 `node --experimental-strip-types tools/balance-defense.ts`를 실행합니다. 1-1·1-4·2-4 × 3난이도 × 4전략으로 총 36조건을 60Hz로 계산합니다.

1-1은 이안·훈련0·용병 없이 시작합니다. 1-4와 2-4 재도전은 카르·훈련1입니다. 타워 없음, 3타워와 2개 분기, 타워 전체 확장, 전체 확장과 직접 조작을 비교합니다. 직접 조작은 2.5초마다 위험한 적 쪽으로 이동·돌진하고 필살기를 사용합니다. 코인·피해·승리 상태를 주입하지 않지만, 조작 지연이 없는 이상적인 입력 모델이므로 사람의 난이도 체감을 대신하지 않습니다.

정예 2-4 결과:

| 전략 | 결과 | 마을 / 외곽 체력 | 전투 시간 |
|---|---|---:|---:|
| 타워 없음 | 패배 | 0 / 0 | 89초 |
| 3타워 | 패배 | 0 / 1 | 218초 |
| 전체 확장·자동 공격 | 승리 | 20 / 10 | 172초 |
| 전체 확장·이동·돌진·필살기 | 승리 | 20 / 12 | 146초 |

초반 1-1은 정예에서도 3타워로 충분히 방어됩니다. 나중에 합류한 카르로 숲 1-4를 다시 하면 타워 없이도 본 마을만 지키고 외곽을 잃는 승리가 가능합니다. 첫 진입의 학습 여유와 성장 후 재도전의 강함을 남긴 상태입니다. 숙련자용 후반 콘텐츠를 더 늘릴 때는 별도 도전 목표와 보스 패턴을 조정하는 편이 좋습니다.

## 검증 범위

자동 테스트는 이동·돌진·정지 상태, 포물선 정점과 착탄, 시간 간격별 넉백, 정찰과 실제 편성 일치, 기존 저장 호환, 난이도 보상·중복 지급 방지, 기존 게임 기록을 검증합니다. `npm test`와 `npm run build`로 확인합니다.

최종 자동 테스트 70개와 프로덕션 빌드가 통과했습니다. Chromium 실제 화면에서 다음 원정을 끝까지 플레이했습니다.

| 실제 화면 플레이 | 결과 | 지급·저장 |
|---|---|---|
| 1440×1080 · 정예 1-4 재도전 | 89격퇴, 4웨이브 승리 | 98G(정예 +28 포함), 2,280→2,378G |
| 390×844 터치 · 여유롭게 1-1 첫 원정 | 52격퇴, 4웨이브 승리, 리엘 합류 | 220G(추가 퀘스트80 포함) |

두 플레이 모두 귀환·새로고침 후 캠페인과 난이도·지역별 최근 기록을 확인했습니다. 콘솔 오류·경고·실패 요청·가로 넘침은 없었습니다. 별도로 320×740과 1366×768에서 시작 버튼이 화면 안에 들어오는지, 정찰 패널, 동작 줄이기, 정지 중 SVG가 유지되는지 확인했습니다. Space로 정찰 패널을 열 때 필살기가 발동하지 않고, Shift+Tab은 돌진을 선택하지 않습니다.

## 렌더 비용 비교

장식 파편에 예산을 두고, 투사체 본체·피해 숫자·타깃·보스 연출을 유지했습니다. 고정 스프라이트 프레임을 재사용하고 중복 피격 필터와 지형 노이즈 필터를 제거했습니다. 웨이브 편성은 엔진 내부에서 재사용하며 정찰 패널은 전투 수치가 바뀔 때만 갱신합니다.

적48·타워8·효과60·투사체18의 합성 장면을 같은 Chromium 1000×700·DPR1·개발 빌드에서 비교했습니다. 각 측정은 워밍업30회 후120회 렌더이며, 전→후→후→전 순서입니다.

| 측정 | 전 | 후 |
|---|---:|---:|
| 전체 SVG 노드 | 1,645 | 1,354 |
| 효과 노드 | 622 | 334 |
| 이미지 수 | 68 | 68 |
| 1차 120회 렌더 시간 | 11.95초 | 10.51초 |
| 2차 120회 렌더 시간 | 14.37초 | 9.93초 |
| React 렌더 중앙값 범위 | 37~48ms | 32.1~34ms |

첫 비격리 측정에서는 후 버전이 느렸으므로 그 결과를 개선 근거로 사용하지 않았습니다. 이후 소스 스냅샷을 독립 주입해 같은 부하로 비교했습니다. 위 수치는 합성 장면의 비용이며 일반 전투 FPS나 모든 기기의 속도 향상을 보장하지 않습니다. 증거와 재현 스냅샷은 `/workspace/.cloud-setup/evidence/arcana-render-comparison.json` 및 `evidence/render-benchmark/`에 있습니다.

실제 기기의 Safari·Firefox, 장시간 발열·배터리와 저사양 휴대폰 성능은 별도 검증 대상입니다. 클라우드 Chromium의 렌더 비용 측정은 실제 휴대폰 FPS를 뜻하지 않습니다.

## 컨셉 대비 개선

[동작 컨셉](../art-source/defense/atlases/melee-motion.png)의 넓은 발과 무거운 망치 준비를 기존 모델·PC/모바일 전투와 비교했다. 기존 강철·청동·청록 천·방패·수염을 유지하며, **걸음에서 망치 공격으로 바뀔 때 두 발이 즉시 고정 위치로 옮겨지던 문제**를 선택했다.

여덟 보행 자세 각각에서 출발하는 실제 관절 클립을 추가했다. 떠 있는 발(양발 접지 시 뒤쪽 발)을 먼저 옮기고, 그 발을 짚은 채 반대 발을 옮긴다. 몸통은 지지 발 쪽으로 체중을 정리하고 고개·방패팔·망치 상완·팔꿈치·손목을 기존 준비 자세로 연결한다. 시작은 기존 걸음과 같으며 **0.16초 이후 모든 기존 메시의 월드 변환은 원본 공격과 일치한다.** 타격 0.24초·전체 공격 0.52초·반동·회수·망치 궤적·피해 판정을 유지한다.

전투에서는 움직이는 영웅/용병 브론의 공격 생성 시 `walkEntry`를 한 번 기록한다. 0–40ms는 출발 걸음, 40–100ms는 첫 발, 100–160ms는 둘째 발 자세를 표시한 뒤 기존 높은 준비·내려치기로 이어진다. `hitAt`에 비례한 시뮬레이션 시간으로 선택하므로 일시정지·배속에 따른다. 필살기·돌파·정지 강타·동작 줄이기는 기존 표시를 쓴다. 진입 아틀라스가 하나라도 실패하면 기존 망치/보행 세트를 유지하고, 기존 세트 실패도 원래 대체 표시를 따른다.

접지는 모델 내부 좌표 기준이다. 전장 이동을 잠그거나 새 이동 명령의 미발사 공격 취소 규칙을 바꾸지 않는다. 이동 중 월드 좌표 발 고정, 방향 전환 보간과 강타 후 걸음 복귀는 이번 범위에 포함하지 않는다.

## 산출물과 재생성

- [편집 원본](../art-source/defense/dwarf-entry.blend): 원래 157개 편집 메시·재질·베벨을 유지한다. 8개 관절×8액션 세트 `Bron entry N / 관절 이름`을 같은 N(0–7)으로 지정한다. 기본 N=0이며 모든 세트는 fake user로 보존한다. 기존 `dwarf-locomotion.blend`, `dwarf-hammer-sequence.blend`는 변경하지 않는다.
- [실제 GLB](../public/defense/models/dwarf-entry.glb): `dwarf-entry-0`…`dwarf-entry-7`, 각 100fps·53키 시점·0.52초. 23,190삼각형·55개 묶음 메시·18재질, 1,428,864바이트. 작업실의 56개 메시 집계는 다중 재질 primitive 분리 때문이다. 8클립이 한 메시 집합을 공유하며 이미지 평면이나 텍스처 이미지는 없다.
- [공통 카메라 PNG](../public/defense/models/dwarf-entry.png), [128개 원본 PNG](../art-source/defense/dwarf-entry-frames/): 8방향×8출발 자세×0.06/0.12초. 384×384, 정사영 6.8, 지면 (192,330).
- `dwarf-entry-{0..7}-atlas.webp`: 방향마다 16셀, 3072×192, 셀 192×192, 지면 (96,165), 기존 브론과 같은 표시 배율 `1.2×6.8/5.8`. 합계 516,652바이트, 추가 RGBA 디코드 픽셀 합 18MiB. 실제 기기 GPU 메모리 측정은 아니다.
- [메타데이터](../public/defense/models/dwarf-entry.json): 원본·컨셉·생성기/산출물 해시, 렌더 설정, 클립·방향별 경계와 접지 검사.
- [생성기](../tools/blender/build_dwarf_entry.py): `npm run models:dwarf-entry` — Blender 4.3+, ffmpeg. 렌더 없는 원본 검사: `npm run models:dwarf-entry -- --check`. 납품 GLB 비교·접지·해시 검사: `npm run models:dwarf-entry:check`.
- 작업실 **브론 · 걸음에서 강타로**에서 출발 걸음 1–8을 선택해 재생한다. 기존 단일 WebGL 장면을 쓰며 GLB 실패 시 PNG임을 표시하고 재생을 끈다. 전투는 베이크 2.5D를 유지한다.

## 남은 범위

전투는 두 중간 베이크이며 연속 관절 보간이 아니다. 화면 게시 간격·2배속에 따라 한 공격의 모든 짧은 포즈가 표시된다고 보장하지 않는다. 시작 위상은 마지막 시뮬레이션 걸음이며 직전 화면의 걸음과 차이가 날 수 있다. 강체 다리 구조를 유지하므로 무릎 IK·전장 이동 중 발 고정·연속 방향 전환은 후속 범위다.

다음 후보는 **리엘/브론의 공격 회수→보행 연결**이다. 실제 Android 메모리·성능도 미검증이다. 이번 회차는 예약 상태를 조회·변경하지 않았고 Claude API 호출, main 병합, 서비스 배포를 수행하지 않았다.

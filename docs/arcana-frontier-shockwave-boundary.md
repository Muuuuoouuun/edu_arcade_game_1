# 변경 전장 충격파의 다리·수면 접촉

2026-11-10 · 기준 `51e2ff9518795ab30a690d9b5a5eb3c502a29ef6`. [은서리 컨셉](../art-source/defense/concepts/2026-11-06/silverfrost-pass.png)과 가로 3D 전장을 보며 다리에서 충격파를 사용했다. 기존 접촉 고리는 지면에 투영되지만 한 구간의 네 꼭짓점 중 단차가 하나라도 있으면 구간을 통째로 숨긴다. 또 타격 전 범위 고리는 중심의 접선 평면에 놓여 강 위에 뜬다.

타격 전 예고와 타격 후 고리를 실제 지면·교량·수면 높이에 투영한다. 높이 차가 큰 구간 또는 전장 끝만 각도와 반경을 4×4로 나누고, 그중 단차를 넘지 않는 조각을 되살린다. 단차를 직접 잇는 작은 조각은 생략하여 수직 벽을 만들지 않는다. 평지에서는 접촉 고리 64구간, 준비 고리 32구간을 그대로 사용한다. 경계에는 여전히 작은 틈이 남을 수 있고, 교량·강둑 뒤는 실제 3D 깊이로 가려진다.

충격파 반경 8, 기본 망치 범위, 0.28초 접촉과 피해·넉백·이동 판정은 그대로다. 예고 고리와 접촉 고리의 폭은 각각 기존 비율을 따른다. 일시정지·배속은 시뮬레이션 시간, 동작 줄이기는 정지된 고리와 파편 생략을 유지한다. 캠페인 전투는 기존 2.5D다. 기존 3D 지형·카르 모델과 편집 원본, GLB·베이크는 재사용하며 새 모델을 만들지 않았다.

## 자원과 검증

- 기존 한 장면·효과 슬롯 풀을 재사용한다. 고정 크기 버퍼의 활성 정점 범위만 갱신하며, 다음 효과가 더 작아지면 이전 조각은 그리지 않는다. 최악 용량은 접촉 고리 슬롯당 CPU 배열 약 60KiB(이전 약 3.75KiB), 준비 고리 약 30KiB이며 GPU 복사본도 사용한다. 슬롯은 화면 종료 시 해제한다.
- 다리 중심, 배율 1인 표본에서 접촉 고리의 수평 투영 면적은 17.1256→19.1924 전장 단위²다. 평지 표본은 19.5721과 128삼각형으로 같다. 722개 위치·배율의 활성 59,636개 조각 중심에서 실제 표면과 0.9단위 이상 차이 나는 사례는 없었다. 이는 표본이며 모든 위치의 틈이 사라졌다는 뜻은 아니다.
- PC 1024×576·가로 모바일 844×390의 실제 지휘 화면에서 다리 클릭/이동, 0.28초 전 준비·접촉, 일시정지·2배속·동작 줄이기를 확인했다. 카르 GLB 실패 시 기본 3D 모형, 메뉴 이미지 실패 시 이전 미리보기의 대체 경로도 검사했다. 모바일 배포 산출물에서 타이틀→마을→전장→준비→접촉을 실행했다. 전체 테스트 508개와 웹·모바일 빌드가 통과했으며, 비교 화면은 저장소 밖 회차 증거 폴더에 남겼다.
- 844×242 Chromium SwiftShader, 적 12개·다리 위 영웅의 각 3초 단일 표본에서 접촉 전후 평균 96.87/94.09ms, 호출 41/41, 삼각형 42,084/42,260이었다. 준비 전후 평균 98.11/96.47ms, 호출 40/40, 삼각형 41,892/42,292였다. 짧은 소프트웨어 측정이므로 성능 향상을 확정하거나 실제 기기 프레임 속도로 해석하지 않는다.

실제 Android/iOS GPU·발열, 극단적인 단차의 잔여 틈, 보스 등 여러 충격파가 동시에 활성화되는 상황의 메모리는 후속 검증 대상이다. 새 실제 3D 맵, 물리 충돌이나 신규 스킬 판정을 추가한 작업은 아니다.

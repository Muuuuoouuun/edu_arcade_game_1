# 달빛 늑대의 달리기와 전장 보폭

2026-11-07 KST 회차. 기준 `9b39a17a8dee7166576ccc25198f9454bca6dc70`, 소유 브랜치 `codex/arcana-stage-experience-20261106`. 원격 main `2eabc76`, Claude `da333f1`/`bf7c1c6`은 변동이 없었다. 별도 PR #81의 번개탑 작업과 앞선 모델·지형·성문·공격 계보를 보존했다.

## 컨셉과 구현

`public/defense/snow-atlas.png`의 작은 은빛 동료와 기존 보행 원본, PC/모바일 전투 화면을 실제로 비교했다. 큰 귀·초록 눈·목장식·둥근 몸은 이미 모델에 있었지만, 발의 짧은 움직임에 비해 전장 이동이 커서 몸이 미끄러졌다. 기존 전투는 방향과 무관하게 64 보드 단위마다 한 걸음을 반복했다.

이번에는 **실제 발의 밀기·회수 동작과 전장 이동량을 연결**했다. 대각선 발 두 쌍이 번갈아 주기의 25% 동안 지지한다. 각 발은 지지 중 모델 단위 1.06만큼 뒤로 밀고, 나머지 75% 동안 완만하게 앞으로 회수한다. 발의 최대 들어 올림은 0.24, 몸은 지지 때 최대 0.025 낮아지고 비행 구간에서 최대 0.09 올라간다. 기존 귀·꼬리·목장식의 후속 움직임은 유지한다. 빠른 따라가기에 맞춘 대각선 달리기이며, 이전 기본 보행과 달리 네 발이 모두 공중에 있는 구간이 있다.

한 주기의 전진 거리 4.24 모델 단위를 공통 카메라의 8방향으로 투영했다. 기본 표시 크기 73에서 한 주기는 동/서 약 64.04, 대각선 약 33.51, 남/북 약 25.50 보드 단위다. 이동한 각 구간을 해당 방향의 보폭으로 나눈 `gaitCycles`를 시뮬레이션에 누적한다. 방향이 바뀌어도 지난 전체 이동 거리를 새 방향 보폭으로 다시 계산하지 않는다. 모바일의 큰 표시 크기에는 보폭도 비례해서 늘린다.

이 값은 시각 상태다. 이동 속도·경로·표적·피해·공격 시점을 바꾸지 않는다. 정지·일시정지 때 주기가 멈추고, 2배속도 기존 고정 시뮬레이션 스텝을 따른다. 동작 줄이기는 방향별 중립을 사용하며, 이미지 실패 시 기존 동료 삽화 세트로 돌아간다. 물기 원본·GLB·PNG·WebP·소켓은 기준 바이트를 보존했다.

## 산출물과 재생성

```sh
# 기존 물기 산출물을 보존하고 보행만 갱신
npm run models:pet-wolf -- --walk-only
# 출력물을 바꾸지 않는 방향/포즈 경계 검사
npm run models:pet-wolf -- --walk-only --check
# 물기와 보행 전체 재생성
npm run models:pet-wolf
```

Blender 4.3.2, ffmpeg, Cycles CPU 64 samples를 사용했다. `--walk-only`는 기존 `moonlight-wolf.json`과 물기 산출물이 필요하다. 전체 명령은 물기와 보행을 모두 생성한다.

| 산출물 | 경로/규격 |
| --- | --- |
| 생성 코드 | `tools/blender/build_pet_wolf.py` |
| 편집 원본 | `art-source/defense/moonlight-wolf-walk.blend`, 2,864,716바이트 |
| 실제 보행 클립 | `public/defense/models/moonlight-wolf-walk.glb`, `moonlight-walk`, 0.8초, 1,370,600바이트 |
| 공통 카메라 원본 | `art-source/defense/moonlight-wolf/moonlight-walk-{방향}-{포즈}.png`, 8×8장, 384×384 |

| 생성된 보폭 상수 | `src/games/defense/petWolfGait.ts` |

기존 정사영 카메라 크기 6.8, 원본 지면 `(192,330)`, 배포 지면 `(128,220)`, 삼각형 20,712개·39메시·10재질을 유지한다. 20개 노드가 실제로 움직이며, 작업실의 단일 3D 장면에 연결된다. 전투는 베이크 이미지이며 GLB를 요청하지 않는다. 이미지 평면을 3D 모델로 사용하지 않았다. 아틀라스 해상도·개수는 동일해서 전체 동료 RGBA 디코딩 규모는 약 32MiB로 유지된다.

## 검증

저장소 밖 `/tmp/arcana-hourly-20261107-1334/`에 기준·소유권·범위·수용 기준, 전후 화면과 검증 로그를 남겼다. 새 환경에서는 임시 증거가 사라질 수 있으며 원본·생성 코드·규격은 저장소에서 복구한다.

- 전체 테스트 **226개 중 225개 통과**, 기존 수학 `(3×7)÷5`의 실제 4/기대 4.2 실패만 남았다. 최종 TypeScript/Vite 빌드와 diff 공백 검사 통과. 추가 검사는 방향 전환·구간 분할·정지·배속·일시정지·표시 크기와 접지 좌표를 다룬다.
- 스테이지 1/5/8, 드루이드 영웅 또는 드루이드 용병의 이동·웨이브·방향 전환·일시정지·배속을 기준과 **10,851회** 비교했다. 추가한 시각 값 `gaitCycles`를 제외한 모든 상태가 같았다.
- 원본/GLB 81프레임·20노드의 변환 오차 최대 약 `5.37e-7`, 시작/끝 오차 약 `2.94e-17`, 발바닥 최소 높이 0.005다. 클립·해시·아틀라스 알파·경계를 확인했다.
- 8개 정방향의 지지 포즈에서 발의 투영 좌표와 몸의 전진을 합산했다. 기본 크기에서 최대 접지 오차는 기준 약 14.98 보드 단위에서 새 동작 약 `9.82e-6`으로 줄었다. 이는 **선택된 지지 포즈의 기하 측정**이며, 8포즈 이미지 사이의 연속 미끄러짐이 0이라는 뜻은 아니다.
- 실제 Board의 920조합(공격 시점·보행 단계·방향·PC/모바일·동작 줄이기·물기/보행 이미지 실패) 통과. 별도 192조합에서 실제 SVG 배율·위치와 발 좌표를 연결해 지지 위치를 검사했다. 최대 화면 투영 오차 PC 약 `0.000044px`, 모바일 약 `0.000019px`였다.
- Chromium 1440×900 / 390×844에서 실제 진입·이동·정지·웨이브·물기·일시정지/재개·1배/2배·동작 줄이기를 조작했다. 이동 중에도 일시정지하면 위치·포즈·누적 주기가 고정됐고, 재개 후 표시 프레임이 누적 주기와 일치했다. 물기 관측 길이는 PC 444/191ms, 모바일 442/192ms(1배/2배, 브라우저 관측 간격 포함)였다.
- 같은 방향·이동 거리·화면 크기의 전후 화면을 비교했다. 작업실 PC/모바일의 실제 GLB 재생/정지·회전·메시 보기·동작 줄이기·다운로드, GLB 실패 시 PNG 대체도 통과했다. 예상 밖 페이지 오류나 전투 GLB 요청이 없었다.

초기 검사에서 새 테스트의 변수 타입 추론과 배속 적용 위치에 대한 잘못된 가정을 수정했다. 배속은 UI가 고정 스텝을 더 실행하는 방식이다. 초기 로그를 남겼으며 기존 수학 오류와 구분했다.

## 남은 차이

8방향/8포즈 베이크이므로 포즈 사이의 발 미끄러짐과 정방향 사이의 측면 오차는 남는다. 남북 방향은 카메라 투영 보폭이 짧아 같은 화면 이동 속도에서 주기가 빠르고, 특히 30Hz 게시·2배속에서는 일부 자세가 생략될 수 있다. 시간을 늘려 피해·이동 규칙을 바꾸거나 벽시계로 보행을 구동하지 않았다.

임의 보행→물기 전신 보간, 화면 크기 변경 순간의 위상 유지, 연속 회전·지형 IK, 실제 Android 성능은 후속 범위다. 다음 우선 후보는 **달빛 늑대의 보행→물기 발 자세 연결**, 이어서 마을 건축의 깊이·가림이다.

Claude API와 예약 도구는 사용하지 않았다. 예약 활성 상태·다음 실행 성공은 확인하지 않았으며 이번 개발 결과와 구분한다. main 병합·서비스 배포도 수행하지 않았다.

# 가로 전장과 서리 협곡

2026-11-09 (KST). `codex/arcana-stage-experience-20261106`, 기준 `82530a5`.

극지 전장 컨셉 `art-source/defense/concepts/2026-11-09/polar-battlefield.png`의 눈 처마, 푸른 얼음 절벽, 어두운 수로, 석조 성문을 실제 변경 전장에 옮겼다. 숲과 설산을 전장 선택 화면에서 고를 수 있으며 세 모드 모두 적용된다. 이번에는 같은 이동 경로를 사용하는 배경 변형이며, 새 미션이나 보상 체계는 추가하지 않았다.

- 지형: 경계 바깥의 비대칭 빙하 능선, 협곡 안쪽 눈 처마와 고드름, 수면 위 얼음 조각, 눈 쌓인 다리 난간. 기존 경사·교량·수로 충돌 규칙을 유지한다.
- 성문: 실제로 열린 통로, 9개 방사형 아치 돌, 층별 석조 기둥, 눈 덮인 흉벽, 남색 깃발과 황동 등불. 지형과 별도 GLB로 로드한다.
- 밝기: 서리 장면에 ACES 톤 매핑을 적용해 강한 햇빛에서도 눈·돌의 밝은 면이 흰색으로 뭉개지지 않도록 했다. 숲 장면은 기존 설정을 유지한다.
- 가로 플레이: 기존 캠페인과 변경 전장은 세로 화면에서 입력과 진행을 막고 회전 안내를 표시한다. 다시 가로가 되어도 직접 재개한다. 메뉴·거점·모델 작업실은 세로에서도 사용할 수 있다.
- React는 선택·HUD·회전 안내를, Three.js의 기존 단일 장면은 입체 전장을 담당한다. 기존 2.5D 캠페인 배경을 실시간 3D로 전환한 것은 아니다.

## 편집 및 재생성

```sh
npm run models:frontier-frost
npm run models:frontier-frost:check
```

`art-source/defense/frontier-frost.blend`는 기존 `frontier-terrain.blend`의 경사·교량 구조에서 파생되며 지형 428개, 성문 38개의 편집 가능한 메시를 보존한다. 원본 숲 파일과 생성기는 수정하지 않았다. 성문은 별도 컬렉션에 있고, GLB 내보내기 때 원점으로 옮긴다. 이미지 평면이나 텍스처로 모형을 대체하지 않는다.

`public/defense/models/` 산출물:

- `frontier-frost.glb`: 11,864 삼각형, 정점 색상 1표면.
- `frontier-frost-gate.glb`: 456 삼각형, 정점 색상 1표면.
- `frontier-frost.png/.webp`: 가로 960×540 공통 전체 카메라 베이크. 배경 선택 미리보기.
- `frontier-frost-crossing.png`: 가로 960×540 교량 단면 확인용 렌더.
- `frontier-frost-gate.png/.webp`: 투명 384×384 성문 베이크. 작업실 실패 시 미리보기와 향후 2.5D 배치용이며 기존 캠페인 성문을 교체하지 않는다.
- `frontier-frost.json`: 원본·생성기·산출물 해시, 카메라, 범위, 재생성 명령.

모델 작업실에서 `?model=frontier-frost`와 `?model=frontier-frost-gate`로 실제 메시를 회전하거나 와이어프레임으로 확인한다. GLB 실패 시 PNG를 보여주며, PNG도 실패하면 미리보기 부재를 알린다. 변경 전장의 GLB 실패는 기본 입체 모형으로 계속한다.

## 검증 기록

- 빌드 통과. 전체 테스트 429개 중 428개 통과. 기존 무관한 수학 테스트 `(3 × 7) ÷ 5`의 `4 !== 4.2` 한 건은 그대로다.
- GLB 해시, 실제 광선 716개 지면 높이, 다리 상판 높이 0.36, 열린 아치 통로, 삼각형·표면 예산, `.blend` 재열기 확인.
- PC 1440×900 / 모바일 844×390: 배경 선택, 포탑 건설, 일시정지, 배속, 화면 회전 후 수동 재개. 기존 캠페인도 세로 입장→가로 복귀→재개→재회전 확인.
- 실제 키보드·터치 이동, 공격 준비/피해 시점, 정지 픽셀 동일성, 동작 줄이기, 배속, 돌진 취소/환급, 충격파 확인.
- 모델 작업실 PC/모바일 회전·메시 보기, GLB/PNG 실패 확인. 지형·성문·선택 이미지 동시 로딩 실패에서도 진행 가능. 회전 때 누르고 있던 이동 입력을 해제한다.
- 빌드된 게임에서 PC/모바일 각 정상/지형 실패 4경우의 실제 다리 클릭·터치, 2배속 횡단, 수면 이동 차단, 동작 줄이기, 동쪽 강변 도착을 확인했다.
- WebGL 픽셀 검사에서 협곡 벽 뒤의 파란 탐침은 가려지고 벽을 숨기면 드러난다. 캔버스는 하나다.

소프트웨어 WebGL(Chromium/SwiftShader, 모바일 뷰포트, 지휘 모드, 순차 측정)의 1/10/30 적 비교에서 평균 프레임 시간은 숲 88.71/94.64/132.52ms → 서리 67.54/82.18/105.02ms였다. 새 지형 자체는 숲보다 356삼각형 늘지만 단순화된 석조 성문으로 전체 장면 비용은 줄었다. 이는 실기기 60fps 통과를 의미하지 않으며 Android GPU 측정은 남아 있다.

원격 main `4472e03`의 PR98 히트스톱과 Claude `6924533`의 운영 기획64를 확인했다. 이번 범위에서는 별도 통합하지 않았다. 기존 개발 계보의 지형·성문·영웅·통나무 병사·봉화 기능은 유지한다.

남은 차이: 컨셉의 자연스러운 얼음 곡면, 밧줄 다리, 고유 극지 적은 아직 없다. 건축물 기둥의 정밀 충돌도 후속 범위다. 이번 성문은 고정 모형이며 피격/붕괴 동작은 다음 후보다. 별도 일정 예약, main 병합, 서비스 배포, Claude API 호출은 하지 않았다.

# 변경 전장 · 시뮬레이션 시간으로 움직이는 돌진

기존 녹음 컨셉의 낮게 체중을 싣는 망치 영웅과 직전 OpenAI 돌진 시안, PC·가로 모바일 전장을 비교했다. 이전에는 실제 이동 좌표가 입력 한 프레임에 바뀌었고, 86회차의 지면 흔적만 그 경로를 보여 줬다. 이번에는 영웅의 **실제 게임 좌표**가 이동한다.

솔로 돌진은 같은 방향으로 최대 5단위를 초당 25단위로 이동한다. 최대 거리는 시뮬레이션 0.2초이고 경계에서 짧게 막히면 같은 속도로 더 빨리 끝난다. 기존 20개 경로 단계 각각의 선분이 강의 금지 구역을 가로지르는지도 검사해, 두 표본 사이에서 다리 모서리를 스치는 경우를 차단한다. 기존 3초 대기시간과 진행 중 공격 취소·미발동 쿨다운 환급은 유지한다. 발자국과 기존 청록 흔적은 실제로 이동한 거리까지만 진행한다.

돌진 중 방향키와 지면 목표는 착지 전 경로를 바꾸지 않는다. 지면 목표는 착지 후 이어지고, 방향키는 착지 후 다시 적용된다. 공격·스킬·상호작용은 이동 중 시작하지 않으며 해당 버튼을 잠시 비활성화한다. 돌진은 무적이 아니다. **적의 0.28초 접촉 시점에 실제 위치가 아직 범위 안이면 피해를 받고, 벗어났으면 회피한다.** 이전의 즉시 순간이동과 전투 결과가 달라질 수 있다.

기존 카르의 실시간 3D 모델과 거리 기반 보행을 사용하고, 이동 중 몸을 짧게 앞으로 기울인다. 기울기 때문에 발끝이 지형을 관통하지 않도록 돌진 중에는 발 메시 전체의 최저점을 검사한다. 두 GLB가 실패한 기본 영웅은 몸 기울기를 생략하지만 같은 게임 이동과 흔적을 사용한다. 동작 줄이기에서는 기울기와 흔적을 생략하되 플레이어가 조작하는 실제 이동은 유지한다. 일시정지·2배속은 시뮬레이션 시간에 적용된다. 새 Blender 모델·애니메이션 클립이나 기존 2.5D 캠페인 전환은 없다.

## 검증

- 1/4·1/2·3/4·완료 위치, 2배속, 일시정지, 기존 공격 취소·환급, 착지 후 입력, 도중 지면 목표, 공격 중 입력 차단을 검사했다. 짧은 0.5단위 경로는 0.02초에 끝난다.
- 다리 양쪽 모서리와 16방향의 시간 표본에서 통행 금지 구역에 들어가지 않는지, 표본 사이를 스치는 반례가 차단되는지 확인했다. 적 공격 직전에 시작한 돌진은 실제로 벗어나기 전에는 피해를 받는다.
- 카르의 평지·경사·다리, 8방향·3개 기울기 시점에서 양쪽 발 메시의 지형 비관통과 반복된 정지 시점의 안정성을 확인했다. 모든 지형과 움직임의 완전한 발 IK는 아니다.
- PC 1024×576 키보드와 가로 모바일 844×390 터치로 보행→스킬 준비→돌진 취소→중간 이동→일시정지·동작 줄이기·2배속→착지 후 스킬 접촉을 조작했다. 두 영웅 GLB 요청 실패 폴백에서도 확인했다. PC 마우스·모바일 터치의 지면 목표가 돌진 중 대기되고, 실제 3D 영웅이 앞 물체에 가려지는 것도 검사했다. 모바일은 Chromium 에뮬레이션이다.
- 전체 테스트 532개, 웹 빌드와 모바일 오프라인 빌드를 통과했다. 모바일 패키지에서도 같은 조작 흐름을 확인했다. 단독 SwiftShader 표본에서 단일 캔버스의 드로콜 38개와 삼각형 46,210개는 변경 전후 같았다. 소프트웨어 렌더러의 짧은 표본이므로 실기기 성능 보장은 아니다. 기존 빌드에도 나타나는 Three.js 그림자 설정 경고가 남아 있다.

실제 Android/iOS GPU와 사용자 플레이, 복잡한 동적 장애물과 다른 적 종류의 타격 조합은 후속 검증이 필요하다. 이동 중 공격을 누르면 입력은 버려지며 자동으로 예약되지 않는다.

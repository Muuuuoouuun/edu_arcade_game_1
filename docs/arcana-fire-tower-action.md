# 화염 수정탑 Lv.2 — 고정 기초와 수정 충전·방출

## 컨셉과 실제 차이

`art-source/defense/concepts/2026-10-29/props/six-tower-modules.png`의 수정탑은 석조 기초·금속 지지대·큰 발광 수정이 구분된다. 기존 화염탑의 주황 수정과 어두운 돌, 청동 테두리는 유지했다. 전투 화면에서는 전체 탑이 흔들리고 발사 광원이 수정 옆에 생겨, 무거운 기초와 움직이는 코어를 구분하기 어려웠다.

이번에는 **기초를 고정하고 수정과 네 청동 지지대만 움직인다**. 수정이 낮아져 충전한 뒤 솟아오르고, 지지대는 실제 회전축을 중심으로 펼쳐졌다가 복귀한다. 좌우 표적을 바꿔도 석조 문양이 뒤집히지 않는다. 준비 광원·발사 섬광은 현재 수정의 투영 좌표에 놓이고, 마법탄도 방출 자세의 같은 좌표에서 출발한다.

`towers.blend`의 기존 형상을 독립 원본으로 가져와 수정 코어의 이동·배율과 네 지지대의 회전 곡선을 작성했다. 수정은 준비에서 0.21 모델 단위 내려가고 0.9배로 모이며, 방출에서 0.14 올라가고 1.06배로 팽창한다. 지지대는 방출 때 0.43rad 펼쳐진다. 원본의 기초·벽·장식 76메시는 고정이다.

## 시점과 전투 연결

기존 엔진의 시전 준비 **0.15초**, 반동 **0.24초**를 그대로 따른다. 피해·사거리·표적·이동·저장은 바꾸지 않았다.

| 자세 | 원본 시각 | 전투 선택 |
| --- | --- | --- |
| 중립 | 0초 | 준비/반동 없음 |
| 모으기 | 0.05초 | 준비 진행률 0~0.6 |
| 충전 | 0.13초 | 준비 진행률 0.6~1 |
| 방출 | 0.15초 | 발사 후 반동 잔여 >0.18초 |
| 반동 | 0.21초 | 잔여 >0.10초 |
| 가라앉기 | 0.30초 | 잔여 >0초 |
| 중립 복귀 | 0.39초 | 잔여 0초 |

전투는 6개 베이크 자세를 선택하고 작업실은 0.39초의 실제 GLB 곡선을 재생한다. 별도 벽시계 애니메이션이 없어 일시정지·배속과 일치한다. 동작 줄이기는 중립 모델을 유지하며 광원·탄 출발점도 중립 소켓을 사용한다. 코어의 기존 절차적 회전은 작성된 클립과 중복 적용하지 않는다.

이미 발사된 탄은 기존 엔진의 `sourceLevel` 스냅샷을 사용하므로 현재 탑의 강화·판매 여부에 의존하지 않는다. 소켓 보정은 도착 시 0으로 줄어들며 충돌 좌표에는 영향을 주지 않는다. 아틀라스 또는 원본 대기 렌더가 실패하면 기존 화염탑 이미지와 기존 연출을 사용한다. Lv.3와 번개 분기는 이번 클립을 사용하지 않는다.

## 제작물과 재생성

```sh
npm run models:fire-action
npm run models:fire-action -- --check
```

Blender 4.3.2, Cycles CPU 48 samples, ffmpeg를 사용한다. 카메라는 기존 포탑과 같은 정사영 7.5, 위치 `(9,-12,12)`, 주시점 `(0,0,2.35)`다. 전투는 2.5D이며 유닛별 WebGL 렌더러를 추가하지 않았다.

- 생성기: `tools/blender/build_fire_tower_action.py`.
- 편집 원본: `art-source/defense/fire-tower-action.blend`.
- 실제 모델: `public/defense/models/fire-tower-action.glb`, 클립 `fire-core-release`.
- 공통 카메라: `art-source/defense/fire-tower-action/{rest,gather,charged,release,rebound,settle}.png`, 640×640.
- 작업실 대체 렌더: `public/defense/models/fire-tower-action.png`.
- 전투: `public/defense/models/fire-action-atlas.webp`, 2304×384의 6포즈.
- 규격·소켓·해시: `public/defense/models/fire-tower-action.json`, `src/games/defense/fireTowerSockets.ts`.

기존 640px 카메라 지면 `(320,488.648)`과 크롭 `(32,24,576,576)`, 표시 배율 1.16을 유지한다. 전투 배포 프레임은 384px, 크롭 `(19.2,14.4,345.6,345.6)`다. 메시를 부모 관절·재질별로 묶어 작업실은 **15,872삼각형·17메시**, GLB 약 869KiB다. 전투 아틀라스는 98,484바이트(약 96KiB)이며 디코딩 RGBA는 **3.375MiB 추가**다. 실제 모바일 GPU 메모리 측정값은 아니다.

## 검증과 남은 범위

증거 폴더 `/tmp/arcana-hourly-20261107-1142/`에 기준/소유권/미완료 상태, 원본 및 전후 화면, 검사 코드와 로그를 남겼다. 임시 폴더는 환경 교체 때 사라질 수 있으므로 재생성에 필요한 파일은 저장소에 포함한다.

- 전체 테스트 **220개 중 219개 통과**, 기존 무관한 수학 `(3×7)÷5` 기대 4.2/실제 4 실패만 남음. TypeScript/Vite 빌드 통과.
- 소켓의 원본 투영값, 충전/방출 경계, 잘못된 입력, 동작 줄이기, 레벨·분기 격리, 이미지 실패와 파일 해시 검사.
- 편집 원본 40프레임과 GLB 재불러오기에서 기초 변환 및 시작/끝 차이 0. 코어와 네 지지대가 실제로 움직이고 복귀. GLB 0.39초·6개 애니메이션 채널.
- PC 1440×900·모바일 390×844의 실제 Board 35조합과 Lv.3 분기 확인. 섬광/탄 출발점은 같은 소켓이며 전투에서 GLB를 요청하지 않음.
- 실제 진입→마법탑 건설→화염 강화→웨이브→일시정지/재개→2배속→동작 줄이기 조작. 최종 PC 공격 관측 366/192ms, 모바일 333/173ms(1배/2배, 브라우저 관측 간격 포함). 타격 전 방출 자세 없음.
- 작업실 PC/모바일 실제 GLB 재생·중립 복귀·회전·와이어프레임·동작 줄이기·다운로드, GLB 실패 시 PNG 대체 확인. 예상 밖 페이지 오류 없음. 모바일 확대 화면에서도 6단계·정지·배속·동작 줄이기를 확인했다.

검사 과정에서 방출 자세의 WebP 필터 가장자리가 크롭 경계에 닿는 것을 발견해 상승 높이를 0.22→0.14로 줄이고 다시 베이크했다. 처음 GLB 재불러오기 검사는 Blender 가져오기 프레임이 0부터 시작하는 점을 놓쳤다. 검사기를 0~39프레임으로 고쳐 원본의 1~40프레임과 맞췄다. 모바일 첫 자동화는 지도 확대 전환 도중 건설 지점을 눌러 실패했으며, 전환 완료 후 터치해 통과했다. 이 검사기 문제와 모델 경계 수정의 로그를 구분해서 보존했다.

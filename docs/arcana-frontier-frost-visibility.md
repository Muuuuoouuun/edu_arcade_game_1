# 서리 협곡 절벽 뒤 영웅 가독성

2026-11-10. 기준 `c6146bd9d243a0be3574dc7253b7a5ae8733254b`. 은서리 고개 컨셉과 실제 가로 변경 전장을 비교하면 눈 덮인 절벽이 깊이를 만들지만, 낮은 모바일 카메라에서 동쪽을 지나는 영웅의 몸을 가렸다. 직전 작업의 1,944개 시선 표본 중 기존 절벽에 의해 가린 52개는 모두 모바일 조건에서 나왔다.

지휘·솔로 모드에서 영웅이 전장 가장자리에 가까우면, 카메라에서 영웅 중심과 주변을 향한 광선으로 가리는 지형 재질을 찾는다. 영웅 주변의 작은 화면 영역에서 **영웅보다 카메라에 가까운 픽셀만** 점차 제외한다. 뒤쪽 땅은 유지하고, 가림이 없거나 방어 모드일 때는 지형을 온전히 그린다. 이동·공격·피해 판정과 클릭/터치에 쓰는 지면·교량 메시, 카메라는 변경하지 않는다. 하나의 Three.js 장면과 기존 실시간 3D 지형 GLB를 재사용하며 기존 2.5D 캠페인에는 적용하지 않는다.

한 표면으로 합쳐진 설산에 매 프레임 5개 광선을 그대로 쏘는 비용을 줄이기 위해, 정적 단일 메시의 삼각형 인덱스를 8×8 영역으로 나눈 CPU 전용 검사 구조를 지형 로딩 때 만든다. 방어 모드에서는 만들지 않는다. 꼭짓점과 재질은 원본을 공유하며 검사 구조는 렌더링하거나 입력에 사용하지 않는다. 지형 대체 로딩 시 이전 검사 구조와 셰이더 훅을 해제한다. 다중 메시·스킨 메시·인스턴스 등은 원본 광선 검사로 대체한다. 눈·절벽 모델의 `.blend`·GLB·공통 카메라 렌더·메타데이터와 재생성 명령은 [기존 서리 숲 기록](arcana-frontier-frost-forest.md)에 있으며 이번에 모델을 다시 제작하지 않았다.

## 검증 범위

- 서리 지형의 PC/가로 모바일, 지휘/솔로, 세 줌, 전체보기의 720개 위치·카메라 조합에서 분할 검사와 원본 메시 검사의 결과가 같았다. 내부의 1,176개 추가 표본에서는 경계 검사 범위 안쪽에 가려진 영웅이 없었다. 원본 기준점에 대한 단위 검사도 함께 실행한다.
- 가로 모바일에서 실제 교량 클릭·이동 후 동쪽 절벽에서 기존에는 가려지던 영웅을 확인했다. 같은 경로의 PC·모바일 이전/이후 화면을 회차 증거 폴더에 저장했다. 충격파 준비와 타격, 일시정지·2배속·동작 줄이기에서도 위치·판정과 국소 시야를 확인했다.
- 새 지형과 이전 GLB의 단계별 실패, 기본 절차 지형, 메뉴 미리보기 실패, 기존 녹음 성문과 맵 전환을 확인했다. 모바일 배포 빌드에서 타이틀부터 지휘와 일시정지까지 실행했고 전체 테스트 506개와 웹·모바일 빌드가 통과했다. 검사는 표본이며 모든 카메라·위치에서의 가림 해소를 보증하지 않는다. 지형 뒤의 분대원이나 적은 이 처리의 대상이 아니다.
- Chromium SwiftShader에서 844×242 렌더 영역, 적 12명, 이동하는 영웅의 동쪽 절벽 시점으로 각 3초씩 한 번 비교했다. 이전/이후 평균 프레임 간격은 118.29/120.90ms, p95는 각각 150ms, 렌더 호출은 67회, 삼각형은 43,452개였다. 소프트웨어 렌더의 짧은 표본이므로 실제 기기의 프레임 속도로 해석하지 않는다.

실제 Android/iOS GPU의 프레임 시간·발열과 스크린 리더 체험은 별도 검증이 필요하다. 물체의 물리 충돌이나 실제 3D 캠페인 전환을 추가한 작업은 아니다.

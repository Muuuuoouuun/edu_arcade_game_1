## 게임과 미술의 기준

- 2026-11-12 캐릭터 미술 보정: 신규 캐릭터도 기본 영웅 아틀라스의 큰 머리·짧은 팔다리와 입체적인 판타지 재질을 따른다. 문화권·종족·무기의 다양성은 유지한다. [비율·질감 제작 기준](arcana-character-art-standard.md)과 [테마별 보정판](../art-source/defense/concepts/2026-11-12-characters/base-theme-v2/README.md)을 새 시안 제작의 기준으로 사용한다.

- 아르카나는 동료를 모으고 영웅을 직접 지휘해 타워와 함께 마을을 지키는 **독립 모바일 판타지 디펜스**다. 기존 캠페인의 영웅 이동·타워 배치·자동 공격·웨이브·속성 상호작용·마을 성장과 모바일 조작을 출발점으로 한다. 선택형 전술 힌트는 가능하나 문제 풀이와 암기를 진행 조건으로 만들지 않는다.
- 사용자의 후속 요청에 따라 낡은 2D 전장 이미지에 맞춘 설계를 끝내고 실제 3D 지형과 모델 중심으로 전환한다. 기존 영웅·포탑의 모델, 재질, 문화권과 무기 정체성은 보존·발전시킨다. 참고 이미지의 카메라·맵 가독성은 배움의 대상이며 아르카나의 세계관과 캐릭터를 사용한다.
- 네 거점 테마와 세계관 일러스트는 유지한다. 극지·열대, 신규 사건·보스·문화권 세부는 시안 또는 제안으로 표시하고 채택 전 확정 사실로 취급하지 않는다. 스토리·점수 랭킹은 장기 기획이며 구현 완료가 아니다.
- 기존 교육용 아케이드, [카드·퀴즈 기반 방어 실험](arcana-guard/README.md), Rush·Frontier는 별도 작업이다. 기존 캠페인에 그들의 퀴즈·마나·새 전투 규칙·성장·저장 형식을 자동으로 혼합하지 않는다.

## 보존과 충돌 주의

- `work`의 `towers.blend`, 기본 타워 GLB/PNG, `manifest.json`, `build_towers.py`는 main의 동명 파일과 다르다. 덮어쓰지 않는다. 개선 타워 생성 옵션은 구버전 생성기에 있어 따로 격리하고 출력 경로를 안전하게 바꾸기 전 실행하지 않는다.
- 이전 작업 공간 `/workspace/edu_arcade_game_1`의 카메라 비교 HTML·코드·이미지·임시 이안 `.blend`는 **미추적이므로 원격 work 브랜치에 없다**. 옛 2D 맵을 불러올 수 있는 각도 실험이며 현재 게임의 전장으로 채택하지 않는다. 기존 작업 공간은 그대로 보존하며, [각도 비교 사본](../art-source/defense/archive/camera-study-20261109/README.md)을 제작 자료로만 모아 두었다.
- 저장소 밖 `/workspace/generated_images`의 40개 파일 가운데 18개는 현재 기준 작업트리의 추적 이미지와 바이트 단위로 같은 파일을 찾지 못했다. [SHA-256 목록](arcana-branch-inventory/generated-images.json)은 원본·변환본의 시각적 동일성을 판단하지 않는다. 허브/레이스 자료도 섞여 있으며 전체가 아르카나 자료라는 뜻은 아니다. Higgsfield 시안 일부는 기존 기록에 원격 URL만 있어 로컬 원본 존재가 확인되지 않았다.
- 오래된 기획 루프, 시안, 수치 분석은 작성 당시의 기록이다. 현재 활성 예약 작업이나 동작하는 앱 기능으로 간주하지 않는다. 브랜치·원본·외부 파일은 삭제하지 않는다.

## 통합 순서

1. **비교·보존:** Frontier, `work`, Claude 브랜치의 원본·실제 GLB·애니메이션 클립·생성기·의존성·용량을 현재 main과 개별 비교한다. 경로 충돌은 덮어쓰지 않고 출처와 기준 SHA를 기록한다. 카메라 실험은 보존 사본을 만들었고 저장소 밖 이미지는 별도 백업이 필요하다.
2. **게임 계약:** 현재 캠페인의 저장·웨이브·영웅 이동·설치 위치·속성·접근성을 기준으로 Frontier의 지형 좌표·충돌·투사체·카메라·조명·모델 접점을 분리한다. 별도 실험의 수치와 모드를 가져올 때는 명시적으로 설계·검증한다.
3. **작은 세로 조각:** 숲 1개 스테이지에서 영웅 1명, 기본 타워 1종, 적 1종을 실제 3D로 연결한다. 모션의 공격 판정 시점·발 접지·가림·터치·HP바를 기존 시뮬레이션에 맞춘 뒤 설산·타워 분기·나머지 영웅으로 넓힌다. 2D 전장 이미지는 되살리지 않는다.
4. **품질과 출시:** 실기기 Android의 프레임·발열·메모리·배터리·WebGL 복구와 세로·가로 입력을 측정한다. 두 카메라에서 작은 화면 가독성·실루엣·질감·적/아군 구분을 확인하고 성능 예산과 폴백을 정한다.
5. **정리 확정:** PR 병합 여부와 병합 후 tip, 백업 상태, 작업 중 브랜치를 재확인하고 필요하면 별도의 정리 계획을 세운다. 이름이나 오래된 날짜만으로 브랜치를 삭제하지 않는다.

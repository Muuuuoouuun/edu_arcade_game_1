원격 main `2eabc76`, Claude `bf7c1c6`·새 `f84397e`, 단일 작업 트리와 진행 작업을 확인했다. Claude 50회차는 main의 삽화를 기준으로 한 리엘 제작·발사점 제안이다. 통합 브랜치에는 이미 실제 리엘/루나 모델·방향별 공격·발사 소켓이 있으므로 재제작하지 않는다. 리엘/루나의 현재 모델에 대한 축소 가독성 비교는 별도 후보로 남긴다. 열린 PR #81의 번개 표적·연쇄 로직은 별도 작업이다.

## 컨셉과 실제 변경

[모듈 컨셉](../art-source/defense/concepts/2026-10-29/props/six-tower-modules.png)의 넓은 포신·금속 띠·튼튼한 받침을 기존 Lv.3 모델, PC/모바일의 실제 건설·강화·전투 화면과 비교했다. **Lv.2에서 조준·반동하던 파쇄포가 최종 강화 후 정지 모델로 바뀌고 기초 전체가 흔들리는 차이**를 줄인다.

현무암 포신·금장 포구·돌 포탄·주황 왕관·금빛 고리·붉은 문양을 유지한다. 상부 포대와 적재대가 함께 8방향으로 조준하며, 금장 포신과 쌍 피스톤은 포신 축으로 뒤로 밀린다. 최종 강화 전용으로 넓은 강철 가이드 레일, 움직이는 황동 받침과 연결대, 고정 끝막이와 갑판 지지대를 실제 메시로 추가했다. 기초·깃발·벽 받침은 고정된다.

반동 경로를 비우도록 적재대와 왕관/고리를 뒤로 0.38 이동하고, 고리는 0.32 올리고 왕관은 0.12 낮췄다. 기존 느슨한 돌 포탄 3개는 제거했다. 붉은 깃발을 성곽 측면으로 낮추고 황동 벽 받침 4개를 추가해 상부 회전 경로와 분리했다. 원래 `towers.blend`와 Lv.2 산출물은 보존한다.

기존 발사 시점 0.28초와 후속 반동 0.24초를 유지한다. 실제 GLB는 발사 전 자세를 유지하다 0.29초에 최대 반동, 0.52초에 중립으로 돌아온다. 전투는 준비·반동·복귀·정착 4포즈를 사용한다. 섬광과 포탄 출발점은 발사 순간의 금장 포구 끝에 고정하며, 이후 포신만 뒤로 움직인다. 발사 당시 등급·방향을 보존해 강화·판매·표적 이동이 이미 날아간 포탄의 출발점을 바꾸지 않는다. 피해·범위·연사 간격·판정은 변경하지 않는다.

왕관이 비스듬한 방향에서 잘리지 않도록 모든 렌더에 공통 정사영 배율 8.0을 쓴다. 이전 7.5 카메라 대비 표시 배율을 `1.16×1.025×8/7.5`로 보정하고 생성된 지면 기준을 사용해 기존 Lv.3의 전장 크기와 발 위치를 보존한다. 전투는 2.5D이고 작업실은 기존 단일 WebGL 장면의 실제 GLB다.

## 산출물과 재생성

- [편집 원본](../art-source/defense/crush-cannon-lv3-action.blend): 개별 메시·재질·베벨·포신 관절·고정 기초.
- [실제 GLB](../public/defense/models/crush-cannon-lv3-action.glb): `crush-cannon-fire`, 0.52초. 포신 관절의 이동에 피스톤·황동 받침·연결대가 함께 따른다.
- [공통 카메라 PNG](../public/defense/models/crush-cannon-lv3-action.png), [8방향×4포즈 PNG](../art-source/defense/crush-cannon-lv3-action/): 640×640, crop (32,24,576,576).
- 전투 `crush-lv3-action-{0..7}-atlas.webp`: 각각 1024×256 RGBA. 8장 디코드 픽셀 합은 8MiB이며 실기기 GPU 측정값은 아니다.
- [메타데이터](../public/defense/models/crush-cannon-lv3-action.json): 원본/컨셉/생성기/산출물 해시, 32포즈 경계·소켓, 기초 고정, 상부/깃발 및 포신/적재대·고리 간섭 검사.
- 생성: `npm run models:crush-action-lv3` (Blender 4.3+, ffmpeg). 렌더 전 검사: `npm run models:crush-action-lv3 -- --check`.
- 실제 내보낸 GLB의 발사 시점·고정 부품·반동·복귀 검사: `npm run models:crush-action-lv3:check`.
- 작업실: **파쇄포 · 최종 강화**. GLB 실패 시 PNG라고 표시하고 재생 버튼을 비활성화한다.

## 검증 기록

- 최종 GLB 1,382,332바이트, 32,194삼각형, 28 glTF 메시·30프리미티브·15재질. Three.js 작업실은 30개 메시 노드로 표시한다. 원래 Lv.3는 `towers.blend`와 정지 렌더만 있었으며 별도 Lv.3 GLB는 없었다.
- 전투 WebP 8장 합계 320,136바이트. 기존 640×640 정지 WebP 36,300바이트는 실패 대체용으로 유지한다. 새 아틀라스의 RGBA 픽셀 합은 기존 자산에 추가되는 8MiB이며 메모리 절감으로 해석하지 않는다. 실제 Android 메모리/프레임 성능은 미측정이다.
- 32개 PNG와 8개 WebP의 크기·알파·크롭 경계, 원본/컨셉/생성기/산출물 SHA-256 일치. 공통 카메라 변경 후 지면 투영과 표시 배율이 이전 Lv.3 접지/크기를 보존하는 계산을 검사했다.
- 편집 원본과 실제 GLB의 53시점 검사에서 포신·금장 포구·피스톤·황동 받침·연결대가 움직이고, 기초·고정 레일·적재대·왕관/고리는 공격 중 고정된다. 기초 이동 및 중립 복귀 오차 0. Three.js에서 고정 메시 25개의 이동 0, 0.28초까지 반동 없음, 0.285초 반동 시작, 0.52초 복귀를 확인했다.
- 포신과 적재대/고리 90쌍을 53시점에서 검사해 표면 교차 0. 상부 71메시와 고정 깃발 8개를 8방향×53시점에서 검사해 표면 교차 0. 새 가이드 기구와 적재대/고리도 별도 53시점 검사 통과. 전체 모델의 모든 부품 쌍에 대한 물리 시뮬레이션은 아니다.
- `npm run build` 통과. `npm test`: **250개 중 249개 통과**, 기존 수학 문제 `(3 × 7) ÷ 5`에서 `4 !== 4.2` 1건 실패. 기준 커밋에서도 동일하게 재현했다. 관련 신규 실패 없음.
- 기준 엔진과 변경 후 엔진을 2스테이지×3난이도×1,800스텝으로 비교해 모든 상태가 일치했다. 제외한 필드는 없으며 강화·판매·배속·일시정지를 포함한다.
- 실제 DefenseBoard 6조건×48상태 통과: PC 1440×900, 모바일 390×844, 좁은 화면 320×740, 동작 줄이기, 아틀라스 실패, 기본 이미지 실패. 발사 포탄 중심과 실제 포구 투영의 화면 오차는 최대 0.000088px. 강화·판매 후 출발점 유지, 기초 전체 흔들림 없음, 전투 중 GLB 요청 없음.
- 실제 게임 UI에서 건설→파쇄 분기→최종 강화→웨이브, 일시정지·복귀, 1배·2배속, 동작 줄이기, 모바일 터치·확대 보기 통과. 조기 반동 0건, 네 포즈 확인. 관찰된 공격 표시 시간은 PC 456/236ms, 모바일 474/206ms(1배/2배)이며 성능 벤치마크는 아니다. 모바일 전체 보기에서는 세부 레일보다 방향과 포신 반동이 먼저 읽히며 확대 보기에서 구조가 더 분명하다.
- PC/모바일 작업실의 실제 GLB 재생·정확한 자세 복귀·메시 보기·회전·동작 줄이기·다운로드 주소 확인. GLB 실패 시 `PNG · 렌더 이미지` 표시와 재생 비활성화 통과. 페이지 오류와 가로 넘침 없음. 모바일은 브라우저 뷰포트/터치 검사이며 실기기 검증은 아니다.

저장소 밖 증거 폴더는 `/tmp/arcana-hourly-20261107-2133/`다. 전후 전투 화면, 실제 전체/확대 화면, 32포즈 비교, 작업실/실패 대체 화면, 빌드·테스트·물리 상태 비교·모델 검사 로그를 보관한다. 초기 왕관 크롭과 깃발 끝장식 간섭 실패 기록도 보존했고 최종 베이크 전에 수정했다.

## 남은 범위

전투는 4포즈·8방향이며 연속 회전이나 관절 보간은 아니다. 완충 장치는 시각적 기구로 유체·기계 시뮬레이션이나 낱개 포탄 장전까지 구현한 것은 아니다. 실제 Android 성능은 미검증이다. 다음 후보는 영웅 보행→공격 전신 연결, 현재 리엘/루나 모델의 축소 가독성 비교, 마을 건축 가림이다.

이번 실행은 개발 루프 1회다. 예약을 생성·변경하거나 현재 예약 상태를 조회하지 않았으며, Claude API 호출·main 병합·서비스 배포를 하지 않았다.

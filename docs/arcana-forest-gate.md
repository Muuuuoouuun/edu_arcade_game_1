# 녹음 성문의 실제 아치 구조와 전투 가림

2026-11-06 일곱 번째 컨셉 개발 회차. 기존 성문은 삽화 전체가 유닛보다 먼저 그려져, 기둥 앞뒤에서 영웅과 적의 순서가 맞지 않았다. 숲 지역의 녹음 테마에 실제 성문 모델과 유닛 깊이 정렬을 연결했다.

## 컨셉과 구현

기준 컨셉은 `art-source/defense/concepts/2026-10-29/castles/verdant-citadel.png`와 기존 녹음 성문 삽화다. 석조 아치, 기둥을 감싼 뿌리, 초록 지붕, 등불과 잎 문장을 큰 형태로 옮겼다. 전투 크기에서 돌·목재·지붕을 구분하도록 재질을 나누고, 뿌리는 끝으로 갈수록 가늘어진다.

- 쐐기돌 13개와 내부 모르타르가 아치를 이룬다. 양쪽 기둥은 석재 코스·모르타르 코어·기초석으로 구성한다.
- 아치 아래는 실제 빈 통로다. 검은 면을 붙이거나 정지 그림을 3D처럼 표시하지 않는다.
- 전망대의 기둥·난간, 겹친 지붕 판재, 뿌리와 등불은 개별 메시다. 편집 원본은 162개 부품을 유지한다.
- GLB는 평가된 메시를 재질별 10개 메시로 묶었다. 작업실에서 22,630개 삼각형을 확인했다. 전투는 약 35KB의 WebP 한 장을 사용하며 GLB를 요청하지 않는다.

대상은 **숲 지역의 녹음 테마**다. 설산의 적설 표현과 나머지 성 테마는 기존 삽화/SVG를 유지한다. 피해량·통행 판정·마을 체력·저장 형식은 변경하지 않았다.

## 산출물과 재생성

```bash
npm run models:forest-gate
```

- 제작 코드: `tools/blender/build_forest_gate.py`
- 편집 원본 / 고정 카메라 렌더: `art-source/defense/forest-gate.blend`, `forest-gate.png`
- 실시간 3D / 미리보기: `public/defense/models/forest-gate.glb`, `forest-gate.png`
- 전투 이미지: `public/defense/models/forest-gate-game.webp`
- 카메라·접지점·크기·부품 수·파일 해시: `public/defense/models/forest-gate.json`
- 같은 명령에서 생성하는 화면 배치 계약: `src/games/defense/forestGateModel.ts`

512×512 정사영 렌더에서 원점의 접지점은 약 `(256,399.923)`이다. 표시 크기 170×170에 맞춰 이미지 위치를 계산하며, 카메라를 바꾸면 생성된 배치 계약도 함께 갱신된다. 제작 환경의 Blender에는 OpenImageDenoise가 없어 Cycles 96샘플·디노이즈 끔으로 생성한다.

작업실은 `/model-lab.html?model=forest-gate`에서 실제 GLB 회전·메시 보기·시점 초기화를 제공한다. 정적 구조물이므로 공격 재생 버튼은 표시하지 않는다. GLB 실패 시 PNG라는 표기와 함께 렌더 이미지로 대체한다.

## 전투에서의 순서와 실패 대체

마을 원점은 `(830,318)`, 확장 거점은 `(840,131)`과 배율 0.82다. 모델 카메라에서 앞쪽 기초 기준점을 투영해 마을 `Y≈327.612`, 확장 거점 `Y≈138.882`를 정렬 기준으로 사용한다. 성문은 영웅·적·포탑과 같은 Y 정렬 목록에 들어간다. 뒤쪽 유닛은 기둥·아치에 가려지고 열린 통로에서는 보이며, 앞쪽으로 나오면 성문 위에 그려진다.

이는 단일 기준점으로 정렬하는 2.5D 가림이다. 실시간 전장의 깊이 버퍼나 성문 충돌을 추가한 것은 아니다. 전투 효과는 기존 효과 레이어를 사용한다. 성문 그룹은 포인터 이벤트를 받지 않아 이동·건설 입력을 가로채지 않는다.

성문 로딩 결과는 배경 대체 화면과 유닛 정렬 모델이 공유한다. 모델 이미지 실패 시 같은 테마의 기존 삽화, 삽화도 실패하면 SVG 성문을 표시한다. 테마를 바꾼 뒤 이전 이미지 요청이 늦게 끝나도 새 테마를 덮어쓰지 않는다. 파괴된 확장 거점의 흐린 표시는 유지한다.

## 검증

- Blender 원본 재열기와 GLB 재가져오기: 네 높이에서 통로를 관통하는 광선은 비충돌, 양쪽 기둥 광선은 충돌. 전체 메시가 렌더 경계 안에 들어간다. 전투 WebP의 통로 알파는 투명이다.
- 관련 57개 검사 통과. 원격 main의 새 약점·보상·선두 표적 검사와 기존 포탑 반동 검사를 함께 보존했다. 전체 182개 중 181개 통과이며, 기존 수학 엔진 `(3 × 7) ÷ 5`의 4/4.2 불일치 1건은 남아 있다. 프로덕션 빌드 통과.
- 설치된 Playwright·Chromium 1440×900 / 390×844 실제 UI에서 성문 옆 6번 지점 포탑 건설, 영웅 앞뒤 이동, 일시정지/재개, 2배속, 동작 줄이기를 확인했다. 모바일 전체/확대 전장을 확인했다.
- 고정 상태의 실제 전투 컴포넌트에서 마을·확장 거점 앞뒤 정렬, 파괴된 거점 표시, 세 가지 다른 테마와 설산, 모델/삽화 실패 대체, 늦은 요청 이후 테마 보존을 확인했다.
- 작업실에서 회전·메시 표시·동작 줄이기·GLB 실패 대체를 확인했다. 예상 밖 페이지 오류와 가로 넘침은 없었다. 실제 Android 기기 성능은 아직 측정하지 않았다.

컨셉의 미세한 이끼·나뭇결·석재 표면과 다른 테마의 구조 모델은 남은 품질 범위다. 다음 동작 후보는 성문 침입 충격과 실제 피해 시점의 연결이다. 이번 회차는 예약 상태를 확인하거나 변경하지 않았다.

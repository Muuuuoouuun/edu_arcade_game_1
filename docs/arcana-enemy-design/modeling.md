## 가장 중요한 제작 제약 5개
1. 현재 전달물은 2.5D 스프라이트다. 기존 6종의 편집 가능한 Blender 계층을 재사용하고 새싹·보스 모델은 신규 제작 제안으로 구분한다. GLB·리깅·런타임 애니메이션이 이미 있다고 말하지 않는다.
2. 이동 위치·속도·피해·동결·사망은 엔진 이벤트가 권위다. 걷기는 엔진 이동 거리에 맞춰 발 접지 위상을 바꾸는 in-place 루프다. 로컬 발은 접지 동안 뒤로 움직여 월드 접지를 유지하고 골반은 상하로만 보정한다. root-motion 데이터는 제작 참고만 사용하고 게임 경로를 두 번 이동시키지 않는다.
3. 동일 유닛의 모든 포즈는 고정 직교 카메라·원점·ground anchor·스케일·공통 crop을 사용한다. 48/64 CSS px에서 흑백 실루엣만으로 7종을 구분한다. 프레임마다 자동 맞춤 확대 금지. 빙설/숲 양쪽 배경과 좌우 반전을 확인한다.
4. windup/strike/recover는 마을 도달 연출 또는 실제 구현된 보스 능력에만 연결한다. 주변 영웅을 때려 HP를 깎는 것처럼 연출하지 않는다. hit는 상체 흔들림/짧은 재질 반응으로 locomotion·보스 충전 시계를 덮어쓰지 않는다. 고목왕의 빨라짐을 신규 근접 공격으로 바꾸지 않는다.
5. 보스 경고는 몸 실루엣 변화+짧은 게이지/아이콘으로 보여준다. 서리군주의 효과는 실제 동결 타워에만 짧게 표시한다. 화면 전체 눈보라/플래시 금지. 보스 처치 필수·도주 즉시 패배는 향후 규칙 제안이며 현행 엔진 기능이 아니다.

## 애니메이션 팩·인계
- 일반 팩 제안: idle 2, walk 6, windup 2, strike 1, recover 2, hit overlay 1, death 4 = 유닛당 18포즈. 일반 적에게 실제 타격 시스템이 추가되지 않는 한 도달 연출은 필수 납품에서 제외 가능. 초기 납품 우선순위는 walk 6/hit 1/death 4다.
- 보스 팩 제안: idle 2, walk 8, 능력 windup 3, release 1, recover 2, interrupted 2, hit overlay 1, death 6 = 25포즈. 고목왕은 가속 walk 변형 4포즈 추가 후보. 충전 포즈의 보간 재생 시간은 실제 2.5초 상태값에 연결한다.
- 일반 windup 0.20–0.35초/strike 0.08–0.12초/recover 0.20–0.35초, death 0.35–0.60초는 제안이다. 사망 시 논리 제거/보상은 즉시 엔진이 확정하고 death는 별도 잔상이다. hit 0.06–0.10초 상체 레이어 제안, 공격·충전 타이머 재시작 금지.
- 384px 프레임 18장 압축 전 RGBA는 약 10.1MiB/종, 25장은 약 14.1MiB/종이다. WebP 파일 크기와 디코드 메모리는 다르다. 한 줄 6912px/9600px 시트를 피하고 5열×4행/5열×5행 등 2048px 이내 페이지를 제안한다. 보스 512px는 여러 페이지가 필요하며 실제 48/64px 비교 후 결정한다. 한 번에 전종 전체 고해상도 팩을 미리 읽지 않고 스테이지별 로딩을 검토한다(현재 미구현).
- 정예 복제는 기존 몸/리그 재사용+크기 고정. 나무의 깃발 가지, 돌의 어깨 쐐기, 금속의 이중 등핀 같은 외곽 부속 1개와 엠블럼을 색과 함께 사용한다. 컬러만 바뀌는 정예 금지. 정예라는 신규 능력/스탯은 별도 규칙 승인이 필요하다.
- 납품 파일 제안: source.blend, pose-map.json(이름·ground·nativeFacing·카메라·크롭·루프·이벤트 표시), 투명 atlas.webp, 48/64px 양배경 비교판. 신규 모델의 GLB는 향후 뷰어 요구가 있을 때 별도 산출물로 명시한다.
- 수용 확인: 9종 흑백 축소 구분, 6연속 보행 발접지, 좌우 반전, 사망 전후 크기 고정, 무기 잘림 없음, charge 중 hit가 경고를 지우지 않음, 전역 필살기 차단과 시각 반응 동시 발생, 실제 피해 없는 아군에 피해 숫자 금지. 여기서 확인 항목은 제안이며 실행한 테스트가 아니다.

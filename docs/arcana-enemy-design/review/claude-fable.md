# 인계안 독립 검토 (2026-11-09)

## 과장 여부 판정
- **확인됨**: 문서는 6종 json을 "GLB가 아닌 baked 2.5D atlas(1152×384, 3포즈)"로, `build_*.py`를 "keyframe/armature 미확인"으로 기술하며, 새싹·보스는 신규 제안으로 분리했다. GLB·리깅 완료로 과장한 문구는 없다. 삼각형/재질/포즈 수는 모두 "추정"으로 표기됨.
- **가설**: 표의 피벗 목표(늑대 18–24, 보스 20–28)는 문서가 인용한 기존 `build_wolf.py` 피벗(목·머리·턱·꼬리·4다리 ≈ 8개)의 2–3배다. "기존 계층 재사용"이라 쓰면 리깅 신규 작업량이 과소평가될 수 있다.

## 높은 우선순위 수정 (5개)

1. **[높음 / art.ts·atlas 포맷]** 포즈 확장(일반 3→18, 보스 4→25)은 `art.ts:76–112`의 walk-a/walk-b/hit→idle/charge/death 매핑과 1152×384 3포즈 json 포맷 변경을 전제한다. 초기 납품안(walk 6/hit 1/death 4=11포즈)조차 현행 로더와 불일치. 문서에 "현행 로더 미지원, 별도 코드 작업 필요"를 명시하고 아트 납품과 로더 변경을 분리 승인해야 한다.
2. **[높음 / 발접지·경로 권위]** "발 접지 위상을 엔진 이동 거리에 맞춘다"는 요구는 옳으나, 현재 walk-a/walk-b 전환이 시간 기반인지 path progress 기반인지 문서에 확인 기록이 없다. `engine.ts:348–350` 고목왕 1.55배 가속 시 시간 기반이면 발 미끄러짐이 발생한다(가설). 선택 기준을 확인한 뒤 거리 기반 프레임 인덱스를 요구사항으로 고정할 것. 거리 기반이면 "고목왕 가속 walk 4포즈"는 불필요할 수 있음.
3. **[중간 / 예산]** 계산값(18장 10.1MiB, 25장 14.1MiB, 5×4 페이지 2048px 이내)은 정확하다. 그러나 9종 합산 디코드 메모리 ≈ 100MiB+이며, 현행 6종(≈1.7MiB×6 ≈ 10MiB) 대비 약 10배. 페이지 분할은 메모리를 줄이지 않고 스테이지별 로딩은 미구현. 48/64 CSS px 표시 대비 384px은 6–8배 오버샘플이므로, 초기 납품을 11포즈로 제한하고 256px 실측 비교를 선행 조건으로 추가할 것.
4. **[중간 / 보스 충전]** "interrupted 2포즈·차단 시 고리 끊김"과 "충전 보간을 실제 2.5초 상태값에 연결"은 `engine.ts:400–416`의 충전 진행도·전역 차단 상태가 렌더러에 노출될 때만 가능하다. 노출 여부가 문서에 확인되지 않았다(가설). 확인 전까지 interrupted 포즈는 선택 납품으로 내리고, 보스 4포즈→25포즈도 `/defense/boss-models.webp` 로더 변경 항목으로 분리할 것.
5. **[낮음 / 범위·검증]** 새싹 도적은 `MONSTER_MODELS`에 없는데 현재 어떻게 렌더되는지(폴백) 미기재. 또한 "48px 흑백 실루엣 7종 구분" 수용 기준에 판정 방법(예: 배경 2종×반전 2 비교판, 판정자 수)이 없어 합격/불합격 판단이 불가능하다. 기준을 수치화할 것.

## 제작 진행 판단
**조건부 진행.** 문서의 기술 사실 기술과 권위 분리(엔진 path progress·충전 시계·사망 확정)는 적절하다. 다만 ① 로더/포맷 변경 작업 분리, ② 발접지 프레임 선택 기준 확인, ③ 해상도·메모리 실측 비교를 선행한 뒤 초기 납품(walk 6/hit 1/death 4, 기존 6종 우선)만 착수하고, 보스 25포즈·새싹 신규 모델·GLB·정예 복제는 보류를 권고한다. 본 검토는 문서 검토이며 코드 실행이나 테스트를 수행하지 않았다.

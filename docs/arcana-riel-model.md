# 리엘의 실제 모델과 방향별 활 발사·보행

2026-11-07 KST, `codex/arcana-stage-experience-20261106`의 `e580a7f`에서 이어갔다. 원격 main `785154a`, Claude `c03beb5`/`bf7c1c6`와 기존 이안·브론·서리늑대·포탑·지형의 완료 기록을 확인했다. 작업 트리는 깨끗했고 겹치는 개발 작업은 없었다.

## 컨셉과 구현

`art-source/defense/atlases/ranged-motion.png`의 리엘은 초록 후드와 망토, 금발, 긴 귀, 가죽 장구, 곡선 활로 구별된다. 기존 전투는 세 장의 삽화를 좌우 반전하고 별도의 큰 SVG 활 효과를 겹쳤다. 실제 리엘 모델이나 활대·시위 관절은 없었다.

열린 후드의 두께, 뾰족한 귀, 얼굴을 감싸는 금발, 잎 모양 튜닉·금장, 망토, 장화·팔 보호대·화살통과 굽은 활을 실제 메시로 제작했다. 첫 렌더를 보고 활을 얼굴 바깥으로 옮기고 화살 길이를 늘렸다. 최종 옆모습에서 두 발이 겹치던 부분은 앞뒤로 벌린 지지 자세로 보완했다. 기존 삽화의 복잡한 덩굴 장식과 세밀한 얼굴·천 표현은 작은 크기에 맞춰 단순화했다.

여덟 방향은 실제 원본을 회전해 렌더한다. 활과 화살을 쥔 손을 뒤집지 않으며, 영웅·용병의 대기·보행·발사에 같은 몸을 사용한다. 초상화와 영웅 선택 화면은 기존 컨셉 삽화를 유지한다. 대시와 필살기도 기존 전투 우선순위를 유지하면서 모델 몸을 표시한다.

## 활과 발사 시점

| 클립 | 원본 움직임 | 전투 표현 |
| --- | --- | --- |
| `riel-cast` | 0.28초, 중립→당기기→0.10초 발사→회수→중립 | 대기·당기기·발사·회수 4포즈 |
| `riel-walk` | 0.8초, 활을 들고 양발 지지/회수와 망토·머리카락 움직임 | 이동 거리 기준 8포즈 |

몸통·고개·머리카락·망토·양다리, 양팔의 상완/전완, 양손, 활대 8구간, 시위 2구간, 장전 화살을 실제 변환 노드로 연결한다. 시전은 100fps의 매 프레임에서 활대 끝·시위·당김점을 같은 좌표로 계산한다. 화살은 발사 전까지 시위와 함께 뒤로 이동하고, 발사 프레임에 숨긴 뒤 회수 과정에서 다시 장전된다. 시전 중 발은 고정된다. 스킨 리그나 발 IK를 구현한 것은 아니다.

전투의 `hitAt=0.1`, `duration=0.28`은 기존 값이다. 준비·발사·회수 포즈는 이 시간을 따르고 작업실은 실제 GLB 클립을 보간한다. 전투의 구간별 이미지 표시를 연속 3D 렌더라고 표현하지 않는다.

실제 `arrow-socket`을 공통 카메라로 투영해 발사점으로 사용한다. 발사 당시 방향 `launchAim`과 기본/승급 몸 크기 `sourceSize`를 저장하므로 이후 표적 추적·영웅 이동·승급으로 이미 날아간 화살의 출발점이 바뀌지 않는다. 모바일 유닛 배율도 반영한다. SVG 화살의 촉은 로컬 x=16이므로 새 모델 화살에는 -16 보정을 적용해 **촉 끝**이 소켓에서 출발하도록 했다. 다른 화살과 로딩 실패 대체의 기존 기준은 유지한다.

완전한 새 이미지 세트가 준비되면 기존 큰 SVG 활과 범용 몸 흔들기를 끈다. 한 장이라도 실패하면 리엘 전체가 기존 삽화 세트로 돌아가며, 다른 영웅의 모델은 유지한다. 일시정지와 배속은 기존 시뮬레이션 시간을 사용한다. 동작 줄이기는 보행 순환·당김·회수 대신 대기/발사 단서를 남긴다. 피해·사거리·추적·충돌·보상·승패 규칙은 바꾸지 않았다.

## 원본과 재생성

```bash
npm run models:elf
npm run models:elf -- --check
npm run models:elf -- --preview
```

전체 생성은 Blender와 FFmpeg를 사용한다. `--check`는 포즈의 카메라 경계를 검사하며, `--preview`는 0·1방향의 네 시전 포즈를 `/tmp/arcana-elf-preview-{direction}-{pose}.png`에 출력한다.

- 제작 코드: `tools/blender/build_elf.py`
- 편집 원본: `art-source/defense/riel-archer.blend`, `riel-archer-walk.blend`
- 공통 렌더: `art-source/defense/riel-archer/`, 384×384 투명 PNG 96장, Cycles CPU 64샘플
- 전투: `public/defense/models/riel-cast-{0..7}-atlas.webp`, `riel-walk-{0..7}-atlas.webp`, 256px 셀 4개/8개
- 작업실: `public/defense/models/riel-archer.glb`, `riel-archer-walk.glb`와 같은 카메라 PNG. `/model-lab.html?model=riel-archer` 및 `?model=riel-archer-walk`
- 메타데이터: `public/defense/models/riel-archer.json`, 카메라·포즈 경계·화살 끝·클립·컨셉 및 납품 파일 해시
- 생성 좌표: `src/games/defense/elfSockets.ts`, 위 명령이 함께 재생성

정사영 배율 6.8, 원본 지면 `(192,330)`, 전투 셀 지면 `(128,220)`, 표시 배율 `1.2×6.8/5.8`로 기존 영웅 카메라를 유지한다. 포즈별 자르기나 확대율 변경은 없다. 원본은 편집 가능한 개별 부품이며 GLB는 관절/재질별로 묶는다. 이미지 평면으로 만든 모델이 아니다.

GLB는 시전 1,200,816바이트, 보행 1,193,152바이트이며 각각 **16,734삼각형·55메시·14재질**이다. 새 전투 WebP는 총 465,312바이트, 디코딩한 RGBA 픽셀 합은 **24MiB**다. 기존 대체 이미지도 로드하므로 메모리 비용이 추가된다. 실제 기기의 GPU 메모리 측정값은 아니다. 전투에서는 GLB를 요청하지 않으며 유닛별 WebGL 렌더러도 만들지 않는다.

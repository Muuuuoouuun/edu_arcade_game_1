# 청운의 실제 모델과 방향별 부적 시전·보행

2026-11-07 KST, `codex/arcana-stage-experience-20261106`의 `76ee421`에서 이어갔다. 원격 main `785154a`, Claude `42728f7`/`bf7c1c6`와 기존 완료 기록을 확인했다. 작업 트리는 깨끗했고 겹치는 로컬 개발 작업은 없었다. Claude 45회차의 속성별 피격 기획과 구현을 마친 검토 대기 PR #78도 읽었다. 해당 PR의 물·번개 색 변경을 이번 모델 작업에 합치지는 않았다.

## 컨셉과 구현

실제로 열어 본 원본은 `art-source/defense/atlases/ranged-motion.png`, `art-source/defense/concepts/2026-10-29/heroes/talisman-caster.png`, 같은 폴더의 `motion/talisman-cast-keyposes.png`다. 기존 청운 전투는 삽화 세 장과 좌우 반전을 사용했다. 청록 도포·흰 겹깃·넓은 소매·검은 묶음머리·붉은 끈·호박색 부적을 실제 메시로 옮겨 방향이 달라도 같은 장비와 몸을 유지하도록 했다.

도포의 벌어진 앞자락·금장·구름 장식, 뒤쪽 천의 두께, 붉은 허리 매듭·술, 부적집, 검은 앞머리·상투·금장 머리 장식·묶음머리, 장화와 바지, 소매 안쪽과 손, 붓의 대나무 손잡이·금속 고리·붓털을 구분했다. 부적은 두께와 붉은 양각 표시가 있는 메시이며 위쪽 종이 조각을 별도로 움직인다. 작은 화면에서 읽히도록 원본의 세밀한 자수·천 주름·얼굴을 단순화했다. 초상화와 영웅 선택 화면의 삽화는 유지한다.

## 움직임과 전투 연결

| 클립 | 원본 움직임 | 전투 표현 |
| --- | --- | --- |
| `cheongun-cast` | 0.33초, 대기→모으기→들어 올리기→0.15초 내밀기→반동→회수 | 여덟 방향의 대기·준비·발사·회수 4포즈 |
| `cheongun-walk` | 0.8초, 양발 지지/회수와 반대 팔·도포·머리카락·종이의 후속 움직임 | 여덟 방향의 이동 거리 기준 8포즈 |

몸·머리·머리카락·뒤 도포·양다리·앞자락 두 개·양쪽 상완/전완·손·부적·종이 조각의 **16개 변환 노드**를 움직인다. 양팔은 손과 팔꿈치 위치로 상완/전완의 길이·방향을 함께 계산한다. 초기 보행의 키 사이에서 팔 끝이 약 0.00046 모델 단위 벌어지는 것을 검사로 발견해 시전과 보행 모두 100fps의 매 프레임에서 다시 계산했다. 시전 중 다리와 장화는 고정한다. 스킨 리그나 지형 발 IK는 아니다.

전투의 기존 `hitAt=0.15`, `duration=0.33`을 유지한다. 실제 `seal-socket`을 공통 카메라로 투영해 준비 광원과 마법탄 출발점에 사용한다. 발사 당시 방향 `launchAim`과 기본/승급 크기 `sourceSize`를 저장해 추적·이동·승급 후에도 이미 발사된 탄의 시작점을 보존한다. 모바일 유닛 배율도 반영한다.

영웅과 용병의 대기·보행·시전·돌진·필살기에 같은 모델 몸을 사용한다. 완성된 16장 이미지 세트가 준비되면 범용 몸 흔들기와 고정 손 위치의 마법 입자를 중복하지 않는다. 한 장이라도 로딩에 실패하면 청운 전체를 기존 삽화 세트로 대체하며 다른 완료 모델은 유지한다. 동작 줄이기는 대기/발사 단서를 남기고 보행 순환·준비·회수를 생략한다. 일시정지와 배속은 기존 시뮬레이션 시간을 따른다. 피해·사거리·추적·충돌·보상·승패는 바꾸지 않았다.

## 원본과 재생성

```bash
npm run models:tao
npm run models:tao -- --check
npm run models:tao -- --preview
```

전체 생성은 Blender와 FFmpeg를 사용한다. `--check`는 포즈의 카메라 경계를 검사하며 `--preview`는 0·1방향의 네 시전 포즈를 `/tmp/arcana-tao-preview-{direction}-{pose}.png`에 출력한다.

- 제작 코드: `tools/blender/build_tao.py`
- 편집 원본: `art-source/defense/cheongun-tao.blend`, `cheongun-tao-walk.blend`
- 공통 렌더: `art-source/defense/cheongun-tao/`, 384×384 투명 PNG 96장, Cycles CPU 64샘플
- 전투: `public/defense/models/cheongun-cast-{0..7}-atlas.webp`, `cheongun-walk-{0..7}-atlas.webp`, 256px 셀 4개/8개
- 작업실: `public/defense/models/cheongun-tao.glb`, `cheongun-tao-walk.glb`와 같은 카메라 PNG. `/model-lab.html?model=cheongun-tao` 및 `?model=cheongun-tao-walk`
- 메타데이터: `public/defense/models/cheongun-tao.json`, 카메라·포즈 경계·부적 소켓·클립·컨셉 경로와 납품 해시
- 생성 좌표: `src/games/defense/taoSockets.ts`, 위 명령이 함께 재생성

정사영 배율 6.8, 원본 지면 `(192,330)`, 전투 셀 지면 `(128,220)`, 표시 배율 `1.2×6.8/5.8`로 기존 영웅 카메라를 유지한다. 포즈마다 자르거나 확대율을 바꾸지 않는다. 원본은 개별 부품으로 편집하며 GLB만 관절/재질별로 묶는다. 이미지 평면 모델이 아니다.

최종 GLB는 시전 1,826,196바이트, 보행 1,840,300바이트이고 각각 **26,668삼각형·51메시·13재질**이다. 전투 WebP 합은 433,850바이트, 디코딩한 RGBA 픽셀 합은 **24MiB**다. 기존 대체 이미지도 로드하므로 추가 메모리 비용이 있다. 실제 기기의 GPU 메모리 측정값은 아니다. 전투는 베이크한 2.5D이고 GLB를 요청하지 않는다. 작업실만 실시간 3D이며 유닛별 WebGL 렌더러는 추가하지 않았다.

## 검증과 남은 차이

전후 화면·검사 코드·로그·소유권과 상태 기록은 저장소 밖 `/tmp/arcana-hourly-20261107-0638/`에 남겼다.

- 관련 엔진·공격·에셋 테스트 **105개 통과**, 전체 **208개 중 207개 통과**. 기존 수학 게임 `(3 × 7) ÷ 5` 정답 4/4.2 불일치 1건이 남아 있다. 최종 타입 검사·프로덕션 빌드 통과.
- 기준 엔진과 스테이지 1·4·5·8 × 강화/판매 유무의 8게임을 매 프레임 비교했다. 게임마다 청운 탄 78~155발을 관측했고 새 발사 시각 기록 두 필드를 제외한 전투 상태가 일치했다. 별도 테스트로 추적·이동·승급 후 발사점과 용병 크기를 검사했다.
- 최종 `.blend` 재열기·GLB 재가져오기 통과. 시전의 고정 다리/장화 메시 12개 변환 차이 0, 발바닥 최저 높이 약 0.005 모델 단위, 보행 때 한쪽 발은 지지하고 반대쪽 최고 높이는 약 0.125다. 시작/끝 자세 차이는 0.000001 미만, 원본/GLB 관절 행렬 차이는 최대 약 0.00000054다. 모든 원본 프레임에서 양쪽 상완/전완/손 연결도 검사했다. 초기 연결 실패와 수정 로그를 보존했다.
- 최종 PNG 96장·WebP 16장의 크기·투명 경계·잘림·납품 해시, GLB의 실제 클립 이름·길이·이미지 미사용 검사 통과.
- Chromium 1440×900 / 390×844에서 입장→이동→정지→웨이브→시전→일시정지/재개→2배속을 실제 UI로 조작했다. 보행 8포즈와 시전 4포즈, 발사 전 strike 포즈 없음, 동작 줄이기의 대기/발사를 확인했다. 관측 공격 구간은 PC 314/174ms, 모바일 344/162ms(1배속/2배속)로 브라우저 관측 간격을 포함한다. 모바일 기본 확대 화면의 실제 시전도 확인했다.
- 영웅/용병 × 8방향 × (대기·공격 7시점+보행 8포즈) × PC·모바일·동작 줄이기·시전 이미지 실패·보행 이미지 실패 **1,200조합** 통과. 중복 몸 변형·부분 로딩의 몸 교대·전투 GLB 요청·페이지 오류가 없었다.
- 준비 광원/투사체 시작점은 영웅/용병·승급 유무·8방향·PC/모바일/동작 줄이기/실패 대체 **256조합**으로 검사했다. 원본 투영과 화면 좌표 오차는 최대 약 0.000034px였다.
- 최종 작업실 PC/모바일의 실제 GLB 시전/복귀·보행 재생/정지·자동 회전·메시 보기·다운로드 링크·동작 줄이기·GLB 실패 시 PNG 대체를 확인했다. 전후 게임 화면과 모델을 직접 비교했으며 페이지 오류·가로 넘침은 없었다.

같은 몸의 8방향 자세와 부적에서 출발하는 발사점으로 기존 삽화 반전·장비 위치 불일치를 줄였다. 컨셉의 유연한 허리 회전·천 주름·표정은 더 다듬어야 한다. 보행→시전 전신 보간, 연속 회전, 실제 Android의 메모리·성능은 미완료이며 모바일 검증은 Chromium 에뮬레이션이다.

다음 후보는 영웅의 보행→공격 발 전환, 루나의 도포·지팡이 실제 모델, 남은 성 테마의 입체 건축이다. 기존 완료 모델과 포탑 단위는 반복하지 않는다. 이번 회차는 예약 상태를 조회·변경하지 않았으며 Claude API 호출·자동 main 병합·서비스 배포도 수행하지 않았다.

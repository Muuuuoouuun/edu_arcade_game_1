# 이안의 실제 모델과 방향별 시전·보행

2026-11-07 KST, `codex/arcana-stage-experience-20261106`의 `56db2f8`에서 이어갔다. main `785154a`, Claude `c03beb5`/`bf7c1c6`와 진행 중인 작업을 확인했다. 이번 회차에서 원격 기획·완료 작업과 겹치는 병합이나 재제작은 없었다.

## 컨셉에서 전투로

`art-source/defense/atlases/ranged-motion.png`의 이안은 꺾인 파란 모자, 밝은 머리카락, 금색 테두리 코트와 큰 수정 지팡이로 구별된다. 기존 전투는 삽화 세 포즈를 잘라 좌우 반전했으며, 이안의 실제 3D 모델은 없었다. 브론·서리늑대·포탑의 완료된 단위는 유지하고 이안의 몸과 시전을 선택했다.

모자의 넓은 챙과 꺾인 끝, 아이보리 머리카락, 남색 코트의 갈라진 자락, 크림색 속옷, 가죽 장화·책, 금장과 사파이어 수정 지팡이를 실제 메시로 제작했다. 첫 공통 카메라 렌더를 보고 천을 어둡게 조정하고 수정을 키웠다. 머리·몸통·지팡이팔·손목·반대팔·망토·양다리를 독립 관절로 연결했다. 이미지 평면을 모델로 표시한 것이 아니다.

영웅과 용병 모두 같은 원본으로 대기, 보행, 시전, 복귀를 표시한다. 여덟 방향은 원본 자체를 회전해 베이크하므로 지팡이를 쥔 손을 반전하지 않는다. 보행도 함께 만든 이유는 이동할 때만 삽화 몸으로 돌아가는 단절을 피하기 위해서다. 초상화와 영웅 선택은 기존 컨셉 삽화를 유지한다.

## 움직임과 발사점

| 클립 | 실제 원본 동작 | 전투 표시 |
| --- | --- | --- |
| `ian-cast` | 0.33초, 중립→0.10초 준비→0.15초 발사→0.25초 회수→중립 | 대기와 준비·발사·복귀 4포즈 |
| `ian-walk` | 0.8초, 양다리 지지/회수와 몸통·팔·망토의 작은 움직임 | 이동 거리 기준 8포즈 |

시전 중 다리·장화는 고정하고 상체와 지팡이로 힘을 전달한다. 보행에서는 한쪽 장화가 지면을 지지하고 반대쪽이 올라간다. 스킨 리그, 발 IK, 임의 이동 속도에서의 완전한 미끄러짐 방지는 구현하지 않았다. 작업실은 실제 관절 클립을 보간하고, 전투는 대표 포즈를 구간별로 표시하는 2.5D다.

수정 끝의 `cast-socket`을 같은 카메라로 투영해 준비 광원과 발사체 출발점을 연결했다. 엔진은 마법탄을 발사할 때 `launchAim`과 기본/승급 몸 크기 `sourceSize`를 기록한다. 이후 표적 추적, 영웅 이동, 승급으로 이미 발사한 탄의 출발점을 바꾸지 않는다. 모바일 표시 배율도 반영한다. 피해·충돌·사거리·보상·승패 규칙은 바꾸지 않는다.

범용 몸 흔들기와 고정된 손 주변의 마법 입자는 모델 시전과 중복하지 않도록 했다. 기존 대시·필살기의 우선순위를 유지하면서 같은 몸과 방향을 사용한다. 일시정지와 배속은 전투 시뮬레이션 시간을 따르고, 동작 줄이기는 대기/발사 단서만 남긴다. 16개 방향 이미지가 모두 준비돼야 교체하며, 한 장이라도 실패하면 이안 전체를 기존 삽화 표현으로 되돌린다.

## 원본과 재생성

```bash
npm run models:mage
npm run models:mage -- --check
npm run models:mage -- --preview
```

전체 재생성은 Blender와 FFmpeg를 사용한다. `--check`는 카메라 경계를 검사하고, `--preview`는 `/tmp/arcana-mage-preview-*.png`에 정면 대각선 시전 미리보기를 만든다.

- 제작 코드: `tools/blender/build_mage.py`
- 편집 원본: `art-source/defense/ian-mage.blend`, `ian-mage-walk.blend`
- 공통 렌더: `art-source/defense/ian-mage/`, 384×384 투명 PNG 96장, Cycles CPU 64샘플
- 전투: `public/defense/models/ian-cast-{0..7}-atlas.webp`와 `ian-walk-{0..7}-atlas.webp`, 256px 셀 4개/8개
- 작업실: `public/defense/models/ian-mage.glb`, `ian-mage-walk.glb`와 같은 카메라 PNG. `/model-lab.html?model=ian-mage` 또는 `?model=ian-mage-walk`
- 메타데이터: `public/defense/models/ian-mage.json`의 카메라, 포즈 경계, 소켓, 클립, 컨셉 및 납품 파일 해시
- 전투 소켓: `src/games/defense/mageSockets.ts`, 위 명령이 함께 재생성

정사영 배율 6.8, 원본 지면 `(192,330)`, 전투 셀 지면 `(128,220)`, 표시 배율 `1.2×6.8/5.8`로 기존 영웅 카메라와 맞춘다. 포즈마다 자르기나 크기 보정을 하지 않는다.

GLB는 시전 1,393,588바이트, 보행 1,397,436바이트다. 각각 21,122삼각형, 내보내기 메시 객체 36개, 14재질이다. 작업실에서 37개 메시로 보이는 것은 다중 재질 primitive 분리 때문이다. 전투 WebP 16장은 총 532,880바이트이며 RGBA 픽셀 합은 **24MiB**다. 기존 대체 이미지도 로드하므로 메모리 비용이 추가된다. 이 수치는 실제 기기의 GPU 메모리 측정값이 아니다. 전투는 GLB를 요청하거나 유닛별 WebGL 렌더러를 만들지 않는다.

## 검증

증거와 전후 화면은 저장소 밖 `/tmp/arcana-hourly-20261107-0437/`에 기록했다.

- 관련 테스트 **99개 통과**, 전체 **202개 중 201개 통과**, 타입 검사와 프로덕션 빌드 통과. 기존 수학 게임 `(3 × 7) ÷ 5`의 4/4.2 정답 불일치 1건은 남아 있다.
- 기준 엔진과 스테이지 1·4·5·8, 강화/판매 유무의 8게임을 매 프레임 비교했다. 새 시각 기록을 제외한 피해·투사체·충돌·승패·보상 상태가 일치했다. 별도 엔진 검사에서 이동 표적·영웅 이동·승급 후 발사 방향/크기 보존과 용병 크기를 확인했다.
- `.blend` 재열기와 GLB 재가져오기: 시전의 다리·장화 메시 10개 변환 차이 0, 전 프레임 최저 발바닥 약 0.005 모델 단위. 보행 중 한쪽 발은 같은 높이를 유지하며 반대쪽 최대 높이는 약 0.145다. 시작/끝 자세 차이는 0.000001 미만, 원본/GLB 관절 행렬 차이는 최대 약 0.00000036이다.
- PNG 96장과 WebP 16장의 해상도·투명 경계·잘림, 납품 해시, GLB의 실제 클립 이름·길이와 이미지 평면 미사용을 검사했다. 소켓은 기본/승급/모바일 크기에서 원본 투영과 일치했다.
- Chromium **1440×900 / 390×844 터치 뷰포트**에서 입장→이동→정지→웨이브→시전→일시정지/재개→2배속을 실제 조작했다. 두 환경에서 8개 보행 포즈와 준비·발사·복귀를 관측했다. 발사 전에 발사 포즈가 나오지 않았으며 동작 줄이기는 대기/발사만 남았다. 관측 시전 구간은 PC 375/166ms, 모바일 323/176ms(1배속/2배속)로 브라우저 관측 간격을 포함한다.
- 제어 상태에서 영웅/용병×8방향×(대기·시전 7시점+보행 8포즈)×PC·모바일·동작 줄이기·시전 이미지 실패·보행 이미지 실패 **1,200조합**을 검사했다. 몸의 중복 변형·장비 좌우 반전·부분 실패의 몸 교대가 없고, 기존 대시/필살기와 전투 GLB 미요청도 확인했다.
- 작업실 PC/모바일에서 시전/복귀, 보행 재생/정지, 자동 회전, 메시 보기, 다운로드 링크, 동작 줄이기와 GLB 실패 시 PNG 대체를 확인했다. 페이지 오류나 가로 넘침은 없었다. 첫 검사는 정지 버튼 직후의 이전 캔버스를 비교해 실패했다. 검사 시계를 다음 화면 갱신까지 진행하도록 수정한 뒤 통과했으며 초기 실패 로그도 보존했다.
- 편집 전·후 같은 전장/위치/시점 화면과 실제 전투·모델 작업실을 직접 비교했다. 작은 크기에서도 모자·코트·수정의 구분을 유지하고 시전 방향과 탄 출발점이 연결된다. 원본 삽화의 섬세한 천 주름·얼굴 표정까지 재현한 결과는 아니다.

모바일 검증은 Chromium 에뮬레이션이며 실제 Android 성능 검증이 아니다. 다음 후보는 엘프의 활 시위·방향별 발사 모델 또는 이안의 보행→시전 발 자세 보간이다. 연속 회전, 발 IK, 천·얼굴의 세밀한 표현과 저사양 메모리 검증은 남아 있다.

이번 회차는 예약 자동화의 현재 활성 상태를 조회·변경하지 않았다. Claude API 호출, 자동 main 병합, 서비스 배포도 수행하지 않았다.
